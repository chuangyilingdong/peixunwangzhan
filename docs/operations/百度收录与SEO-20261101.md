## 五、`ecs.misoos.com` 重复站（2026-11-01 16:21 已处理）

### 它不是潜在风险，是已经在发生

改之前查了当天的 `access.log`：`ecs.misoos.com` 共 **104 条请求**，其中
**`Baiduspider-render/2.0` 占 47 条、全部 200**，还执行了 JS，把
`/api/public/website-content/HOME` 和一批素材图都取走了。百度已经在抓这个重复站。

根因：`sites-enabled` 里只有 `aicyld.com` 与 `www.aicyld.com` 两个 server 块，
**没有任何 `default_server`**，nginx 把第一个 443 块当成了 catch-all。
任何指向本机 `8.138.150.19` 的域名都会拿到整套官网。

### 改动

新增 `/etc/nginx/sites-enabled/zz-default-host.conf`：

| Host | 80 | 443 |
| --- | --- | --- |
| `aicyld.com` | 301 → https（原有） | 200（原有） |
| `www.aicyld.com` | 301 → 主域（原有） | 301 → 主域（原有，验证文件例外） |
| `ecs.misoos.com` | **301 → aicyld.com** | **301 → aicyld.com** |
| 其它未知 Host | 301 → aicyld.com | **444（关连接，不发任何字节）** |
| 任意 Host 的 `/api/health` | — | 200（按 IP 也能探活） |

设计说明：

- **80 端口统一 301 回主域**：没有证书问题，任何陌生域名都被并回主域；
- **443 未知 Host 用 444 而不是 301**：证书只有 `aicyld.com`，浏览器会先报证书错误，
  301 对人没有意义；关连接能保证一个字节都不外泄；
- **`ecs.misoos.com` 在 443 单独给 301**：实测 Baiduspider 不校验证书域名就会跟 301，
  给它一条 301 能把已有索引的权重并回主域，比直接断掉更有利于收录；
- **保留 `/api/health`**：仓库里的健康检查是
  `curl --resolve aicyld.com:443:8.138.150.19 https://aicyld.com/api/health`（带 aicyld.com 头，
  本来就不受影响）。留这条是为了以后真用 IP 做监控时，不被 444 误判成宕机。

## 七、SPA 收录问题

官网是 Vite SPA，服务器返回的 HTML 只有 3060 字节的加载壳（「正在进入课堂」），
正文全靠 JS。robots/sitemap 修好只解决“发现 URL”，不解决“抓到正文”。

实测有一个有意义的细节：**Baiduspider-render/2.0 会执行 JS**——它在 `ecs.misoos.com`
上确实把 `/api/public/website-content/HOME` 和素材图都请求了。所以不是完全抓不到内容，
但渲染队列优先级低、预算小，不能指望它当主要通路。

要稳定排名，需要：

- 公开页预渲染（`/`、`/marketplace`、`/works`、`/handbook`、`/faq`、`/download`、
  `/compare`、`/demo`、`/terms`、`/privacy`、`/minors`）；
- 或在 `index.html` 加载壳里放可见的 H1/品牌介绍兜底；
- 每页唯一 title/description/canonical（运行时已经做了，但预渲染要固化进 HTML）。

### 顺带发现的 soft 404

路由里 `path='*'` 回落到 `<Home/>`（`apps/website/src/main.jsx:2265`），
任何不存在的 URL 都返回 **200 + 首页内容**。这是典型 soft 404，
容易让百度把大量无效 URL 当成正常页面。改预渲染时一起处理：
未知路径应该返回真正的 404（`index.html` 里带 `noindex` 也行），而不是首页。
