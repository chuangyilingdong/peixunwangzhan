**上游契约坑（都已被适配器/渠道配置吸收）：**

1. `POST /openapi/v2/query` 的 `taskId` **必须是数字串**；非数字回
   `1007 failed to parse request body`（不是「任务不存在」）。上游返回的 ID 本身是数字串，正常链路不受影响。
2. `minimax/music-2.6`：`lyrics` 非空才出歌；空歌词必须 `isInstrumental: true` **且不能带 lyrics 字段**。
   空串提交也会先 `QUEUED`，随后 `FAILED「模型响应异常」`——很容易被误判成偶发故障。
3. `rhart-image-g-2-official`：强制 `quality`（只能是 `low/medium/high`，`auto` 会被拒）。
   适配器默认 `high`（`options.quality` 可覆盖）。
4. `minimax/hailuo-h3`：分辨率只认 **`2K` / `768P`**（大写 P），时长 5–15 秒；
   已在**视频备用渠道**的 `modelCapabilities["minimax/hailuo-h3"]` 声明 `resolutions: ["768P","2K"]`。
   其余模型枚举与平台默认值一致：g-2.5 为 `1k/2k/4k`，seedance 为 `480p/720p/1080p/2k/4k`。
5. `GET /openapi/v2/models` **不能当模型清单/探活**：任何 Key 都回 `200 PARAMS_INVALID`。
