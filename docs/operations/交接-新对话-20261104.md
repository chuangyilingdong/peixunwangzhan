**上游契约坑（都已被适配器/渠道配置吸收）：**

1. `POST /openapi/v2/query` 的 `taskId` **必须是数字串**；非数字回
   `1007 failed to parse request body`（不是「任务不存在」）。上游返回的 ID 本身是数字串，正常链路不受影响。
2. `minimax/music-2.6`：`lyrics` 非空才出歌；空歌词必须 `isInstrumental: true` **且不能带 lyrics 字段**。
   空串提交也会先 `QUEUED`，随后 `FAILED「模型响应异常」`——很容易被误判成偶发故障。
3. `rhart-image-g-2-official`：强制 `quality`（只能是 `low/medium/high`，`auto` 会被拒）。

### 1.11 价目表（成本价，2026-11-04 下午）

口径：RunningHub 价格页是 **USD**，用户确认 **1 USD = 1 元**，因此 `$0.05 → 5 分`。
写入的是渠道级 `upstreamUnitPrices`（模型级未用），验证过 `computeContractCost` 逐档命中。

| 渠道 | 成本价（分） |
|---|---|
| 文生图主 / 图生图主（g-2.5） | `perImageFen=5`（按次，$0.05） |
| 文生图备 / 图生图备（g-2-official） | `byResolution`: 1k=20 / 2k=40 / 4k=59（按 **quality=high** 档，$0.198/0.396/0.594） |
| 视频主（seedance） | `perSecondFen=8`（480p）；byResolution 480p=8 / 720p=16 / 1080p=20 / 2k=22 / 4k=25；`audioExtraPerSecondFen=0` |
| 视频备（hailuo） | `perSecondFen=8`（768P）；byResolution 768P=8 / 2K=12；`audioExtraPerSecondFen=0` |
| 音乐 | `perCallFen=12`（$0.12/次） |

文本（2026-11-04 晚补）：`channel-mtp9razp` 的 `upstreamUnitPrices.TEXT =
{ inputFenPer1MTokens: 50, outputFenPer1MTokens: 200 }`（输入 0.5 元 / 输出 2 元每百万 token）。
缓存命中价 0.02 元/百万没有字段可表达，按未命中价计。

- `audioExtraPerSecondFen` 必须显式配 0：不配的话「含音频」的视频成本会算成 UNKNOWN。
- 代价与偏差：
  - 官方图片固定 `quality=high`；改成 medium/low 成本会变，价目表也要跟着改。
  - seedance 有**最低计费时长**（输出 5s→按 9s、10s→17s、15s→25s 计），平台成本模型只按
    `时长 × 每秒价`，**会低估短视频成本**（5s/480p 算 40 分，实际 72 分）。要精确得加一条
    「最低计费时长」规则，属后续改动。
  - 视频按「无参考视频」档计价；带参考视频时 seedance 单价更低（480p $0.05/秒），平台目前不区分。
  - **对外价未动**（仍是模态基础价/原模型价），学生端售价需要产品再定。

### 1.12 主备怎么切、什么错才切（代码事实）

- 选路：`modelRoutes`（按模型）> `imageModeChannels`（图片按生成方式）> `modalityChannels`（按模态）> 默认渠道。
  图片的主/备按「文生图」「图生图」各自独立；RunningHub 直连上游，不走算力网关。
- 只有**同时满足**下面所有条件才切备用：
  1. 配了备用渠道；
  2. 还没拿到上游 `taskId`（`submitted=false`）；
  3. 还没开始输出（`emitted=false`）；
  4. 学生没取消；
  5. 错误被标记 `safeToRetry=true`。
- RunningHub 会切：`401/403`（认证失败）、`429`（限流）、**其余 4xx**（含 400 参数被拒 / 404 地址不对）。
- RunningHub **不切**：`5xx`、超时、任务已提交后轮询失败、任务 `FAILED/CANCEL`、
  配置类错误（Key 未配、family 没有对应路径、走错文生/图生渠道）。
- 文本（OpenAI 兼容）只切 `401/404/429`；`5xx`/超时/参数错都不切。
- 切换会写两条 `compute_attempts`（第 1 条 FAILED、第 2 条走备用渠道）；两条都失败才把错误抛给学生。
- **切备用前会把分辨率收进备用渠道的枚举**（`adaptOptionsToCandidate`，`55ca05a7`）：
  视频主 480p/720p → 备用 768P；1080p/2k/4k → 备用 2K。
  否则主渠道 480p 失败后原样发给只认 768P/2K 的 hailuo，会被上游 400（备用等于白配）。
  映射取「不低于原清晰度的最小档」，成本用量按映射后的分辨率记。
- 音频：hailuo 适配器不发 `generateAudio`，但**实测上游本身会出音轨**（ffprobe 真实产物：
  hailuo `AAC, mean -32.4dB / max -12.5dB`；seedance 带音频 `AAC, mean -25.1dB`）。
  所以「带音频」的课切到备用**不会变无声**，只是不再由这个开关控制。
