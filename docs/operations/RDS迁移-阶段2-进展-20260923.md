## 三、阶段 2 里踩到、并已修掉的真问题（每条都是实测出来的）

```text
1. **mysql2 的连接池会一直挂住进程** → CLI 脚本干完活不退出。
   实测：idleTimeout=1500 **不足以**放行（进程照样挂着）；脚本明明打印了 passed，却被运行器判成"超时失败"
   —— 这种"假失败"会让整套验证失去意义。修法：显式 closePool()（unref 太危险：查询在途时事件循环可能空掉 → 静默丢语句）。
2. **连接池的关闭不能写在模块顶层**：seed.js 末尾那句 `await closePool()` 被 import 时也会跑 →
   把调用方正在用的池提前关掉（实测表现：后续查询全报 "Pool is closed"，打挂 p4-o09）。改成"仅入口直接运行时"。
3. **schema.js 不只是建表，还插"默认行"**（平台模态开关 / 告警阈值 / platform_settings）。
   MySQL 下不跑 schema.js → 这些表是空的 → 表现是"AI 能力全被平台关掉"（isModalityEnabled 一律拦）。
   生产 RDS 在阶段 0 已从 SQLite 整库复制过这几张表，所以线上不缺；**新建库必须补**（夹具已按"从 SQLite 现读现搬"处理）。
4. **并行跑两套验收会抖**：全量 SQLite 套件与 MySQL 套件同时跑时，p13 挂了一次；
   静下来重跑就过（CPU 争抢导致服务器起不来/超时）。
   **教训：验证要么串行跑，要么对"单独跑能过、在套件里失败"的项单独复核 —— 别把抖动当成回归。**

5. **方言面比预想大**：`NOW_SQL` 的 strftime、`MAX(a,b)`、`ON CONFLICT`、`PRAGMA`、`json_each`、
   `json_extract` 的"带引号返回"…… 其中两条**会静默出错**（不是报错）：json_extract 的引号、NOW_SQL 的格式位数。
```

## 四、卡在哪：验收套件的夹具写去了 SQLite（**这是下一步的主体**）

```text
155 个验收脚本里 **114 个自己直接开 SQLite 造夹具**（`new DatabaseSync(dbPath)` + `db.prepare(...).run()`，
全是**同步**写法）。MySQL 驱动下应用读的是 MySQL，而这些夹具写进了一个没人看的 SQLite 文件
→ 脚本表现成"数据不存在"（例如 p78 读到的 student 是 undefined）。

已建立的验证装置（都在 scripts/，已入库）：
· scripts/acceptance-suite.mjs        --fast / --tag / --compare（与基线对跑，出现"基线绿→现在红"退出码 1）
                                     新增 --mysql：每脚本前**重置 MySQL 库**（结构由代码现生成，不另写一套建表脚本），
                                     并用包装层跑（见下）
· scripts/mysql-test-db.mjs           重置库 + 把"schema.js 导入期写的默认行"从 SQLite 现读现搬
· scripts/acceptance-script-wrapper.mjs  脚本结束后显式关池（否则 mysql 驱动下全被判超时）

要把 MySQL 全量套件跑通，需要把上面那 114 个脚本的**同步夹具改成驱动无关**（走数据层的异步 API）。
这是**另一个 codemod 量级**的活（上千处同步调用点 + 要把 `db.prepare().run()` 改成 `await aq(...)`）。
建议下一步就做它 —— 做完之后，"全量 150 个脚本在 MySQL 上对基线零回归"才是可交付的证据。
```

## 五、怎么复现/继续（本机验证环境）

```bash
# 1) 起一个一次性 MySQL 8（国内源可拉；Docker Hub 直连不通）
docker run -d --name aicyld-mysql-test -e MYSQL_ROOT_PASSWORD=rds-phase2-test \
  -e MYSQL_DATABASE=aild_admin -p 13306:3306 docker.m.daocloud.io/library/mysql:8.0 \
  --character-set-server=utf8mb4 --collation-server=utf8mb4_general_ci

# 2) 把"代码认为的结构"灌进去（结构由应用自己的 CLI 现生成 → 不会与代码走偏）
MYSQL_HOST=127.0.0.1 MYSQL_PORT=13306 MYSQL_USER=root MYSQL_PASSWORD=rds-phase2-test \
MYSQL_DATABASE=aild_admin node scripts/mysql-test-db.mjs --reset --seed

# 3) 跑验收（--mysql 会自动每脚本重置库 + 用包装层关池）
MYSQL_HOST=127.0.0.1 MYSQL_PORT=13306 MYSQL_USER=root MYSQL_PASSWORD=rds-phase2-test \
MYSQL_DATABASE=aild_admin node scripts/acceptance-suite.mjs --fast --mysql

# 4) SQLite 侧（当前生产路径）随时可回归：不加 --mysql 即可
node scripts/acceptance-suite.mjs --fast
```

> ⚠️ 三件与验证有关的事实，别忘了：
> · **RDS（真实目标）在本机连不上**（同 VPC 内网）；SSH 隧道能通，但**那个 RDS 账号没有建库权限**
>   （只能访问 `aild_admin`），所以本机验证用的是 Docker 里的同版本 MySQL（8.0.46 vs RDS 8.0.36）。
> · `DB_DRIVER` 默认 `sqlite` —— **生产不受影响**，切换是一个显式动作。
> · 需要真验 RDS 时：在**服务器上**跑（它能连 RDS），或让运维给一个测试库的权限。
