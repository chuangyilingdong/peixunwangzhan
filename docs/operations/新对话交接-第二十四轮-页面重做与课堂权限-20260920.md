## 二、这一轮做了什么（七件）

### A. 机构端作品列表并入 VibeCoding 作品（`d537d43` / `51440c2`）

用户：「机构/老师看不到学生提交的作品」。真因：**机构端「作品管理」的列表只读 `works` 表（画布）** ——
学生从创作环境交上来的网页/PPT 从来没进过这个列表；而平台端与学生端早就是"两类合并"的视图。
现在并入（`source: 'VIBECODING'`、带 entryFile / 课包 / 课时 / 课堂 / 是否上广场），两类合并后统一排序
（精选仍置顶，其余按提交时间倒序）。筛选差异写在注释里：这类作品没有 `PUBLISHED` 状态，
那个筛选值等价于"已发布到官网"；举报只挂 `works`，所以待处理举报恒 0。

实测（**生产库副本 + 临时实例**，脚本 `.tmp/verify-work-preview.mjs`）：机构列表 8 件里 **5 件 VibeCoding**
（改前 0 件）、机构端取打地鼠作品 200（入口文件与内容都在）。

### B. 平台端作品库加「预览」（`21e7ec4`）

那一列原来只有「发布到官网 / 编辑（只改标题描述）/ 彻底删除」，**没有任何看内容的入口**。
现在新增 `GET /api/admin/vibecoding-works/:id`（带 files/entryFile/artifacts + 服务端拼好的 fileUrls）
与 `:id/files/:name/(preview|download)`（超管；准入只认这份作品快照里出现过的 fileId），
作品行加「预览」：网页在不带 allow-same-origin 的沙箱里真跑、文档给服务端转的 PDF。

⚠️ 第一版**少写了 `admin/` 前缀**（admin 应用的接口路径约定是 `admin/...`），请求打到
`/api/vibecoding-works/:id`，界面报「接口不存在」——见坑㊸（在第二十三轮那份里：401 = 路由在、404 = 路由不在）。

### C. 机构管理员可以管理本机构老师创建的课堂（`15e85de` / `44886d5`）

用户：「老师端可以结束课堂，但是机构端没办法对机构下面老师创建的课堂结束。应该机构端是拥有老师端的所有权限才对。」

原来口径是「**写操作仅课堂负责人可执行；机构管理员对其他课堂只读**」，落在**三处**：
`assertSessionManager`（写路径唯一守卫）、详情里的权限投影 `canManage`（界面因此连按钮都不给）、
解散预检的 `OWNER_MATCH`。**而且守卫 p96 正面钉着它**（`机构管理员结束课堂 → 403`），
所以它是被当成预期行为固定下来的，不是漏写。

现在收成**一个**判定 `canManageSession(auth, session)`：**负责人本人，或本机构的机构管理员**；
三处都改用它。⚠️ 机构管理员那一支**必须同时比 `org_id`**，否则 A 机构的管理员能改 B 机构的课堂。
界面文案跟着改成「只读课堂：只有负责老师或本机构的机构管理员可以管理。」。

守卫 p96 里四条旧断言**全部翻过来**（canManage false→true、PUT 403→应当成功、
**结束老师创建的课堂 403→应当 200 且状态变 ENDED**、解散预检 OWNER_MATCH 应当 passed），
p111 那条预检标签也跟着改。

### D. 平台端「素材与宣传物料」页面重做（`ca12b48`）

用户：「这个页面进入应该就是卡片展示，然后右上角有个添加按钮，然后一步步上传物料等等。逻辑布局全部要重做一下，要更合理」。

重做前那页的问题不是配色，是**信息架构**：一进页面先看到「安全上传」和一张 9 字段长表单，
而这一页真正要管的是**已有物料**；三块面板与表格各说各话，上传的文件与新建的物料没有关系；
点「统计」还要去另一栏看结果。

现在：主体是**物料卡片网格**（封面或分类底色 + 分类/已停用角标 + 范围/资源是否就绪/使用次数），
右上角 **「+ 添加物料」→ 三步向导**（① 上传文件（可跳过；传完可以用它的公开地址当封面）
② 填写信息与授权范围 ③ 确认），统计与启停回到卡片上（统计是弹窗）。
口径没变：物料与文件**分别登记**（`resourceUrl` 留空 = "资源待配置"）；`FileUploadPanel` 仍原样导出。

### E. 机构端/老师端「课程中心」改卡片（`bc00704`）

用户：「机构端/老师端的课程中心应该是卡片形式展示，类似于灵动学习那种形式」。
**直接复用学生端那套 `course-package-*` 类**（在 `@platform/shared/styles.css` 里，机构端本来就加载）
—— 同一个课包在两端观感一致，也不必再养一套新样式。封面左下角写「来源 · 版本」（不再重复标题）。

### F. 课时表三处调整（`1edda42` / `0b8a4ca`）

- 课程卡片**删掉「查看课时」**（留「查看课程」），连带它就地展开的课时块与死状态 `expanded`；
- 课时表**删掉「正文」列**（线上每行都是「—」）；
- **序号改成行号**（原来显示 `lesson.sort` —— 那是"第几节"的编排序号，删过课时就跳号，用户看到 1,2,4,5…）；
- 时长/操作/教学素材三处加 `white-space: nowrap`（窄列把「查看」「教学素材」折成了竖排）；
- 「查看」按钮文案 → **「查看课件」**。

### G. 教学素材「无权访问」的真因（`53f5dcd` / `f6ba0c7`）

用户报：老师打开 1-4 的备课 PPT，预览里报「当前账号无权访问此教学素材」。

真因又是**界面与权限不同口径**：界面（`normalizeLesson`）是**逐键**回退 —— 快照里没有
`teachingGroups` 这一键时显示的是**实时**素材清单；而权限（`teachingAssetVisibleToOrg`）**只认快照**。
生产数据实锤：1-4 那节课实时挂着 2 个素材（PPT + 教案），而它的快照是在**挂素材之前**定格的
（有 `published_content`、没有 `teachingGroups` 键）。旧判据命中 **0 节**、新判据命中 **1 节**。

改法：判据拆两支，与界面完全一致 —— ① 快照里有这一键 → 以快照为准；② 没有 → 按实时表判。
⚠️ 顺带说清一个**混合态**：现在"快照里有素材键"的课时按快照判、没有的按实时判。
要真正让素材走草稿隔离，得在平台上对课包点一次「**更新发布**」把当前素材定格进快照。

## 三、不许破的口径（承接 1–51；**本文新增 52–57**）

52. ⭐ **同一份东西在不同端的读面要用同一套形状**：机构端缺 VibeCoding 作品、
    机构端课程列表是表格而学生端是卡片 —— 这类"平台看得到、机构看不到/不一样"的缺失是**静默的**。
    做新读面前，先看平台端与学生端**已经怎么读**，能合并的按同一形状合并，能复用的类名直接复用。
53. ⭐ **权限判定只写一处，且必须与界面同一条规则**：`canManageSession(auth, session)` 是课程管理的唯一判据
    （写路径、详情权限投影、解散预检三处共用）。机构管理员那一支**必须比 `org_id`**，否则跨机构越权。
54. ⭐ **"界面看得到、点开说无权"一律是两条规则不一致**（口径㉞ 的再犯）：教学素材那条就是
    —— 可见性判据必须与界面**逐键回退**一致（快照有 key 按快照、没有按实时）。
55. ⭐ **页面重做的方向：入口是"管现有事物"，不是"先填表"**：主体给对象列表（卡片/网格），
    新增收进右上角按钮 + **分步向导**；对象自己的动作（统计、启停）放在对象上，别让它跳到别的面板。
56. ⭐ **同类对象优先用卡片/网格**（封面 + 角标 + 就地动作），别用一张长表格；
    并且**复用已有的卡片类**（`course-package-*`、`material-*`），不要每个页面各写一套样式。
57. ⭐ **表格里的序号用"行号"，不要用业务排序字段**：`lesson.sort` 是"第几节"，删过就跳号
    （用户看到 1,2,4,5…）。窄列记得 `white-space: nowrap`，否则中文会被折成竖排。

## 六、这一轮踩过的坑（承接 1–65；**本文新增 66–71**）

66. ⭐⭐ **模板字符串里别写反引号**：我在一条 SQL 的**注释**里写了 markdown 风格的 `` `normalizeLesson` ``，
    而它就在 JS 模板字符串里 —— 模板被提前闭合，服务端文件直接语法错误。
    **还好自检挡住了**：`node --check` 不过、`deploy` 脚本拒绝构建与切软链，生产始终没切到坏版本。
    （同一类还有"脚本写 `\` 被吃掉一层"，见第二十三轮坑 62。**这两次都说明：往 JS 里写特殊字符要用编辑器工具逐字写。**）
67. ⭐ **验证前端页面的脚手架有两个必踩点**：
    ① 临时实例**只跑 API、不提供前端静态文件** —— 页面得自己 `vite build` + `vite preview` 起；
    ② `vite preview` 的 `/api` 代理读的是**运行时**的 `VITE_DEV_API_TARGET`（构建时设没用），
    而且 admin/org 的 preview 配了 `strictPort`。我漏了 ① 和 ②，于是页面里的请求打到空端口，
    截图里出现一条**假的**「服务器内部错误」—— 我差点把它当成接口挂了（单独打接口是 200）。
68. ⭐ **同一台机器上连着跑浏览器守卫会把 2 核机压到 SSH 都连不上**（`banner exchange` 超时、负载 20~60，
    而 `vmstat` 里 CPU 还是 idle —— 那是刚过去那波尖峰的衰减值）。判断"是我的改动坏了还是机器忙"：
    **先看这两个守卫走不走你改的页面/接口**（都不走 → 单跑、等负载回落）。别急着让用户改安全组。
69. **机器会来一次干净重启**（本轮 19:29 一次 `poweroff`，日志里没有 OOM/watchdog 痕迹）：
    服务是 `enabled` 所以开机自动拉起，五入口 200、数据与 release 都没变。
    **先确认 `systemctl is-enabled`**，否则重启后线上就是躺着的。
70. **守卫红了先看它红在哪一步**：`p93` 本轮红在它自己要调 LibreOffice（`soffice --convert-to pdf` 命令失败），
    与改动无关 —— 这类"环境依赖型"守卫的红，别当成回归去查代码。
71. **改口径一定要同时翻守卫**：本轮 p96 里四条断言正面钉着旧口径（机构管理员只读），
    不翻就是"改了代码、守卫照样红"。反过来，翻守卫时**顺手把新口径的边界也钉上**
    （p96 里补的"机构管理员结束老师创建的课堂应当生效 + 状态变 ENDED"就是用户报的那个场景）。
