# 修复 · 内容审核失败统一文案（2026-10-31）

## 问题

画布生图失败时，学生/老师会看到两种完全不同的长文案：

```text
AI 服务暂时不可用（The generated result did not pass the content review.
Adjust the prompt or reference materials and try again.）

AI 服务请求频率受限（AI 供应商调用失败（上游：相同输入在24小时内已有2次内容审核失败，
该输入已进入12小时冷却期，请修改提示词或参考素材后再试））
```

用户口径：**这两条是同一个错误**，提示应该直接写「内容审核没通过」。

## 根因

- 第一条是上游的英文审核失败（`content review`）；
- 第二条是同一输入在 24 小时内连续 2 次审核失败后，上游进入 12 小时冷却期；
- 平台原来把上游原文分别包进「AI 服务暂时不可用（…）」和「AI 服务请求频率受限（…）」，
  所以看起来像两个不同的故障；
- 审核失败的原文被透传，学生既看不懂英文，也不知道下一步该做什么。

## 修复

统一文案：

```text
内容审核没通过。请调整提示词或参考素材后再试。
```

判断范围（中英文、冷却期都归同一类）：

```js
/content\s*(review|safety|policy)|safety\s*system|moderation|内容审核|内容安全|
 内容未通过|审核(?:失败|未通过|没通过)|冷却期|filtered\s*by[^.]*safety|
 rejected[^.]*(?:safety|content)/i
```

落点：

1. **新任务**：`apps/server/src/services/providerContract.js` 的 `normalizeProviderError()`
   - 内容审核/冷却判断放在 `429` / `UPSTREAM` 分支**之前**（冷却期上游就是 429，
     不提前拦会被包装成「请求频率受限」）；
   - 错误码统一归到 `GENERATION_PROVIDER_SAFETY_REJECTED`；
   - 原有 `SAFETY` 分支文案也改成同一句。
2. **历史 job**：`apps/server/src/routes/aiGeneration.js` 的 `normalizeJob()`
   对 `error_message` 调 `normalizeGenerationErrorMessage()`，旧记录打开时也显示新文案。
3. **画布/作品快照里的旧 `generationError`**：
   `packages/shared/src/generationErrors.js` 提供同一份正则与文案；
   - 学生画布 `canvasWorkspace.jsx` 初始化快照与失败回流时归一；
   - 老师课堂作品弹窗、平台端作品预览、官网作品详情只读画布也归一（只改显示副本）。
4. 上游原文不再进 `generation_jobs.error_message`；`compute_attempts` 仍保留原始原因，
   排查/对账看得到，但学生看不到英文长文。

## 验证

- `scripts/p30-provider-error-detail.mjs` 增加三类断言，全部通过：
  - 中文「内容未通过 AI 服务安全策略」→ 统一文案 + SAFETY 码；
  - 英文 `content review` → 统一文案 + SAFETY 码；
  - 12 小时冷却（429）→ 统一文案 + SAFETY 码（不能被 429 抢走）；
  - 非审核错误（prompt length / 服务器繁忙）仍然保留各自的原因。
- 客户端归一测试：英文审核、中文冷却、prompt length、服务重启中断四条输入，
  前两条变统一文案，后两条原样保留。
- 生产 release 的 `providerContract.js` 实测两条真实文案均归一。
