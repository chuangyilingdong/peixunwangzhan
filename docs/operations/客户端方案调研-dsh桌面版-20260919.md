# 客户端方案调研：dsh 能不能做成学生桌面端（2026-09-19）

> 起因：用户口径「vibecoding 课堂不用网页了，直接下载客户端（Windows 和 macOS Apple 芯片），
> 但要跟我们的课程和学生体系关联上；首页有下载入口；老师开课点进入课堂能自动拉起客户端」，
> 并且认为这样能减轻服务器负担。
> 本文只记**调研事实与依据**，方案取舍见最后一节。所有结论都标明来源（实测/代码/文档）。

## 一、结论摘要

1. **服务器减负这件事成立，但省的不是网页那一层。** 省的是「每个学生一个 ~490MB 的学生环境进程」
   （见 `host-user/README.md:183-184`、`architecture/多学生并发-扩容设计.md:23`：RSS 470-520MB、
   cgroup 上限 768MB、本机 1.6GB → **同时约 2 个学生**）。把运行时搬到学生自己的电脑上，
   每生占用从 ~490MB 变 0；省不掉的是模型调用必须继续走我们的网关（授权次数/计费/成本观测/内容治理）。
2. **dsh 支持 Windows，而且是上游一等目标**（不是我原来担心的「只有 Linux」）。实测 + npm 元数据见第二节。
3. **已经有人把「桌面端」这一层做完了**：`dataelement/dsh-desktop`（MIT，Electron），发布
   Windows x64 安装器与 macOS Apple Silicon dmg，**macOS 已公证、Windows 安装器已签名**，带自动更新。
   我们不需要从零写外壳、签名和更新。
4. ⚠️ **这是一次产品决策的反转**：仓库历史里 `5deabb4`「删除桌面客户端（产品决定：客户端不要了）」
   已经把 `/api/admin/client-releases`、`/api/public/downloads`、官网 `/download` 页与头部/底部入口、
   `client_download_releases` 建表、以及营销文案里对客户端的承诺**全部删掉**
   （`docs/archive/交接说明-部署历史.md:462-467`）。要走客户端，这些要**有意地重建**。

## 二、dsh 的平台支持（实测）

在**本机（Windows 10.0.26200）** 用 `C:/Program Files/nodejs/node.exe`（v24.19.0）实装：

```
mkdir .tmp/dsh-win-spike && npm i @deepseek-ai/dsh@0.1.5-rc.1 --registry=https://registry.npmmirror.com
node node_modules/@deepseek-ai/dsh/lib/bin.js --version   →  0.1.5-rc.1   ✅ 在 Windows 上跑起来了
```

装出来的平台相关包（**Windows 路径真的存在**）：

| 包 | 作用 |
|---|---|
| `@deepseek-ai/dsh-sandbox-windows-acl` | Windows 沙箱后端：「restricted-token spawn + orphan-SID 写白名单」，实现文件齐全（`runner.js` / `token.js` / `spawn.js` / `workspace-sid.js` / `win32-abi.js` / `acl.js` / `path-boundary.js`） |
| `@deepseek-ai/dsh-pwsh-local` / `dsh-pwsh-sandbox` | PowerShell 壳后端（Linux 上我们用的是 bash） |
| `@deepseek-ai/node-addon-landlock-run` | Linux 侧的沙箱（我们生产现在用的就是它） |

- npm 上 `@deepseek-ai/dsh` 的 `os` / `cpu` 字段为空（不限制平台），`bin: { dsh: 'lib/bin.js' }`。
- ⚠️ `@deepseek-ai/dsh-sandbox-macos-seatbelt` **在 npm 上 404**（没找到 macOS 沙箱后端）。
  macOS 那条路要靠 DSH Desktop 自己的实现来确认 —— **未验证**，别当成已知结论。

## 三、DSH Desktop（`dataelement/dsh-desktop`）

- 自述：**"A local-first, cross-platform desktop app for DeepSeek Harness"**；MIT；owner 是 `dataelement`
  （即 Univer 的同一家）。
- 发布物（`0.9.1-beta`，从 GitHub Releases API 读到的体积）：
  `dsh-desktop-windows-x64-setup.exe` **163.8MB**、`dsh-desktop-mac-arm64.dmg` **176.6MB**、
  `mac-x64.dmg` 181.1MB，另有 `latest-mac.yml` / `.blockmap`（electron-builder 自动更新）。
- 按其 README：**macOS 版本由 Apple 签名并公证**；Windows x64 安装器**已签名**（他们说明 SmartScreen
  信誉要慢慢积累）。启动后不久检查更新、之后每 6 小时一次，**下载前先问用户**。
- 架构上与我们的既有做法**同构**，这是最关键的一点：
  - `DSH_HOME` = `{Electron userData}/harness`，其下有 `profiles/web/package.json`（**插件依赖与 bundles**）、
    `profiles/web/cordis.patch.yml`（**用户 patch**）、`settings.yaml`、`.credentials.yaml`、`sessions/`、
    `storages/`、`.agent-presets/`、`skills/`；
  - 官方文档明确：**profiles / plugins / workspaces / sessions 都放在应用目录之外**，升级后保留；
  - 网页版（`npx @deepseek-ai/dsh web`）与桌面端的 **Preset / Skill / 插件清单格式兼容**
    （`docs/web-to-desktop-migration.zh.md`）。
  - 也就是说：我们现有的 `student-runtime.cordis.yml`（审批策略 `never`、权限预设 `workspace-write`、
    沙箱策略 + `workspaceRoot`、模型只走我们的网关、禁用一批成年入口）与两个插件
    （brand-plugin / feature-plugin）**有正当的落点**，不是硬塞。
- 它还提供：宿主 UI 插件与 slot 契约、插件市场安装器（`packages/dsh-desktop-market-installer`）、
  可迁移的 `.dshpreset` 预设包、以及一份 `docs/patch-plugin-contract.md`
  （规定「品牌/面板/按钮优先用 slot 与宿主服务，patch 只用于补上游缺口」）。
- 底座是 `@deepseek-ai/dsh@0.1.5-rc.2`（**我们生产钉的是 rc.1**）。
- 上游 `deepseek-ai/deepseek-harness` 自己也有 `apps/desktop`（其文档 2026-09-08 查阅），
  并且他们有 `docs/source-build-contract.md`（**可以自己从源码构建**）。

## 四、六条需求分别落在哪一层

| # | 需求 | 落点 | 现状 |
|---|---|---|---|

| 2 | 学生提交作品（html / ppt 等），我的作品可见、可交平台后台 | **基本已有**：`vibecoding_submissions` + `/my-works`（已合并 canvas `works` 与 vibecoding 两条线）+ 后台 `vibecoding-works` 与 plaza 发布（`vbt_` token、要版权确认） | 新增的只是「由客户端上传文件」（现在是服务端去工作区收集） |
| 3 | 签名证书 | 不在本方案内（用户自办）；若采用 DSH Desktop，其构建已签名 | — |
| 4 | 建课时选 vibecoding → 可设「发送按钮能按几次」 | **服务端网关计数**（客户端本地计数随手可改）；课时/课包配置 + 后台表单 | 全新。⚠️ 会反转 2026-09-18 的「只观测不拦人」口径（`services/sessionCostCap.js:11-16`、`p112` 专门断言超限也放行） |

| 6 | 建课时（选 vibecoding）可预设提示词，客户端显示、点击自动填入对话框 | 课时配置 + 后台表单（数据层）；客户端侧用**宿主 slot 插件**渲染成可点的提示词块、点击写入输入框（我们现有 feature-plugin 的 client 半边已经证明这条路可行：`conversation.input.left` slot + `ctx.remote.commands.execute`） | 全新 |

## 五、风险与未决问题

**风险**
- DSH Desktop 是 **0.9.1-beta / early preview**，自述「可能与社区插件不兼容」，且底座是 dsh **rc.2**
  而生产钉的是 **rc.1** → **插件/slot 漂移**是我们最实际的维护成本；必须**钉死桌面端版本**并每次升级重验。
- 依赖第三方 beta 支撑学校的生产产品：需要自留后手（钉版本 + 自托管安装包 + 必要时按
  `source-build-contract.md` 自己构建；源码是 MIT）。
- 品牌/商标：dsh 是 MIT，但其文档要求**项目名里不要用 DeepSeek Harness 全称**（建议用 DSH 缩写），
  品牌本身是可替换插件（我们已经是这么做的）。**「把别人的桌面应用换成我们的牌子发给学校」这件事的
  授权口径，仓库里没有任何记录**（`VibeCoding改用dsh-方案-20260916.md:141-142` 当年就列为待办，
  `BRAND_GUIDELINES` 那条结论至今没补上）—— 要发学生之前得先把这条落定。
- 学生机器上跑 agent 的安全边界：现在服务端有 Landlock + 768MB 内存上限 + 审批策略 `never` 兜着，
  搬到本机后**内存与进程上限没有了**，改成 Windows ACL 只锁写。这是把「能执行模型生成代码」的 agent
  放到未成年人的电脑上，需要产品上明确接受。
- Univer 办公插件当前是**未授权**状态（它自己弹 "Univer Office License Required"）：搬到客户端只是把
  那 ~480MB 搬走，授权问题还在。

**未决（决定方案形态的那一个）**
- **我们的登录门放在哪**：DSH Desktop 的宿主是它自己的 Electron main（splash / safe-mode 页在它手里）。
  要「先登录我们的账号才能进」有三种做法：① 用它的宿主 UI 插件/slot 做一道门（若能挂到启动前）；
  ② 我们做一个**很薄的启动器**先登录、再拉起 Harness（不动它的壳）；③ 从上游 `apps/desktop` 自己构建
  （完全可控，但要自己维护构建与更新）。**这一条必须先确认**，它决定「采用 / 包装 / 自建」。

## 六、建议的推进顺序

1. **先确认登录门形态**（上面那条未决）：读 DSH Desktop 的 `docs/architecture.md` 与
   `src/preload/AGENTS.md`、宿主 slot 清单，判 ① 是否可行；不可行就走 ②（薄启动器）。
2. **服务端先做**（三种形态都需要、且不依赖客户端选型）：
   课时/课包级的 `vibeCoding.sendLimit` 与 `vibeCoding.presetPrompts` + 后台建课表单 + 网关按课堂计数
   + 给客户端的「我的课程 / 当前课堂 / 本课参数」接口 + 守卫。
3. **再做客户端最小闭环**（Windows）：安装 DSH Desktop 底座 → 塞我们的 patch 层与两个插件 →
   改成只走我们的网关 → 登录门 → 拉到当前课堂才放开对话区 → 作品上传回平台。
4. 之后：官网下载入口（含版本清单）、自动拉起（自定义协议）、macOS、以及 #4/#6 的客户端侧渲染。

# 追加：决策与进展（2026-09-19）

## 决策

用户选定**第 3 条**：从上游 `deepseek-ai/deepseek-harness` 的 `apps/desktop` **自己构建**（完全可控，
登录门/品牌/深链都在我们手里），而不是采用第三方 DSH Desktop 或做薄启动器。

## 已打通：Windows 构建（含三个坑）

上游桌面端是「Electron 壳 + 完整 dsh Web 应用」，`apps/desktop` 是 `private: true`（没发 npm），
所以**只能自己构建**。实测在本机（Windows 10.0.26200 / node 24.19.0）**构建成功并跑通**：

```bash
# 钉住版本的上游检出放到 .tmp/dsh-harness（gitignore）
pnpm install --registry=https://registry.npmmirror.com
# 打包（无签名；签名四件套见 apps/desktop/.env.windows）
pnpm package:desktop:win:x64:unsigned
```

产物：`deepseek-harness-0.1.6-alpha.2-win-x64.exe`（**294MB**）+ `.blockmap`（自动更新用）。
冒烟：直接跑 `win-unpacked/` 里的主程序，Electron 起来、本地 dsh 在
`http://127.0.0.1:19387/?token=…` 提供服务（与上游文档说的默认端口一致）；
附带检查 `Office runtime versions and document round trips passed` —— **Windows 上 pptx/docx/xlsx
的生成与读写实测可用**（内置 LibreOffice + python-pptx）。

⚠️ **三个 Windows 坑**（都会再咬人）：

1. **PATH 里的 `node` 是 v16**（微信开发者工具那份），而 pnpm 要 ≥22.13 →
   必须把 `C:\Program Files\nodejs` 放在 PATH 最前。
2. **打包要 `apps/desktop/.env.windows`**（从 `.env.windows.example` 复制），而且
   **不回退到 shell 环境变量**；`DSH_DESKTOP_APP_ID` 与 `DSH_DESKTOP_MANDATORY_UPDATE_*`（**未签名也必填**）都得有。
3. **Git Bash 的 GNU tar 把 `E:\…` 当远程主机**（`Cannot connect to E: resolve failed`），
   打包在 `release:pack` 那步挂掉。修法：让 `tar` 指向 Windows 自带的 bsdtar（`System32/tar.exe`），
   而且 PATH 里那个目录必须写成 **MSYS 形式 `/e/...`** —— 写成 `E:/...` 在 bash 里是**无效目录**（冒号被当路径的一部分）。

## 已就绪

- **品牌脚本**：`deploy/desktop/rebrand-client.mjs`（改 productName / 安装包名 / 外壳文案；
  `--dry-run` 验过会命中 3 个文件）。品牌合规结论见该文件头：MIT 允许再分发与换牌，
  **项目名不得用 "DeepSeek Harness" 全称**（商标），描述可写「基于 DSH 构建」，且不得暗示官方背书。
- **服务端已上线**（release 20260919T035341Z）：发送次数上限、预设提示词、`/api/student/runtime/client-context`。

## 还没做（按依赖顺序，含已定位的插入点）

1. **登录门**：插在 `apps/desktop/src/main.ts` 的 `reconcileBackend()` 里 ——
   现在是 `await navigateMain(applicationUrl)` 后直接 `backend.start(...)`；要在前面加一步
   「没有我方会话 → 先加载我们自己的登录页；登录后拿 `client-context`；`classroom:null` 就停在
   『等老师开始上课』页；有课堂才继续起 dsh」。
   窗口 preload 用现成的 `src/preload-app.ts`（加一组 `lingdong` IPC 即可，**不必新增 preload 入口**）。
2. **只走我们的网关**：`src/host-process.ts` 的 `desktopNodeEnvironment()` 会把 Electron 主进程的
   `process.env` 原样传给 dsh —— 所以登录后把 `PLATFORM_GATEWAY_KEY` 写进 `process.env` 再启动即可；
   模型路由靠往 profile 写 `cordis.patch.yml`（本仓库 `deploy/dsh-student/student-runtime.cordis.yml`
   是 Linux 版原型，Windows 要换 pwsh、去掉 `/opt` 路径、审批/沙箱那几段可沿用）。
3. 预设提示词渲染成可点块 + 剩余次数显示（宿主 slot 插件；`feature-plugin` 的 client 半边是现成范例）。
4. 作品上传回平台（复用 `/api/student/runtime/submit` 那条链路，把"服务端去工作区收"换成"客户端上传"）。
5. 深链 `lingdong://`（`electron-builder` 的 `protocols` + `setAsDefaultProtocolClient`）+ 官网下载入口与版本清单。

## 为什么没有"直接发布"

客户端**没有登录门就拿不到网关密钥** —— 那样的包启动后 dsh 能开、但所有模型调用都会失败，
等于一个不能用的客户端（还可能把上游默认的模型渠道暴露给学生）。所以**先不发布**，
把上面第 1、2 步做完并实测（本机起临时服务端登录 → 拿到密钥 → dsh 只走我们网关）之后再出包上线。

# 追加二：登录门与下载页已落地（2026-09-19 晚）

## 已完成并实测

- **客户端打出来了**：`lingdong-client-0.1.6-alpha.2-win-x64.exe`（294MB，我们的品牌：
  程序名「灵动ai创作客户端」、安装包名 lingdong-client-*）。构建方式：
  `apply-client-gate.mjs` + `rebrand-client.mjs` 打在上游检点上，再
  `pnpm package:desktop:win:x64:unsigned`。
- **登录门跑通了**（本机端到端）：启动 → 我们的登录页（`platform-gate.ts` + `gate/login.html`）→
  用学生账号登录**本地验证台**（`/api/auth/login`）→ 取 `client-context` →
  登录门自己写下 `~/.dsh/lingdong.patch.yml` 并把 `PLATFORM_GATEWAY_KEY` /
  `PLATFORM_GATEWAY_BASE_URL` 写进 `process.env` → dsh 在 127.0.0.1:19387 起来。
  「老师没点立即上课 → 只显示等老师开始上课」那条也由服务端的 `classroom:null` 驱动。
- **官网下载页上线**（release 20260919T044004Z）：`/download` + 首页入口 + 页脚链接；
  安装包放在 release 之外的 `/srv/ai-kids-platform/downloads/`，nginx 给了 `/downloads/`；
  `manifest.json` 记版本/体积/sha256，页面读它（不写死文件名）。

## 还没验证的一件事（下一步第一件事）

**dsh 是否真的把模型调用路由到我们的网关**：客户端里 dsh 的模型列表仍显示上游那一条
（`deepseek-official/deepseek-v4-pro`），说明 `lingdong.patch.yml` 虽然被挂进了 `patchFiles`
（已确认打包产物里有这段代码、文件也确实被登录门写出），但**补丁条目是否命中、渠道是否注册**还没证实。

排查建议（按成本从低到高）：
1. 用 dsh 的本地 API 看模型/provider 列表 —— 它的 API 是 **GraphQL**（`/api/v1/graphql`，
   不是 REST），要先摸 schema；
2. 让 dsh 真发一次请求，看**我们网关的日志/`usage_records`** 有没有进来（这是最硬的判据）；
3. 若补丁条目确实没命中，检查 id 是否存在于桌面 profile 的组合树里（`patchFiles` 的 overlay 语义是
   id-targeted），必要时改成 dsh 的 **insert 列表**形式来注册 `llm-pi-ai` 渠道。

## 还差的三件（都不影响"能登录、能进课堂"）

1. 客户端里 **dsh 自己的 Web UI 还没换品牌**（标题栏仍写着 deepseek HARNESS）——
   上游那份 `deploy/dsh-student/rebrand.mjs` 就是干这个的，把它套到客户端的 dsh 树上即可。
2. **预设提示词**还没在客户端渲染成可点块（数据已随 `client-context` 下发）。
3. **作品上传**（客户端把工作区文件交回平台）与**深链 `lingdong://`**（官网点「进入课堂」自动拉起）。
