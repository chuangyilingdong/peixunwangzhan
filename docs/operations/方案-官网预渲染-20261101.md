# 官网预渲染：让百度抓到正文（2026-11-01，SEO 方案 B）

## 一、问题

官网是 Vite SPA —— 服务器返回的 HTML 只有 **3060 字节**，人眼能看到的文字只有「正在进入课堂」。

实测（2026-11-01，不带 JS 直接 fetch）：

```text
/              3060 字节
/handbook      3060 字节
/marketplace   3060 字节
/works         3060 字节
```

**四个页面一字不差**。也就是说：sitemap 里的 11 个页面百度**都能发现**，
但抓到的都是同一份空壳 —— 没有任何可排名的正文。

`sitemap` 只解决"百度知道有这个网址"，不解决"这个网址写了什么"。

## 二、做法

在构建期把公开页渲染成静态 HTML（`apps/website/scripts/prerender.mjs`）：

```text
vite build apps/website
  → 起一个本地静态服务，/api 反向代理到线上（所以 CMS 文案是真内容）
  → Chromium 逐个打开 11 个公开页
  → 等 networkidle（数据加载完）+ 250ms（页面的 SEO effect 落 title）
  → 把渲染完的 DOM 存成 dist/<路由>/index.html
```

**不改业务代码**：抓的就是真实渲染结果，每页的 title/description/canonical
本来由页面自己设置（`main.jsx` 的 SEO effect），所以天然各不相同。

React 用的是 `createRoot().render()`（不是 hydrate），浏览器拿到预渲染 HTML 后会正常
重新渲染 —— 不会出现 hydration mismatch，也不需要改挂载方式。

### 与构建流程的关系

`deploy/production/build-production.sh` 里插在 `stamp-junshi` **之后**、复制 dist **之前**
（必须在 stamp 之后：预渲染抓的是最终 dist，编号要已经打进去）。

应急跳过：`PRERENDER_SKIP=1`（退回只有空壳的老状态，别长期开）。

### nginx 的三处改动（**不在仓库里，改的是 `sites-available/aicyld.com`**）

| 改动 | 为什么 |
| --- | --- |
| `try_files $uri` **`$uri/index.html`** `$uri/ /index.html` | 只写 `$uri/` 时 nginx 会对 `/handbook` 做 **301 补斜杠**（`/handbook/`），与 sitemap/canonical 里的 `/handbook` 对不上 —— 每页多一次跳转、多一个重复地址 |
| `location /` 里加 `expires -1` | 预渲染之后**这里发出去的每份 HTML 都是入口文档**。不 no-cache 的话，换版后浏览器继续用旧 HTML，而它引用的 `/assets/index-<旧哈希>.js` 已被新 release 删掉 → **白屏** |
| 新增 `location ~* \.(woff2?\|png\|jpe?g\|webp\|…)$ { expires 7d; }` | HTML 变 no-cache 之后，字体/图片要单独给长缓存，否则每次都回源 |

⚠️ 为什么 `expires -1` 必须写在 `location /` 里：`try_files` 命中文件时是在**当前 location
上下文**里直接发的，不会重新匹配别的 location —— 写在单独的正则 location 里对 `/handbook` 无效
（这就是第一版的做法，实测没生效）。

备份：`/root/aicyld.com.bak-before-prerender-20261101T155207Z`

## 四、边界（要知道的）

1. **内容停留在构建那一刻**：CMS 改了文案，要等下次发布才反映到预渲染 HTML 里。
   对 SEO 无害（爬虫拿到的是上次发布快照），但运营改完首页不要期待立刻被百度看到。
2. **只预渲染静态公开页**：`/works/<token>`、`/marketplace/<id>`、`/u/<token>` 这类动态详情页
   仍走 SPA 兜底（抓不到正文）—— 它们本来也不在 sitemap 里。
3. **软 404 还没修**：不存在的路径仍然返回 200 + 首页内容。搜索引擎会把它们当重复页面。
   修它要按"已知路由白名单"配 nginx，是独立的一件小事，本次没做。
4. **不是立即见效**：预渲染只是让"能被排名"成立，收录与排名通常要 2-6 周观察。

### 差点闯祸的一个 bug（记下来）

首版预渲染是从 `http://127.0.0.1:6187` 打开页面的，而页面的 canonical / og:url 由
`window.location.origin` 生成，于是发出去的 HTML 写着：

```html
<link rel="canonical" href="http://127.0.0.1:6187/handbook">
```

**这比不做预渲染危害大得多** —— 等于主动告诉百度"真页面在 localhost"，
可能直接把刚收录的页面搞掉。是发布后做结构检查（看 canonical 长什么样）才发现的。

修法两层：

1. 落盘前把 `http://127.0.0.1:<端口>` 全量替换成 `https://aicyld.com`；
2. 替换后若仍残留本地地址 → **让构建失败**（宁可没有预渲染，也不要错的 canonical）。

守卫补一条：任何预渲染页里不许出现 `127.0.0.1` / `localhost`，canonical 必须是 https。

### 修复后逐页确认

```text
/              https://aicyld.com
/marketplace   https://aicyld.com/marketplace
/handbook      https://aicyld.com/handbook
/works /faq /download /compare /demo /terms /privacy /minors  均对应自身路径
残留 127.0.0.1：0 处
```

> 首页 canonical 是 `https://aicyld.com`（无尾斜杠），sitemap 里是 `https://aicyld.com/`。
> 根路径的尾斜杠对搜索引擎是同一个地址，暂不处理；真要统一，改的是 `main.jsx` 里那段
> canonical 计算（运行时也是无斜杠，改就要两边一起改）。

## 七、事故：nginx 宽正则把机构端 logo 干掉了（2026-11-02 修复）

### 现象

机构端登录页与工作台**左上角 logo 变成破图**（一个白框里一个裂图标），两侧都是 `/org`。

### 根因

为了让官网字体/图片拿到长缓存，我加了一条**宽正则**：

```nginx
location ~* \.(woff2?|ttf|png|jpe?g|webp|gif|ico|svg|mp4|webm)$ {
    root .../apps/website;   # ← 这个 root 只对官网成立
    expires 7d;
}
```

**nginx 里正则 location 的优先级高于普通前缀 location。** `/org/`、`/admin/` 是普通前缀
（没写 `^~`），所以 `/org/favicon.png`、`/org/assets/lingdong-ai-logo-*.webp` 全部被这条正则
劫走，套上了 `apps/website` 的 root → 文件不存在 → **404**。

文件本身好好的（`apps/org/favicon.png` 一直在），只是被路由到了错误的目录。

### 修法

删掉宽正则，只保留**不会匹配到别的应用**的窄规则：

```nginx
location ^~ /fonts/ { root .../apps/website; expires 7d; access_log off; }
location = /favicon.png            { root .../apps/website; expires 7d; access_log off; }
location = /favicon.ico            { root .../apps/website; expires 7d; access_log off; }
location = /apple-touch-icon.png   { root .../apps/website; expires 7d; access_log off; }
```

`/assets/` 本来就有 `location ^~ /assets/`（`^~` 让它在正则之前生效），不受影响。

### 验证

```text
/org/favicon.png        200      /org/apple-touch-icon.png  200
/org/favicon.ico        200      /admin/favicon.png         200
/org/assets/lingdong-ai-logo-CGaEmCf0.webp   200
/admin/assets/lingdong-ai-logo-CGaEmCf0.webp 200
/favicon.png   Cache-Control: max-age=604800（长缓存仍在）
/handbook      Cache-Control: no-cache（入口文档仍不缓存）
```

备份：`/root/aicyld.com.bak-before-logo-fix-20261102T001xxxZ`

### 教训（写进规范）

> **nginx 里不要写能匹配到多个应用的正则 location。**
> 正则优先于普通前缀，而每个应用的静态目录 root 不同 —— 一条“给官网加速”的规则，
> 就会把机构端/管理端的所有图片打成 404，而且**发布流程完全不报错**（HTML 200、接口 200，
> 只有图片 404）。要么用 `^~` 精确前缀，要么用 `=` 精确路径。
