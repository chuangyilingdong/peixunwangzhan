# OSS 接入（2026-09-23）—— 设计、步骤、回滚

> 目标（来自迁移文档 §三 的第 1 步）：**把上传/媒体的读写改成 OSS**，私有素材走签名 URL。
> 真实收益有二：① 这台机的**公网出口只有 5 Mbps**，媒体全从它出去会拖慢所有用户；
> ② 学生私有素材不该有公网地址（现在靠平台自己的授权口，改成签名地址更干净）。

## 设计（为什么这么做）

```text
【一】零依赖手写 OSS 客户端（apps/server/src/services/objectStorage.js）
  这是**刚上线**的生产，多一个依赖就多一份 lockfile 与构建面；而我们要的只有四个动作
  （放、签发 URL、取到本地、删）。V1 签名规则公开稳定（HMAC-SHA1 + 固定拼法），手写更好审计。

  ⚠️ **两个端点分清**是省钱提速的关键：
    OSS_ENDPOINT          公网端点 → 给**浏览器**签发的 URL 用它
    OSS_INTERNAL_ENDPOINT 内网端点 → **服务器自己**读写用它（同地域 ECS 走内网：免流量费、更快）
  没配内网端点就退回公网，不会坏。

【二】每行自己回答"我在哪儿"（apps/server/src/services/fileStorage.js）
  判据放在 `file_assets.metadata.storageBackend` —— 表里本来就有 metadata JSON 列，
  **不用改 schema**；**没有这个字段的（全部历史数据）一律当本地盘**。
  所以：打开开关不会让老数据"搬家"，回滚也只是把标记去掉。

【三】开关是两段，缺一不可（fail-closed）
  ① env 里有 FILE_STORAGE=oss  ② bucket/AK/SK/端点都齐
  任何一段不满足就退回本地盘 —— 绝不允许"半开"（上传写进 OSS 一半、读的时候找不到）。
  这一条被守卫 p136 钉住了。

【四】读的时候怎么发字节
  · OSS 行 → 平台**302 到带签名的临时地址**（15 分钟），字节由 OSS 直接服务，不经过我们
    （授权判断在这之前已经做完，签名地址只是"取件凭证"）
  · 本地行 → 照旧流式下发（Range 支持原样保留）

【五】课件预览的特别处理
  Office 转 PDF 用的 LibreOffice **只认本地文件**，所以 OSS 上的课件预览会先
  `getObjectToFile` 取到 `uploads/.oss-preview-cache/<fileId>` 再转换（同一份只下一次）。
```

## 步骤（按顺序做，每步都有验收）

```text
① 代码上线（**已完成**，2026-09-23）
   OSS 客户端 + 适配层 + 上传/下载/预览接线 + .env.example 文档；构建 38 通过 / 0 失败。
   此时 FILE_STORAGE 没设 → 存储后端判定是 local，**行为与之前完全一致**。

② 配非密钥项（**已完成**）
   /etc/ai-kids-platform/production.env 里已写入：
     OSS_BUCKET=cn-guangzhou-aliyun-cloudauth-2026063015598321
     OSS_REGION=cn-guangzhou
     OSS_ENDPOINT=oss-cn-guangzhou.aliyuncs.com
     OSS_INTERNAL_ENDPOINT=oss-cn-guangzhou-internal.aliyuncs.com
     OSS_PREFIX=lingdong
   FILE_STORAGE 故意**先不打开**。

③ 用户贴密钥（**这一步只能由用户在控制台做**）
   密钥是密码级的东西：不进仓库、不进文档、不进聊天记录。做法见下一节。

④ 验连通性（密钥到位后第一件事）
   cd /srv/ai-kids-platform/source
   export $(grep -E '^(FILE_STORAGE|OSS_)' /etc/ai-kids-platform/production.env | xargs)
   /srv/ai-kids-platform/runtime/node/bin/node deploy/production/migrate/09-verify-oss.mjs
   验的是真链路：内网写 → 内网探 → **公网签名 URL 取回同一份字节**（这一步最容易错）
   → 覆盖响应头生效 → 删掉测试对象。任何一项 ✗ 都**先别打开 FILE_STORAGE**。

⑤ 回填历史文件（275 个）
   node deploy/production/migrate/10-backfill-uploads-to-oss.mjs --dry-run   # 先看范围
   node deploy/production/migrate/10-backfill-uploads-to-oss.mjs             # 真做
   安全设计：**默认保留本地文件**；每个对象"先传→再探→字节数对得上"才写标记；
   幂等，可中途断、可反复跑；失败的行仍是本地盘（读路径不受影响），修完重跑即可。

⑥ 打开开关
   在 env 里把 # FILE_STORAGE=oss 的注释去掉 → systemctl restart learning-platform-production
   验收：新上传一个文件，看它落 OSS 且能正常下载/预览；老文件照旧能读。

⑦ 观察一段时间再考虑省磁盘
   默认**不删本地文件**（回滚只要去掉标记）。确认稳定后，真要省磁盘再加 --prune-local 重跑。
```

## 回滚（三档，都很快）

```text
· 只回滚"新上传"：把 FILE_STORAGE 改回 local → 重启。新上传回本地盘，历史行不受影响。
· 回滚"某一行"：把那一行 metadata.storageBackend 去掉 → 它立刻按本地盘读（本地文件还在）。
· 全量回滚：FILE_STORAGE=local + 批量去掉 metadata 里的 storageBackend 标记。
  ⚠️ 如果跑过 --prune-local，本地文件已经删了，那就得先把对象从 OSS 拉回来再回滚。
```

## 用户贴密钥的做法（不进聊天记录）

用**阿里云控制台的「云助手 / 发送命令」**（不用登录机器，也不用给任何人密码）：

1. ECS 控制台 → 实例 → 选中新机 → **运维与监控 → 发送命令 / 云助手**
2. 命令类型选 **Shell**，粘贴下面这段（把两个值换成你自己的），执行：

```bash
cd / && cp -a /etc/ai-kids-platform/production.env /etc/ai-kids-platform/production.env.bak-$(date -u +%Y%m%dT%H%M%SZ)
printf '\nOSS_ACCESS_KEY_ID=%s\nOSS_ACCESS_KEY_SECRET=%s\n' '在这里粘贴 AccessKey ID' '在这里粘贴 AccessKey Secret' >> /etc/ai-kids-platform/production.env
chmod 600 /etc/ai-kids-platform/production.env
grep -c '^OSS_ACCESS_KEY_' /etc/ai-kids-platform/production.env
```

3. 最后一行应输出 `2`（两个键都写进去了）。贴完告诉一声，我接着跑第 ④ 步。

> ⚠️ 贴之前请确认 RAM 子账号的权限是**只准动这一个 bucket**的自定义策略，
> 而不是 `AliyunOSSFullAccess` —— 那个密钥会长期躺在这个文件里。
