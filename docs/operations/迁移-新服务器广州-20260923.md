### 又踩到这几个（2026-09-23 深夜补记）

```text
⑦ **在国内机器上构建，pnpm 会静默卡死**。
   runtime 里的 pnpm 是 **corepack 壳**，第一次用要去网上取 pnpm 二进制；而 pnpm install
   仍按 node_modules/.modules.yaml 里记的 **registry.npmjs.org** 去核对 —— 国内直连是
   "连上但不传数据"（实测卡在连 Cloudflare 104.16.x.x，60 秒零字节增长，`--reporter=silent`
   让日志里一个字都没有，看起来像死机）。两处都要改：
     export COREPACK_NPM_REGISTRY=https://registry.npmmirror.com
     printf 'registry=https://registry.npmmirror.com\n' > /root/.npmrc
   改完 `pnpm config get registry` 应回显镜像；再跑构建。
   （本次重建产物里的 pnpm 版本是 11.19.0 —— 仓库 packageManager 字段声明的那个，
     不是旧机命令行上看到的 12.5.1。corepack 在仓库目录里会按 packageManager 取。）

⑧ **搬运脚本会把"已经改好的新机配置"覆盖回旧值**（这次真发生了）。
   05-push 的**第一梯队**里有一项是 `/etc/ai-kids-platform/`（环境文件）。
   我在 08:32:13 把 env 域名改成 aicyld.com，而那次重启的 05-push 恰好在 08:32:40 之前
   又把旧机的 env 推了一遍 → **env 被静默改回 iicili.cyou**（证据：rsync 会保留 mtime，
   新机上那份 env 的 mtime 是旧机的 2026-09-21 14:00）。
   危害：服务一旦重启就会用旧域名（CORS/链接全错），而构建会把旧域名烤进前端产物。
   铁律：**切过域名之后，任何"重推配置"的动作都是回退**。搬运必须一次性做完，
   或者在重推前把 env / nginx 站点 / DB 订正这几项排除掉。
   同一次事故里我也确认了：DB 的 485 行订正、前端产物、nginx 站点、监控脚本**都没被覆盖**
   （只有 env 命中），恢复方式就是重新 sed 一遍 env + 重启服务。

⑨ **旧机上的绝对路径会跟着脚本一起搬过来**：
   `production/bin/daily-backup.sh` 里写死了 `/srv/ai-kids-platform/internal-test/source`

   **每日备份会一直失败**（实测报 "No such file or directory"），

     mkdir -p /srv/ai-kids-platform/internal-test
     ln -sfn /srv/ai-kids-platform/source /srv/ai-kids-platform/internal-test/source
   为什么软链更好：RUNBOOK 里的运维命令（`cd /srv/ai-kids-platform/internal-test/source && node scripts/...`）
   写的也都是那个路径，软链让它们原样可用。改完实测备份 `state: ok`、健康检查四项全 ok。
```

### 带宽的实测结论（给以后遇到同类问题的人）

```text
旧机出网：**3.0–3.2 Mbps**（原始配置，并发 4 条也一样 → 是整机限额）
升级到 100 Mbps 后：**聚合 ~10 Mbps**（单流 ~2.7 → 开 BBR 后 ~8.9），仍吃不满 100
  · 旧机**下行 126 Mbps**（从国内镜像 31.6MB 两秒下完）→ 说明整机网络没被限在 10
  · 8 条并发只到 7.8 Mbps，且重传计数极大 → 瓶颈是**出方向**这一侧的限额/丢包组合
  · **开 BBR 有效**：`modprobe tcp_bbr` + `sysctl net.core.default_qdisc=fq
    net.ipv4.tcp_congestion_control=bbr`（Ubuntu 26.04 默认只有 reno/cubic，要手动 modprobe）
  · 但**改带宽本身不需要重启** —— 它确实即时生效了（3.3 → 10 Mbps 那一截就是它的功劳）
  · 结论：跨地域搬大量数据时，先把 BBR 打开再搬；带宽能升就升，但别指望单流跑满
  · ⚠️ 如果旧机是**按固定带宽**计费，升级是按时长收费的 —— 搬完记得降回去或释放实例
```

### 换域名时**最后一个**必须查的地方：dsh 的学生入口域名

```text
⑫ `run-student-user.sh` 里 `PUBLIC_IP="${PUBLIC_IP:-iicili.cyou}"` ——
   学生环境的入口地址（EDGE_URL）就是用它拼的：https://<PUBLIC_IP>:<端口>/?t=<票据>。

   学生点进去就是死路（而且平台日志一切正常）。
   修法（不要改脚本，改成配置）——在 broker 的单元里加一行：
     Environment=PUBLIC_IP=aicyld.com      # dsh-host-broker.service
   为什么放单元里：broker 用 execFile 调脚本且没传 env，所以子进程**继承 broker 的环境**；
   这样脚本本身将来换代也不会把域名丢掉。
   验收：起一个冒烟环境，看 stdout 的 EDGE_URL 是不是新域名。

   排查方法（照抄）：`grep -rn "<旧域名>" /opt/dsh-host-user/ /opt/dsh-runtime/etc
   /opt/dsh-runtime/home /etc/systemd/system/` —— 本次只有这一处命中。
```
