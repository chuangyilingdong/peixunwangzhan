## 二、这一轮做了什么

### A. 补完上一轮欠的两处核验（第二十七轮 §五 第 6 条）

**① 画布「老师一点结束课堂，学生端就自己退出」—— 真浏览器，通过。**
走真链路：真浏览器里的学生画布 + org-admin 的**真接口**结束课堂（不是直接改库）。实测：

```text
结束前页面上没有那条提示（对）
老师结束课堂（接口 200，9ms）
结束 → 7526ms 提示出现（画布每 10 秒问一次 session-state，落在窗口内）
页面上的原话：老师已结束课堂（MANUAL），正在回到课程中心…
提示 → 跳走 1435ms（口径是留 1.6 秒）
落点 /learn，页面上是「我的课程」
```

截图三张在服务器 `.tmp/page-shots/sessend/`（提示那一刻、落点、跳之前）。核验脚本
`.tmp/then-session-end.mjs`（用下面 B 的 `--then` 钩子写的）。

**② 机构端/老师端作品预览（用户图5）—— 真浏览器，读面通过。**
`/org/works` 点「查看作品」→ 预览块「作品内容 · …」打开、**默认停在「作品内容」**（不是画布）、
「作品内容 / 创作画布」两个标签都在。截图 `.tmp/page-shots/orgwork/`。

⚠️ **同一次运行撞出了 C 那个真问题**：那 3 张图在浏览器里是**坏的** —— 脚手架日志里
`ERR_BLOCKED_BY_ORB https://getapib.org/...`。追下去才知道上游那些地址已经 403（见 §二.C）。

### B. `page-shot` 长出 `--then` 钩子（顺带查清 `--click` 为什么"点不动"）

`--click` 只能按文案点一下；而"老师结束课堂 → 学生端自己退出""点开预览看弹窗里的东西"这类
要**等状态翻转、看跳没跳**，按一下按钮什么都验不出来。新增 `--then <文件.mjs>`：
它导出的 `run({ page, api, db, log, shot })` 可以任意 await / 断言 / 自己截图，返回值进 `report[i].then`；
返回 `{ expectRedirect: '/learn' }` 时，底下那条「被重定向了」的断言会**改成"必须落到这个地址"**
（是把断言换准，不是关掉）。

**`--click` 点不动的真因**：机构端「作品管理」每一行都有一个「查看作品」（实测 **8 个**），
而 `--click` 只取 `first()`，命中哪一类全看列表排序 —— **不是按钮点不了**。这条已经写进脚手架头部。

### C. ⭐⭐ 生成产物归档：上游给的是**临时地址**，我们只存了引用

**怎么发现的**：验机构端作品预览时，浏览器日志里 3 条 `ERR_BLOCKED_BY_ORB`。
追下去——那些媒体地址全是站外的上游图床，逐条 curl：

```text
media_assets 44 行里，32 行的 asset_url 是**站外**地址：
  getapib.org（图）21 条、腾讯 COS（视频/音乐）11 条
getapib.org 那 21 条实测：14 条还 200，**7 条已经 403**（CloudFront 回 application/xml）
  → 浏览器按 ORB 挡掉 → 读面里就是一片坏图占位
视频那条域是好的（200 / video/mp4 / 513KB）
```

「任务成功」不等于「这件东西以后还在」—— 与口径 71（交给外部的素材对方可能读不到）是**同一族的另一半**：
外部给的地址，对方随时可以收回。

**修法**（`apps/server/src/services/generatedAssetArchive.js`）：生成成功时把产物**下载回来**、
存成**学生本人的私有素材**（`/api/student/file-assets/<id>/download`，与「学生自己传的图」「PPT 插画」
逐字同一条路），再把 `media_assets.asset_url/preview_url` 换成它。

三条刻意的取舍（**两条方向的失败策略正好相反，别改混**）：

```text
① 这个方向失败**绝不报错**：学生已经花过钱、上游已经出片，为了一次归档失败把整条成功判死，
   比丢一个地址糟得多 → 一律 best-effort，拿不到就保留原地址 + 在 metadata.archive 里记原因。
   （反面 upstreamMediaMirror 是"我们的素材传给上游"，那边失败**必须报错** ——
     静默的后果是"生成出一段跟参考无关的作品"。）
② 存成**私有**素材（PRIVATE + /api/student/...），不是 PUBLIC_PLATFORM：
   未提交作品里的图不该有公网地址。发布时广场走"作品专属公开代理"（见下）。
③ 只收**我们自己落盘校验认得的类型**（png/jpg/webp/gif/mp4/webm/mp3/wav/ogg）。
   上游会给 QuickTime 容器（`.mov`，品牌 `ftypqt`）—— 字节嗅探只看得到 `ftyp`、会判成 mp4，
   而浏览器**播不了** qt 品牌（2026-09-21 那次 `.mov` 事故）。存一份"看着是 mp4、其实播不动"的东西
   比留个会过期的外链更糟（它看起来是好的）→ 直接跳过并记原因。
```

### D. 三条读面一起接上（少一处就是"图还是不出来"）

产物变成我们自己的私有地址之后，**四处读面各有各的取法**，一处不接就是"看得到作品页、图却 403"：

```text
· 学生端「我的作品」/ 报名页：早就有 imageUrls + resolveSrc（转 data:）—— 不用动。✓
· 课堂预览 ClassroomWork：早就有 snapshotImage —— 不用动。✓
· **广场**（新增）：访客未登录，拿不动 /api/student/... →
    · 新路由 `GET /api/public/works/<token>/images/<fileId>`，准入与作品详情**逐字同一条件**
      （`share_token=? AND is_public=1`）+ fileId 必须出现在这份作品的快照里；
    · `publicWorkRow` 把 fileId 形式的媒体地址换成这个代理 → 前端 `srcOf` 直接用 `item.url` 就能显示，
      **前端一行没改**。
· **机构端**（补齐）：作品详情那条路由的准入清单原来只认画布快照里的素材 →
    把**归档件也算上**（`media_assets` 里的 fileId）；列表下发 `imageUrls`（批量查一次，
    别每行一个查询）；前端预览补 `resolveSrc`（`<img>` 发不出 Authorization 头，要转 data:）。
· 画廊：加载失败时显示「图片已失效，读不出来了」，而不是只留一个浏览器破图图标。
```

### E. 存量回填（这以前产出的东西不会自己变好）

`deploy/production/backfill-generated-media.mjs`，**默认干跑、要 `--apply` 才写**。三处一起改：

```text
① media_assets.asset_url / preview_url   —— 读面「做出来的东西」那一栏的来源
② student_projects.canvas_snapshot       —— **画布本身就存着那个地址**
③ works.canvas_snapshot                  —— 提交时抄的一份，**广场的媒体清单正是从它提的**
只改 ① 等于没改（广场依旧显示那个会过期的外链）。
```

**在副本上实跑的结果**：

```text
32 条目标 → 归档成功 25 条（14 png / 10 mp4 / 1 mp3，49MB，落到上传根）
            跳过 7 条：上游已经 403（救不回来，保留原地址）
复查：已归档 25；仍挂外链 7；快照里残留的**已归档**地址 0 处
```

⚠️ **这个脚本中途被杀过一次（被 580 秒的 timeout 掐掉），因此改了设计**：替换表从
`metadata.archive.sourceUrl` **从库里推**，而不是用"本次跑出来的那份内存清单" ——
否则库已经改了、快照还没改，下次重跑只看"这次成功了几条"就**永远漏改**那批快照。
现在它天然可续跑，跑第二遍会报「无需改动」。

## 三、不许破的口径（承接 1–87；**本文新增 88**）

### ⭐⭐ 口径 88：外部给的产物地址**不是你的** —— 拿到手就存一份

上游返回的图/视频地址是**临时的**，过期后返回 403，而且**不会有人通知你**：
任务成功、日志干净、数据库里那一行看着好好的，只有把读面打开才发现是一片坏图。
判据只能量**产物本身现在还在不在**（逐条请求看状态码），不能看任务状态。

与口径 71 是同一条道理的两半：
71 是"你交给外部的东西，对方可能读不到"（素材传上游）；
88 是"外部交给你的东西，对方随时会收回"（产物归档）。
**两边都不能假设"传过去了/拿到了"就等于"以后还在"。**

配套的三条落地口径（都写进 §二.C 的取舍里了）：

```text
· 归档失败**绝不能让这次生成失败**（学生已经花过钱、上游已经出片）—— 与"素材传上游失败必须报错"正好相反；
· 归档件存成**本人私有**素材，别图省事存成公网可取（未提交作品里的图不该有公网地址）；
· 只存**我们自己的落盘校验认得的类型**：上游会给 `.mov`（`ftypqt`，浏览器播不了），
  存成一份"看着是 mp4、其实播不动"的东西比留个会过期的外链更糟。
```

配套一条**读面口径**：我们自己的媒体在四个读面上各有各的取法 ——
**改一处读面时要把四个都过一遍**（广场 / 我的作品 / 机构预览 / 课堂预览），
其中广场那条是唯一"未登录访客"的，必须由服务端给**作品专属的公开代理**，不能让前端去取私有地址。

## 四、这一轮踩过的坑（承接 1–108；**本文新增 109–112**）

### 坑 109：`--click` 遇到**同名按钮**只点第一个，看起来像"按钮点不动"

机构端「作品管理」每一行都有一个「查看作品」（实测 8 个），`page.getByRole(...).first()` 命中哪一条
**完全看列表排序**。我上一轮记的"`--click` 在这几页点不动"其实是这个 —— **不是按钮真的点不了**。
要挑特定那一行就自己按行找（`--then`），别急着改选择器。
**教训**：说"点不动"之前先数一下同名元素有几个。

### 坑 110：脚本跑到一半被杀 → 库改了、快照没改（**半成品状态最难发现**）

回填脚本逐条下载、慢，被 580 秒的 timeout 掐掉过一次。第一版的"替换表"是**本次跑出来的内存清单**，
于是：库里的 25 条已经改了，而快照里的旧地址一个都没换 —— 重跑时因为"这次成功 0 条"，
那批快照就**永远漏改**，而且现象是"看起来已经做完了"。

**修法**：替换表从**库里的 `metadata.archive.sourceUrl`** 推（谁归档过就换谁），天然可续跑；
并且脚本自己复查"快照里还有没有**已归档**的地址"，非 0 就 `exitCode=1`。
**教训**：一次性迁移脚本要能**中途重入**，判据要从**落库的状态**推，不能从"本次跑了什么"推。

### 坑 111：口径改了，**守卫的断言没跟着换** → 那条每跑必红

第二十七轮 §二.T 把画布 toast 的红绿与"留不留"从**猜消息里的字**（`message.includes('失败')`）
换成了 `errorText()` 的标记（`isErrorText`），但 `p110` 那条断言还钉着旧写法 —— 全量守卫里
**它一直是红的**，而红的内容是"上一轮已经改掉的东西"。这正是 README 里记过的同一类毛病
（口径删了断言要跟着删，否则发布会误报 / 真出问题时被当成老毛病）。

**同类第二处**：`p75` 钉着"轮询次数恒等于 2"，而第二十七轮 §二.Q ③ 改成"瞬时错误按退避重试到
deadline"之后次数不再固定（实测 8 次）。**在未改动的 HEAD 上实跑确认过它也是红的**（不是本轮引入）。
本轮把两条都换到新口径上（p75 改成"至少提交 + 轮询一次"）。
**教训**：改判据的那一轮，**顺手 grep 一遍钉着旧判据的守卫**。

### 坑 112：以 root 跑的数据脚本，落盘文件**服务用户读不到** → 前台 502 + "图片已失效"

回填脚本我是以 `root` 跑的（迁移脚本的常态），而 `persistSecureUpload` 落盘的文件属主是 root、
权限 `0640`；生产服务跑在 `ai-kids-prod` 下 —— **它读不到**。现象很有迷惑性：

```text
公网：502（nginx 说 "upstream prematurely closed connection while reading response header"）
盘上：文件在、字节数也对（stat 看不出任何异常）
界面：作品页整页「图片已失效，读不出来了」
```

**而且它骗过了副本上的浏览器核验** —— page-shot 起的临时实例也是 root，读得到，截图一切正常。
**只有打线上才发现。**（与 README 里"客户端更新清单属主从 root 改成 ai-kids-prod"是同一条。）

修法：① 本次落盘的 24 个文件当场 `chown ai-kids-prod:ai-kids-prod`；
② 回填脚本里加上"以 root 跑时把刚落盘的文件交还给上传根的属主"（`process.getuid() === 0` 才做）。
**教训**：**以 root 跑的数据脚本，凡是写了文件，都要把属主交还给服务用户**；
以及**权限这类问题只有"以服务用户打线上"才看得出来**。
