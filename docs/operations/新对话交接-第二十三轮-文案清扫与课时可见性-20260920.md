### C. 课时可见性改「快照口径」+ 存量迁移（`10ca093` / `79a37ed` / `2c91414` / `0216234`）——本轮最重的一件

用户报：「我在课包创建了新的课时，选择发布状态。但是课包还没发布，在图1机构/老师端却已经能选了」。

**根因**：草稿隔离只做了一半 —— 课时的**字段**走快照，**成员与状态**却按实时的 `status='PUBLISHED'` 过滤。
判据见 `apps/server/src/lib.js` 的 `publishedLessonVisibilitySql`（**只写这一处**）：
课包**一节课时都没定格过** → 回退实时（老数据口径）；定格过 → **只认快照里的 status**。
四个读面都换了：`normalizeSeries`（课时数 + 清单）、官网课包列表、官网课包详情、学生端 `getStudentCourses`。

**存量数据必须迁移**（`deploy/production/migrate-lesson-snapshot-baseline-20260920.mjs`）：
切判据前若不补基线，S1 会从 **9 节掉到 0 节**、`测试` 从 **2 节掉到 0 节**（它们已有的快照里没有 status 键）。
迁移**只写 status 一个键**：不动 `published_title`、不动课包快照、已有快照的其余键原样保留。
**顺序不能反**：先整库备份 → 干跑 → 迁移 → 核对 → 才发布代码。

生产实测：34 节课时补了基线，每个课包「迁移后可见数 == 迁移前实时已发布数」（S1 9=9、测试 2=2、S2 0=0），
发布后官网 `lessonCount` 仍是 9 / 2、`deliveryModes` 仍是 `["CANVAS"]` / `["VIBECODING"]` —— 谁都没少看到课时。
留底：`production/data/backups/lessons-published-content-before-20260920-*.json`。

### D. p111 那条「既有的红」：根因与记录的不一样（`cc5e04b` / `9a36712` / `62618ed` / `de0931b` / `f2dbb72`）

夹具 `.tmp/test-sample.pdf` 是上一轮手工塞的**单页**最小 PDF，而那几步假设文档有多页 ——
单页时「下一页」本来就该禁用，去点它必然 30 秒超时。

更要命的是它**崩在断言汇总之前**：前面所有 `expectText` 的失败只进 `problems` 数组，
而打印清单与 PASS/FAIL 的代码在最后 —— **整条守卫是哑的，只看得见红、看不见红在哪**。
（我改文案时就被它坑过：跑完拿不到任何失败清单，只能去 grep 产物。）

修法：夹具改成守卫**自产 3 页 PDF**（不再依赖没进仓库的文件），于是它第一次跑到底 ——
**又露出 5 条从没跑到过的失败断言**（上一轮删掉的「页面边界」等），一并改掉。现在 `UI CHECK PASSED`。
另外 `p112` 的「退休⑥」反过来改了：旧断言要求那两个文件里**必须**出现「不拦学生」，文案删了那句话就没了意义。

### F. 预览沙箱的「存储替身」：**「图1 无法正常玩」的真因**（`a2582dd`）

用户报：学生那份「简单打地鼠」在作品预览里**画得出来但点不动**（标题、9 个洞、按钮都在）。

真因**不在作品里**：预览跑在不带 `allow-same-origin` 的 sandbox 里（口径⑧，不能放松）⇒ 文档是
opaque origin ⇒ `localStorage` **一读就抛 SecurityError**；而那份游戏**第 165 行**正是
`let best = Number(localStorage.getItem('whack_best') || 0);` —— 顶层就抛，整个 `<script>` 当场结束，
`startBtn.addEventListener('click', startGame)`（第 237 行）永远没跑上。

修法：`buildPreviewDocument` 给学生文档预插一份**内存版** `localStorage/sessionStorage/cookie`
（与已有的 console 桥同一个插入点、同在学生脚本之前）。三个预览面共用这一个函数 ⇒ 一处改动三处生效。
**它不放松隔离**：文档仍是 opaque origin，照样读不到主站与别的作品。

⚠️ 管不到广场那 9 件**导入**作品（nginx 直接发 `entryUrl`，我们不参与拼装）：其中
「单词小侦探」也用了存储，但读被 try 包着，只是丢持久化（要彻底解决得把导入件改成走外壳页）。

### G. 作品卡片自动封面（`5d74a75` / `2204ad6`，**未部署**）

用户口径：「图2 学生发布的作品应该自动生成个封面」。原来卡片只有一个类型 emoji + 标签，一排作品一个样。
两层：① 服务端给了真封面（`coverUrl`）就用真的；② 没有 → 按作品信息**当场画**一张内联 SVG
（类型定色系与插画、标题哈希定色相偏移与构图、首字做水印）。纯函数，同一件作品永远同一张。

⚠️ 第一版色相只抖 ±12°，实测 15 张画布作品几乎分不出来（等于没做），第二版拉到 ±45° 并轮换

### H. 查看层预览改「逻辑视口 + 等比缩放」（`16723b2` / `a38b5f2`）

用户报（图1 红框）：学生作品页的预览区右侧出现了**内层滚动条**（游戏本身已经能玩了）。

真因：**查看层那个共享预览把框体高度写死成 `62vh`**（`.c-replay__frame`），内层学生页就按这个高度当
视口渲染 —— 720 视口下只有约 446px，而打地鼠/贪吃蛇这类学生页要 ~600px，于是内层滚起来。
**这正是口径㉖ 点过名的坑**；广场早在第二十二轮就用「逻辑视口 + 等比缩放」修过（`PL_FRAME_MIN`），
只是**查看层这个共享组件没走那套**。

改法：把广场那套搬进共享的 `PreviewFrame`（`PREVIEW_LOGICAL_MIN`，与广场同一组数 640×768）——
量可用空间 → 算出"不小于 640×768"的逻辑视口 → 整张 iframe 等比缩放到装下为止（有空间时封顶 1）。
用 `fitToLogical` 开关打开、**默认关**：`ReplayPreview`（学生「我的作品」/ 广场作品详情 /
机构端课堂作品）打开；工作台的编辑预览与"手机模拟器"保持原样（它俩有自己的 stage 与视口语义，
也没被报过）。CSS 上高度从 iframe 挪到舞台 `.c-replay__stage`。

### I. 机构端/平台端能看见并预览学生的 VibeCoding 作品（`d537d43` + 两个转义修复）

用户两个口径：①「机构/老师看不到学生提交的作品」；②「平台能看到作品，但是也要能预览吧。现在只有个标题」。

  现在并入 VibeCoding 提交（`source: 'VIBECODING'`，带 entryFile/课包/课时/课堂），
  筛选口径的差异写在注释里（这类作品没有 PUBLISHED 状态，那个筛选值等价于"已发布到官网"；举报恒 0）。
- **「作品详情 / 图片 / 文件」三条读路由泛化出机构作用域**（`/api/org/works/...`）：原来只有课堂作用域，
  而有的提交**没挂课堂**，用它根本打不开。课堂作用域行为一字未改；两种作用域返回同一套 URL 前缀，
  `ClassroomWork` 因此改成收 `workBase`、两处复用。
- **平台端**新增 `GET /api/admin/vibecoding-works/:id`（带 files/entryFile/artifacts + 服务端拼好的 fileUrls）
  与 `:id/files/:name/(preview|download)`（超管；准入只认这份作品快照里出现过的 fileId），
  作品库那一列加了「预览」：网页在不带 allow-same-origin 的沙箱里真跑、文档给服务端转的 PDF。

## 三、不许破的口径（承接 1–36；**本文新增 37–45**）

37. ⭐ **「课时对读面（机构端/学生端/官网）可见吗」只认快照**：判据是
    `publishedLessonVisibilitySql(alias)`（`lib.js`），**只写一处**，四个读面共用。
    课包一节课时都没定格过 → 回退实时；定格过 → 只认快照里的 status（没有快照的课时不可见）。
38. ⭐ **回退实时必须放在「课包级」**，不能按课时判：线上 S1 是「9 节已发布里只有 1 节有快照」，
    按课时判会当场掉 8 节（实际会掉到 0 节，见坑⑸）。这条是"老数据没有快照 → 回退实时"的落点。
39. ⭐ **快照里必须带 `status`**：`capturePublishedContent` 写漏它，读面就会把「发布之后新建的课时」
    当成"没有快照"。判据要读它，不是读实时列。
40. ⭐ **读面给出的 status 也走快照**（`normalizeLesson` 的 `pick('status', …)`）：只改"可见性"不改它，
    就会出现「能看到这节课、但它的状态显示成实时值」，机构端详情原来据此又过滤了一次，正好把它滤没。
41. ⭐ **判据不许有第二份**：机构端详情那道 `filter(l => l.status === 'PUBLISHED')` 就是反例
    —— 两条规则不一致会以"假红/假绿"的形式出现，而且极难查。
42. ⭐ **写路径与「能不能真的进这节课」的门禁有意更宽松**（仍按实时状态）：课堂一旦绑定了某节课，
    后来的发布把它盖成草稿，也不该把已经在上的学生踢出去。别顺手"统一"成快照口径。
43. ⭐ **改这条口径之前，先量「迁移前后可见集合」并把它守成不变量**，且**先迁移后发布**。
    改判据 + 存量数据形状不对 = 线上课时当场消失（而且是静默的）。
44. ⭐ **清扫的边界**（口径㉟ 的细化）：删**页面级**说明块与内部观测展示；
    **留** PageHeader 副标题、二次确认弹窗的操作影响说明、空状态/校验/错误、字段级短提示。
45. ⭐ **验证"删掉某块 UI / 某个字段"最硬的证据是在服务器上 grep 已发布产物**
    （本机 node 是 v16，项目要 ≥22，**本地根本构建不了**，所以一切验收只能在服务器上做）。

46. ⭐ **学生代码不能死在我们自己的沙箱里**：预览是 opaque origin，`localStorage`/`sessionStorage`/
    `document.cookie` 一读就抛 —— 而 AI 生成的游戏十有八九在**顶层**读一次最高分。
    凡是"页面画得出来但点不动"，先看 console 里有没有那条 SecurityError，别去作品里找 bug。
    修法固定在 `buildPreviewDocument` 的 preamble（替身 + 桥），别在别处各写一份。
47. ⭐ **作品封面要自动长出来，且优先用真封面**：`coverUrl`（服务端截图，将来）> 内联 SVG 自绘。
    自绘是纯函数（只看 id/标题），所以同一件作品永远同一张；别改成随机 —— 刷新一次换个色就露馅了。
    刻意不"猜内容"（按标题挑吉祥物）：猜错比中性的封面更糟。

48. ⭐ **查看层的预览框体不许用 CSS 写死高度**（`62vh` / `100%` 都不行）：内层学生页的"视口"就是
    那张 iframe 的尺寸 —— 写死多少，学生页就按多少渲染，比它需要的高度矮就**必然滚起来**。
    正确做法是"逻辑视口（≥640×768）+ 整体等比缩放"，判据只写一处（`PreviewFrame` 的
    `PREVIEW_LOGICAL_MIN`，与广场的 `PL_FRAME_MIN` 同一组数）。
49. ⭐ **放大逻辑视口的舞台必须裁剪**（`overflow: hidden`）：不裁剪的话，被放大到上千 px 的 iframe
    会把舞台自身撑宽，下一次测量又基于更宽的舞台 —— **自反馈**（实测滚到 5315px，
    是 p115 新断言抓出来的）。舞台的可用空间由**布局**给，不由内容给。

50. ⭐ **机构端的作品读面必须覆盖两类来源**（画布 `works` + VibeCoding `vibecoding_submissions`）：
    只读一张表就会出现「平台看得到、机构看不到」这种**沉默的缺失**（用户报的正是它）。
    平台端与学生端早就是合并视图，机构端不是。
51. ⭐ **作品预览弹窗要能按"作用域"复用**（`ClassroomWork` 的 `workBase`）：课堂详情按课堂看、
    作品管理按机构看，**渲染逻辑一个字不改**。别为了"没有课堂的作品"再写一个只读列表 ——
    两条路径迟早会各说各话。

## 六、这一轮踩过的坑（承接 1–47；**本文新增 48–56**）

48. ⭐ **本机 node 是 v16，项目要 ≥22** ⇒ `pnpm build` 直接拒跑，连 `node --check` 都把 `.mjs` 当 CJS
    （报错是"不能 use import statement outside a module"，与代码无关）。
    **一切构建与守卫都只能在服务器上做。**
49. ⭐ **守卫崩在断言汇总之前 = 整条守卫哑掉**：`problems` 攒着不打印，最后那行 PASS/FAIL 永远看不到。
    判断一条红守卫时，先看它**有没有跑到最后** —— 别拿"它红了"当"它验过这些"。
50. ⭐ **夹具必须与生产同形状**：p111 直接往库里插课时，快照里没有 `status`，
    加判据之后那节课在机构端直接看不见（课包详情页的「查看」按钮点不到，30 秒超时）。
51. ⭐ **缺口径的存量数据比想象的更糟**：快照里没有 `status` ⇒ 判据把整列课时判成不可见
    （S1 9→**0**、测试 2→**0**），不是"掉几节"。所以那个迁移不是可选项。
52. **课时状态机没有「已发布 → 草稿」**：`DRAFT→[PUBLISHED,ARCHIVED] / PUBLISHED→[ARCHIVED] / ARCHIVED→[PUBLISHED]`。
    写测试想"收回草稿"时被 `assertTransition` 拒了，断言就假红了 —— 测试里连 PUT 的返回码一起断言。
53. ⭐ **`pkill -f "index.js"` 会命中生产进程**（它的命令行里也有 `apps/server/src/index.js`），
    而我拿它清临时实例 —— 生产收到 SIGTERM 优雅退出，unit 是 `Restart=on-failure` **不会**自动拉起，
    `/api/health` 502 了 17 秒（静态页仍 200，因为 nginx 直接发文件）。
    **杀进程要按 PID**；给临时实例起名/加环境变量前缀都要能单独匹配。
54. **用脚本往 JS 文件里写 `\n` 会被吃掉一层**，在字符串里留下真换行、把守卫写成语法错误。
    改成 `String.fromCharCode(10)` 拼（源码里一个反斜杠都不出现）。
55. **终端编码会把中文输出吃掉**：看到"接口没输出"先怀疑编码/管道，别急着怀疑接口
    （那次 `HTTP=200 bytes=1252`，JSON 是好好的）。
56. **临时实例的清理要连数据一起清**：验证用的生产库副本放在 `/tmp` 时，
    里面是**真实用户数据** —— 用完立刻 `rm -rf`，别留在服务器上。

57. ⭐ **沙箱里的存储不是"被禁"，是"一读就抛"**：`localStorage.getItem` 在 opaque origin 下抛
    SecurityError，且是**同步抛**——顶层那一行会让整个脚本当场结束（不是"存不上"，是"全不跑"）。
    表现极具迷惑性：DOM 画得出来（那是 HTML 本身），按钮全哑。真浏览器跑一遍才看得出来
    （p123 就是钉这个，含一条"不带替身必须复现"的反向对照）。
58. **往守卫里插新段落时，先看清后面的段落还在依赖哪个页面**：我把「我的作品」那段插在
    `learnChrome` 之后，而紧接着的「课程卡片」那段还在**期待 /learn 的上下文** ——
    被我这段的 `goto` 一带走，就报成「课程中心：没找到课程卡片」的**假红**（连跑两遍都一样，
    不是偶发；所以"重跑一次看还红不红"能区分偶发与真错，但不能区分"错在哪"）。

59. ⭐ **这台 2 核机器上的"连不上"先看 `uptime` 再看安全组**：SSH 报
    `Connection timed out during banner exchange` 时，若 `vmstat` 显示 `r=0 b=0` 而 load 很高，
    那是**刚过去一波尖峰的衰减值**——snapd 的周期性刷新（chromium 就是 snap）加上连跑浏览器守卫
    就能把它压几分钟。别急着让用户去云控制台改 IP（安全组那条是另一回事，`git push` 通不通能区分）。

60. ⭐ **`INSERT OR IGNORE` 会把"值不合 CHECK"这件事静默吞掉**：p115 夹具给
    `vibecoding_conversations.status` 写了 `'ACTIVE'`（CHECK 只允许 DRAFT/SUBMITTED/ARCHIVED），
    那一行被悄悄丢掉，直到下面 `vibecoding_submissions` 的外键才炸出
    「FOREIGN KEY constraint failed」—— 现场看着像外键配错，其实是夹具自己写坏了。
    临时库每次都是新的 ⇒ **夹具用普通 INSERT，让它错就当场炸**。
61. **别把"舞台类"只写在 CSS 里、忘了组件真的渲染的是哪个类名**：我给高度写了 `.c-replay__stage`，
    而组件渲染的是 `c-preview__stage` + 追加类 —— 结果舞台没有裁剪样式，直接踩上面的坑 60 那种
    自反馈。新加的钩子类，写完就去产物或 DOM 里确认它真的存在。

62. ⭐⭐ **含反斜杠的 JS 不要用脚本（python/shell 引号）写**：这一轮踩了**两次** ——
    `'\'`、`[%\_]`、`ESCAPE '\'` 被吃掉一层，写成 `''` 就是语法错误。
    而且**前端构建拦不到服务端文件**（vite 只打包前端），只有服务端跑起来才炸。
    反过来也有一条好用的检查：`node --check apps/server/src/.../*.js` 在服务器上（node 24）直接有效。
63. ⭐ **连着跑浏览器守卫会把这台 2 核机压到 SSH 都连不上**（`Connection timed out during banner exchange`，
    负载 20~60，`vmstat` 里 CPU 还是 idle —— 是刚过去那波尖峰的衰减值）。
    判断"是我的改动坏了还是机器忙"最省事的办法：**看这两个守卫走不走我改的页面/接口**；
    本轮 p111/p115 都不经过新加的页面，单跑（等负载回落）就都绿了。
    别在没确认前让用户去云控制台改安全组。
64. **机器会来一次干净重启**（本轮 19:29 一次 `poweroff`，日志里没有 OOM/watchdog 痕迹）：
    服务是 `enabled`，开机自动拉起，五入口 200、数据与 release 都没变。
    但**先确认 `systemctl is-enabled`**，否则重启后线上就是躺着的 —— 这台机器上值得记住。
