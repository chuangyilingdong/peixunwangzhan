### C. 课时可见性改「快照口径」+ 存量迁移（`10ca093` / `79a37ed` / `2c91414` / `0216234`）——本轮最重的一件

用户报：「我在课包创建了新的课时，选择发布状态。但是课包还没发布，在图1机构/老师端却已经能选了」。

**根因**：草稿隔离只做了一半 —— 课时的**字段**走快照，**成员与状态**却按实时的 `status='PUBLISHED'` 过滤。
判据见 `apps/server/src/lib.js` 的 `publishedLessonVisibilitySql`（**只写这一处**）：
课包**一节课时都没定格过** → 回退实时（老数据口径）；定格过 → **只认快照里的 status**。
四个读面都换了：`normalizeSeries`（课时数 + 清单）、官网课包列表、官网课包详情、学生端 `getStudentCourses`。

**存量数据必须迁移**（`deploy/production/migrate-lesson-snapshot-baseline-20260920.mjs`）：
切判据前若不补基线，S1 会从 **9 节掉到 0 节**、`测试` 从 **2 节掉到 0 节**（它们已有的快照里没有 status 键）。
迁移**只写 status 一个键**：不动 `published_title`、不动课包快照、已有快照的其余键原样保留。
**顺序不能反**：先整库备份 → 干跑 → 迁移 → 核对 → 才发布代码。

生产实测：34 节课时补了基线，每个课包「迁移后可见数 == 迁移前实时已发布数」（S1 9=9、测试 2=2、S2 0=0），
发布后官网 `lessonCount` 仍是 9 / 2、`deliveryModes` 仍是 `["CANVAS"]` / `["VIBECODING"]` —— 谁都没少看到课时。
留底：`production/data/backups/lessons-published-content-before-20260920-*.json`。

### D. p111 那条「既有的红」：根因与记录的不一样（`cc5e04b` / `9a36712` / `62618ed` / `de0931b` / `f2dbb72`）

夹具 `.tmp/test-sample.pdf` 是上一轮手工塞的**单页**最小 PDF，而那几步假设文档有多页 ——
单页时「下一页」本来就该禁用，去点它必然 30 秒超时。

更要命的是它**崩在断言汇总之前**：前面所有 `expectText` 的失败只进 `problems` 数组，
而打印清单与 PASS/FAIL 的代码在最后 —— **整条守卫是哑的，只看得见红、看不见红在哪**。
（我改文案时就被它坑过：跑完拿不到任何失败清单，只能去 grep 产物。）

修法：夹具改成守卫**自产 3 页 PDF**（不再依赖没进仓库的文件），于是它第一次跑到底 ——
**又露出 5 条从没跑到过的失败断言**（上一轮删掉的「页面边界」等），一并改掉。现在 `UI CHECK PASSED`。
另外 `p112` 的「退休⑥」反过来改了：旧断言要求那两个文件里**必须**出现「不拦学生」，文案删了那句话就没了意义。

## 三、不许破的口径（承接 1–36；**本文新增 37–45**）

37. ⭐ **「课时对读面（机构端/学生端/官网）可见吗」只认快照**：判据是
    `publishedLessonVisibilitySql(alias)`（`lib.js`），**只写一处**，四个读面共用。
    课包一节课时都没定格过 → 回退实时；定格过 → 只认快照里的 status（没有快照的课时不可见）。
38. ⭐ **回退实时必须放在「课包级」**，不能按课时判：线上 S1 是「9 节已发布里只有 1 节有快照」，
    按课时判会当场掉 8 节（实际会掉到 0 节，见坑⑸）。这条是"老数据没有快照 → 回退实时"的落点。
39. ⭐ **快照里必须带 `status`**：`capturePublishedContent` 写漏它，读面就会把「发布之后新建的课时」
    当成"没有快照"。判据要读它，不是读实时列。
40. ⭐ **读面给出的 status 也走快照**（`normalizeLesson` 的 `pick('status', …)`）：只改"可见性"不改它，
    就会出现「能看到这节课、但它的状态显示成实时值」，机构端详情原来据此又过滤了一次，正好把它滤没。
41. ⭐ **判据不许有第二份**：机构端详情那道 `filter(l => l.status === 'PUBLISHED')` 就是反例
    —— 两条规则不一致会以"假红/假绿"的形式出现，而且极难查。
42. ⭐ **写路径与「能不能真的进这节课」的门禁有意更宽松**（仍按实时状态）：课堂一旦绑定了某节课，
    后来的发布把它盖成草稿，也不该把已经在上的学生踢出去。别顺手"统一"成快照口径。
43. ⭐ **改这条口径之前，先量「迁移前后可见集合」并把它守成不变量**，且**先迁移后发布**。
    改判据 + 存量数据形状不对 = 线上课时当场消失（而且是静默的）。
44. ⭐ **清扫的边界**（口径㉟ 的细化）：删**页面级**说明块与内部观测展示；
    **留** PageHeader 副标题、二次确认弹窗的操作影响说明、空状态/校验/错误、字段级短提示。
45. ⭐ **验证"删掉某块 UI / 某个字段"最硬的证据是在服务器上 grep 已发布产物**
    （本机 node 是 v16，项目要 ≥22，**本地根本构建不了**，所以一切验收只能在服务器上做）。

## 六、这一轮踩过的坑（承接 1–47；**本文新增 48–56**）

48. ⭐ **本机 node 是 v16，项目要 ≥22** ⇒ `pnpm build` 直接拒跑，连 `node --check` 都把 `.mjs` 当 CJS
    （报错是"不能 use import statement outside a module"，与代码无关）。
    **一切构建与守卫都只能在服务器上做。**
49. ⭐ **守卫崩在断言汇总之前 = 整条守卫哑掉**：`problems` 攒着不打印，最后那行 PASS/FAIL 永远看不到。
    判断一条红守卫时，先看它**有没有跑到最后** —— 别拿"它红了"当"它验过这些"。
50. ⭐ **夹具必须与生产同形状**：p111 直接往库里插课时，快照里没有 `status`，
    加判据之后那节课在机构端直接看不见（课包详情页的「查看」按钮点不到，30 秒超时）。
51. ⭐ **缺口径的存量数据比想象的更糟**：快照里没有 `status` ⇒ 判据把整列课时判成不可见
    （S1 9→**0**、测试 2→**0**），不是"掉几节"。所以那个迁移不是可选项。
52. **课时状态机没有「已发布 → 草稿」**：`DRAFT→[PUBLISHED,ARCHIVED] / PUBLISHED→[ARCHIVED] / ARCHIVED→[PUBLISHED]`。
    写测试想"收回草稿"时被 `assertTransition` 拒了，断言就假红了 —— 测试里连 PUT 的返回码一起断言。
53. ⭐ **`pkill -f "index.js"` 会命中生产进程**（它的命令行里也有 `apps/server/src/index.js`），
    而我拿它清临时实例 —— 生产收到 SIGTERM 优雅退出，unit 是 `Restart=on-failure` **不会**自动拉起，
    `/api/health` 502 了 17 秒（静态页仍 200，因为 nginx 直接发文件）。
    **杀进程要按 PID**；给临时实例起名/加环境变量前缀都要能单独匹配。
54. **用脚本往 JS 文件里写 `\n` 会被吃掉一层**，在字符串里留下真换行、把守卫写成语法错误。
    改成 `String.fromCharCode(10)` 拼（源码里一个反斜杠都不出现）。
55. **终端编码会把中文输出吃掉**：看到"接口没输出"先怀疑编码/管道，别急着怀疑接口
    （那次 `HTTP=200 bytes=1252`，JSON 是好好的）。
56. **临时实例的清理要连数据一起清**：验证用的生产库副本放在 `/tmp` 时，
    里面是**真实用户数据** —— 用完立刻 `rm -rf`，别留在服务器上。
