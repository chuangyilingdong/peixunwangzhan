## ⚠️ 关键约束：抖音按 IP 风控，生产服务器出不了登录二维码（2026-10-25 实测）

| 环境 | 有头浏览器打开 douyin.com/user/self | 结果 |
|---|---|---|
| 本地 Windows（家用/办公 IP） | Edge，headless=False | ✅ 自动弹登录框，二维码清晰可截 |
| 生产 Linux（数据中心 IP） | Playwright Chromium + Xvfb，页面正常渲染 | ❌ 登录弹窗不渲染；页面里出现 `rc-verifycenter`（抖音验证中心）iframe |

- 生产页面的「登录」按钮可以点到（6 个元素、BUTTON/SPAN 都在），点击后页面无变化 → 登录组件被验证中心拦掉。
- 已排除的干扰项（都修好了，别再查这三处）：① Playwright Chromium 要装到服务用户可读路径（`PLAYWRIGHT_BROWSERS_PATH`，默认落 /root）；② 服务用户 HOME 必须可写（ProtectSystem=strict 下服务的 HOME 只读，有头 Chromium 会 SIGTRAP）；③ `contextlib.redirect_stdout` 会吞掉 worker 的结果行（要保存原始 stdout 引用）。
- **结论**：服务端扫码登录在生产 IP 上不可用。需要用户侧的登录入口（本地连接器 / 浏览器扩展 / 手动 cookie），或给服务器换非数据中心出口。
- 已实现的降级仍然有效：**游客模式浏览器旁路**能读公开主页作品（本地实测 21 条，含赞/藏数），业务上「看同行在发什么」不依赖登录。

| 能力 | 状态 | 证据 |

| 作品列表 `/aweme/v1/web/aweme/post/` | ❌ 被拒 | worker: `works_status=unavailable, works_error=APIResponseError` |
| 单条作品详情 `/aweme/v1/web/aweme/detail/` | ❌ 被拒 | worker: `{"error":"access_denied"}`（HTTP 403） |

- f2 已是最新版 0.0.1.7；`ttwid` 游客凭证获取正常；网页版 / iesdouyin 分享页都是 JS 反爬壳无 SSR 数据。
- **影响面**：不只是十一期的批量同步，**四期的「单条作品采集+转写」也不可用**（同一个 worker）。`resolveDouyinTarget`（短链解析）正常。
- 四期（10-24）验证过，10-25 起被拒 —— 抖音侧收紧未登录访问，不是我们改坏的。
- 已做：`fetchDouyinProfile` 首屏不再误带 cursor（原先会导致连昵称都读不到、误报「取不到这个主页」）；作品列表被拒时归因写清「主页可读（昵称，粉丝 N），但抖音拒绝了作品列表接口，这是抖音侧风控」。
- **可能的解法（待定）**：① 机构提供抖音登录 cookie（worker 已支持 `payload.cookie`，需设计凭证存储）；② 接第三方付费采集；③ 等抖音放松（不可控）。

## 必须记住的坑（都真实踩过）

1. **测试用 Node v24**（`C:\Program Files\nodejs`）：PATH 排第一的微信开发者工具 node v16 会让验收套件 16 个全红。
2. **MySQL TEXT/MEDIUMTEXT 列没有字面量默认值**：INSERT 必须显式给全所有列；ALTER 加列用 `TEXT NULL`。
3. **sessions 表时间是 ISO 字符串比较**（`expires_at <= nowIso()`）。
4. **生产 TEXT 渠道 = api.deepseek.com**（Key 在 `production/data/provider-secrets/provider-secrets.json`，AUTH_PEPPER AES-GCM 加密）；联网搜索是独立 Search API（`/v1/tools/search`，同 Key）。
5. seedance.nz：image 用 `resolution:"1k"`；i2v 参考图在顶层 `images` 数组；identify-face 必须**完整签名 URL** + ffmpeg baseline/faststart（生产已装 ffmpeg）；产物白名单 mp4/webm；`seedanceAsrConfig` 是 async 别漏 await。
6. 提示词要求 JSON 时**只许一个对象**：两个 JSON 会让 parseLooseJson* 丢数据（蓝图那次的教训）。
7. 工作流 action 的 if/else 必须同一条链，插新分支别另起 `if`（六期前踩过链尾 400）。
8. 本地开发热点搜索：`WORKBENCH_FAKE_SEARCH=1`；本地跑 API 记得带 `JUNSHI_DOUYIN_PYTHON="E:/XiaoLingDang/_internal/.douyin-runtime/python.exe"`。
9. **`junshiWorkbench.js` 从 `handleJunshiWorkbench` 起是一个巨型函数**：六期的 `parseLooseJsonObject`/`WORKFLOW_KINDS`/`wfOut` 等全都嵌套在它内部，**模块级代码看不见**（七期编导稿管线第一版就因此 ReferenceError）。给这条文件加模块级辅助函数时，别引用 714 行之后的任何名字；要 JSON 解析就自带（七期 `firstJsonObject` 是范本）。
10. **生产视频渠道（MiniMax-H3 外部适配器）实测口径**：分辨率只认 `480P`/`768P`（`720p` 被拒），单次成片上限 30 秒；15s/480P 一条实测 2.25 元。前端档位已对齐（`WB_RESOLUTIONS`/`WB_DURATIONS`），后端不硬校验、靠渠道报错兜底。
11. 会话冒烟铸造：`token_hash` = sha256(bearer token) 的 hex（`lib.js tokenHash`），不是随便填的占位串。
12. **坑 9 会在每个新模块级管线再犯一次**：十期 assetBytes / parseLooseJsonObject、十一期 startTranscription 又各栽一回（四回）。规律不变——巨型 handler 内的任何名字对模块级不可见。**新写管线前先跑这条检查**：
    ```bash
    H=$(grep -n "^export async function handleJunshiWorkbench" apps/server/src/routes/junshiWorkbench.js | cut -d: -f1)
    for fn in 你要调的函数; do L=$(grep -n "^async function $fn|^function $fn" apps/server/src/routes/junshiWorkbench.js | head -1 | cut -d: -f1); echo "$fn $L (handler=$H)"; done
    ```
    行号 > handler 的就必须先搬到「路由标记」之前。
