## 数字人（2026-10-25 复测 + 降级已上线）

### 上游实测结论（都实测过）

- **预置音色 TTS 可用**：`doubao-seed-audio-1.0` + `speaker`。
- **参考音频直出可用**：`doubao-seed-audio-1.0` + `metadata.audio_url`（不训练 speaker）。
- **音色克隆仍不可用**：`doubao-voice-clone` 503「No available channel」；`minimax-voice-clone`「Model response exception」。
- **底片 i2v 可用，但请求形状必须是顶层 `images`**：旧代码放 `metadata.images` 会 400「image-to-video requires at least one input image」。已修。
- **identify-face 可用，但返回 `results` 数组**：`session_id` / `face_id` 分在两条 `outputType=text` 子 JSON 里；旧 parser 解析失败。已修（`parseFaceSession` 递归兼容）。
- **kling-lip-sync-video 的 `session_id has expired` 是误导性报错，不是会话真过期**：2026-10-25 22:13 生产探针，用同一份刚生成的 identify-face 会话，1–4 秒内并行提交 4 个变体：
  - 4700ms 底片 + `soundEndTime` 5000 / 4700 / 4600 → 全部报 `session_id has expired`；
  - 同一会话 + `soundEndTime` **4000** → 成功出片（0.39 元）；
  - 另一条 5300ms 底片 + `soundEndTime` 4700 → 成功。
  - 结论：`soundEndTime` 必须比 identify-face 返回的 `end_time` 早约 700ms；上游把参数越界误报成会话过期。camelCase `sessionId/faceId` 是必须的，snake_case 会报 `sessionId is required`；`faceId` 必须是字符串（数字会 500）。
- **`wan-2.7-spicy-i2v`（图+音频）502 Bad Gateway**，暂不可用。

### 已踩过的部署坑（别再查）
1. Playwright Chromium 默认装到 `/root/.cache`，而服务以 `ai-kids-prod` 运行 → 必须 `PLAYWRIGHT_BROWSERS_PATH=/srv/ai-kids-platform/runtime/ms-playwright` 并 chown。
2. 服务单元有 `ProtectSystem=strict`，服务的 HOME 只读 → 有头 Chromium 写配置失败会 **SIGTRAP**；worker 必须显式传可写 HOME（代码里已传 `os.tmpdir()/junshi-douyin-home`）。
3. `contextlib.redirect_stdout` 会把 `sys.stdout` 换成 devnull → worker 的 `emit()` 必须写「重定向之前保存的」原始 stdout。
4. 生产 Linux 没有系统 Chrome，`launch_browser` 要优先用 Playwright 自带 Chromium（已改）。
5. 扩展 `content_scripts` 需要两段：MAIN world（能拦 fetch、没有 `chrome.runtime`）+ 隔离世界桥接（用 window 事件通信）。

## 必须记住的坑（都真实踩过）

1. **测试用 Node v24**（`C:\Program Files\nodejs`）：PATH 排第一的微信开发者工具 node v16 会让验收套件 18 个全红。
2. **MySQL TEXT/MEDIUMTEXT 列没有字面量默认值**：INSERT 必须显式给全所有列；ALTER 加列用 `TEXT NULL`。
3. **sessions 表时间是 ISO 字符串比较**（`expires_at <= nowIso()`）；冒烟铸造 `token_hash = sha256(token)` 的 hex。
4. **生产 TEXT 渠道 = api.deepseek.com**（Key 在 `production/data/provider-secrets/provider-secrets.json`，AUTH_PEPPER AES-GCM 加密）；联网搜索是独立 Search API（`/v1/tools/search`，同 Key）。
5. seedance.nz：image 用 `resolution:"1k"`；i2v 参考图在顶层 `images` 数组；identify-face 必须**完整签名 URL** + ffmpeg baseline/faststart；产物白名单 mp4/webm；`seedanceAsrConfig` 是 async 别漏 await。
6. 提示词要求 JSON 时**只许一个对象**：两个 JSON 会让宽松解析丢数据。
7. 工作流 action 的 if/else 必须同一条链，插新分支别另起 `if`。
8. 本地开发热点搜索：`WORKBENCH_FAKE_SEARCH=1`；本地跑 API 带 `JUNSHI_DOUYIN_PYTHON="E:/XiaoLingDang/_internal/.douyin-runtime/python.exe"`（这个 venv 里有 f2 + playwright）。
9. **`junshiWorkbench.js` 从 `handleJunshiWorkbench` 起是一个巨型函数**：六期的 `parseLooseJsonObject` / `WORKFLOW_KINDS` / `wfOut` / `startTranscription` 等曾全嵌在它内部，**模块级代码看不见**（七/十/十一期各栽过一次，共四回）。新写模块级管线前先跑这条检查，行号 > handler 的必须先搬出来：
   ```bash
   H=$(grep -n "^export async function handleJunshiWorkbench" apps/server/src/routes/junshiWorkbench.js | cut -d: -f1)
   for fn in 你要调的函数; do L=$(grep -nE "^(async )?function ${fn}\b" apps/server/src/routes/junshiWorkbench.js | head -1 | cut -d: -f1); echo "$fn $L (handler=$H)"; done
   ```
10. **生产视频渠道（MiniMax-H3）实测口径**：分辨率只认 `480P`/`768P`（`720p` 被拒），单次成片上限 30 秒；15s/480P 一条实测 2.25 元。前端档位已对齐，后端靠渠道报错兜底。
11. **浏览器/虚拟显示三处必看**：Chromium 装到服务用户可读路径（`PLAYWRIGHT_BROWSERS_PATH`）；worker 传可写 HOME（否则 SIGTRAP）；worker 的 emit 写原始 stdout（`redirect_stdout` 会吞）。
12. **抖音按 IP 风控**：任何「服务端直连抖音」的方案在生产都不可行，别再试 cookie 注入/换 UA/换 headless——已实测无效。只有「用户侧读 + 服务器下载」成立。
13. Python heredoc 里写含引号的 JS/bash 代码极易被吃掉（本轮踩了两次，写了坏文件）。复杂替换用 `node -e` 或先写成文件再执行。
14. **扩展 zip 不能放 `/downloads/`**：该前缀由 `handlePublicAssets` 接管，最终 X-Accel 到 `/srv/ai-kids-platform/downloads/`（客户端安装包目录），站点 `public/downloads/` 不参与；线上表现为 nginx 404「无法从网站上提取文件」。扩展包放 `public/assets/junshi/`，走 `/assets/` 站点根；该前缀有 7 天强缓存，换包时改 `?v=`。
15. **抖音作品字段的两个坑**：顶层 `share_url` 常为 null，真实分享链接在 `share_info.share_url`（扩展已做回退）；公开接口对他人作品常把 `statistics.play_count` 给 0，只有自己登录态的主页才可能拿到真实播放数——不要把 0 当成解析失败。
16. **视频参考图不能直接发工作台私有 URL**：`/api/junshi/workbench/assets/:id/file` 要登录态，上游抓不到；必须先用 `uploadToSeedance` 换 24h 直链（按 assetId 缓存 20h）。MiniMax-H3 声明 `OMNI_REFERENCE`，会走 `referenceItems`，`generationOptionsFor` 没拿到 `firstFrameUrl`/`referenceAssets` 时会明确报错，不静默降级。
17. **分镜原帧的秒数下限是 3 秒**：`parseDirectorScript` 把 `shot.seconds` 钳到 3–60；2 秒的分镜会被抬成 3 秒，抽帧时间按「分镜起点 + min(1, 秒数/2)」算。真实 i2v 5 秒 480P 约 0.75 元/条，别在验收里反复跑。
18. **十六期「确认制作」不直接扣渲染费**：只创建 `video_works` 并生成编导稿；成片渲染仍要用户确认编导稿后提交。预检文案已写明，别为了「像原版」改成直接调 `startWorkRender`。
19. **聊天方案事件在 `done` 之后**：后端先发 `done`，再异步提炼并发 `event: plan`。前端必须在收到 `done` 后继续读到流关闭；不要在 `done` 就关闭 reader，否则方案卡要刷新才出现。
20. **十六期迁移 43 同时补两个 `plan_id`**：`messages` 和 `video_works` 都要补列；生产必须先跑 43 再切 release。SQLite 侧两个 ALTER 在 `db.exec(SCHEMA)` 之后执行，别写进建表字符串（会报 `near "try": syntax error`）。
21. **生产冒烟清理 job 要按 id，不能按 detail**：`jobDone()` 会把 `junshi_workbench_jobs.detail` 从任务 id 覆盖成「编导稿已生成」。本次冒烟按 detail 删 job 漏了一条，后来按 id 补删。先记下冒烟前的 job id 集合，事后按新增 id 删。
22. **生产浏览器 e2e 的登录态**：junshi 读 `localStorage['ai-kids-platform.session.v1.org']`，值是 `{token,expiresAt,user,organization}`。用临时会话时 token 只放 `.tmp` 文件、不打印；跑完删 token 文件、sessions 行和测试数据。`expiresAt` 必须是 ISO 字符串。
23. **Seedance 2.0 i2v 的参考图在顶层 `images`**：放 `metadata.images` 会 400「image-to-video requires at least one input image」。数字人底片和视频工作台的 i2v 都按这条口径。
24. **identify-face 返回 `results` 数组**：`session_id` / `face_id` / `end_time` 分在 `outputType=text` 子 JSON 里；`parseFaceSession` 已递归兼容并返回 `endTime`。别按单对象解析。
25. **音色克隆不可用时的兜底**：`doubao-voice-clone` 503、`minimax-voice-clone` 模型异常；改用 `doubao-seed-audio-1.0` + `metadata.audio_url`（参考音频直出）。UI 标「参考直出」，不要冒充训练克隆。
26. **Kling 的 `session_id has expired` 是假报错**：真正约束是 `soundEndTime` 必须比 identify-face 的 `end_time` 早约 700ms。生产探针：4700ms 底片 + 5000/4700/4600 全失败，4000 成功；5300ms 底片 + 4700 成功。用 `safeLipSyncEndTime(endTime)`，不要写死 5000。camelCase `sessionId/faceId` 必须，`faceId` 必须是字符串。
27. **数字人 clone custom id 只能字母数字**：`minimax-voice-clone` 的 `custom_voice_id` 不接受下划线；`jwv2_...` 不能直接传，代码已改成 `voice` + 去非字母数字。底片 i2v 用 `seconds:'6'`，`soundEndTime` 由面部分析的 `end_time` 动态计算（当前上限 5000），别再写死。
