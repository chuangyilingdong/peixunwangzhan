# 客户端三平台更新与下载契约（2026-11-02）

## 目标

平台侧同步支持 `win-x64`、`mac-arm64`、`mac-x64` 三个客户端平台。客户端仓负责三包构建与原子发布；平台仓负责清单校验、后台上传/展示和官网下载选择。

## 服务端契约

- `CLIENT_PLATFORMS` 顺序固定为 `win-x64`、`mac-arm64`、`mac-x64`。
- 严格上传文件名：
  - `lingdong-client-<版本>-win-x64.exe`
  - `lingdong-client-<版本>-mac-arm64.dmg`
  - `lingdong-client-<版本>-mac-x64.dmg`
- 宽松只读解析允许历史构建后缀，但必须能识别 `mac-x64` 并取出版本。
- 发布单平台安装包时只更新对应 `files[target]`，其他平台条目保持不变。
- `stale` 检查覆盖三个平台：文件版本与清单顶层版本不一致时必须报告。

## 后台契约

- 上传入口接受并校验 `mac-x64.dmg`。
- “当前发布包”展示 Windows（x64）、macOS（Apple 芯片）、macOS（Intel 芯片）三个条目。
- 每个条目展示文件名、大小、版本、SHA256；缺失时展示规范文件名示例。
- 上传提示明确三平台必须同版本、由客户端仓发布脚本一次性原子发布。

## 官网契约

- 下载页读取 `manifest.files['win-x64']`、`manifest.files['mac-arm64']`、`manifest.files['mac-x64']`。
- Mac 下载卡片提供“Apple 芯片 / Intel 芯片”切换。
- 浏览器能检测到架构时使用检测结果；无法可靠检测时默认 Apple 芯片，用户可手动切换。
- 当前选中架构缺失时显示准备中，不回退到另一架构。

## 验收

1. 文件名解析覆盖 `mac-x64.dmg`，非法 Linux 包仍被拒绝。
2. 清单同时存在三平台同版本文件时 `stale` 为空。
3. 任一平台版本落后时 `stale` 包含该平台。
4. 后台上传 `mac-x64.dmg` 后只更新 Intel 条目，另外两个条目不变。
5. 后台页面展示三个平台及各自规范文件名。
6. 官网切换 Apple 芯片 / Intel 芯片时下载 href 分别指向 `mac-arm64` / `mac-x64`。
7. 官网在选中平台缺失时显示准备中，不生成另一种架构的下载链接。
## 验证命令

```bash
pnpm test:client-three-platform
pnpm test:client-multiplatform-download
pnpm build
```
