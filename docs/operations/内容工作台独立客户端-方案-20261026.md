# 内容工作台独立客户端方案（junshi-desktop）

日期：2026-10-26  
状态：第一阶段已实现并通过启动、登录、工作台接入与 Windows 打包验证

## 结论

招生军师内容工作台单独做桌面客户端，不依赖、不复用 `E:\灵动ai客户端` 的 ZCode 底座。

第一版采用 Electron：

- 桌面壳负责账号登录、会话安全保存、窗口生命周期和桌面菜单；
- 内容工作台继续复用现有 `/junshi` 页面，保证功能与网站一致；
- 账号仍使用 `POST /api/auth/login`，`clientType=org`；
- 机构、权限、数据和历史内容继续由 `aicyld.com` 平台统一持有；
- 客户端不建立第二套账号体系，也不复制业务数据库。

## 为什么适合客户端

内容工作台的核心业务包含抖音同行采集、自动同步、长任务、文件素材和后台通知。这些能力更适合由本地客户端承担：

1. 抖音采集从用户本地 IP 和本地浏览器登录态发起；
2. 客户端可常驻托盘，按计划执行同步；
3. 本地文件目录、视频上传和下载更自然；
4. 长任务可显示系统通知，并在窗口关闭后继续执行；
5. 会话可保存到系统安全存储，不需要每次登录网页。

## 进程与状态所有权

```text
Electron Main
  ├── 平台账号登录 / 安全会话
  ├── 工作台窗口生命周期
  └── 后续：本地抖音采集与同步调度

Workbench Renderer
  └── 现有 /junshi 页面与业务交互

aicyld.com 平台
  ├── 账号、机构、权限
  ├── junshi_workbench_* 业务数据
  ├── AI / 视频 / 转写调用
  └── 历史任务与发布数据
```

唯一状态所有者：

- 登录事实：平台服务端；
- 客户端会话缓存：Electron Main，使用 `safeStorage` 加密；
- 工作台业务数据：平台数据库；
- 本地采集与同步队列：客户端 Main（第二阶段）；
- 页面展示状态：现有工作台 Renderer。

## 第一阶段范围

- 独立 Electron 应用：`apps/junshi-desktop`；
- 机构账号登录，支持二次验证码；
- 登录会话加密保存；
- 登录后打开现有内容工作台；
- 退出登录时清理平台会话和本地工作台存储；
- 支持 Windows 安装包构建；
- 不修改 ZCode 客户端仓库。

## 第二阶段范围

- 客户端内嵌本地抖音浏览器；
- 使用本地 IP 和独立浏览器配置采集同行主页；
- 本地同步调度，按频率读取主页、下载与转写；
- 通过现有 `douyin/assistant` ingest 接口上报平台；
- 托盘、开机启动和系统通知；
- 自动更新。

## 边界

- 不绕过抖音登录、验证码或风控；
- 不在客户端保存明文密码；
- 不把平台业务数据复制成第二份真相；
- 第一阶段不重写现有工作台页面；
- 付费视频渲染仍由用户在确认页显式确认。
