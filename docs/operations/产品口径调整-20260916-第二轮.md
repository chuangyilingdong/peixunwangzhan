> 用户看界面提的 7 条，逐张截图。本篇记**每条的口径与实现边界**（尤其哪些是「只删 UI、保留后端」，
> 哪些是**口径变更**）。领域口径以 `docs/README.md` 为准。
> 生产 release `20260916T144948Z` / commit `28f3614`；全量守卫 113/113。

## 1. 「套餐」彻底退出 AI 能力判定

**现象**：画布课堂生成报「当前套餐未开通该 AI 能力」（学生建号时默认不绑套餐 → 一律 403）；
平台用户列表还有一列「套餐」显示「未绑定」。

**口径**：套餐（`billing_packages`）不参与「学生能不能用某个 AI 能力」的判定。
现在只看三道：**平台模态开关 → 课堂开放的能力 → 课时开放的能力**。

**改了什么**：
- `routes/ai.js`、`routes/aiGeneration.js`：`assertCapability` 删掉读 `billing_packages` 能力位的那一支
  （连带删掉 `PACKAGE_CAPABILITY_BY_MODALITY`、`packageForUser` 与错误码 `PACKAGE_CAPABILITY_DISABLED`）。
- `studentAiCenter`：删掉两条学生**无从处理**的拒绝理由（「当前账号未绑定可用套餐」「套餐未开通该能力」），
  并去掉返回值里的 `packageEnabled`（`available` 改为只看课堂/暂停/范围）。

**没动什么**（有意）：
- `billing_packages` 表、`orgAdmin` 里的套餐 CRUD、「学员开通」那条线（席位/有效期）**都保留** ——
  这轮只拆 AI 判定里的这一层，不与「学员席位」这件事混在一起。
- 平台用户**列表列**与**导出 CSV**里的「套餐」列删了（显示「未绑定」已无意义）；
  API 的 `billingPackageName` 字段保留（其它读取方可能还在用）。

## 2. 课时「课时正文 / 教学指引」只删 UI

**口径**：用户要「这个模块直接删除」。

**实现边界（重要）**：**只删抽屉第 1 步的那个 textarea**，字段与所有下游**保留**。理由：
1. 同一字段还被第 2 步「VibeCoding 入口 → 给学生的编程任务 / 素材说明」编辑（另一个标签、另一个用途）；
2. 它会注入 VibeCoding 课堂的系统提示词（`routes/vibecoding.js`）—— 连字段一起删会**静默改变课堂里 AI 的行为**，
   那是产品行为变更，不该混在「删一个输入框」里做；
3. 机构端课时详情、官网课程详情、公开接口都还在读它。

> ⚠️ 遗留观察（本轮**没改**）：同一个 `lessonContent` 字段有两个编辑入口（第 1 步的正文、第 2 步的编程任务），
> 谁后保存谁覆盖。现在第 1 步的入口没了，实际只剩第 2 步那一个 —— 但如果以后要恢复，
> 得先把「一个字段两种语义」这件事理清。

## 3. 「不可加」名单改成搜索才显示原因

**现象**：课堂详情「添加学员」右栏把所有不可加学员连原因一起铺出来；机构上百人时没法看。

**口径**：默认**不铺**；只提示「本机构另有 N 人暂时不可加入：在上面搜姓名或账号，就会显示他不能加入的原因」。
搜索命中的不可加学员才连原因（+ 占用课堂）显示。

**实现**：纯前端（`apps/org/src/pages/Classrooms.jsx`）—— `visibleBlocked` 改成「有关键词才过滤，否则空」。
接口与 `classroomSessions.sessionCandidates` 一行没改。

> ⚠️ **仍未解决的规模化问题**（本轮没动）：`/candidates` 接口一次返回**本机构全部学员**，
> 且每人 3–4 条 SQL 的 N+1（无分页、无 search 入参）。机构学员上百时这里会很慢。
> 彻底改法是给接口加 `?search=&limit=`、前端防抖查询 —— 那会动 p56/p62/p66/p78 几条守卫，另起一轮做。

## 4. 【口径变更】课堂入口按「课时已发布的类型」放行

**现象**：老师创建课堂要**自己选**「课堂模式」—— 但上课类型明明是平台在课包课时里设定的，
而且平台端课时配置的原话是「两种都开：学生在这节课可以选『画布创作』或『VibeCoding』进入」。
课时能开两种，课堂的单值把其中一种废掉了。

**新口径（用户 2026-09-16 拍板）**：
- 老师**不选**了：创建课堂弹窗里的「课堂模式」改成**只读平铺**（把该课时已发布的全部类型都显示出来）。
- 入口判定从「课堂的 `class_sessions.delivery_mode`」改成「**课时已发布的 `deliveryModes`**」：
  一个课时开两种 → 两个入口都亮；只开一种 → 另一种**仍然锁死**；老数据没有数组时回退单值。
- `class_sessions.delivery_mode` **保留**（仍会写 modes[0]、仍下发），但**不再有门禁作用**。
  这样老课堂、老读取方都不受影响。

**改动面**：`services/studentContext.js`（`lessonAvailability` 与 `resolveProjectUsageContext` 两处）、
`packages/shared/src/classroom.jsx`（学生端卡片：两种都开时画布按钮与 VibeCoding 入口**并列**，
kicker 显示「画布课堂 / VibeCoding 课堂」）、`apps/org/src/pages/Classrooms.jsx` + `Classrooms.css`（只读字段）。

**规则由新增守卫 `p104` 钉住**（纯函数、含反例：只开一种必须锁死、老数据回退、前三道闸门优先）。

**连带同步的 4 处旧断言**（它们原本断言「一个课堂只有一种入口」，属旧口径）：
`p6-classroom-delivery-mode-e2e`、`p6-classroom-course-tree-e2e`、`p66-student-grant-gate`、
`p78-classroom-student-flow` —— 它们的夹具课时本身就是 `["CANVAS","VIBECODING"]`，
按新口径两个入口都该亮，已改正并在注释里指向 p104。

> ⚠️ **这条是本次唯一的语义变更**：学生现在能在「两种都开」的课堂里两个入口都进
> （包括在 VibeCoding 课堂里建画布项目）。若产品其实想要「老师选一个」的旧行为，回退点很清楚：
> 把 `studentContext.js` 两处改回 `sessionMode === 'CANVAS' / 'VIBECODING'` 即可。

## 6. 开创作环境被 nginx 掐成 504

**根因（读代码 + 实测配置）**：开环境是**同步等**宿主起容器 —— 平台侧超时 90s、
宿主脚本自己还会等 dsh 打印 token（最长 ~60s）；而 nginx 的 `location /api/`
**没写 `proxy_read_timeout`** ＝ 默认 **60s**。于是「慢一点的学生先被 nginx 掐成 504」，
前端把 504 显示成「服务暂时不可用，请稍后重试」—— 学生会以为系统坏了。

**这一层已修**：给 `location ~ ^/api/student/runtime/(launch|stop)$` 单独放宽到 180s
（模板 `deploy/production/nginx.conf.example` 与应用同步改；生产 `/etc/nginx/sites-enabled/iicili.cyou` 已打补丁并 reload）。

### 6b.【已修】冷启动 17.9s → 复用 0.07s

用户复报「进 VibeCoding 课堂还是卡很久，应该秒进才对」。上机实测拿到数字：

```text
冷启动（脚本里 systemctl stop + 重起 dsh）：18.793s
复用（环境还活着，只换票据重写 nginx 入口）：0.068s / 0.069s / 0.034s
```

**改法**（`deploy/dsh-student/host-user/run-student-user.sh`）：复用优先 —— 单元在跑
+ 起得不太久（运行时密钥 6h，取 4h 余量）+ 日志里还能捞到 dsh 的 token + 上次的入口配置还在，
就只**换票据重写入口 + reload**，直接返回；任一条不满足才走原来的冷启动。
冷启动那整段用 `if [ "${REUSED}" = 0 ]` 包起来，**中间那些行一字未动**
（不手抄 systemd-run 与票据闸门那几段安全配置）。

**为什么以前那么慢**：环境往往还活着（学生刷新、老师再点、掉线重进都走这条路），
脚本却无条件停掉重起 —— 白等一次 dsh 冷启动。

顺带修掉两个坑：
1. **空票据 = 不锁门**：闸门是 `if ($ticket = "${TICKET}") { set $ok 1; }`，
   票据为空时恒成立 → 该端口对任何知道它的人开放。平台侧一定给票据（24 字节随机），
   但脚本现在**拒绝空票据**，宁可直接失败也不写出没锁的入口。
2. **每次启动刷一行 `unbound variable`**：nginx 配置用的是**未加引号的 heredoc**，
   注释里的反引号会被当命令替换真的执行。已清掉（这条注释现在也不敢写出那个符号本身）。

**根因里仍没做的**：
- 没有进度反馈：「一个 POST 一直挂着」，所以按钮只能干写「正在开环境…」；
- `/api/student/runtime/stop` **前端从没调用过**，课堂结束也不回收环境 ——
  没人再进来时，那个 dsh 进程会一直占着内存（约 470–520MB）与端口池（18201-18220 共 20 个）；
- 这台机器 1.6GB，第二个学生进来仍会被 swap 拖慢（文档实测 9.7s → 59s 的退化）。
  扩容是另一件事（见交接文档）。

### 6c.【已修】改完复测出现的 403 —— nginx reload 的排空窗口

复用改完、用户复测时报「**现在报错 403**」。端到端复现（登录学生 → 调平台 launch →
立刻请求返回的 edgeUrl）拿到时间线：

```text
launch 返回 200，耗时 95ms
配置写在 23:03:44.432
23:03:44.571 用返回的票据请求 → 403
同一张票据过一会儿再请求   → 302
```

**根因不是票据没换，是 `systemctl reload nginx` 的排空窗口**：reload 只是给 master 发信号，
**老 worker 要把手里的连接排空才退出**（当时还有一个 22:59 起的老 worker 在 shutting down）。
这中间到达的新连接可能被老 worker 按**旧配置（旧票据）**处理 → 403。而平台拿到的 URL 是
**直接给浏览器打开**的，所以这个窗口对学生是可见的。

同样的时序在改造前的冷启动路径上也存在（配置写 + reload 也在最后），只是那时每次要等 18 秒冷启动，
请求不容易正好落进窗口；现在秒回，反而更容易撞上。

**改法**：写完入口、reload 之后，**用请求本身当探针**轮询到入口真的返回 302/200 才继续
（每 200ms 一次、最多 5 秒）；一直不放行就**不把地址交出去**（`exit 6`），让平台报失败 ——
比给学生一个打不开的地址强。没装 curl 的机器跳过探针并明确提示（不静默假装验过）。

**修完端到端复验**：launch 327ms（探针等了约 230ms，仍远快于原来 17.9s）、
返回后立刻请求 302、跟完重定向链最终 **200** 且页面就是 dsh 界面（`<title>灵动ai</title>`）。

## 7. AI 对话里的 DSML 工具调用标记（**只止血，没治本**）

**现象**：学生创作环境的对话里，助手消息出现 `<|DSML|_|calls> <|DSML|_|invoke name="run_code"> …`。

**根因**：我们的 OpenAI 兼容网关**请求侧丢掉了 `tools`、响应侧只认 `content`**
（`routes/runtimeGateway.js` 只转发 role+content；`services/openaiCompatibleProvider.js` 没有
`tool_calls` 分支；渠道模板的占位符里也没有 tools）。模型拿不到结构化工具通道，
就按 DeepSeek 系的原生习惯把工具调用**当正文吐出来**，网关再原样透传。

**本轮做的（止血）**：新增 `services/dsmlFilter.js`，在网关出站前把这段标记摘掉。
- 只锚 `DSML` 这个字面量 —— **绝不**用「去尖括号」这类宽正则（学生就是用这套环境写 HTML/JS 的）；
- 处理跨 SSE 分片的半截标记；有安全阀（一整块迟迟不收尾就不再吞）；
- 摘掉时打一行 `[runtimeGateway] 摘掉工具调用标记 N 字符`，用来判断上游是否还在漏。

**没做的（真正的修法）**：把 `tools` / `tool_calls` 打通（请求侧转发 `tools`、响应侧把
`tool_calls` 增量回给客户端）。**不做这个，agent 永远调不到工具** —— 学生看到的会是
「AI 光说话不干活」。这需要真机验证上游（deepseek 直连 / new-api）是否支持 `tools` 再动，
见交接文档。
