## 二、这一轮做了什么

### A. 报错是怎么触发的（生产数据实锤）

一句话：**同一节课的"框体列表"，画布读实时、判定读快照。**

```text
学生画布上画出来的框体 + 右侧「课堂素材」
  ← normalizeProject() → lessonCanvasConfig(lessonId)        = 实时素材表（course_lesson_materials）
点「生成」时服务端校验 boxId
  ← studentContext → normalizeLesson(asPublished: true)      = 已发布快照 published_content
两边指向两批不同的 id → 学生「看得见新框体，点一下说不属于本课」
```

生产上到底几节课会报（只读诊断 `.tmp/diag-normalize.mjs`，**直接调用生产代码** `normalizeLesson`）：

| 课时 | 快照里有 `generationBoxes` 键？ | 实时框体 | 学生读面拿到 | 结果 |
|---|---|---|---|---|
| **1-1 AI 初识：召唤哪吒** | 有（11 个） | 11 个（**全新 id**） | 快照那 11 个旧 id | 0/11 相交 → 点哪个都报 |
| 其余 16 节（1-2、1-4…2-10） | **没有这一键** | 各有 2~13 个 | **0 个** | 判定侧拿到空数组 → 点哪个都报 |

⚠️ 这里有个**我上一轮（第二十五轮文档）没说准的地方**，记下来免得下次又踩：
`normalizeLesson` 对缺键的默认是**空数组**，不是"回退实时"——
`merged = snapshot ? { ...snapshot, generationBoxes: Array.isArray(...) ? ... : [] } : null`
所以"快照存在但缺这一键"的课，判定侧一个框体都不认。**一眼看不出**，只有让真代码跑一遍才知道。

**时间线**（1-1）：`course_lessons.updated_at` 与它全部素材/素材组的 `created_at` 都停在
**2026-09-20T08:53:23.968Z** —— 那一刻这节的素材被**整体重建**成一批新 id（服务端
`replaceLessonCanvasConfig` 本来是**保留 id** 的，注释写着"每次保存换新 id 会让学生端节点认不出来"，
前提是调用方把 id 传回来），重建之后**没有人对课包点「更新发布」**，快照还停在重建前那批 id 上。
当天 9:06–15:43 还有一串"单节课整体重建"（1-2、2-1、2-2、2-5…2-9 各一次）。

### B. 修法：读面与判定**共用同一个函数**

```text
lib.js 新增 mergedLessonCanvas(lessonRow, liveCanvas)
  · 快照里**有哪一档用哪一档**（capabilities / materialGroups / generationBoxes），缺的档回退实时；
  · normalizeLesson（判定侧）与 normalizeProject（画布侧）都改用它 —— 再也不各写一遍；
  · normalizeProject 需要课时的快照 → student.js 三处 project 查询补 `lesson.published_content AS lesson_published_content`。
```

为什么缺键必须**回退实时**而不是给空数组：那 16 节课的快照是"发布早于生成框体这个功能"时定格的，
给空数组等于**把学生手里的框体全没收**（它们现在能正常用，正是因为两边都回退到同一份）。
这与第二十四轮「教学素材可见性」那条判据是同一个形状（逐键回退）。

### C. 修完之后，每节课是什么行为（要跟用户对齐这点）

| | 学生看到 | 生成 | 你要怎么才能换新 |
|---|---|---|---|
| **1-1**（快照里有框体这一键） | 快照里那批**旧的** 11 个（标题「任务一：」那套） | 正常（两边同源） | 点一次「更新发布」 |
| **其余 16 节**（快照里没有这一键） | 仍然是实时那批（= 你重建后的新框体） | 正常 | 也是「更新发布」——**发布之后快照里就有这一键了，从那一刻起才真正隔离** |

也就是说："没发布不生效"这条口径**对"发布过带框体版本"的课立刻成立**（1-1），
对那 16 节要等你发布一次（它们此前从没带着框体发布过）——**这是数据事实，不是代码没改到位**。

### D. 守卫：p54 补了一整段 ④（含反向自检）

```
④ 框体 / 课堂素材也要隔离，而且画布与「点生成」的判定必须是同一份
  ✓ 发布后：学生端课时读面拿到框体 A
  ✓ 发布后：学生画布（项目 payload）也是框体 A
  ✓ 重建但没发布：学生端课时读面仍是框体 A（未发布不可见）
  ✓ 重建但没发布：学生画布（项目 payload）仍是框体 A —— 与判定同一份
  ✓ 重建但没发布：拿**画布上那个框体**去生成，不会报「生成框体不存在或已不属于本课」
  ✓ 更新发布后：学生端课时读面换成框体 B / 学生画布也一起换成框体 B（全部同步）
```

⚠️ **为什么钉在 p54 而不是 p28**：p28（生成框体守卫）一直全绿，是因为它那节课**从来没发布过** ——
没有快照时两边都回退实时，天然同源。**这个 bug 只在"发布过"的课上出现**，只能钉在会发布的那条守卫里。
反向自检（把 `normalizeProject` 改回读实时）实测**原样复现**用户看到的那句话：
`GENERATION_BOX_NOT_FOUND / 生成框体不存在或已不属于本课`。

## 三、不许破的口径（承接 1–60；**本文新增 61–62**）

61. ⭐⭐ **同一份东西的"读面"与"判定"必须同源**：学生画布画的框体、与点生成时服务端校验 boxId 用的
    列表，**必须是同一个函数的输出**（`mergedLessonCanvas`）。这一条与口径 34/54 是同一族
    （「界面看得到、点开说无权」/「预检与真正那一步不同口径」）——**写两处迟早会漂**，这次漂的代价是
    17 节课的框体点不动。
62. ⭐ **"缺键给空数组"与"缺键回退实时"是两个语义，选错就是静默事故**：快照缺某键时，
    **给空数组 = 把用户手里的东西全没收**（那 16 节课的框体），**回退实时 = 老数据行为不变**。
    老数据（发布早于该功能）要的是后者；「已定格的课包不允许回退」只适用于**可见性判据**
    （第二十三轮），**展示/可用性**一律逐键回退。
