## 四、关键设计约定（必须遵守）

```text
1. 学生功能在 apps/website，没有独立 apps/student（已删除，不恢复）
   学生登录 → 回 / → 右上角头像 → 进入学习/我的作品/我的积分/我的课程/学习统计
2. 课堂画布是"受控"的：学生不能右键建节点
   节点来源 = 左侧素材面板的「生成框体」+「本节课画布素材」
3. 平台课包本身没有有效期；有效期挂在「课包 → 机构」的授权上
   course_assignments.expires_at，到期后该机构立即看不到该课包
4. 生成参数（比例/清晰度/时长/是否生成音频）来自「模型能力」配置，代码里不写死
   - 配置位置：计费与模型 → 渠道 → 模型能力（channel.modelCapabilities）
   - 请求体由模板生成：channel.requestTemplates，占位符见下
   - 生成时以「课时配置」为准，客户端提交的取值一律不采信
   - 调用上游前先做能力/套餐预检，业务拦截不进入重试
5. 课程广场 = 所有「已发布 + 所有机构可见」的课包自动收录，分画布课程 / VibeCoding 课程两类
   没有人工上架/审核流程
6. 作品链路：学生提交 → 平台在「平台作品库」点「发布到作品广场」→ 官网 /works 可见
   机构端只做点评与机构精选，不再有审核/发布权
7. 教学素材 = 教师备课资料：学生端与公开接口不下发 teachingGroups；
   文件走机构端受控下载路由，公开下载路由拒绝该分类
8. 课堂类型 delivery_mode：课包级默认（course_series.delivery_mode），课时继承、可单独改
   VibeCoding 已预留但运行时未实现（发布会被拦）
9. AI 渠道：一个渠道可配多个模型；课时可从对应模态渠道的模型下拉单选
   生成时课时选的模型优先于渠道默认模型
```

## 六、运维手册（生产发布流程）

```bash
# 1. 推送
git push origin main

# 2. 服务器：拉取 → 备份 → 构建 → 切软链 → 重启 → 健康检查
ssh -i ~/.ssh/ai_kids_platform_ecs_temp_ed25519 root@39.106.183.200
cd /srv/ai-kids-platform/internal-test/source        # 目录名沿用，实际是生产部署源
export PATH=/srv/ai-kids-platform/runtime/node/bin:$PATH
git pull --ff-only origin main
bash deploy/production/backup-production.sh          # 必须，先备份
bash deploy/production/build-production.sh           # 产出 production/releases/<stamp>
R=$(ls -dt /srv/ai-kids-platform/production/releases/* | head -1)
ln -sfn "$R" /srv/ai-kids-platform/production/current
systemctl restart learning-platform-production
curl -fsS http://127.0.0.1:8789/health
```

- **回滚**：切回上一 release + 重启；数据库备份在 `production/backups/`。
- **注意**：数据库迁移是幂等 `ALTER TABLE`/`CREATE TABLE IF NOT EXISTS`，重启自动执行。
- 详见 `deploy/production/README.md`、`RUNBOOK.md`。
