## 四、关键设计约定（必须遵守）

```text
1. 学生功能在 apps/website，没有独立 apps/student（已删除，不恢复）
   学生登录 → 回 / → 右上角头像 → 进入学习/我的作品/我的积分/我的课程/学习统计
2. 课堂画布是"受控"的：学生不能右键建节点
   节点来源 = 左侧素材面板的「生成框体」+「本节课画布素材」
3. **课包「发布 ≠ 授权给机构」**（2026-09-11 第十六轮定稿，用户原话：「发布的时候所有机构都是
   不可见的情况，发布的时候只是会出现在首页课程广场里供大家看，然后再是授权给机构，才会出现在
   机构后台」）
   - 发布（PUBLISHED）＝ 上架官网课程广场给人看，**不对任何机构生效**；
   - 机构后台能看到/使用平台课包，唯一途径是「机构授权」里有一条 ACTIVE 且未过期的记录；
   - 平台课包本身没有有效期；有效期挂在「课包 → 机构」的授权上（`course_assignments.expires_at`，
     NULL＝永久），到期或撤销后该机构**立即**看不到（不需要定时任务，判定就在 SQL 里）；
   - 「可见范围 visibility」现在只表示**上不上课程广场**：`ALL_ORGS`＝上架（公开可见）、
     `ASSIGNED_ORGS`＝不上架（只给已授权机构）、`PRIVATE`＝不上架、不对外；
   - 唯一定义在 `lib.js: orgSeriesAccessSql()`，8 处查询共用（机构端列表/详情、平台端
     accessibleSeries/accessibleLesson、学生端 studentContext、教学素材、教学任务），
     别再往任何一处抄一份带 `visibility='ALL_ORGS'` 的旧条件；

19. ReactFlow 的 Handle 在只读态（`nodesConnectable={false}`）**仍然渲染 DOM**，别用 `return null`
   或 `display:none` 藏它：`getEdgePosition` 找不到 handle 就让整条连线不渲染（hide 要用 opacity:0）
20. 连线拖拽的**落点判定是 `elementFromPoint`**：如果 handle 里塞了图标（svg），命中到的是子元素，
   ReactFlow 会退回「最近 handle（connectionRadius 内）」的兜底路径——能用，但别把 connectionRadius 调太小。
   另外拖动时 `mousedown` 必须**正好落在圆点上**，偏出去十几像素就变成拖框体（本地验证脚本踩过好几次）
21. 撤销历史别按事件条数记：拖动框体是每帧一个 `position` change、打字是每键一个 change，
   照搬「每次变更 push 一条」会让一次拖动攒几十条记录（撤销只能一点一点退）。
   做法见 `CanvasSurface`：拖动/缩放用手势底稿（`gestureRef`，手势开始留底、结束记一条），
   连续输入用 700ms 窗口合并（`COALESCED_EDIT_KEYS` + `lastEditRef`，undo/redo 时重置）
22. **别靠读源码还原参考的视觉效果**：参考里很多组件的 CSS 是运行时生成的
   （border-beam 就是 `[data-beam]` + `::after/::before` + `@property` 动画拼出来的）。
   正确做法是把包渲染一遍、把生成的 CSS 抓出来（脚本见第七节「参考组件原始 CSS 的取法」），
   再做并排对比页。本轮第一版就是只读了源码、漏掉一层 `::before`，观感差了十万八千里。
23. **fitView 会把内容垂直居中**：内容越高，最下面的框体越贴近画布底边。
   面板类浮层要贴在框体下方时，这直接决定「框体下面还剩多少地方」——
   所以 `fitViewOptions.maxZoom` 不只是缩放观感问题（1.8 → 1.2 把面板与框体的重叠从 100px+ 收到约 14px）。
   同理，任何贴着框体渲染的浮层（状态条、工具栏）都要先想清楚「下面还有没有地方」。
24. 面板/浮层贴着框体算位置时，**水平居中要在夹不住的时候换策略**：
   参考实现的 `getFloatingPanelPosition` 是「居中后硬夹在视口内」，框体靠边时浮层会被推到
   离框体很远的地方（用户反馈的「错位」）。我们的做法是居中放不下就与框体的左/右边对齐，
   浮层始终「连着」框体。垂直方向则是永远在下方（只贴底边，不翻到上方）。
25. **卡片尺寸是内容撑出来的**，所以图片会反过来决定卡片多大：
   `width: 100%` 的图片按卡片宽度铺开后高度 = 宽度/比例（9:16 成图 → 卡片长到 1355 flow px），
   而图片的**原始宽度**只要写成 `width: auto` 就会参与卡片的 shrink-to-fit、把卡片撑宽（实测 559px）。
   贴边浮层（输入面板）依赖卡片尺寸，所以媒体一律「宽度占满 + `max-height` + `object-fit: contain`」。
26. **fitView 是「居中」的**：内容越高，底下预留的空间越少（正好是 (画布高-内容高)/2）。
   任何「贴在框体下方」的浮层都要靠**分边 padding** 把内容顶到上面去，
   而且 padding 数字是**比例**不是像素（`parsePadding`），要留固定像素得写 `'320px'`。
27. **贴框体的浮层：锚点必须和框体在同一个坐标系里**（第十六轮重新定稿，本条前面写过三版全错）：
   面板要「锚在画布坐标系」——平移/缩放画布时它跟着框体一起动，也就是**实时订阅视口 transform**。
   前几版写的是「手势中不动、松手后重新落位」，那是把浮层钉在**屏幕**坐标系里，
   一拖画布就和框体分家（用户第七、十、十五、十六轮反复反馈的根因，第十六轮原话：
   「如果我移动画布，输入框就保持跟框体一起」）。
   两条配套：① 手势进行中**不夹取**（夹取会让它在半路停住，看着还是分家），松手后再落位；
   ② 夹取不能删——容器是 `overflow:hidden`，框体贴右边缘时不夹会把面板右下角的「生成」按钮裁掉。
46. **上游模型不会去抓我们的公网地址**（2026-09-11 图片上传时实测）。给模型传
   `https://iicili.cyou/api/public/file-assets/…/download` 会**直接报错**；换成 `data:` URL 立刻正常。
   凡是"让模型看一张图"的需求，都必须**内联**（base64）；外链只对浏览器有效。
   推论：任何"先上传再给模型一个 URL"的设计，都要先问一句"上游抓得到吗"。
47. **别把"平台侧的能力声明"当成"模型的真实能力"**（同一轮的教训）。我先前根据渠道配置里

   与模型无关；实测该模型能读图。**要判断模型能力，发一次真请求，别读配置猜。**
48. **渠道请求模板里的 `messages` 会被多轮历史整份替换**。想让 TEXT 渠道模板带的东西（system 提示词、

45. **生产的 nginx 配置有两份，而且只有一份生效——你改的很可能是没人读的那份**（2026-09-11 06:28 UTC 复核时发现，
   是那次「CSP 漏 blob:」现场改 nginx 留下的后患）。现状：`/etc/nginx/sites-enabled/iicili.cyou` 是**普通文件**、
   **不是**指向 `sites-available/` 的软链（4552B，09-11 12:44），里面才有 `img-src … blob:`、`media-src … blob:`、
   SSE 的 `proxy_read_timeout 300s`、`/vibe-preview.html` 外壳；而 `sites-available/iicili.cyou` **还是旧版**
   （没有 blob:、没有 media-src、仍带着 /student 那两段 location）。
   👉 谁按老习惯 `ln -sf`、或把 available 拷回 enabled，这三样会**静默一起回退**（拖进画布的图不显示、
   SSE 对话断流、学生作品预览被 CSP 拦），nginx 也不会报错。**动 nginx 前先 `diff` 这两份，改完记得两边都写。**

49. **只设 `AI_PROVIDER` 环境变量是没用的：渠道策略里 provider 缺省会默认成 `local-mock`**

41. **「fetch 到了」不等于「显示得出来」：CSP 会把 blob: 悄悄拦掉**

   带不了 `Authorization` 头，`/api/student/file-assets/<id>/download` 这种路由必然 401、
   **图片永远出不来**（而且界面上看不出发过请求，只看得到一个空框）。
   做法：宿主传 `resolveAssetUrl`，画布用 `useDisplayUrl` 先解析成 blob: 再渲染；
   ⚠️ 解析完成前**先别渲染原始地址**（否则白挨一个 401），另外 `fetchBlobUrl` 别再拼 baseUrl
   （快照里存的就是 `/api/...` 根路径，拼完变成 `/api/api/...`，实测 404）。
38. **「浮层永远贴在目标旁边」和「浮层永远完整可见」只能选一个，别用夹取去凑**：
   第十六~十七轮在同一个地方来回改了两次，最后才想明白：面板 660px、框体 170px、画布 1222px，
   **居中必然越界**。三条路只有一条对：
   - 夹住面板（参考实现的做法）→ 框体靠边时面板被按在画布边上、和框体分家（用户报了两次）；
   - 让面板越界 → 被容器 `overflow:hidden` 裁掉，框体贴右边缘时连「生成」按钮都点不到；
   - **动画布让位**（选的这条）→ 面板永远在框体正下方且完整可见。代价是画布会被动一下，
     所以让位必须只在「用户动的是框体」时发（frameKey 变化），用户平移画布时不许发，否则就是橡皮筋。
   判断「用户到底在动什么」比调位置公式重要得多。
37. **「用了没声明的 state」这种白屏，静态检查必须按组件分段看**：
   website main.jsx 的 InnerCircleHeader 用了 `showStudentMenu` / `setShowStudentMenu` 却没声明，
   **已登录学生**打开官网首页 `ReferenceError` 整页白屏（未登录正常，所以藏了很久）。
   坑点：同名的 setter 在**同文件的另一个组件**里声明过 —— 按文件粒度查「未定义标识符」查不出来，
   必须按「缩进 0 的组件」分段比较「声明的名字」与「用到的 setXxx」。p34 的判定二就是这么做的。
   写这类扫描时记住：`[\w$]*` 配负向断言会回溯出截断名字（`setCooki`），正则里别写「后面不能跟 :」，
   改成匹配后单独判断；方法调用（`.setItem`）、对象键（`setX: null`）、全局定时器、
   多行 import / `export {...} from` 都要排除，否则误报到没法用（第一版报了 48 条，全是假的）。
36. **同一段访问控制 SQL 抄了 8 份 = 迟早改漏**：机构可见条件
   `((owner_type='PLATFORM' AND (visibility='ALL_ORGS' OR assignment.id IS NOT NULL)) OR ...)`
   在机构端列表/详情、平台端 accessibleSeries/accessibleLesson、学生端 studentContext、
   教学素材、教学任务里各有一份。第十六轮改口径时全部收敛到 `lib.js: orgSeriesAccessSql()`。
   以后改「谁能看到课包」只动这一处；新增查询要 LEFT JOIN course_assignments
   （条件用 `assignmentActiveSql()`）并把这个片段拼进去（片段里的 `?` 就是当前机构 id，
   参数顺序别挪位）。
35. **授权续期分支只查 id 会炸**：`course_assignments` 的续期走 `assertTransition(status → ACTIVE)`，
   如果 `SELECT` 没带 `status`，拿到 `undefined` 直接抛「status 无效」。这条路径只有在
   「对已授权的机构再次授权」时才会走到，所以生产上一直没暴露。改这类状态流转时，
   顺手确认查询把状态字段带出来了。
34. **「自动让位」这类会动画布的逻辑，必须区分「用户手势中」和「手势结束」**：
   面板算 overflow 用的是冻结的锚点，拖画布期间它是常数 → 去抖一到就会在用户拖动过程中插一脚
   （表现为「移动画布时输入框乱动」）。要用手势状态（ReactFlow 的 onMoveStart/onMoveEnd）挡掉，
   并且同一缺口只请求一次，否则会来回弹。
33. **静默 catch 会把「保存失败」变成「学生以为存上了」**：自动保存原来 `catch {}` 吞掉错误，
   线上出现过「课包被归档 → 保存接口一直 404 → 界面显示已保存 → 刷新全丢」。
   凡是「后台自动写回」的路径，失败都必须冒到界面上（哪怕只是一行红色状态）。
   排查这类问题时，**先看线上访问日志里那个写请求的返回码**，比在本地反复猜快得多。
32. **「能存能取」不等于「会去存」**：p33 这类冒烟只验证服务端 PUT/GET 快照成功，
   而「客户端判断要不要存」的逻辑（内容签名）坏掉时它照样绿 —— 线上表现是「刷新全复原」。
   凡是「前端决定何时把状态写回」的逻辑，都要么补静态守卫（见 p39），要么在浏览器里真做一次
   「改 → 等自动保存 → 刷新 → 对比」的闭环验证。
31. **在组件里插 hook 先看依赖变量声明了没有**：这次把 `requestRoom`（依赖 `getViewport`）插到了
   `useReactFlow()` 解构**之前**，deps 数组是立即求值的 → TDZ `ReferenceError` → 整页白屏
   （构建和 p34 都发现不了，只有真人打开才炸）。另外同一个组件里已有 `setViewport` 这个 state setter，
   引 ReactFlow 的命令式 `setViewport` 要改名（现在是 `setFlowViewport`），否则会静默调用错的那个。
   教训同第七轮：插完 hook 先在浏览器里打开一次。
30. **「槽位画幅」≠「素材比例」**：占位板（还没生成）没有自身尺寸，用槽位画幅是对的；
   但真实画面的尺寸必须由素材自己决定，否则素材比例与槽位不一致时（16:9 成图放进 9:16 框体、
   或框体没配画幅时退回 2:1）框会被拉成扁的、图被 contain 放宽出黑边（第十一轮用户反馈）。
   另外：给 `<img>` 同时写 `width:auto` 与 `aspect-ratio` 时，`aspect-ratio` 会盖掉图片的固有比例，
   要放开就显式写 `aspect-ratio: auto`。
29. **贴框体的浮层锚点别只做一半**：锚点「只在框体动时重取」→ 平移完面板丢在一边（第十轮反馈）；
   实时订阅 transform → 平移时追着框体跑、到边缘被夹住（第七轮反馈）。
   正确口径是「**进行中不动 + 结束后归位**」：视口变化时不重取，`onMoveEnd` 触发一次重取。
   验证这种时序问题别用 cua.drag（一次调用把整条路径发完，采不到中间帧），
   在页内 `setInterval` 采样、或用一个「离散的视口变化」（滚轮/缩放按钮）再分时刻取样最快。
28. **`margin: auto` 不参与宽度计算**：素材区用 `margin: 12px auto` 居中时，auto 那部分对卡片的
   max-content 贡献是 0，于是「图片框体卡片」比「视频框体卡片」窄 24px（同类卡片不一致）。
   要居中就用固定 `margin` + `align-self: center`（外层是 flex 列，交叉轴就是水平方向）。
```

```text
{{model}} {{prompt}} {{title}} {{aspectRatio}} {{resolution}}
{{durationSeconds}} {{durationSecondsNumber}} {{audio}} {{voice}} {{n}} {{messages}}

70. 【「带上游原文」会把最误导人的那句话还给终端用户】额度耗尽时我先把学生文案改对了，
    却又用 `withDetail()` 拼上上游原文 → 学生实际看到的是「本节课的算力额度已用尽…（AI渠道认证失败
    （HTTP 403）。请在管理后台重新填写并保存该渠道 API Key。（上游：insufficient quota））」：
    真正的原因（钱花完了）被那句给运维看的话盖住了。**是新写的守卫断言照出来的，不是我看出来的**。
    教训：面向学生的错误文案要**整句断言**（断言里带上「不该出现的那句」），别只断言关键词存在。
71. 【口径一改，闸门的位置就得跟着改】用户先说「预算按学生算、填在课时上」，后来又拍板
    「按学生 × 课包，且四种模态都算进这个上限」—— 后一句直接**推翻了闸门放在网关**这个前提
    （视频/音乐走不了网关，只有应用侧能看见四种模态）。我一开始的直觉是把网关令牌额度继续当闸门，
    结果发现那只能管住两种模态。教训：**先问「这个闸门能不能看见所有要被它管住的东西」**，
    再选拦在哪里；看不见的那部分等于没闸。
73. 【复用 SQL 片段要连它依赖的别名一起带上】我给「学生进课」加门禁时，为了区分两种拒绝原因写了个
    小查询，里面复用了现成的 `orgCourseAccessSql()` —— **而那段 SQL 引用了 `assignment` 这个别名**，
    我的查询没带 `course_assignments` 的 JOIN → 运行时报 `no such column: assignment.id` → 接口 500。
    新写的守卫第一条断言就红了，**服务端日志直接写着原因**（所以挂了先看日志，别猜）。
74. 【加门禁要顺手数清「谁会撞上它」】这道门禁一加，三条既有守卫当场变红（p11 / p52 / p9-r04）——
    它们自己造课包、自己造学员，但都停在「机构授权」这一步。这不是守卫坏了，而是**真实链路本来就该多走一步**
    （分给学员），所以正确的修法是给守卫补上这一步，而不是放宽门禁。顺带把种子数据也补了，
    否则演示账号自己都进不去。

72. 【模块导入测试又一次当场抓到漏导入】新服务 `computePool.js` 忘了导入 `rows`，
