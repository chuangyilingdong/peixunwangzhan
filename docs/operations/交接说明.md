**生图：通过。** 学生端画布「生成框体」→ 生图，job `generation_4e3f536c28644b288282`

**生视频：原配置不可能成功，换成文生视频模型后通过。**
- 原配置 `hailuo-h3-i2v` 必失败：job `generation_ebbc543e611042898890` FAILED /
  `GENERATION_PROVIDER_UPSTREAM_ERROR`。
- 手工复现上游请求，三种写法（默认模板 / 去掉 metadata / 字段提到顶层）都返回
  `HTTP 400 {"code":"invalid_parameter","message":"firstFrameUrl is required"}`。
  即 `hailuo-h3-i2v` 是**图生视频（i2v）**，必须传首帧图；平台只发文本，代码里也没有
  `firstFrameUrl` 支持，所以该模型在本产品中不可能成功。**与 metadata 字段位置无关**。
- 临时把渠道默认模型换成 `seedance-2.0-global-mini-t2v` 后，学生端 job
  `generation_6b579b8abd174fb1a4df` SUCCEEDED，耗时 76s，产出真实 `video/mp4`。
  验证后**已还原**为 `hailuo-h3-i2v`。
- 结论：**视频链路（请求模板 + 轮询 + 资产落库）是通的，问题只在模型选型**。

**失败不扣费：已确认。** 两个失败任务 `credits_charged=0`，两个成功任务各扣 1。

**沙箱现状（2026-09-09 实测，需用户决策）**
```text
生产 ECS 上 systemd-run 存在，但 ai-kids-prod 用户调用被 polkit 拒绝
（"requires interactive authentication"）；unprivileged userns 也被内核策略挡住
（unshare -U 写 uid_map 报 Operation not permitted），且 ulimit -v 会让 Node 直接崩溃。
结论：要真正隔离地跑 Node 代码，需要额外一步运维改动（二选一）：
  a) 给 ai-kids-prod 配一条最小权限的 sudoers/systemd 代理（只允许固定的 systemd-run 模板）；
  b) 装一个只监听本机 unix socket 的沙箱助手服务（以 root 调 systemd-run，参数固定）。
在此之前服务端运行保持 available=false（不假装成功），学生仍可用浏览器预览 + 控制台。

**2026-09-09 用户决定：不启用服务端沙箱。** 判断依据：收益（跑纯 JS 脚本看文字输出）对当前
VibeCoding 产品形态边际价值有限，而代价是在承载数据库与上游密钥的生产机上常驻一条
「Web 应用可触发 root 操作」的通道（sudoers 代理或本机助手服务），最坏情况代价不对等；
生产内存也偏紧。后续若确有「跑脚本看输出」需求，优先考虑独立机器/容器承担代码执行，
而不是在主生产机上开特权通道。开启与否只影响工作区「服务端运行」按钮，浏览器预览与控制台不受影响。

## 四、关键设计约定（必须遵守）

```text
1. 学生功能在 apps/website，没有独立 apps/student（已删除，不恢复）
   学生登录 → 回 / → 右上角头像 → 进入学习/我的作品/我的积分/我的课程/学习统计
2. 课堂画布是"受控"的：学生不能右键建节点
   节点来源 = 左侧素材面板的「生成框体」+「本节课画布素材」
3. 平台课包本身没有有效期；有效期挂在「课包 → 机构」的授权上
   course_assignments.expires_at，到期后该机构立即看不到该课包
4. 生成参数（比例/清晰度/时长/是否生成音频）来自「模型能力」配置，代码里不写死
   - 配置位置：计费与模型 → 渠道 → 模型能力（channel.modelCapabilities）
   - 请求体由模板生成：channel.requestTemplates，占位符见下
   - 生成时以「课时里该框体的配置」为准，客户端提交的取值一律不采信
   - 调用上游前先做能力/套餐预检，业务拦截不进入重试
5. 课程广场 = 所有「已发布 + 所有机构可见」的课包自动收录，分画布课程 / VibeCoding 课程两类
   没有人工上架/审核流程
6. 作品链路：学生提交 → 平台在「平台作品库」点「发布到作品广场」→ 官网 /works 可见
   机构端只做点评与机构精选，不再有审核/发布权
7. 教学素材 = 教师备课资料：学生端与公开接口不下发 teachingGroups；
   文件走机构端受控下载路由，公开下载路由拒绝该分类
8. 课堂类型 delivery_mode：课包级默认（course_series.delivery_mode），课时继承、可单独改
   VibeCoding 已预留但运行时未实现（发布会被拦）
9. AI 渠道：一个渠道可配多个模型；课时可从对应模态渠道的模型下拉单选

      ① `::after` 描边：白色高光锥形 + 9 个彩色椭圆斑 ∩ 亮弧 ∩ 1px 边框圈；
      ② `::before` 内壁辉光：同一组彩色斑（更淡）+ 内阴影，遮罩把光压在**离边 28px 以内**
         ——这一层是「柔光」观感的关键，第一版漏掉它、只留描边，看起来就是一道硬线；
      ③ 外发光晕（blur 8px）。三层的透明度严格照参考的 `0.26 / 0.42 / 0.24 × strength(.67)`，
      别随手调亮。面板 padding 放在 `.learning-canvas__panel-inner` 而不是面板本身——
      遮罩是按元素自己的 content-box 挖圆环的，面板留 padding 会把光圈推进去
    - 连线：贝塞尔曲线 + 沿路径游走的主色发光段（自定义 GlowEdge），不渲染箭头，方向由光带动效表达；

      避免学生连错后没法取消；连线悬停变亮加粗、选中变主色
    - **框体两侧的小圆 ＋ 连接点**（2026-09-10 第六轮，按参考；**只认拖拽，不做点击自动连接**）：
      从圆点按住拖一条线，落到另一个框体的圆点上即建立连接（ReactFlow `ConnectionMode.Loose`，
      两侧 handle 都声明成 source，所以左右都能起线也能接收；`connectOnClick={false}` 关掉单击起线）。
      两个实现要点：handle 必须渲染在 `.learning-node` **外面**（卡片 overflow:hidden 会裁掉探出的圆点）；
      **只读模式下也要留在 DOM 里**（CSS opacity:0 隐身）——删掉的话 ReactFlow 找不到 handle，
      已提交作品里原有的连线会一起消失（已实测：只读态 2 条连线照常渲染、连接点全隐身）
    - **连线两端到底点在哪个圆点**：`resolvePortSides()` 是唯一规则（渲染 displayEdges 与查重 onConnect 共用）。
      历史快照里的连线没有 handle 字段，按两节点左右位置补 facing 的两侧——只影响渲染、**不写回数据**，
      免得把老画布白白标记成「有未保存改动」。查重按「哪两个圆点被连上」比较（`edgePortPairKey`，
      方向不算差异），否则一条老连线能从反方向再连一次、两条线正好重叠
    - **卡片标题**（2026-09-10 第七轮，按用户反馈）：默认是纯文本（16px，比原来的 13px 大两档），
      **双击才进编辑态**——单击就能编辑的话，学生想拖卡片往往点进输入框里，拖不动还以为卡了；
      编辑态的输入框只占标题栏一段（`min(200px, 58%)`）而不是铺满整条，剩下的地方留给拖卡片
    - **学生可以把桌面文件拖进画布**：走 `POST /api/student/file-assets/upload`（新增，仅 STUDENT，
      归本人 + PRIVATE，复用 persistSecureUpload/reserveUpload 的扩展名/魔术字节/25MB/频次校验），

    - 回归网：`scripts/p38-student-canvas-upload.mjs`（本人可见/未登录取不到/类型拦截）

6. 本地 mock 产出的音视频不是真文件（mock://…），本地验不了播放。
7. 模型能力是「管理员声明的白名单」，不是自动识别；上游 /models 只返回 id。
8. **hook 不能出现在提前 return 之后**（2026-09-10 画布课堂整页白屏的成因）：
   `canvasWorkspace.jsx` 里自动保存的 useState/useRef/useEffect 被写在
   `if (project.loading) return <Loading/>` 后面 → 加载态渲染 19 个 hook、数据到了变 24 个，
   React 抛 #310 并卸载整棵树（白屏，控制台只有一句 "Minified React error #310"）。
   三端构建能过、33 个 API 冒烟全过，**只有真人打开页面才会炸**。
   教训：冒烟过 ≠ 页面能开；动过前端组件后，除了冒烟还必须真在浏览器里打开一次。
   已加静态守卫 `scripts/p34-hook-order-guard.mjs`（命中即 exit 1）。
   移动这类 hook 时，把它依赖的衍生值（如 `editable` / `runningCount`）一起上移，否则 deps 数组会踩 TDZ。
9. `useData()` 每次渲染都返回新对象（`{...state, refresh}`），**不要把整个对象放进 useEffect 依赖**，
   否则定时器会被反复重置、永远等不到那 5 秒；依赖用 `generations.data` 这类稳定引用或派生标量。
10. React Flow 缩放把手有两个坑（学生反馈「框体没法放大缩小」的成因）：
    - 它自带的 `.react-flow__resize-control.handle{width:5px}` 比单类选择器更具体，
      自定义把手尺寸必须写足三层（`.learning-canvas .react-flow__resize-control.learning-node__resize-handle`），
      否则你的 16px 会被压回 5px；
    - `.learning-node` 的 `overflow:hidden` 会把探出节点四角的把手裁掉（右下角几乎完全点不到）→
      `NodeResizer` 要放在被裁切容器的**外面**（现在是 `.learning-node` 的兄弟节点）。
11. 官网匿名统计同意条是 fixed 悬浮在底部的，会盖住画布最下面一条（底部把手点不到）：
   用 `body:has(.analytics-consent) .student-canvas-viewport{height:calc(100vh - 330px);flex:0 0 auto}`
   在它出现时缩短画布。注意视口本身有 `flex:1`，只加 margin/padding 会被 flex 长回去。
12. 框体参数（比例/清晰度/时长/含音频）现在是「**平台留空＝学生在课堂里自选**」：
   留空的服务端不能填默认值（`normalizeGenerationBox` 会保持空），并把该模型的 `paramOptions`
   随框体下发给学生端渲染下拉；学生选的值必须**落库 `generation_jobs.request_options`**——
   异步 worker 会按框体重新解析一次参数，不落库的话学生的选择会被重算成默认值。
   平台填了则该参数学生只读：服务端只认框体，并且只记录真正生效的学生选择（锁定项不写库）。
14. 拆模块（2026-09-09 那次 communication.js 拆分）留下的隐藏坑：**同一个域里跨文件用了没导出的函数/常量**，
   静态看没问题、构建也过，直到真的请求到那个接口才 500（`ReferenceError: helpFeedbackRows is not defined`）。
   修法是把共享件放进本域的 `helpers.js` 统一导出；改完用 `esbuild --bundle` 打一遍、或写个
   「引用了兄弟文件里的名字却没导入」的小扫描，比逐个接口试快得多。
15. **守卫只认单行早返回会漏**：`if (pathname.startsWith('/learn') && !session) { return <Navigate/> }`
   这种跨行写法在 website main.jsx 里藏了很久——学生会话一过期就白屏（React #300），而不是跳登录页。
   p34 现已同时识别「单行 if(...) return」与「if(...) { 换行 return }」，全仓复扫无其他实例。
   同类坑的通用形态：**hook 必须全部在提前 return 之前**，包括那些「看起来不像 return」的提前返回。
16. 生成状态靠**回到页面时**用服务端任务对账：`generation_jobs` 告诉前端哪些框体已完成/失败，
   画布节点据此补结果或翻失败（只补「缺失节点」是不行的，已在画布上的节点会永远停在生成中）。
   轮询依赖该列表里还有 QUEUED/RUNNING；任务早结束而页面还停在「生成中」时，刷新一次即恢复。
17. 排查前端白屏别只信 dev server：反复改文件、HMR 大量 update 之后，dev 服务器会冒出**假的**
   hook 顺序报错。先用 `vite build` 出来的 dist 复现一次再下结论（本轮被这个绕了一圈）。
18. ReactFlow 的 `.connectionindicator` 是**常驻类**，不是「正在拖线」的标志：
   `connectionindicator: isConnectable && (!connectionInProcess || isPossibleEndHandle) && (…)`，
   没有连线时它也算 true，所以不能拿它做「平时隐身、拖线时才亮」的开关。
   想区分拖动中得自己看 `connectingfrom`（起点）/ `valid`（可落点），或者干脆让连接点常亮低透明度
   （第六轮就是这么定的：静止 0.4，悬停/选中/可落点 1）
19. ReactFlow 的 Handle 在只读态（`nodesConnectable={false}`）**仍然渲染 DOM**，别用 `return null`
   或 `display:none` 藏它：`getEdgePosition` 找不到 handle 就让整条连线不渲染（hide 要用 opacity:0）
20. 连线拖拽的**落点判定是 `elementFromPoint`**：如果 handle 里塞了图标（svg），命中到的是子元素，
   ReactFlow 会退回「最近 handle（connectionRadius 内）」的兜底路径——能用，但别把 connectionRadius 调太小。
   另外拖动时 `mousedown` 必须**正好落在圆点上**，偏出去十几像素就变成拖框体（本地验证脚本踩过好几次）
21. 撤销历史别按事件条数记：拖动框体是每帧一个 `position` change、打字是每键一个 change，
   照搬「每次变更 push 一条」会让一次拖动攒几十条记录（撤销只能一点一点退）。
   做法见 `CanvasSurface`：拖动/缩放用手势底稿（`gestureRef`，手势开始留底、结束记一条），
   连续输入用 700ms 窗口合并（`COALESCED_EDIT_KEYS` + `lastEditRef`，undo/redo 时重置）
22. **别靠读源码还原参考的视觉效果**：参考里很多组件的 CSS 是运行时生成的
   （border-beam 就是 `[data-beam]` + `::after/::before` + `@property` 动画拼出来的）。
   正确做法是把包渲染一遍、把生成的 CSS 抓出来（脚本见第七节「参考组件原始 CSS 的取法」），
   再做并排对比页。本轮第一版就是只读了源码、漏掉一层 `::before`，观感差了十万八千里。
23. **fitView 会把内容垂直居中**：内容越高，最下面的框体越贴近画布底边。
   面板类浮层要贴在框体下方时，这直接决定「框体下面还剩多少地方」——
   所以 `fitViewOptions.maxZoom` 不只是缩放观感问题（1.8 → 1.2 把面板与框体的重叠从 100px+ 收到约 14px）。
   同理，任何贴着框体渲染的浮层（状态条、工具栏）都要先想清楚「下面还有没有地方」。
24. 面板/浮层贴着框体算位置时，**水平居中要在夹不住的时候换策略**：
   参考实现的 `getFloatingPanelPosition` 是「居中后硬夹在视口内」，框体靠边时浮层会被推到
   离框体很远的地方（用户反馈的「错位」）。我们的做法是居中放不下就与框体的左/右边对齐，
   浮层始终「连着」框体。垂直方向则是永远在下方（只贴底边，不翻到上方）。
25. **卡片尺寸是内容撑出来的**，所以图片会反过来决定卡片多大：
   `width: 100%` 的图片按卡片宽度铺开后高度 = 宽度/比例（9:16 成图 → 卡片长到 1355 flow px），
   而图片的**原始宽度**只要写成 `width: auto` 就会参与卡片的 shrink-to-fit、把卡片撑宽（实测 559px）。
   贴边浮层（输入面板）依赖卡片尺寸，所以媒体一律「宽度占满 + `max-height` + `object-fit: contain`」。
26. **fitView 是「居中」的**：内容越高，底下预留的空间越少（正好是 (画布高-内容高)/2）。
   任何「贴在框体下方」的浮层都要靠**分边 padding** 把内容顶到上面去，
   而且 padding 数字是**比例**不是像素（`parsePadding`），要留固定像素得写 `'320px'`。
27. **浮层跟着框体的「锚点」策略要写清楚**：实时订阅画布 transform 会让浮层在平移时追着框体跑、
   追到边缘又被夹住（看着像乱动，用户第九轮反馈的就是这个）。贴框体的浮层应该只在
   「框体位置变化 / 换选中框体」时重取 transform；平移缩放期间保持不动。
32. **「能存能取」不等于「会去存」**：p33 这类冒烟只验证服务端 PUT/GET 快照成功，
   而「客户端判断要不要存」的逻辑（内容签名）坏掉时它照样绿 —— 线上表现是「刷新全复原」。
   凡是「前端决定何时把状态写回」的逻辑，都要么补静态守卫（见 p39），要么在浏览器里真做一次
   「改 → 等自动保存 → 刷新 → 对比」的闭环验证。
31. **在组件里插 hook 先看依赖变量声明了没有**：这次把 `requestRoom`（依赖 `getViewport`）插到了
   `useReactFlow()` 解构**之前**，deps 数组是立即求值的 → TDZ `ReferenceError` → 整页白屏
   （构建和 p34 都发现不了，只有真人打开才炸）。另外同一个组件里已有 `setViewport` 这个 state setter，
   引 ReactFlow 的命令式 `setViewport` 要改名（现在是 `setFlowViewport`），否则会静默调用错的那个。
   教训同第七轮：插完 hook 先在浏览器里打开一次。
30. **「槽位画幅」≠「素材比例」**：占位板（还没生成）没有自身尺寸，用槽位画幅是对的；
   但真实画面的尺寸必须由素材自己决定，否则素材比例与槽位不一致时（16:9 成图放进 9:16 框体、
   或框体没配画幅时退回 2:1）框会被拉成扁的、图被 contain 放宽出黑边（第十一轮用户反馈）。
   另外：给 `<img>` 同时写 `width:auto` 与 `aspect-ratio` 时，`aspect-ratio` 会盖掉图片的固有比例，
   要放开就显式写 `aspect-ratio: auto`。
29. **贴框体的浮层锚点别只做一半**：锚点「只在框体动时重取」→ 平移完面板丢在一边（第十轮反馈）；
   实时订阅 transform → 平移时追着框体跑、到边缘被夹住（第七轮反馈）。
   正确口径是「**进行中不动 + 结束后归位**」：视口变化时不重取，`onMoveEnd` 触发一次重取。
   验证这种时序问题别用 cua.drag（一次调用把整条路径发完，采不到中间帧），
   在页内 `setInterval` 采样、或用一个「离散的视口变化」（滚轮/缩放按钮）再分时刻取样最快。
28. **`margin: auto` 不参与宽度计算**：素材区用 `margin: 12px auto` 居中时，auto 那部分对卡片的
   max-content 贡献是 0，于是「图片框体卡片」比「视频框体卡片」窄 24px（同类卡片不一致）。
   要居中就用固定 `margin` + `align-self: center`（外层是 flex 列，交叉轴就是水平方向）。
```
