# 新对话交接 · 教学素材预览（2026-09-17）

> 起因：老师点「在线预览」看不到素材，页面上回显
> `{"code":"TEACHING_ASSET_FORBIDDEN","message":"教学素材仅教师可见"}` —— 而他**就是**教师。
> 查下来是两个 bug 叠在一起，加上后来用户提的三条新要求（素材永不过期、去掉所有下载入口、新增全屏）。

## 一、为什么「教师看不到教师素材」（两个 bug 叠在一起）

### 1.1 真凶：快照把短时票据冻死了

`apps/server/src/lib.js` 的 `normalizeLesson`：课时有 `published_content` 快照时（机构端读的就是快照），
教学素材整份从快照取 —— 包括 `previewUrl`。而 `previewUrl` 里是**只活 1 小时的签名票据**。

结论：**发布 1 小时之后，这节课的素材预览永久失效。**

实测证据（用备份库只读查的）：出问题那节课的 PPT 与教案，票据到期时间 `2026-09-16 19:28`，
而用户点开是在 `2026-09-17 17:27` —— 过期 22 小时。两个素材，两个都过期。

### 1.2 让错误信息说谎的：iframe 带不了鉴权头，回落到共用的 cookie

预览开在 `<iframe>` 里，iframe **没法带 `Authorization` 头**（票据存在的理由就是这个）。
票据一失效，`routes/fileAssets.js` 的预览路由就回落到会话鉴权，于是走 `lib.js` 的 `readToken`：
**先 Authorization，再 `platform_token` cookie**。

而 cookie 是这么种的：`platform_token=…; Path=/; HttpOnly; SameSite=Lax` ——
**`Path=/` 且无 `Domain`，属于整个 `iicili.cyou`**，`/`、`/admin/`、`/org/`、`/student/` 四个端共用一份，
谁在这个浏览器里最后登录就是谁。用户浏览器里恰好是**学生会话** → `role === 'STUDENT'` →
`TEACHING_ASSET_FORBIDDEN` 抛出 → 界面显示「教学素材仅教师可见」。

> ⚠️ **这条错误码只在 `role === 'STUDENT'` 时抛出**（`fileAssets.js`），完全没登录时会先抛 401。
> 所以下次再看到它，先怀疑「这个请求用的身份不对」，而不是「这个人不是老师」。

**当时的应急办法**：在机构端重新登录一次（覆盖 cookie）→ 立刻就能看。
原因：票据虽然失效，但回落分支一旦拿到**教师**身份，`teachingAssetVisibleToOrg` 是放行的。

## 二、改了什么

### 2.1 素材随时能看（不再依赖长链接）

1. **快照不再冻结 `previewUrl`**（`lib.js` 新增 `teachingGroupsFor`）：
   标题/说明/排序仍按快照定格，但 `previewKind / previewUrl` 一律**现签**。
2. **点开素材那一刻再取一张新票据**：机构端点「在线预览」时调用
   `GET /api/org/file-assets/:id/preview-ticket`（需登录 + 同一套 `authorizeFileAccess`）。
   这样「抽屉开了几小时」也不影响 —— 不靠把票据变长命，而靠每次用的时候现签。

### 2.2 去掉所有下载/导出入口（用户列了五个，后来又要求连快捷键一起堵）

⚠️ **那一排「下载 / 旋转 / 打印 / 保存到云端硬盘 / ⋮文档属性」是 Chrome 内置 PDF 阅读器的 UI，
不在我们的 DOM 里，删不掉。** 而且更要命的是：**Ctrl+P / Ctrl+S / 右键菜单都由浏览器（插件）处理，
不经过我们的页面** —— 事件收不到，也就拦不住。

所以最后的做法是**不再用浏览器内置阅读器**，改成 `apps/org/src/components/TeachingAssetViewer.jsx`
里用 **pdf.js 把每页画到 `<canvas>`**。DOM 全归我们之后，三件事才成立：

1. **拦快捷键**：`document` 上 capture 阶段拦 `Ctrl/Cmd + P / S / U` 并 `preventDefault`
   （capture 是为了抢在浏览器默认行为之前）。
2. **吃右键**：面板上 `contextmenu` 直接 preventDefault —— canvas 上不会出现「图片另存为」。
3. **打印藏内容**：`@media print { .preview-overlay, .ta-panel { display:none !important } }`，
   万一从浏览器菜单走打印，打出来是白纸。

顺带的好处：页码总数回来了（pdf.js 自己知道 `numPages`，原生阅读器一关就没有了），
键盘翻页（←/→/PageUp/PageDown/空格）也顺手加上了 —— 讲课时很好用。

pdf.js **按需加载**（动态 `import()`），构建成独立 chunk（主包只涨了约 8KB；
`pdf-*.js` 438KB + worker 1.2MB 只在真打开素材时才拉）。

视频/图片仍是原生元素，但：视频 `controlsList="nodownload noplaybackrate noremoteplayback"` +
禁画中画，图片 `draggable=false` + `user-select:none`，整块面板屏蔽右键。

### 2.3 全屏观看（用户的主要诉求：上课就是打开这些素材在讲）

全屏的是**整个面板**，不是内容区 —— 这样全屏里仍然够得着「上一页 / 下一页 / 缩放 / 退出全屏 / 关闭」。
进了全屏就翻不了页的话，这个功能等于没有。

另外：Esc 在全屏时只退出全屏，不关查看器（老师按 Esc 的意图几乎总是「退出全屏」）。

## 四、还没做 / 有代价的地方（别误以为做了）

1. **截屏与录屏拦不住**，这是 web 的物理限制（能看见就能被拍下来）。
   另外**开 DevTools 看 Network 就能拿到文件字节** —— 浏览器里做不到「物理上取不到」。
   当前做到的是：界面上没有下载入口、快捷键被拦、右键被吃、打印出白纸。
2. **共用 cookie 是个双向隐患**（**本轮没动**）：如果某台机器上最后登录的是教师，
   **学生端的 iframe 会以教师身份鉴权** —— 拿到 `fileId` 就有可能读到教师备课资料。
   触发条件是同一浏览器里教师登录过（教室共用电脑很常见）。这条比原来的 bug 更值得单独修一轮，
   改的是鉴权口径，影响面大，要单独评估。
3. **作品预览里的「下载原文件」按钮没动** —— 那是学生作品的入口，与教师素材是两回事。
4. 教师素材目前**只有机构端**有这个查看器；平台管理端还是老样子（真要统一，
   把 `TeachingAssetViewer` 搬过去即可，它只依赖 `api.fetchBlobUrl`）。

## 五、上线后当场踩到的坑：`.mjs` 被 nginx 当成 octet-stream（已修）

第一次上线（release `20260917T095548Z`）后老师打开素材，看到：

```
文档解析失败：Setting up fake worker failed: "Failed to fetch dynamically imported module:
https://iicili.cyou/org/assets/pdf.worker.min-Dswkl-cV.mjs"
```

**文件是 200 能取到的**，所以只看状态码 / 只看「资源在不在」发现不了。真正的原因量出来了：

```
.mjs  →  Content-Type: application/octet-stream      ← 加上 X-Content-Type-Options: nosniff
.js   →  Content-Type: application/javascript
```

nginx 编译内置的类型表里有 `application/javascript js;` 但**没有 `mjs`**，
于是 `.mjs` 回落成 `octet-stream`；配上 `nosniff`，浏览器**拒绝把它当模块脚本执行**。

### 修了两处（互为兜底）

1. **构建侧（跟 git 走，不依赖服务器配置）**：`apps/org/vite.config.mjs` 里把 `.mjs` 产物
   统一改名成 `.js`（`assetFileNames`）。换台机器、换个反代都不会再犯。
2. **服务器侧（根因）**：`/etc/nginx/mime.types` 的 javascript 那行加上 `mjs`，
   `nginx -t && systemctl reload nginx`。已写进 `deploy/production/nginx.conf.example` 顶部。

### 三个坑，都记在 nginx.conf.example 的注释里

- **别在 `server{}` 里写 `types { … }` 补** —— 那会替换掉整张类型表，css/js/png 一起报废。
- **改完要等 reload 生效再验证**：我第一次改完立刻探测，拿到的还是旧行为（octet-stream），
  差点误判成「这个文件没被加载」。加个 `sleep 1` 再看就是对的了。
- 我第一次还误判了一轮：`grep "include.*mime.types"` 没匹配上（那行行首是**制表符**），
  于是以为 nginx 根本没加载类型表、把改动还原了 —— 实际上 include 是好的。
  **判断之前先看清那一行到底长什么样**，别靠一次 grep 的成败下结论。

> 教训（比这个 bug 本身值钱）：**本地 `vite preview` 永远测不出这一类问题** ——
> 它自己会按对 MIME 返回。所以这类「只有生产才犯」的故障，验收必须包含
> **部署后对真实站点取响应头**这一步，而不是只看本地浏览器跑通。
