## 二、这轮（2026-09-16 第二轮）做完并**验证过**的

1. **模型名映射（原「下一步 1」）**：容器补丁层里的模型 id 只是**给学生看的槽位名**。
   网关现在按「意向」解析：政策里的 `modelRoutes` 优先 → 默认 TEXT 渠道的模型清单里认得出就用 →
   认不出就用**这条渠道自己的 model**。**绝不把容器报的字符串原样发上游**（以前会：轻则上游 400、重则按别的模型计费）。
2. **读图：图跟着模型走（原「下一步 2」）**。这里先纠正上一轮的一个**错误假设**：我原以为
   「读图要另配一条视觉渠道」，于是加了一道「不配就 409」的闸门。实测与代码都证明**这是错的** ——
   我们的模型（`deepseek-flash` 那条渠道）本来就能看图，平台老 VibeCoding 的聊天一直把图当内容块
   发给同一个模型（代码里还记着实测：data URL 答出「红 蓝」，外链报错）。真正缺的是两件事：
   - dsh 的 pi-ai 适配器对**手写声明的模型**默认只认文本，所以补丁层要给模型写 `input: [text, image]`
     （官方原文：*Declaring images is what makes a hand-declared vision model usable*）。没这一行，
     学生贴的图根本不会进请求体。已验证组合树里带上了这个声明。
   - 网关这一层以前把多模态 content 压成 `"[object Object]"`（图片在网关就没了），现在只放行
     text 与 `http(s)`/`data:image`，其余（含容器内的 `file://` 路径）丢掉。
   于是**默认语义 = 图走同一条 TEXT 渠道、同一个模型**，费用照常进算力账；政策里的 `visionChannelId`
   （后台「读图渠道」）降级成**可选覆盖**（留空即默认），不再是一道卡人的闸门。
   容器入口脚本仍然把 `@liustack/modlens`（那个给纯文本模型用的视觉桥）的凭据钉到我们网关：
   我们这条路上用不到它，但万一将来把学生指到纯文本模型、或者有人点了它，钱也仍然进我们的账。
   （**待定**：模型已能直接看图，modlens 要不要干脆关掉那一行？它会在模型选择器里多出
   「(modlens vision)」条目，属于冗余；关行不删包的做法与 `dsh-at-file` 一致。）
3. **容器宿主（机器那一半）落成脚本**：`deploy/dsh-student/host/`
   （装机 / 拉起 / 停 / 兜底回收 / 自检；平台与宿主之间只有「一个脚本 + 几个参数」这一层接口）。
   本机实测：自检 8/8；拉起脚本起的容器带票据能出真界面、复用 cookie 200、别人的旧 cookie 403。
4. **部署侧缺口补上**：`production.env` 必须配 `RUNTIME_GATEWAY_SECRET`（不配则 `/api/gateway/v1/*` 一律
   拒绝服务，故意 fail-closed），RUNBOOK 记了生成方式、何时更换、如何确认生效。
5. 守卫：`p97` 扩到 20 项（名字解析 4 种情形、带图请求默认跟着模型 / 配了读图渠道才改走、
   记账里留 `modelResolution` 与 `withImages`、多模态不被压扁）；新增 `p98` 真容器端到端

## 五、硬约束与已踩的坑（换会话后别再踩一遍）

1. **dsh 只绑 127.0.0.1 且拒绝 `--host 0.0.0.0`** → 对外入口必须由**容器内**的 nginx 提供。
2. **`dsh plugin` 在 PATH 没有 pnpm 时会打印提示但退出 0** —— 插件一个没装却“构建成功”。装完必须断言包真进了 profile。
3. **`dsh-ppt-composer` 把 `dsh-ppt@0.1.1-rc.2` 声明成 registry 依赖**，而 npm 上同名的 `dsh-ppt@0.4.2` 是**别人的项目**：
   必须用 pnpm override 指到本地 tarball。
4. **`dsh-ppt` 只能当依赖不能同时当 bundle**（两者都注册 `dsh-ppt-bundled`，双挂载整棵树起不来）。
5. **入口「已补过 token」的 cookie 必须按容器唯一**（现用本次 dsh token 的 sha256 前 16 位）；固定值或票据值会误判 → dsh 401。
6. nginx 要 `absolute_redirect off`；脚本必须 LF 且有 shebang。
7. **`dsh-at-file` 与 0.1.5-rc.1 不兼容**（要更新的 `settingsNamespace` 导出），已禁用；dsh 升级后再开。
8. 官方 `SAFETY.md`：实验软件、**未做安全审计、不得视为生产可用** → 隔离由我们的容器负责。
9. **`docker --tmpfs` 默认带 `noexec`**（实测 `rw,nosuid,nodev,noexec`）：dsh 启动要在 `/tmp` 落一个原生模块回退加载器，
   noexec 会让它加载不上 → 插件树报 `Cannot find package '@linxin666/dsh-web-all'`、界面根本起不来。
   必须写 `--tmpfs /tmp:...,exec`（二分定位出来：只有加 tmpfs 的那一档失败）。
10. **回收脚本读 `docker inspect` 的 `StartedAt`（UTC），别把结尾的 `Z` 截掉**：截掉后 `date` 按当地时间解释，
    东八区下每个容器都「已经跑了 8 小时」，第一个 cron 周期就把学生全踢了（实测踩到）。
11. **网关这一层曾经把多模态内容压成字符串**（`String(content)` → `"[object Object]"`）：学生的图在网关就没了，
    上游只看到一句空话、钱照花。现在只放行 text 与 `http(s)`/`data:image`。
