## 三、下一步（按优先级，都不依赖外部等待的排前面）

1. **模型名映射**：dsh 报的模型名（如 `deepseek-flash`）要映射到我们渠道里的 model id；
   现在 `providerSelectionForModality` 按既有策略挑渠道，映射缺失会落到默认渠道。
2. **modlens（视觉插件）的凭据**：它读图要自己的模型渠道。**必须让它指向我们的网关**，
   否则读图花的钱不进我们的账（它默认会去找 OpenAI/Gemini 之类）。
3. **端到端拉通**（主线）：门禁通过 → 平台签发运行时密钥 → 拉起容器（注入密钥 + 票据）→ 学生进界面创作
   → 用 dsh 的 `deliverables/presented` 事件取产物清单 → 走我们现有 `/submit`（按产物、版权确认、只允许网页/PPT/Word/Excel）。
   - 顺带解决：**工作区预选**（现在要学生手动选一次；平台用 API 建会话时可以预选 `/home/student/workspace`）。
   - 待定：学生界面要不要隐藏「设置」入口（里面有模型选择等）。
4. **并发与资源**：见下一节。需要按同时在线创作人数配机器规格与预热池。

## 四、阻塞项（要用户/资源）

- **一台能跑容器的机器**：现在这台生产机 **没有 docker/podman**，而且只有 **2 vCPU / 1.6GB**
  （连一个带 Chromium 的 agent 会话都紧张）。按「一学生一容器」估：每容器 1–2 vCPU / 1.5–2GB，
  10 人同时上课约 10–20 vCPU / 15–20GB。**用户说机器后续会升级**。
- **这个用途的模型额度/渠道**：确认 dsh 走我们网关时用哪条渠道、给多少额度。
- **并发量级**：峰值同时创作人数（决定机器规格与是否要预热池）。

## 五、硬约束与已踩的坑（换会话后别再踩一遍）

1. **dsh 只绑 127.0.0.1 且拒绝 `--host 0.0.0.0`** → 对外入口必须由**容器内**的 nginx 提供（端口发布从宿主连不上回环）。
2. **`dsh plugin` 在 PATH 没有 pnpm 时会打印提示但退出 0** —— 插件一个没装却“构建成功”。装完必须断言包真进了 profile。
3. **`dsh-ppt-composer` 把 `dsh-ppt@0.1.1-rc.2` 声明成 registry 依赖**，而 npm 上同名的 `dsh-ppt@0.4.2` 是**别人的项目**：
   必须用 pnpm override 指到本地 tarball，否则会把第三方同名包拉进来。
4. **`dsh-ppt` 只能当依赖不能同时当 bundle**（两者都注册 `dsh-ppt-bundled`，双挂载整棵树起不来）。
5. **入口「已补过 token」的 cookie 必须按容器唯一**（现用本次 dsh token 的 sha256 前 16 位）；固定值或票据值会误判 → dsh 401。
6. nginx 要 `absolute_redirect off`（否则 302 会写绝对地址把浏览器带出入口）、脚本必须 LF 且有 shebang（否则 `exec format error`）。
7. **`dsh-at-file` 与 0.1.5-rc.1 不兼容**（要更新的 `settingsNamespace` 导出），已禁用；dsh 升级后再开。
8. 官方 `SAFETY.md` 原文：实验软件、**未做安全审计、不得视为生产可用**，沙箱不保证隔离 → 隔离由我们的容器负责；
   品牌上描述性文字可用「built on DeepSeek Harness」，项目名别用全称。

## 六、本地怎么复现（容器部分）

```bash
# 构建学生运行时镜像（约 8–10 分钟）
docker build -t dsh-student:local deploy/dsh-student

# 起一个（票据由平台签发；本机调试可先随便给一张）
docker run -d --name dsh-student-test -p 18080:8080 \
  -e EDGE_TICKET=<短时票据> \
  -e GATEWAY_BASE_URL=http://host.docker.internal:8789/api/gateway/v1 \
  -e PLATFORM_GATEWAY_KEY=<网关凭据> \
  dsh-student:local
# 学生入口：http://<host>:18080/?t=<短时票据>

# 看组合树里挂了哪些插件
docker run --rm --entrypoint sh dsh-student:local -lc \
  'export PATH=/opt/node/bin:$PATH; dsh --profile web --patch /etc/dsh/student-runtime.cordis.yml --dump-config'
```

后端侧回归：`node scripts/p97-runtime-gateway.mjs`（运行时网关）、
`p16/p18/p26`（老 VibeCoding 链路）、`p70`（三端页面渲染）。
