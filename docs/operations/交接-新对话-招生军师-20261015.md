> Ai 可以参考知识库来跟他们对话，或者引导他们如何对话，然后给出属于他们自己的答案。」

6 位专家：营销军师 / 话术教练 / 文案写手 / 转化教练 / 续费管家 / 合规顾问。


**接口清单**（前缀 `/api/junshi`）：

| 方法 | 路径 | 说明 |
|---|---|---|

`junshi_profiles`（画像）、`junshi_conversations` + `junshi_messages`（会话）。

## 五、踩过的坑（**这部分最值钱，别重复踩**）

### 部署与构建
1. **`/assets/` 是 nginx 的 expires 7d 强缓存**，而 `/junshi/` 的脚本是手工维护的非哈希文件。
   改了脚本但 URL 不变 → 浏览器拿旧脚本，现象是「服务器上是新的、页面还是旧行为」，极难自查。
   → 已用 `stamp-junshi.mjs` 在构建后打内容哈希，**接了 build-production.sh**；别手工改成固定值。
2. **`index.html` 里必须外链脚本**：线上 CSP 是 `script-src 'self'`，内联 `<script>` 被直接拦掉。
   `<style>` 可以内联（`style-src` 放行）。
3. **MySQL 侧建表要单独跑 DDL**：`schema.js` 那段 SCHEMA 只在 sqlite 驱动下执行。
   漏了的现象是「页面能开、只读接口全 200，只有写操作 500」——最难查的一类。
4. **`node --check` 是必需的**：我在 `schema.js` 的**模板字符串内部**注释里写了反引号，
   直接把字符串截断、服务起不来。build-production.sh 第 3 步拦住了。
5. **不要对服务器跟踪的分支 `--amend` + 强推**：会让 15 脚本的 `--ff-only` 失败，
   而 04 构建照跑 —— 结果是「构建成功、服务正常，跑的还是旧代码」。
   恢复：`git push --force prod HEAD:refs/heads/deploy-incoming` + 服务器 `git reset --hard deploy-incoming`。

### 数据层
6. **MySQL 不认 `MAX(a,b)`**：SQLite 的 `max(x,y)` 是标量函数，MySQL 的 `MAX()` 只有聚合形式。
   涉及多方言的 SQL 先在**生产数据层**上试一次，别信本地 sqlite 跑通。
7. **`req.destroyed` 不能用来判客户端断开**：POST 请求体读完之后它本来就是 true。
   用它判「客户端走了」会把**所有生成错误都误判成用户中止**、静默吞掉（连日志都不打）。
   要判就用 `res.on('close')` + `!res.writableEnded`。
8. **SSE 必须发心跳**：DeepSeek 是推理型模型，先思考十几秒一个字节都不吐，
   nginx 会按 `proxy_read_timeout` 掐断。定期写 `: ping` 注释行。
9. **推理事件要去重**：一次回答会推 400–800 个 `reasoning_content` 增量，
   全转发等于白送 12KB/次 + 前端几百次 DOM 重写。只转第一个。
10. **推理型模型会间歇性给空回答**（已修，45136d40）：思考 token 计在输出预算里，而**发出去的
    请求体里根本没有 max_tokens** —— 默认模板只有 model + messages（用"假上游录包"坐实的），
    上游于是套用它自己的小默认值，思考一大正文就空（实测 6 次空 2 次）。修法：`openaiCompatibleProvider`
    支持调用方显式传 `options.maxTokens`（挂在模板渲染之后；模板里写了 max_tokens 的以模板为准），
    `junshiChat` 传 32000。**没有动画布共用的渠道模板**（不传就还是原行为）。自动重试保留兜底。
    线上复测 7 问 7 答、正文 382–781 字、零重试零错误。
    验法留档：`.tmp/verify-maxtokens.mjs`（假 fetch 录请求体，在服务器上跑，Node 22）。

### 前端
11. **高度链必须每层都写确定值**：`.body` / `.chatwrap` 只给 `grid-template-columns` 时行是
    隐式 auto 行、按内容撑开，内部 `overflow:auto` 形同虚设 —— 回答一长就把输入框顶出视口，
    外层全是 `overflow:hidden` 所以「往下拉也没用」。**外壳行一律显式写 `grid-template-rows:minmax(0,1fr)`**。
12. **`input.focus()` 会把 `overflow:hidden` 的祖先滚走**（隐藏 ≠ 不能程序滚动）。
    实测右侧面板 top 跑到 -152px。用 `focus({preventScroll:true})`。
13. **`renderMessages()` 按 state 重建 DOM**：一个字都没生成时 state 里只有用户那条，
    会把刚写上去的提示（"已停止生成"/"这次没有生成内容"）一起冲掉。**没内容就别重排**。
14. **进/退场动画只给「新出现的那个」加类**：`.msg` 曾把 `animation` 写在基础类上，于是
    `renderMessages()` 每次整表重建都会让**所有**气泡重放一遍进场（实测一轮 5 次 `bubble-in`，
    每次回答收尾整屏抖一下）。现在只有 `.msg.enter` 才动，重排一律 `enter:false`。
15. **流式输出绝不能无条件 `scrollTop = scrollHeight`**：用户往上翻读旧内容时会被每个 delta
    （45ms 一次）按着头拽回底部（实测 700ms 从 0 → 957）。口径是「贴底才跟随」+
    离底 > 28px 浮出「回到最新」胶囊；收尾重排要 `keepPos`，别把人拽走。
16. **`grid-area` 显式占位会让自动布局跳过整行**：给 `.jump` 写 `grid-area:2/1` 之后，
    自动布局把 `.msgs` 挤到了第 3 行（实测高度 438px → 32px）。**同一格里的元素要一起显式写**。
17. **面板里有几块内容就写几行**：左栏声明 `auto auto minmax(0,1fr)` 却有 4 个子元素，
    第 4 个落进隐式 auto 行 → 会话列表被钉在底部、**不滚动**，中间还留 116px 空白。
18. **sprite 里的图标要先核对再用**：`ic('x')` 一直有人用，但 sprite 里没有 `i-x` ——
    停止/删除按钮长期是空白方块。加图标时跑一遍引用核对（缺哪个一目了然）。
19. **主题切换是亮度跳变**：`color-scheme` 一翻，整页颜色硬切。做法是切换瞬间给 `html` 挂
    `.theming` 的 260ms 过渡窗口、之后摘掉（常驻会把所有 hover 都拖成慢速淡入）；
    主题选择记得持久化（原来刷新就回系统偏好）。
20. **模型回答是 Markdown，前端必须渲染**：真实回答每篇有 6-8 处 `**加粗**`（提示词要求
    「短段落 + 1. 2. 3. 列点」，模型还会自己加星号小标题）。原来用 `textContent` 直接输出
    → 页面上就是满屏裸露星号，这是「看起来没设计过」的最大来源（2026-10-16 修）。
    做法：`mdHtml()` 先整体转义、再只认「整行加粗→小标题 / 1. 列点 / - 列点 / # 标题 /
    空行分段」几种结构；流式中保持纯文本、收尾重排时转排版。
    XSS 诱饵（`<img onerror>` / `<script>`）实测原样显示为文字。
22. **军师要认登录态，只能走 Bearer —— cookie 那条路是断的**：机构端登录签的 cookie 是
    `platform_token_org`、`Path=/api/org`，浏览器**不会**把它发给 `/api/junshi/*`（服务端
    `readToken` 明明兼容跨端，但请求里根本没有这个 cookie）。可用的通道是 localStorage 的会话
    （三个端共用一个前缀 `ai-kids-platform.session.v1.*`，同源可读），服务端认
    `Authorization: Bearer <token>`。`prototype.js` 里 `authToken()` 统一取 token，`call()` 与
    `streamChat` 都带上；**带 token 被 401 就退回匿名重试一次**（过期/停用/在别处登录时不能让
    整页打不开）。另外：**登录态别拿「画像填没填」猜** —— 原来就这么猜的，刚登录但画像还空的
    用户会被禁用输入框（死路），现在以服务端 `signedIn` 为准。

21. **字体要与主站一致时别自己拼字体栈**：主站字体是 `--cv-font`（`packages/shared/src/styles.css`
    里 104 条 @font-face：Geist 400/500/600 + Noto Sans SC 按 unicode-range 分 101 片），
    字体文件**自托管在 `apps/website/public/fonts/`**（线上 CSP 是 `default-src 'self'`，
    外链字体必被拦）。做法：把 @font-face 段抽成 `assets/junshi/fonts.css` 由页面 `<link>` 引用，
    并把它加进 `stamp-junshi.mjs` 的资源清单（`/assets/` 是 7 天强缓存，字体 CSS 同样要吃内容哈希）。
    实测：104 条声明加载、中文按需取十几个分片、拉丁走 Geist。
