**这一块的权威文档是它自己的 `deploy/dsh-student/README.md`**（含品牌口径、Univer 办公预览、
模型名只当意向、已装插件与坑），改之前先读它。

它自己列的**已知待改进**（照抄，别当已完成）：

1. dsh 会话票据现在是**内部 302** 补的，浏览器地址栏会闪一次；生产做法应由平台后端完成这次交换。
2. `dsh_edge` cookie 的值就是平台票据；生产应换成**按会话**的 cookie 并随会话失效。
3. **产物回传：后端已做、前端还没接** —— `/api/student/runtime/*` 目前没有前端在调；
   而且**二进制产物（PPT/Word/Excel 原文件）的收纳与广场展示口径还没定**
   （现有链路把 `files` 当文本规格、下载时现场渲染，装不下真 `.pptx`）。
   注：产物清单**不以** `deliverables/presented` 为准（它只记路径、还依赖模型记得调用），**以工作区为准**。
4. 工作区要学生**手动选一次**（dsh 界面在选好工作区前不让发消息）；平台建会话时应预选 `/home/student/workspace`。

## 八、几条最容易踩的（细节看各自文档，这里只提醒）

- 「生产跑哪一版」**只认 release 目录的 BUILD-METADATA.txt**，别拿分支 HEAD 对。
- 发布：`.tmp/deploy-002.sh <sha>`，验收 `.tmp/verify-prod-002.sh`；**发布前先 push**（漏推会让服务器 pull 到旧 HEAD）。
- 网页**不再有创作环境**，别再往网页里加 dsh 入口。
- 手动 scp 过的文件会和服务器 `git pull` 打架（要么提交后再传，要么在那台机器上 `git checkout --`）。
- DSH 容器那边的坑（只绑回环要容器内反代、`dsh plugin` 无 pnpm 会静默不装、`dsh-ppt` 同名包是别人的、
  入口标记要按容器唯一…）都在 `deploy/dsh-student/README.md` 与我 9-16 那份方案文档里，别重复踩。
