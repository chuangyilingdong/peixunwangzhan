## 八、几条最容易踩的（细节看各自文档，这里只提醒）

- 「生产跑哪一版」**只认 release 目录的 BUILD-METADATA.txt**，别拿分支 HEAD 对。
- 发布：`.tmp/deploy-002.sh <sha>`，验收 `.tmp/verify-prod-002.sh`；**发布前先 push**（漏推会让服务器 pull 到旧 HEAD）。
- 网页**不再有创作环境**，别再往网页里加 dsh 入口。
- 手动 scp 过的文件会和服务器 `git pull` 打架（要么提交后再传，要么在那台机器上 `git checkout --`）。
- DSH 容器那边的坑（只绑回环要容器内反代、`dsh plugin` 无 pnpm 会静默不装、`dsh-ppt` 同名包是别人的、
  入口标记要按容器唯一…）都在 `deploy/dsh-student/README.md` 与我 9-16 那份方案文档里，别重复踩。
