**两个 bug 是 p111 当场抓出来的**（都不是笔误，是口径错，所以记在这儿）：

1. **002-03「有效课包数」漏了 `grant.id IS NOT NULL`**。原来写
   `SUM(CASE WHEN grant.revoked_at IS NULL THEN 1 ELSE 0 END)`；左连接没匹配到时
   `grant.revoked_at` **同样是 NULL**，于是「一个课包都没有的学生」被数成 **1**，
   连带「授权情况 = 暂无课包」这个筛选**永远返回空**。加上 `grant.id IS NOT NULL` 才对。
   → 教训：在 LEFT JOIN 后的聚合里判「有没有」，要判**被连接表的列**，不能判一个两边都可能为 NULL 的列。
2. **002-06 的三分类把期初结转批次也算进了序号**。`LEGACY_OPENING_BALANCE` 的日期通常最早，
   它占掉 `seq=1`，真正的第一笔采购被挤成「增购」，于是「初次开通」永远是 0。
   改成 `PARTITION BY (assignment_id, purchase_type)` —— 序号**只在 PURCHASE 内部排**。
   → 现在「初次开通」= 该授权单的第一笔**采购**（不是"第一条批次"，那条可能是期初结转）。
