## 三、现有数据（已核对，直接用）

**能直接用**
- `GET /api/org/series-overview`（orgAdmin.js:1077-1130）每项：
  `seriesId, title, coverImageUrl, quotaTotal, quotaUsed, remaining, grantedCount, grantedStudents,
  pendingSessions, activeSessions, endedSessions, dissolvedSessions, teacherCount`；
  `totals{seriesCount, quotaTotal, quotaUsed, remaining, grantedStudents, pendingSessions, activeSessions}`。
  → 图3 的 4 张卡与「总人次/已授权/剩余」**齐了**，只缺**版本 / 开通时间 / 权益状态**。
- `GET /api/org/course-grants?seriesId=`（orgAdmin.js:1133-1148）每项：
  `id, studentId, studentName, studentLogin, seriesId, seriesTitle, grantedAt, revokedAt, revokeReason`。
- `POST /api/org/course-grants`（:1150-1193）body `{seriesId, studentIds[]}`，返回 `{granted, skipped, quotaTotal, quotaUsed}`。
- `course_assignments` 最终列：`id, series_id, org_id, status(ACTIVE|REVOKED), assigned_by, assigned_at, expires_at`
  **+ ALTER 加的 `quota_total`、`quota_used`**（schema.js:1184/1186）。→ 配额就在这两列。
- `license_purchase_batches`（schema.js:1206-1227）：`purchase_type(PURCHASE|LEGACY_OPENING_BALANCE), quantity,
  amount_minor, currency, purchase_status, status, order_no, contract_no, purchased_by, purchased_at` …
- `license_revenue_events`（:1229-1249）：`event_type(GRANT|REVERSAL), quantity(±1), actor_id, occurred_at` …
  写入方 `services/licenseLedger.js`（batch :87-111、GRANT :139-157、REVERSAL :159-192）。

**没有、必须新做**
1. **「最近库存变化」的 `53→52` 前后值：数据库里没有**（没有 `quota_before/quota_after` 列）。
   唯一的 before→after 是通用审计 `audit_logs.before_data/after_data`（schema.js:901），
   机构侧可经 `GET /api/org/audit-logs`（orgAdmin.js:307-319）读到。
   → 建议：**「最近授权」用 grants 真数据（时间/学生/±1），「最近库存变化」的增购与平台调整事件如实说明来自平台侧**，
   不要为了凑出箭头去解析审计日志（脆）。
2. **机构侧没有任何接口读 `license_purchase_batches` / `license_revenue_events`**（已确认：只有平台端在用）。
   → 图5 要**新开一个机构侧接口**读批次表，业务类型映射建议：
   `初次开通` = 该 assignment 的第一条批次；`增购` = 后续 PURCHASE；`平台调整` = `LEGACY_OPENING_BALANCE`。
   `purchased_by` → 经办；`order_no/contract_no` → 备注来源。
3. **机构侧「取消授权」不存在，而且 p55 明确断言它必须 404**（`POST /api/admin/course-grants/:id/revoke` 才是平台路径，
   courses.js:624-650）。图7/图8 要求机构能取消（并返还 1 人次）→ 需要
   **新增 `POST /api/org/course-grants/:id/revoke` 并同步改 p55 的断言**（带日期注释说明这是口径变更，不是测试漂移）。
4. **「正式学习记录 已产生/未产生」没有标志位**，但它有**现成口径**：
   完课判定用的就是「该学生这节课上有没有成功且非 mock 的 AI 调用」（`services/classroomSessions.js:164`）。
   图8 的 5 条校验也都能算：
   `从未进入正式「上课中」课堂`→session_students/session 状态；`没有有效 AI 任务`/`没有有效 CU 消耗`→usage_records；
   `没有课程进度`→`student_lesson_progress`（schema.js:515）；`没有学生作品`→works / vibecoding_submissions。
   → 建议**照课堂预检那样做成预检接口**（`GET /api/org/course-grants/:id/precheck`），
   图8 的 ✓ 必须是真跑出来的（这条纪律上一轮已经立过，见 `新对话交接-课堂按线框图改造-20260917.md` 第三节）。
