## 四、几条花了几小时挖出来的铁律（都是实测，别重走）

### 4.1 dsh 插件：往会话日志写自定义事件 = 把学生的历史写死 ⚠️⚠️

这个 harness（0.1.5-rc.1）加载会话日志时要求：事件类型**要么是它已知的，要么信封带
`ignorable: true`**，否则**拒绝解释整份日志**；而 `session.append()` **没有任何办法**设置那个标记
（只转发 `sourceEventSeqs` / `surfaceOp`，全树翻过：没有写入方在运行时设置它）。
**所以第三方插件在运行时写不出合规的自定义事件。** 我的功能开关第一版就是这么写的，
结果学生点开历史只有一行红字。修法：状态放插件自己的文件（`$DSH_HOME/lingdong-feature.json`）。
细节与修日志的两个坑见 `新对话交接-功能插件写坏会话日志-20260917.md`。

### 4.2 插件的 `inject` 与服务必须一一对应，且 `apply` 必须自己兜异常

- `inject` 里没声明的服务，读它就抛（`cannot get property … without inject`）；
- **`apply` 抛错会让整个 profile 起不来**（学生打开创作环境直接白屏）——所以宿主半边必须
  `try/catch` 兜住，最坏是「开关不生效」，不能是「进不去」。
- 这条上一轮还被人误读成「宿主插件根本挂不上」，整整带偏了一轮方向。

### 4.3 `dsh plugin add` 会重算 bundles —— 会把 `dsh-ppt` 加回去

`dsh-ppt` 只能当依赖、不能进 bundles（会与 composer 抢注册 `dsh-ppt-bundled`，整棵树起不来）。
**任何一次 `dsh plugin add` 之后都要再摘一次**，Dockerfile 里已经这么写（装 univer 那步之后）。

### 4.4 图片「引用（连线素材）」要真的发出去，得三层都对 + 形状要对

前端 payload、服务端 `options.referenceAssets`、请求模板三层缺一层就静默丢；
而且上游（`api.seedance.nz`）要的是**顶层 `images: [url…]`**，与代码里现成的
`{{referenceItems}}`（MiniMax 视频那套 content 项）**形状不同，不能互相顶替**。
现在默认图片模板接了 `{{referenceImageUrls}}`；没连参考图时该键整段消失（纯文生图形状不变）。
**真机验证过**：参考图是一张折纸飞机，产物是同款折纸风格的武将（连构图都留着）。

### 4.5 Univer 插件的代价（装之前要你点头的就是这两条）

- **内存 +~290MB/学生**（RSS 258MB → 550MB，宿主上真量的）。这台 1.6GB 的机器本来就只塞得下
  1-2 个学生环境，装完余量更紧。
- **没有 Chromium** → 「PDF 打印 / 截图 / 幻灯片校验 / SVG 文字测量」不可用；
  **预览与编辑本身是 Univer 在浏览器里渲染，不受影响**。

### 4.6 跑守卫时的 `database is locked` 不是回归

`scripts/lib/classroomFixture.mjs` 用同一个 SQLite 库；开发机上同时开着 vite + `apps/server` 时
会抢库 → 守卫随机失败。**判断口径：单独跑能过、连跑偶发失败 = 抢库**，别为了变绿去改守卫。

### 4.7 剥注释别用正则

`scripts/lib/sourceText.mjs` 的 `stripComments`（逐字符）。用正则剥注释时，源码里一行注释写了
「（/api/**）」，其中的「斜杠+星号」被当成块注释起点，**吞掉 470 行真代码**，断言因此误报。

   装了 univer 之后 pptx 不再走那个面板、症状大概率消失，**根因还在**（dsh 侧，属上游问题）。

   你自己扫一眼最稳。
5. **平台侧 `mode` 列 + 提示词分档现在没有界面在用它**（学生选功能是在 dsh 里）。保留是刻意的
   （删它要连提交/产物一起拆），等专门一轮再收。
6. **学生端原生那个「标准模式 ⌄」还在**（dsh 官方组件，不是我加的）。它与我们那排按钮是两个轴，
