## 二、这轮做完并**真机验证过**的

1. **隔离方案换成「同机独立用户」**（用户口径：成本要紧）。容器 vs 独立用户的实测结论：
   **每个学生内存开销相近**（都约 470–520MB，大头是 dsh 进程本身，不是隔离方式），
   省的是「不用再买一台机器 + 不用 docker 与镜像分发 + 公共运行时只存一份（硬链接共享）」。
   隔离三层：① 一人一个 Linux 用户、家目录 0700（同学之间互不可见）② dsh 自带 Landlock
   （工作区外**写**被内核拒；**只锁写不锁读**，所以 ① 不能省）③ systemd 限额
   （MemoryMax 768M / CPUQuota 150% / TasksMax 256）。
   脚本：`deploy/dsh-student/host-user/{provision-user-runtime,run-student-user,stop-student-user}.sh`。
2. **学生环境入口从公网打通**。实测：裸端口 403（票据闸门在位）、带票据 302（**相对地址**）、
   跟完跳转出「灵动ai」界面、复用 cookie 正常、别人的旧 cookie 403；环境里调模型走我们网关 200
   并落进生产账本（`usage_records` 有 `deepseek-flash SUCCESS`）。
3. **品牌收尾**：把 dsh 面向开发者的「内测声明」弹窗掐掉（它**会挡住学生界面**）；
   又补掉启动画面那个独立的 `HARNESS` 字标。
4. **平台侧拉起**（代码在 `apps/server/src/services/studentRuntime.js` + `routes/studentRuntime.js`，
   守卫 `scripts/p99`）：门禁与「调模型」共用同一个函数；课堂 id 由服务端按名单反查，不让学生传；
   宿主脚本走一条**窄 sudoers**（只放行那两个脚本，跑别的被拒，实测过）。**未部署。**
5. 顺手修的：用户模式漏注入 `PLATFORM_GATEWAY_BASE_URL`（模型网关地址）；生产
   `sites-enabled` 里躺着一个同名 `.bak` 配置（nginx 一直在**同时加载**它，属隐患，已挪走）。

## 三、下一步（按优先级）

2. **查「设置不落盘」这个副作用**：同机独立用户模式下，客户端的设置作用域不是持久化的

## 五、硬约束与坑（这轮新增，上轮 8 条见上一份交接）

1. **宿主 ufw 是第二道墙**：阿里云安全组放行了端口还不够，主机 ufw 默认 deny incoming
   （生产机上原本只放行 22/80/443）。**排查法**：宿主上 `tcpdump -n -i any "tcp port 18201"`
   —— **抓得到 SYN 但客户端一直超时 = 主机防火墙**（安全组丢包时抓不到）。
   三个地方必须一致：① 安全组 ② ufw ③ `run-student-user.sh` 的 `PORT_RANGE`（现 18201-18220）。
2. **dsh 硬注入 `<base href="/">`**（`dsh-host-frontend-static` 里 renderIndex 时插入），
   前端又按 `/plugins/...`、`/assets/...` 绝对路径取资源 → **必须挂在域名根或独立子域，
   不能挂 `/dsh/<名>/` 子路径**（实测：接口层通，前端资源落到官网上，界面起不来）。
3. **dsh 的 `/api` 有一道浏览器信任栅栏**：只认「绑定的网卡地址 + `--trusted-host` 给的额外值」。
   我们绑回环 → 栅栏里只有回环；学生从「域名:端口」进来时**所有 /api 都被 403**
   （界面表现为「自动重连中…」，WebSocket 升不上去）。修法：`--trusted-host 域名 --trusted-host 域名:端口`，
   并且 nginx 转发时要**带端口的 Host**（`proxy_set_header Host $http_host`）。
4. **pnpm 符号链接 + `sed -i` 是陷阱**：`node_modules/@deepseek-ai/<包>` 往往只是指向
   `.pnpm/...` 的符号链接；`sed -i` 会把**符号链接换成普通文件**，而打包器读的是 `.pnpm` 里的真身
   → 补丁「明明写了、线上还是老代码」。**必须走镜像构建期的 `writeFileSync`**（会跟随符号链接）。
5. **客户端 bundle 是服务端现场拼的**（十几 MB 的一个 `/plugins/??...` 响应）：补丁只能在**镜像**里打；
   在真机上临时改文件对已经在跑的进程无效。**验证要看浏览器实际收到的那份响应**
   （抓下来 grep 补丁串），只看文件系统会被骗。
6. **nginx 的 `include` 通配符匹配不到文件会直接报错** → 学生入口目录里必须留一个占位 `.conf`。
7. **用户模式要注入 `PLATFORM_GATEWAY_BASE_URL`**：补丁层里模型地址读的是这个名
   （容器里是入口脚本从 `GATEWAY_BASE_URL` 转写的），漏了就等于 dsh 拿不到网关地址。
8. **dsh 的 303 带绝对 `Location: /`**（与容器里那个 `absolute_redirect` 同源）→
   nginx 要 `absolute_redirect off` + `proxy_redirect` 改写，否则浏览器被带出入口。
9. **镜像里的绝对符号链接**（`@lingdong/dsh-brand → /opt/brand-plugin`）：往宿主提取运行时后
   必须在宿主上补出同一路径，否则 dsh 起不来。提取要用 **tar 流**（`docker cp` 会拒收这类链接）。
10. **设置作用域在用户模式下不持久化**（待查，见「下一步 2」）：表现为「内测声明」判定未读；
    现在用 `plugin-shims.mjs` 把 `WelcomeNotice` 组件改成永不渲染来绕开。
