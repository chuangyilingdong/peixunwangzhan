## 二、这轮做完并**验证过**的

1. **取回产物（宿主侧）**：新增 `deploy/dsh-student/host-user/collect-student-user.sh`
   （分发参数、守身份与工作区）+ `collect-student.mjs`（走查/导出/留存与全部安全判定）。
   三个子命令：`--list` / `--export <工作区相对路径>` / `--preserve`；
   **stdout 只放一行 JSON**，告警与错误走 stderr，失败退出码非 0 并带 `COLLECT_*` 错误码。
2. **收环境前先留存作品**：`stop-student-user.sh` 第一步改成 `--preserve`
   （留到 `/srv/dsh-runtime/deliverables/<时间戳>/`，含 `INDEX.json` 与每份 `MANIFEST.json`）。
   **补这一步之前，「下课」= 学生的作品直接消失** —— 没点过提交的那些就真没了。
   留存失败不拦收环境，但会吵一句。
3. **平台侧两个接口**（`/api/student/runtime/deliverables` 与 `/api/student/runtime/submit`）：
   门禁与开盒子/调模型**同一套**（课堂 ACTIVE + 学生在名单里，课堂 id 由服务端反查）；
   提交即确认版权；产物按**现有作品链路**落进 `vibecoding_submissions`（同一张表、同一套列），
   所以作品广场、平台发布/下架、机构查看这些下游**一行都不用改**。
   网页里的**本地图片**会存成学生的**私有文件资产**并把 HTML 引用改写掉 ——
   与「学生传图、模型用绝对地址引用」是同一套机制，发布时广场那条既有的改写规则会自动接上。
4. **守卫 `scripts/p100-student-runtime-deliverables.mjs`（25 项，本机全绿）**。
   它跑的是**真东西**：后一半用一个「把参数契约照抄一遍」的桩，把平台 → 脚本 → 产物逻辑 → 落库
   整条链真跑一遍。对抗性用例都在里面：`../` 越界、绝对路径、符号链接、超限、非白名单主产物。
5. 既有守卫无回归：`p18`（提交）、`p25`（作品广场）、`p99`（平台拉起，**真容器**）、`p97`（网关）全过。

## 三、**实测纠正**了三处上一轮的说法（这几条最重要）

1. **「提交仍走我们现有 `/submit` 那套规则不变」——对二进制产物不成立。**
   现有链路把 `files` 当**文本规格**存（pptx=JSON 提纲、docx=Markdown、xlsx=CSV），
   下载时用 `services/ooxml/documents.js` 现场渲染成真文件。
   而 **dsh 的 PPT 插件产出的是真二进制 `.pptx`**（`pptx-renderer` 序列化后写盘，实测代码路径），
   塞进现有快照会得到一个「存得下、下载出来是乱码」的作品。所以 `submit` 现在**明确拒绝**
   二进制主产物（错误码 `RUNTIME_DELIVERABLE_BINARY_UNSUPPORTED`），而不是悄悄收下一个坏作品。
2. **现有作品链路只认「同层的扁平文件名」**（三处拦：服务端产物名校验、公开下载口、前端预览；
   HTML 预览只内联精确同名的 `.css`/`.js`，`.svg` 转 data URL，**PNG/JPG 这类引用根本不从文件表解析**）。
   而 dsh 的作品常带子目录。所以 `--export` 会做一次**拍平 + 引用改写**（`mygame/index.html` →
   `index.html`，`assets/hero.png` → `hero.png`，并把 HTML 里的引用一起改掉），改名情况如实上报。
   `--preserve` 不拍平（留存件是底档）。
3. **「设置不落盘」这条大概率是误诊**（上一轮列为待查）。反证：学生家目录里
   `settings.yaml` **属主是学生、可写**，而且 `.dsh/storages/workspace.json` **已经被运行时写过**
   （`global.initialized: true`）——说明设置作用域是在落盘的。当初那个「内测声明」问题，
   按 `4151d62` 的结论真凶是**补丁打错了地方**（pnpm 符号链接那个坑），不是不落盘。
   建议下轮用浏览器改一次设置、再看 `settings.yaml`/`storages/` 有没有变，确认后把
   `plugin-shims.mjs` 里那个 `WelcomeNotice` 补丁撤掉。

顺带核实的两件事：`present` 工具**确实挂在默认 preset 里**
（web 组合默认 `standard`，其中有 `@deepseek-ai/dsh-tool-present`）。
还有一条**版本漂移的实证**：`Dockerfile` 钉的是 `@deepseek-ai/dsh@0.1.5-rc.1`，
宿主上顶层那个确实是 rc.1，但它的**依赖** `@deepseek-ai/dsh-base` 装成了 **0.1.5-rc.2**
（rc.1 那个包把 dsh-base 声明成 `^0.1.5-rc.2`）。也就是说**「固定版本」只钉住了顶层，
传递依赖仍在漂** —— 以后再遇到「代码和文档对不上」时，先查这个，别急着改文档。

## 四、要你拍的口径（这是新一轮的阻塞项）

**二进制产物（PPT/Word/Excel 原文件）怎么收、在作品广场怎么展示？**

背景：网页作品现在能一路走通（预览、发布、机构查看都正常）。PPT 不行，卡在**两处**：

| 卡点 | 为什么 | 可选做法 |
|---|---|---|
| 存 | 作品快照的 `files` 只能装文本 | 存成 `file_assets`（`INTERNAL_PROXY`），和网页里的图片同一套机制 —— 仓库里 `persistSecureUpload` + `prepareFileDownload` 是现成的 |
| 展示 | 广场预览是**客户端按规格文本渲染**的，二进制 pptx 没法预览 | ① 只给下载、不给预览（要动一点广场前端：现在没有「只能下载」这种卡片）② 服务端转 PDF/图片再预览 —— `services/materialPreview.js` 里那套 LibreOffice 转换是现成的 |

我的建议：**②+①组合**（服务端转 PDF 当预览、原文件供下载），因为作品广场的用途就是**给人看**，
一个点了没反应的卡片等于没发。但这条会动到广场前端与预览链路，所以请你定。

## 五、下一步（按优先级）

## 七、这轮新增的坑与事实（上一轮 10 条 + 更早 8 条见各自那份）

1. **平台调宿主脚本时，Windows 风格的反斜杠会被 bash 当转义吃掉**：`runScript` 是
   `bash <脚本>` 调的，守卫里那条桩必须把路径转成正斜杠（踩过，报的是
   `COLLECT_BAD_COMMAND: 不认识的子命令：--session`，看起来像参数错了，其实是脚本根本没跑起来）。
2. **`.sh` 与 `.mjs` 之间有两套参数形式**：平台按 `--session/--student/--list` 调 `.sh`，
   `.sh` 再翻译成 `.mjs` 的子命令形式。写测试时别忘了这一层 —— 桩掉 `.sh` 就等于桩掉了翻译逻辑。
3. **dsh 的 PPT 成品会落在工作区里**（`publishWorkspaceOutput()` 建 `<标题>/` 或 `<标题>-r2/`，
   里面是 PPTD 工程 + 成品 `.pptx`）。这条是**实测代码路径**得到的，不是文档写的 ——
   它决定了「枚举工作区」这个取产物的思路成立。
4. **会话日志默认是 zstd**（`dsh-base` 的 `cordis.patch.yml` 里只配了 `root: dshHomePath('sessions')`，
   没配 `compression`）。想要外部脚本直接读，得在补丁层加 `compression: 'none'`。
   **本轮没用上这条路**（产物以工作区为准），留作以后要对会话做分析时的选项。
5. **PDF/图片的准入名单是「提交那一刻的快照」**：`snapshotImageFileIds` 只认快照里
   `generatedImages`/`attachmentImages`/`embeddedImages` 里出现过的 fileId。
   所以回传时图片必须进快照（本轮做在入口 HTML 那一条 artifact 上），否则发布后广场取不到图。
