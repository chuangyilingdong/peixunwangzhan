## 三、不许破的口径

**第十五轮那五条全部仍然有效**（①平台侧只有"授权次数"没有"算力额度" ②额度一律不拦人、学生端看不到
③内部成本口径不上公开面、验收有反向断言 ④取消授权只有平台端有权限 ⑤上游账户余额只有平台端能看）。
这一轮又长出几条**工程口径**，同样是"踩过之后才写下来的"：

1. **官网文案优先改 CMS**（键：`HOME / INTRO / FAQ / HANDBOOK / BRAND`，后台「官网内容」页）。
   改代码里的 `CMS_FALLBACK` 时要**与 CMS 当前内容对齐**，否则接口慢/挂时会露出不一样的文案
   （本轮"强刷闪旧内容"就是这么来的）。接口回来前**不渲染文案**（`ready = !cms.loading`）。
2. **首页与登录页的按钮是一套 specular 组件**：hero 两个 CTA + 黑底首页顶栏三个入口。
   ⚠️ 只在**黑底**上用（光效是"白线在暗面上扫"，浅底等于看不见）；浅底内页用原来的实心/描边胶囊。
   它渲染的是 `<button>`，导航走 `onClick + navigate`（右键新标签打开不可用）。
3. **字号不许只按 vw 写**：vw 与文字所在盒子的宽度无关，盒一变窄就折行（本轮品牌主张折成三行）。
   要用**容器查询单位 cqw**（`.login-copy` 已设 `container-type:inline-size`）或按字数内联算
   （首页 `.hp-title` 是后者）。同理，`nowrap` 之前必须确保尺寸放得下。
4. **装饰层不许伸到盒子边缘**：环境光斑曾被网格栏（`overflow:hidden`）裁出一条硬边（用户报"有明显的
   边框痕迹"）。做法：不外扩 + 加渐隐遮罩（`mask-image`）。**验证手法**：把视频临时藏掉看整页是否纯黑零边界。
5. **`overflow:hidden` 仍可被程序化滚动**：焦点滚入视野会把整页横向滚（本轮 224px）。要禁止就用
   `overflow-x: clip`。
6. **改守卫断言前先看它在查什么**：本轮有 4 处断言因口径变更失效（`p6` 官网导航标签、`p75`/`p87`
   退役的 `estimatedCostFen`、`verify-production-entrypoints` 的登录文案与"预约演示"）。改的时候要
   注明 `口径变更，不是测试漂移`，并**顺手看它是否已变成空转**（比如查的词已不存在 = 断言失效）。

## 六、守卫与验证怎么用（这一轮更新过的部分）

- **跑守卫用的 node**：`C:/Program Files/nodejs/node`（v24）。**`pnpm` 也必须用它** —— 默认 PATH 的 node 是
  v16，pnpm 会直接报 `requires at least Node.js v22.13`。做法：
  `export PATH="/c/Users/Administrator/.vibe-coding/node:$PATH"`。
- **快**：`node scripts/p70-pages-render.mjs`（三端 **88** 页，含三端登录页；改前端必跑）。
- **全量**：`node .tmp/smoke-run.mjs`（123 个）。⚠️ 本轮给它加了一条：**失败时把子进程输出落到
  `.tmp/smoke-fail-<name>.log`** —— 以前只剩一个秒数，每次都要靠单跑复现去猜原因；这一轮靠它一次定位到
  `schema.js` 的迁移。**但 runner 本身在 .tmp（未受版本控制），建议一并移进 scripts/。**
- **p111 很慢**（约 2 分钟、28 张截图）：它是机构/教师端的真浏览器端到端，改机构端/教师端必跑；
  只改官网跑它没意义。
- **浏览器验收必须是"真浏览器 + 真站点"**：这一轮所有"只有生产才犯"的问题都是这么抓到的。
  生产 CSP 很紧（`script-src 'self'`，没有 `font-src`），外链字体/脚本一律会被拒收。

## 七、这一轮踩过的坑（都值钱，别重复）

1. **bash 里内嵌 `node -e "…"` 改文件会把 `${name}`、反引号当展开/命令替换** —— 我为此两次写坏文件
   （55 个守卫文件里写进了字面量 `${name}`；README 里代码片段被替换成空字符串）。
   **纪律：批量改文件用 Write 写出来的脚本文件（不经 bash 转义）+ 先 dry-run + 先只改一个文件验证，再铺开。**
2. **"偶发守卫红项"不是机器负载**：真根因是 `schema.js` 的启动迁移没有 `busy_timeout`；
   `busy_timeout` 还治不了「延迟事务升级死锁」，所以写事务要用 `BEGIN IMMEDIATE`。
   （我为此先误判成负载、又误扫了 127 处守卫连接，最后靠**失败日志的堆栈**才定性。）
3. **一个"残留"往往有第二个来源**：强刷闪旧内容 = `index.html` 骨架屏（静态 HTML 里的旧文案）
   + CMS 兜底文案，两头都要治。**骨架屏尤其容易漏** —— 它不在任何组件里，只有强刷才看得见。
4. **改文案/组件后要检查"断言是否还在真的断言"**：本轮 `websiteNavRejected` 查的「预约演示」
   已从代码里消失 → 断言变成永远通过（空转），换成只属于官网导航的「灵动学习」才重新有效。
5. **装饰性出血会带来真 bug**：光斑/装饰线伸到容器外 → ①被裁出硬边（视觉）②让容器可被程序化滚动（交互）。
6. **部署脚本的自检是有效的**：本轮它拒绝过一次切换，别绕过它。
