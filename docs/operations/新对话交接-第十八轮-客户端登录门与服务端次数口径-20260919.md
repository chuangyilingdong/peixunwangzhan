   列表下「没有找到答案？联系我们」—— 用户看着实际页面点名删的；页头只剩「常见问题」一行。
3. **改成按端三档** `student / teacher / org`：分段控件切换、各自一套问答、切档收起已展开的；
   **CMS 形状升级** `{title, items}` → `{student, teacher, org}`，后台「官网内容 → 常见问题」三块分别配置；
   迁移脚本加第 ⑤ 步形状升级，**生产已跑**（老 4 条保序进 student、teacher/org 用种子补 2/2）。
4. **顺手修掉一个静默回归**（`799783f`）：`/org` 机构页也读同一个 FAQ 键，形状一改它会

5. 观察（既有、非本轮造成）：线上 `/org/` 是**机构后台应用**（`/org` 301 → `/org/`），

### B. 桌面客户端（本轮主线，**卡在最后一环**）

决策：用户选**第 3 条 —— 从上游 `deepseek-ai/deepseek-harness` 的 `apps/desktop` 自己构建**。

**已打通**：
- **Windows 构建**：上游 desktop 是「Electron 壳 + 完整 dsh Web 应用」且 `private: true`（没发 npm），
  只能自建。本机实测出包：`lingdong-client-0.1.6-alpha.2-win-x64.exe`（294MB）。
  三个 Windows 坑见 §六.8/9/11。
- **登录门**（`deploy/desktop/client-patch/platform-gate.ts` + `gate/*.html`）：
  我们的登录页 → 学号密码登录 → 拉 `/api/student/runtime/client-context`
  （课堂 + 网关地址 + 运行时密钥 + 预设提示词 + 剩余次数）→ **没有正在进行的课堂就不启动创作环境**
  （只显示「等老师开始上课」）→ 有课堂才写补丁层/密钥/default model 并启动 dsh。
- **只走我们的网关**：补丁层（`lingdong.patch.yml`）把模型路由指到 `platform-gateway`、
  默认模型指向我们网关、禁用官方 `llm-deepseek`；**注入点必须用桌面宿主的 `patchFiles`**（见 §六.6）。
- **品牌化**：`rebrand-client.mjs`（productName / 安装包名 / 外壳文案 + **dsh 界面源码里的品牌串**，
  扫 4470 个文件命中 150 个）；应用图标（项目里只有横版字标，用 Chromium 现渲了 1024×1024 方块图**占位**）。
- **深链 `lingdong://`**：`electron-builder` 的 `protocols` + `setAsDefaultProtocolClient` +
  `focusPrimaryWindow()` 里触发等待页重查。

**验证到哪一步（都有证据）**：
- 真客户端里：登录页正常 → 登录成功 → 登录门写下 `~/.dsh/lingdong.patch.yml`、
  把 `settings.yaml` 的默认模型改成 `platform-gateway/deepseek-flash` → dsh 起来后
  **模型选择器显示「平台网关 · DeepSeek Flash」**。
- **路由确实通**（对照实验）：把密钥**预置在进程环境里**启动客户端 → 在界面里发一条消息 →
  平台 `usage_records` 记到 **SUCCESS**、**我们的 `session_students.vibecoding_sends` 变成 1**。

**卡住的一环（下一步第一件事）**：
**登录门事后注入的密钥到不了 dsh** —— 每发一条消息都是「本轮运行失败 · API 密钥无效」(AUTH)，
平台一条用量都没有。对照实验的结论是：**宿主（dsh）在 `main()` 早期就起来了，比登录门还早**，
所以登录之后才写 `process.env`（或写 `~/.dsh/.credentials.yaml` 的 `refs`）都来不及；
把登录门提到 `automaticCheck()` 之前也没解决，说明起宿主的地方还在更前面。
**修法**：让宿主**在过门之后再起**，或**过门后重启一次宿主**。

### C. 服务端：发送次数上限 + 预设提示词 + 客户端进门接口（已上线 `5b65599`）

- **发送次数上限**：建课时（选 VibeCoding）可设「发送按钮能按几次」。这是一套**独立机制**，
  与「算力额度只观测、不拦人」不是一回事（那套的文件头自己写着「要拦人的话那是另一个（不存在的）机制」，
  这就是那个）；落点是**教学节奏**，按次数算。
  · 计数判据 = **对话历史里 user 消息条数的单调最大值**：学生按一次发送只 +1；dsh 自己的内部请求
    （压缩历史、起标题）不计数；⚠️ 必须用单调最大值 —— 只看当次条数等于「压缩一下就能刷新额度」。
  · 对外报的 `used` 封顶到上限；配置在 `classroom_config.vibeCoding.sendLimit`（**不新增表、不迁移**）；
    计数列 `session_students.vibecoding_sends`；判定在网关**打上游之前**（超限返 429 + 中文文案）。
  · **不填 / 0 = 不限次**（没人配置时现状一字不改）。
- **预设提示词**：同一份配置里的 `presetPrompts`（`[{title,text}]`），后台建课表单可增删改。
- **客户端进门接口** `GET /api/student/runtime/client-context`：只发上下文，**不在服务器上开任何进程**；
  没在上的课返回 `classroom:null`（这就是「老师点了立即上课才能进」的服务端兜底）。
- 核验：机制检查 11/11、端到端 15/15、p97 / p108 / p112 全过。

## 六、这一轮踩过的坑（13 条，前一条比一条贵）

1. **幂等判断太松**：`apply-client-gate.mjs` 原来写「文件里有『灵动ai』就跳过」→ 新加的补丁被**整条跳过**。
   改成按每条补丁的**特征串**判断。
2. **口径删了、断言要跟着删**：上一轮给验收脚本加的 `fq-eyebrow` 标记，这一轮用户要求删掉眉题，
   发布时误报「包里缺 fq-eyebrow」。**断言被删掉的东西 = 必然误报**。
3. **改形状要 grep 所有读方**：FAQ 形状一改，`/org` 那块静默退回写死的兜底（p70 只查渲染报错、
   p115 不查条数，两份守卫都拦不住）。判据要用「改一次 CMS，页面跟着变」。
4. **"网关被调了几次"≠"学生按了几次发送"**：dsh 自己会发模型请求（压缩、起标题、工具轮），
   按调用次数算会让「按 1 次发送」吃掉好几次额度。
5. **压缩历史会刷新额度**：第一版判据只看"当次请求里的 user 消息条数" → 学生压缩一次就能继续发。
   正解是**单调最大值**。
6. **补丁层的注入点**：桌面宿主显式传 `patchFiles: []`，而 `profile-context.ts` 是
   `initialProfile?.patches ?? loadOptionalPatches(...)` —— **空数组不是 undefined**，
   所以 profile 里的 `cordis.patch.yml` **永远不会被读**（而且 app 的恢复流程还会把它重置并备份）。
   要挂 `patchFiles`（`apps/desktop-host/src/index.ts`）。
7. **上游默认带的第三方插件会让客户端启动即失败**：`dsh-dream-skin` 导入失败被判成致命
   （弹「无法使用」），必须在打包前禁掉（客户端自己有个「禁用第三方插件并重启」的恢复按钮，
   可以借它一次性关掉）。
8. **Git Bash 的 GNU tar 把 `E:\…` 当远程主机**（`Cannot connect to E: resolve failed`），
   打包在 `release:pack` 就挂。让 `tar` 指向 Windows 自带的 bsdtar（`System32/tar.exe`），
   而且 PATH 里的目录必须写成 **MSYS 形式 `/e/...`**（写成 `E:/...` 在 bash 里是无效目录）。
9. **PATH 里的 `node` 是 v16**（微信开发者工具那份），pnpm 要 ≥22.13 —— 构建前先把
   `C:\Program Files\nodejs` 放到 PATH 最前。
10. ⭐ **宿主在登录门之前就起来了**（本轮最贵）：`main()` 早期就会起宿主，所以登录后拿到的密钥
    写 `process.env` / 写凭据文件都到不了 dsh；把登录门提到 `automaticCheck()` 之前也没用。
    对照实验（本轮最硬的证据）：密钥预置在进程环境里 → 成功；事后注入 → 每轮 AUTH。
11. **Windows 上被句柄占住的空目录删不掉**（`resources` 是空目录却 `Device or resource busy`，
    `Get-Process`/WMI 都查不到持有者，等 8 分钟也不放）→ 给构建根目录加了 `LINGDONG_BUILD_ROOT`，
    换目录重来（缓存可拷过去复用）。
12. **测试动了用户级配置**：本轮为验证改过这台机器的 `~/.dsh/settings.yaml`（默认模型指到我们网关）、
    `~/.dsh/.credentials.yaml`（加了 `refs.PLATFORM_GATEWAY_KEY`）、写了 `~/.dsh/lingdong.patch.yml`、
    复制了一份 `~/.dsh/profiles/desktopdump`。**这些是你自己那套 dsh 的配置**，恢复方式：
    删 `lingdong.patch.yml` 与 `profiles/desktopdump/`，用同目录下的 `.bak-*` / `.lingdong-backup`
    覆盖回 `settings.yaml` 与 `.credentials.yaml`。
13. **守卫自己的解析器也会误报**：`p34` 的注释剥离只认行首 `/*`，漏了 JSX 的 `{/* … */}`，
    于是官网 `main.jsx` 里那句解释 `setAsDefaultProtocolClient` 的注释被当成代码扫，
    报出假的「未声明 setter」。已修（`0fd53f8`）。
