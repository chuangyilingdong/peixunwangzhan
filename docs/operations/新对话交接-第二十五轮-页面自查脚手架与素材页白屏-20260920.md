## 二、这一轮做了什么（四件）

### A. 页面自查脚手架 `scripts/page-shot.mjs`（工具，不是守卫）

**为什么要有它**：机构端 / 平台端 / 学生端登录门**之后**的页面，接口守卫与 p70 渲染守卫都看不见"长什么样"。
第二十四轮重做了两个页面（平台「素材与宣传物料」、机构端课程中心卡片）**却一次都没能自己截图看过** ——
机构端/平台端要登录，而"临时库 + 临时实例"那套只跑 API、不提供前端页面。

**它怎么做的**（一次把第二十四轮坑 67 的两个必踩点都绕开）：

```text
生产库副本（VACUUM INTO 一致性快照，只读）→ 临时实例（只跑 API，副本上重设种子账号口令）
  → vite build 出各端 dist → 自己起一个**与生产同布局的单源静态服务**
     （/admin/ → admin dist、/org/ → org dist、其余 → website dist、/api/ 反代临时实例）
  → 真浏览器：按应用把会话注进 localStorage → 逐页截图 + 收诊断
```

**为什么不用 `vite preview`**：它的 `/api` 代理读的是**运行时**的 `VITE_DEV_API_TARGET`（构建时设没用）、
只绑 `::1`、还配了 `strictPort` —— 上一轮就是在它上面栽的（页面里的请求打到空端口，截图里出现一条**假的**
「服务器内部错误」）。自己起单源服务后，相对请求、会话按路径分桶、SPA 回退都与线上同一套。

**用法**（细节在文件头注释）：

```bash
export PATH=/srv/ai-kids-platform/runtime/node/bin:$PATH
# 最常用：平台端素材页（灌 5 条物料、点开三步向导）+ 机构端课程中心
CHROME_PATH=/usr/bin/chromium-browser node scripts/page-shot.mjs \
  --prod-uploads --seed .tmp/seed-materials.sql \
  /admin/materials --click "添加物料" /org/courses
```

| 参数 | 作用 |
|---|---|
| `--as root\|org-admin\|teacher-1\|student-1` | 换身份（默认按路由推断：/admin→root、/org→org-admin、其余→student-1） |
| `--seed <文件.sql>` / `--sql '<SQL>'` | 往**副本**里灌数据再截 —— 空状态会盖住版面问题（这一轮靠它抓到了白屏） |
| `--click 按钮文案` | 先点再截（可给多次）：向导第二步、弹窗里的样子靠它；点击**前后各留一张**截图 |
| `--check 文案1,文案2` | 断言页面上有这些话 |
| `--text` | 打印整页可见文本（不用开图也能核对文案） |
| `--viewport 390x844` | 看窄屏（口径 57 那类"中文被折成竖排"只在窄列出现） |
| `--no-build` / `--fresh` / `--keep` | 复用 dist / 用种子空库 / 截完不退出留着人肉点 |
| `--out <目录>` | 产物目录（默认 `.tmp/page-shots/<tag>/`：每页 png + `report.json`） |

**硬判据**（少一个它就会变成哑守卫）：会话注进去没有、页面上有没有密码框（登录页的铁证）、
JS 异常、接口 4xx/5xx、请求根本没发出去、空白页、`--check` 的文案。
**它证明不了"好不好看"—— 截图是拿眼睛看的**（这一条写进了它的文件头，因为第一版就把它当成了自己的判据）。

### B. 平台端「素材与宣传物料」：列表非空即整页白屏（真 bug，已修已发布）

**现象**：只要 `promo_materials` 里有任意一条物料，这一页渲染期抛
`ListResultSummary is not defined`（重做页面时少写了一个 import）→ React 没有错误边界 →
**整个 App 子树卸载 = 纯白页**。而且**从此再也进不去**：列表只要非空就崩，运营连"删掉那条修回来"都做不到。

**为什么一直没人看见**（三条叠在一起，正好互相掩护）：

1. 生产库里 `promo_materials` 是空的 → 页面永远走空状态分支；
2. `vite build` 不报这个错 —— JSX 里未定义的标识符是**运行时**错误，不是语法/打包错误；
3. p70 用 `react-dom/server` 渲染、桩 api 的 `items` 是空的、而且渲染是同步的（promise 还没兑现就渲染完了）
   → **所有 `items.length ? 列表 : 空状态` 的列表页，它都只覆盖到空状态那一支**。

**怎么发现的**：上面那个脚手架第一次带着数据截图就抓到了（`--seed` 灌了几条物料）。
**修**：补一行 import。**发布**：release 20260920T135034Z。
**证据**：灌 5 条物料后截图 —— 卡片网格 / 封面 / 分类角标（海报·课程·活动·合作·通用）/「已停用」角标 /
「全部机构·资源已配置·使用 0 次」/「共 5 个物料 · 第 1 / 1 页」全部正常。

### C. 三处裸文件域（同一缺陷类再犯）+ 守卫扩面 + 新守卫

**现象**：平台端素材页三步向导第一步、平台端保留导出的上传面板、机构端「机构文件上传」
各写了一个**裸** `<input type="file">` → 页面上漏出原生「Choose File / 未选择任何文件」，还把那一行撑宽。
**这是 2026-09-16 记录过的同一个缺陷**（当时 p102 只钉了 `CourseManagement.jsx` 一个文件，所以新写的页面照犯）。

**修**（三处同一写法）：包进 `<label className="inline-file-upload">`（全局样式把这个 label 里的文件域藏起来、
由 label 当按钮），文案随状态改（选择文件 / 重新选择文件），选中的文件名在旁边用 muted 显示
（原来靠原生控件显示，藏起来就得自己给）；`input.value = ''` 保留 —— 同一份文件再选一次仍会触发 `onChange`。

**守卫两处口径修正**：

- `p102` 的「不许有裸文件域」从**单个文件**扩到**三端全部 .jsx（46 个）** —— 规则本来就是"文件域一律包 label"，
  按当初出事的那一个文件判，新页面必然照犯；
- 顺手修了 p102 一条**早就漂了**的锚点：「素材编辑器仍有上传行（守卫不是空转）」原来写 `>= 2`，
  而 `623c603`（去掉三栏表单）把上传行从 2 处减到 1 处 —— **这条一直红着，谁也没管**。

**新增 `scripts/p124-list-data-render.mjs`**（真浏览器 + 夹具数据）：临时库 init+seed → 按用例灌夹具 →
真起服务端 + `vite preview`（代理目标用运行时变量传）→ 真 Chrome 登录 → 断言"那个列表真的画出来了"：
① 列表元素计数 ≥ 1；② 该页"共 N 条"那句在；③ 没有 JS 异常、没有 4xx/5xx、没落在登录页。
用例三条：`/admin/materials`（灌 1 条物料，**就是本轮这个 bug**）、`/org/courses`（卡片网格）、
`/admin/organizations`。**带反向自检**：把那个 import 摘掉 → 它必须在**那一条**上变红（实测红了、其它两条照绿）。

## 六、这一轮踩过的坑（承接 1–71；**本文新增 72–75**）

72. ⭐⭐ **自查脚手架也会哑**：第一版把会话键名写成了桶名（`org`）而不是完整键

    这类分支要验，只有一个办法：**喂数据**（p124 的夹具 / 脚手架的 `--seed`）。
74. ⭐ **`git add -A` 会把别人正在写的文件一起提交**：本轮实测 —— 会话开始时工作区是干净的，
    半小时后 `apps/admin/src/pages/ClientUpdate.jsx` 等 4 个新文件 + 4 个改动文件出现在工作区
    （另一个会话在写"客户端更新"那条线），`git add -A` 把我的提交和一个不相干的功能搅在了一起。
    **规矩：提交前先 `git status`，用显式路径 `git add`。**
    ⚠️ 同一条还解释了另一个现象：`git pull` 报 `Please commit your changes or stash them before you merge`
    时，先看是不是**自己早先 scp 上去的文件**（本轮两次都是 —— 手动传过的文件会和 `git pull` 打架，
    第二十四轮文档也记着这条）。
75. ⭐ 生产库副本要取**一致性快照**：`VACUUM INTO`（对正在被写的库也安全，不会拷到撕裂的页），
    失败才回落成"连 `-wal`/`-shm` 一起复制"。脚本对生产库**只读**使用，所有写（重设口令、灌数据）
    都发生在 `/tmp` 的副本上；上传根默认也是临时目录，要看真实素材图再加 `--prod-uploads`。
