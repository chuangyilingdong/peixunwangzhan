## 二、这一轮做了什么

### A. 报错是怎么触发的（生产数据实锤）

一句话：**同一节课的"框体列表"，画布读实时、判定读快照。**

```text
学生画布上画出来的框体 + 右侧「课堂素材」
  ← normalizeProject() → lessonCanvasConfig(lessonId)        = 实时素材表（course_lesson_materials）
点「生成」时服务端校验 boxId
  ← studentContext → normalizeLesson(asPublished: true)      = 已发布快照 published_content
两边指向两批不同的 id → 学生「看得见新框体，点一下说不属于本课」
```

生产上到底几节课会报（只读诊断 `.tmp/diag-normalize.mjs`，**直接调用生产代码** `normalizeLesson`）：

| 课时 | 快照里有 `generationBoxes` 键？ | 实时框体 | 学生读面拿到 | 结果 |
|---|---|---|---|---|
| **1-1 AI 初识：召唤哪吒** | 有（11 个） | 11 个（**全新 id**） | 快照那 11 个旧 id | 0/11 相交 → 点哪个都报 |
| 其余 16 节（1-2、1-4…2-10） | **没有这一键** | 各有 2~13 个 | **0 个** | 判定侧拿到空数组 → 点哪个都报 |

⚠️ 这里有个**我上一轮（第二十五轮文档）没说准的地方**，记下来免得下次又踩：
`normalizeLesson` 对缺键的默认是**空数组**，不是"回退实时"——
`merged = snapshot ? { ...snapshot, generationBoxes: Array.isArray(...) ? ... : [] } : null`
所以"快照存在但缺这一键"的课，判定侧一个框体都不认。**一眼看不出**，只有让真代码跑一遍才知道。

**时间线**（1-1）：`course_lessons.updated_at` 与它全部素材/素材组的 `created_at` 都停在
**2026-09-20T08:53:23.968Z** —— 那一刻这节的素材被**整体重建**成一批新 id（服务端
`replaceLessonCanvasConfig` 本来是**保留 id** 的，注释写着"每次保存换新 id 会让学生端节点认不出来"，
前提是调用方把 id 传回来），重建之后**没有人对课包点「更新发布」**，快照还停在重建前那批 id 上。
当天 9:06–15:43 还有一串"单节课整体重建"（1-2、2-1、2-2、2-5…2-9 各一次）。

### B. 修法：读面与判定**共用同一个函数**

```text
lib.js 新增 mergedLessonCanvas(lessonRow, liveCanvas)
  · 快照里**有哪一档用哪一档**（capabilities / materialGroups / generationBoxes），缺的档回退实时；
  · normalizeLesson（判定侧）与 normalizeProject（画布侧）都改用它 —— 再也不各写一遍；
  · normalizeProject 需要课时的快照 → student.js 三处 project 查询补 `lesson.published_content AS lesson_published_content`。
```

为什么缺键必须**回退实时**而不是给空数组：那 16 节课的快照是"发布早于生成框体这个功能"时定格的，
给空数组等于**把学生手里的框体全没收**（它们现在能正常用，正是因为两边都回退到同一份）。
这与第二十四轮「教学素材可见性」那条判据是同一个形状（逐键回退）。

### C. 修完之后，每节课是什么行为（要跟用户对齐这点）

| | 学生看到 | 生成 | 你要怎么才能换新 |
|---|---|---|---|
| **1-1**（快照里有框体这一键） | 快照里那批**旧的** 11 个（标题「任务一：」那套） | 正常（两边同源） | 点一次「更新发布」 |
| **其余 16 节**（快照里没有这一键） | 仍然是实时那批（= 你重建后的新框体） | 正常 | 也是「更新发布」——**发布之后快照里就有这一键了，从那一刻起才真正隔离** |

也就是说："没发布不生效"这条口径**对"发布过带框体版本"的课立刻成立**（1-1），
对那 16 节要等你发布一次（它们此前从没带着框体发布过）——**这是数据事实，不是代码没改到位**。

### D. 守卫：p54 补了一整段 ④（含反向自检）

```
④ 框体 / 课堂素材也要隔离，而且画布与「点生成」的判定必须是同一份
  ✓ 发布后：学生端课时读面拿到框体 A
  ✓ 发布后：学生画布（项目 payload）也是框体 A
  ✓ 重建但没发布：学生端课时读面仍是框体 A（未发布不可见）
  ✓ 重建但没发布：学生画布（项目 payload）仍是框体 A —— 与判定同一份
  ✓ 重建但没发布：拿**画布上那个框体**去生成，不会报「生成框体不存在或已不属于本课」
  ✓ 更新发布后：学生端课时读面换成框体 B / 学生画布也一起换成框体 B（全部同步）
```

⚠️ **为什么钉在 p54 而不是 p28**：p28（生成框体守卫）一直全绿，是因为它那节课**从来没发布过** ——
没有快照时两边都回退实时，天然同源。**这个 bug 只在"发布过"的课上出现**，只能钉在会发布的那条守卫里。

### I. 单文件上传上限 25MB → 200MB（用户要传 100MB+ 的课件 PPT）

用户问「创建课包上传素材最大多少，我有 100 多 MB 的 PPT 能传吗」→ 当时是 **25MB**（`FILE_UPLOAD_MAX_BYTES=26214400`），
传不了。按三层一起改：

| 层 | 改前 | 改后 | 说明 |
|---|---|---|---|
| **应用** `FILE_UPLOAD_MAX_BYTES` | 25 MiB | **200 MiB** | 代码里还有一层硬顶，同步 100MB → **200MB**（`MAX_UPLOAD_CEILING_BYTES`；env 只能往下调） |
| **nginx** `client_max_body_size` | 30m | **300m** | 必须 > 应用上限，否则轮不到我们说中文、只给一句裸 413（sites-enabled 与 sites-available **两份都改了**） |
| **Cloudflare** | — | 不参与 | 域名现在是 **DNS-only**（公网解析直给源站 IP、nginx 没配 real_ip、日志无 cf-ray）→ 它那层 100MB 上限今天不适用 |

**真正的约束不是读 body，而是病毒扫描**（这次量出来的，也是新加两道保护的原因）：

```text
clamscan 每次调用都要把病毒库读进内存：扫 150MB 文件 峰值 RSS ≈990MB / 9.4s
⇒ 一次 200MB 上传的峰值 ≈ app 400MB + 扫描 1GB ≈ 1.4GB，而机器只有 1.6GB（可用 ~1.1GB）
```

所以同期补了两条**守卫机器**的机制（不是可选项，是 200MB 的前提）：

1. **读 body 之前的内存闸**（`services/uploadBodyGate.js`）：默认「同时 2 份 / 合计 256MB」——
   一份 200MB 天然互斥；超了当场 429 `UPLOAD_BUSY`（中文），**不走到分配内存那一步**；
   名额在请求结束（finish/close）归还，release 幂等。
2. **扫描器包一层内存上限**：`/usr/local/bin/clamscan-limited`（`ulimit -v 1.3GB` + exec clamscan）；
   内存真不够时让**这次扫描失败**（应用回「文件安全扫描失败，上传已拒绝」），而不是让内核 OOM 去挑受害者
   —— 这台机器上 OOM 挑走过学生的创作环境。`FILE_UPLOAD_SCANNER` 指向它。
   另把扫描超时 120s → **240s**（150MB 实测 53s，机器忙时要留余量）。

**实测（新配置下，端到端）**：

```text
① 穿过 nginx 发 120MB 请求体      → 返回**应用自己的 400**（不是 nginx 413）✓ nginx 那道已抬上去
② 生产 env 值起临时实例、真传 150MB → HTTP 200 / 60s，落盘字节 157286404 与源文件一致 ✓
③ 并发两份 150MB                   → 第一份 200 ✓，第二份 429 UPLOAD_BUSY（不是 OOM）✓
   过程中可用内存最低 ~90–125MB（峰值几乎全是 clamscan 的 ~990MB）
```

**守卫**：`p10-file-upload-security` 补三组（硬顶 200MB 且 env 越不过去、超限文案用配置值、
内存闸「2 份/256MB」的四条边界 + release 幂等 + 归零）。

⚠️ **两条遗留（都记进 §五）**：
1. **机器内存薄**：一次 200MB 上传的峰值把可用内存压到 ~90MB。要么**扩容**（这台机器上面还挂着
   「学生环境被 OOM 杀掉」那段事故），要么把上限往回收 —— 现在能跑，但没有余量。
2. **ClamAV 病毒库 16 天没更新**（`/var/lib/clamav/main.cvd` 是 9-05 的，扫描时 ClamAV 自己会警告
   「database is older than 7 days」），而且**没有 freshclam 定时任务** —— 等于拿两周前的库在扫。

### L. 事故：发布重启打断了在途生成（用户报「上游已经扣钱了，但是这边不返回了」）

```text
07:00:38Z  学生点了「生成短片」→ 任务入队、worker 认领、上游受理（会计费）

```

**为什么兜底没接住**：`initializeAsyncGenerationQueue` 当时只回收**租约过期（>5.5 分钟）**的 RUNNING，
而重启那一刻这条任务才 **94 秒** → 被跳过 → 之后再也没有任何东西看它。

**改法（按 worker 判，不按时间猜）**：`worker_id` 里带进程号（`ai-worker-<pid>-<rand>`），
所以**本进程刚起来时，任何 RUNNING 都属于已经没了的那个 worker**：
· 启动时 `interruptOrphanedJobs()` 一律收成 FAILED（码 `GENERATION_INTERRUPTED`，文案给学生看：
  「生成过程中服务重启了，这次的结果没拿到（上游可能已受理）；请重新点一次生成」）
  → 框体随之解封（FAILED 不算占用 ✓ 学生可以重试）；
· **关服钩子**（SIGTERM/SIGINT）也收一次自己的在途任务 → 重启后立刻是"可重试"状态，不必等下次启动；
· 旧的租约判据保留，作为**崩溃**（没走关服钩子）的兜底。

**本次事故的收尾**：那条任务用同一个码/文案标成 FAILED，框体的在途数归零 ✓（学生已可重新生成）。
⚠️ **账上注意**：`usage_records` 里**没有**这笔成本（我们的账本没记到），而上游可能已经计费 ——
这类"上游扣了、我们没记"的差额只能靠官方账单对账找回来（见 `docs/operations/真实三账对照-20260914.md`）。

**守卫** p4-o12 加一条**带反向自检**的用例：造一条"别的 worker 认领、才开始 10 秒"的 RUNNING
（旧判据不会管它）→ 服务启动后必须 FAILED/`GENERATION_INTERRUPTED`、且该框体在途数归零。
摘掉回收调用时这条会红（实测：孤儿仍 RUNNING、在途=1 —— 正是用户看到的现象）。

（驱动保留原声取名为：对口型）」）：

```
· 对口型（默认）  = 第一条音频当 `drive_audio` 发：画面跟着它动，上游缺省 lock_source
                    会把这段音频**原样留在产物音轨**里（实测音轨 vs 源音频 0.997）；
· 声音参考        = 所有音频当 `reference_audio` 发：只借音色、不驱动画面，音轨由上游重新生成
                    （没有驱动音频时上游缺省 native）。
```

链路**一处定义、四处同源**（与「生成方式」那套完全同形，少一环就是"看着配了、其实没生效"）：
后台下拉（只在"能连音频"的框体上出现）→ 保存进快照（`helpers.js` 白名单）→ 服务端归一化
（`normalizeAudioRole`：留空/不认识 → 对口型，**旧课包行为不变**）→ 模板上下文 `audioRole`
→ `{{referenceItems}}` 按它定 role；画布那行读面照它写用法说明。
⚠️ 两处细节：`audio_control.mode=native` 那条当场拒绝**只在真发驱动音频时**生效（锁成声音参考时
不发驱动，native 没东西可中和，不该把课拦死——反向自检钉着）；上游的 `remix_source` /
`reference_only` **按口径不做**（守卫里也钉着"别偷偷加回来"）。
核验（本轮做了两层）：
· **免费**：本地 mock 复演 worker，两档发出的 role 都对（对口型 → `drive_audio`；声音参考 → `reference_audio`，
  芯片也已经是 `用<Audio 1> 的前5秒给@Image 1 …`）；
· **真跑**（走完整队列 + worker，跑的是已发布产物 `20260922T072946Z`）：两档各一次，判据是
  **产物音轨 vs 源音频的互相关** —— 对口型 **0.997（原声被保留）**、声音参考 **0.057（音轨重新生成、
  音频不驱动）**，与两档的语义完全对上。

**② ⭐ 音频引用芯片改成尖括号 `<Audio N>`；图片/视频维持 `@Image/@Video`（A/B 没验出差别）**：

H3 专节「驱动音频与声音参考」的示例原文是 `口型跟随 <Audio 1>，说：<d>[中文] 今天的天气真好。</d>`
—— **尖括号、而且没有 `@`**；而 `@Image 1 / @Video 1` 那套出自"多模态参考"那节。所以音频这条
把学生写的 `@` 一并吃掉、换成 `<Audio N>`（否则会输出 `@<Audio 1>` 这种四不像），并加 `(?![0-9])`
（`音频 10` 不会被当成 1 号）。
**图片/视频的写法 A/B（新脚本 `live-reference-pointer-check.mjs`，¥0.75×2）**：
同一条提示词、同两张参考图（一张亮 ≈119、一张暗 ≈39），只换 `@Image N` / `<Image N>`，判据取
"产物前/后两段的亮度更像哪张源图"。**结果：两臂产物几乎一致** —— 都是"先石头小怪兽、后科技桌面"，
且**末尾那一帧几乎逐像素复现了那张源图**；也就是说：
· **判不出两种写法的差别**（所以**不动**图片/视频的写法，维持 `@Image/@Video`）；
· 指代顺序**没跟着我们写的"先 1 后 2"走** —— 更像模型自己的偏好（角色在前、场景在后）压过了顺序。
⚠️ **顺带修正一条之前的说法**：M/N 那轮我写过"参考图不一定照做"——这次得收窄：**参考图其实很硬**
（尾段帧几乎就是源图）。那次没照做，多半是提示词里"跳舞"的语义压过了参考图。
"序号到底等不等于数组位置"留成下一件（判据别落在模型偏好上，见坑 104）。

**③ ⭐⭐ 提交"不确定"时不再盲目判失败：接住 `X-Task-Id`**（上游文档原文：网关尝试提交但收到超时
（含 408）或 5xx 时，**错误响应可带 `X-Task-Id` 和 `Retry-After: 5`**，"保存该响应头的公共任务 ID 并查询"，
且"未收到公共任务 ID 时，不要推断提交失败或盲目重提"——重发就是**双扣**）。
现在：5xx/408 + 有 `X-Task-Id` ⇒ 当成"**已受理、待查询**"，接着轮询（首次查询按 `Retry-After` 等，
封顶 30 秒），并把任务号交给 `onSubmitted`（落进 `compute_attempts.task_id`，以后能人工找回，见 §五 遗留 16）。
守卫 p6-a01 正反两条（504+X-Task-Id → 查回产物且**只提交一次**；旧代码上跑出"直接判失败"）。
⚠️ 另一条同类事实（文档确认）：**"创建请求超时"不代表任务没创建** —— 我们自己超时（没拿到响应）时
既没有号也不许重发，这一条我们保持"判失败可重试"（学生再点一次会真重发，成本由上游退款兜住）。

## 三、不许破的口径（承接 1–60；**本文新增 61–87**）

61. ⭐⭐ **同一份东西的"读面"与"判定"必须同源**：学生画布画的框体、与点生成时服务端校验 boxId 用的
    列表，**必须是同一个函数的输出**（`mergedLessonCanvas`）。这一条与口径 34/54 是同一族
    （「界面看得到、点开说无权」/「预检与真正那一步不同口径」）——**写两处迟早会漂**，这次漂的代价是
    17 节课的框体点不动。
62. ⭐ **"缺键给空数组"与"缺键回退实时"是两个语义，选错就是静默事故**：快照缺某键时，
    **给空数组 = 把用户手里的东西全没收**（那 16 节课的框体），**回退实时 = 老数据行为不变**。
    老数据（发布早于该功能）要的是后者；「已定格的课包不允许回退」只适用于**可见性判据**
    （第二十三轮），**展示/可用性**一律逐键回退。
63. ⭐ **"要人知道的状态"必须放在**看得见的那一层**上**（用户 2026-09-21：「有修改未发布的应该在
    版本发布这里有明显的提示，而不是点进去才看得到」）。判据与它所指的那处**共用同一个值**
    （`hasUnpublishedChanges`），别各算一遍；角标要能在**选中态**下也看得清（紫底上换半透明白）。
64. ⭐ **画布左侧「生成框体」一眼可辨：四周一圈金色**（border + box-shadow 各一圈，四边完整；
    悬停换色不吃掉它）。**只区分"是不是生成框体"**，模态色（生图/生视频/生音乐）照旧
    —— 那是 2026-09-17 的口径，两条都要在。
66. ⭐⭐ **"能不能进"这类结论必须在服务端定，并按对象类型限死**：客户端运行时（dsh / VibeCoding）
    **只认"这节课声明了 VibeCoding"**（课时类型**可多选**）—— 画布课不下发 `classroom`、
    不下发网关密钥、也不许交作品；**两种同时开时客户端这一侧也放行**。
    ⚠️ **别拿 `class_sessions.delivery_mode` 判**：那只是"跟着课时带的第一个"（老师不再选课堂模式，
    只作历史兼容），用它判会把双开课时误挡（网页两个入口都亮、客户端却回"当前是画布课堂"）。
    客户端拿不到的字段（如 `deliveryMode`）绝不能成为它的判断依据；它只执行平台下发的结论。
    多课堂时**先按类型过滤候选**，点名了不对类型的那节要**明说**（`CLASSROOM_MODE_MISMATCH`），
    绝不静默换成另一节。
65. ⭐⭐ **静态清单是客户端的唯一真相源，两个写方各写一半、谁都不许覆盖对方那半**：
    后台只写**策略**（enabled/mandatory/minVersion/note/channel），发布脚本只写**身份**
    （version/files.name/size/sha256/publishedAt）。当前实现靠"策略另存 + 启动复写"兜住发布脚本的
    整体覆盖；**写这份清单必须原子**（同目录 temp → fsync → rename），因为客户端随时在读它。

67. ⭐⭐ **上传上限有三层，且真正的约束常常不是"读 body"**：应用（`FILE_UPLOAD_MAX_BYTES`，硬顶 200MB）
    **必须小于** nginx 的 `client_max_body_size`（300m）—— 这样"文件太大"这句中文才轮得到我们说；
    Cloudflare 代理时它还有一层 100MB（今天域名是 DNS-only，不参与）。
    ⚠️ 而这个规模下最吃内存的是**病毒扫描**（clamscan 每次加载病毒库 ≈1GB）：
    抬上限必须同时看机器 RAM，并保证有「**读 body 之前**的内存闸」（`uploadBodyGate.js`）——
    否则两份大请求叠起来就是 OOM，而被 OOM 挑走的不止这个进程。
68. ⭐⭐ **"连过来的素材怎么用"是语义问题，不是传输问题**：视频框体上连一张图，
    学生说「图片动起来」= **首帧**（i2v）；只有多素材/视频/音频混合才叫**参考**（启发素材）。
    模型"支持全能参考"不等于"该走参考"——**能当帧就当帧**（`videoInputPlan`）。
    同类提醒：模态值是 `FIRST_LAST_FRAME`（不是 `LAST_FRAME`），客户端与服务端必须用同一串。
69. ⭐ **同一个上游的不同代模型，请求体形状可能不一样 —— 内置模板要按模型名给**：
    2.5 系图片模型把 `output_format`/`resolution` 放**顶层**，2.0 收的是 `metadata` 里那套
    （2026-09-21 用户报「2.5 报错、2.0 正常」）。`requestTemplateFor` 的优先级固定为
    **渠道/模型上配过的 > 内置按模型 > 内置按模态** —— 管理员配过的永远赢，内置只兜底。
70. ⭐⭐ **在途任务必须在"进程边界"上收尾**：启动时收**孤儿**（`worker_id` 不是本进程的一律收掉）、
    关服时收**自己的**。只按"租约过期"回收会漏掉**年轻孤儿** —— 而年轻孤儿的表现最坏：
    上游的钱花了、结果拿不到、**入口还锁着**（框体被判"已经生成过了"，学生点不动）。
    收尾要给**学生看得懂**的码与文案（`GENERATION_INTERRUPTED`「服务重启了…请重新点一次生成」），
    别写"请核查后人工处理"那种给自己看的话。
71. ⭐⭐ **交给我们自己域名之外的素材，别当"传过去了"—— 上游可能压根读不到，而且它不报错**（§二.M）：
    上游在境外，抓 `iicili.cyou` 要么连不上（nginx 日志里一条都没有）、要么读一半断
    （实测 105703/538855 字节），**读不到就当文生跑** → 出一段与参考毫无关系的作品，
    任务状态/列表字段全部正常。修法：要交给上游的素材（首帧/尾帧/参考）先
    `POST {上游}/v1/files/upload` 换成**上游自己的 URL** 再发（上游文档推荐流程，免费，URL 活 24h）。
    ⚠️ 上传要带**文件名后缀**（上游按后缀认类型），且失败**必须报错**（静默等于生成垃圾）。
    诊断入口：`nginx access.log` 里 `GET /api/public/file-assets/<id>/download` 有没有**境外 IP**
    的请求、字节数够不够。
72. ⭐ **同一个上游的"同名系列"可能能力完全不同：内置模板要按**具体模型名**给，别用前缀一把盖**（§二.M）：
    `zhenzhen-image-g-v2.5-flare/sunburst` 收 output_format/quality/background，
    `zhenzhen-image-g-v2.5-lowprice`（线上在用）文档原话"不提供质量档位、输出格式、透明背景或流式选项"
    → 传了就是 400。上一版就是被 `/^zhenzhen-image-g-v2\.5-/` 这个前缀正则一起盖了才没修好。
    上游的全量文档（`/docs/llms.txt`）里**逐模型**列了支持的字段 —— **先读文档，再改代码**。
73. ⭐⭐ **同一份素材在"入队"和"真正执行"两个时刻各解析一次，两次必须得到同一个结果**（§二.N）：
    入队把站内地址写成**绝对地址**存进 job 记录，worker 执行时再拿它解析一遍 ——
    解析函数只认"站内相对地址"的那一版，第二次就得到了空串 → 首帧/参考**被悄悄丢掉** →
    上游收到"没有输入"的请求 → 出一段与参考无关的作品，任务还成功。
    规矩：**素材解析要幂等**（入队的结果喂回去必须还原成它自己），worker 里再加一道
    `assertMediaResolved`（入队有的、执行时不许没有；没有就当场失败并告诉学生怎么办）。
74. ⭐ **不可能成的操作不要给入口**（按钮该藏就藏，§二.O）：
    已经生成过的框体（平台规则：每个框体只能成功生成一次）、不是课时框体的节点 —— 点了必然被服务端拒
    （`GENERATION_BOX_USED` / `GENERATION_BOX_REQUIRED`），留着按钮就是误导（用户原话：「不然会误导别人」）。
    客户端判据必须与服务端**同源**：本课该模态配了框体 → 只有框体节点能生成；
    判据只写一处（按钮显不显示、要不要忽略那条陈旧报错，都读同一个值）。
75. ⭐ **框体不能被"复制"**（§二.O）：框体是课时配置的、每个只能生成一次，复制出来的节点**共用同一个 boxId**
    → 生成必被拒、还让"框体是否已在画布上"的判断错乱。所以学生画布（`allowNodeCreation=false`）
    整段不给复制/粘贴；**撤销/重做不受影响**（闸门位置在它们之后）。
76. ⭐ **「自动」是一个语义，不是"列表里的第一个值"**（§二.O）：视频这条的「自动」按上游语义翻译 ——
    关键帧请求发 `adaptive`（**读首帧图比例**），纯文生/参考请求发固定比例（上游对参考请求显式传
    adaptive/auto 会报错）。折成第一个比例的表现是"4:3 的图被硬拉成 16:9"，也就是用户说的「扁的画面」。
    只在**模板形状对得上**时才翻，别家上游不替它做决定。
77. ⭐⭐ **"怎么用连过来的素材"必须由课包显式定，不能靠连线条数推**（§二.P）：
    文生视频 / 图生视频 / 首尾帧 / 全能参考是**四个不一样的概念** —— 连 2 张图也可能要全能参考，
    不是首尾帧。字段是框体的 `inputMode`（单数，"这节课就要哪种"），与模型声明的 `inputModes`
    （复数，"这个模型能不能"）分工不同；**锁定的方式赢过一切推断**，而且要同时落到三处：
    画布（能不能连线、能连几张）、服务端（素材算什么角色）、请求体（role 让上游知道）。
    改这个字段时把 §二.P 里那七处落点一起看一遍。
79. ⭐⭐ **加"能力字段"时要想清楚"给某个模型配过能力的渠道会不会把它吃掉"**（§二.P ⑤）：
    图片模型的 `inputModes` 原来在 `normalizeModelCapabilities` 里写死成 `[]`，而生产的图片渠道
    **给两个模型都配过能力** → 恒为空 → 框体的「生成方式」存不下来（用户报的就是它）。
    凡是"没配就用默认"的字段，都要问一句：**配过能力的模型会拿到什么**（写死的空数组最坑）。
78. ⭐⭐ **关键帧 + 固定比例：先把画面裁成那个比例再发**（§二.P）：上游会**执行**关键帧请求里的固定比例，
    给它一张比例不符的首帧，它就把图**硬拉**扁（我们固定 16:9 + 1:1 的图 → 人物变椭圆）。
    "生图看着正常"不能当反例：图片模型是**重画**一张目标比例，视频模型是**变形**输入。
    裁不动（没有 ffmpeg 等）就回退成原图；比例本来就一致就不重编码。
80. ⭐⭐ **"平台自己的文件"不等于"能交给上游的文件"，而"能交给上游"也不等于"读得到"**（§二.P ⑦）：
    学生自己上传的素材是 PRIVATE —— 解析那层（只认公开素材）会把它丢掉，镜像那层（HTTP 取
    /api/public/...）又会 403。两道都得单独过：**解析按"是不是他本人的"放行，读取按 storage_key 走磁盘**。
    校验新路径时把这两层分开验，别只验一层就宣布通了。
81. ⭐⭐ **"素材送到了"不等于"上游会用它" —— 上游对素材是有「角色」的**（§二.Q ②）：
    同一条音轨，`reference_audio`（声音参考）与 `drive_audio`（目标音频驱动）在产物上是两回事；
    我们一律按"声音参考"发，学生看到的就是"音频完全没起作用"。**判据只能量产物**
    （音轨 vs 源音频的互相关：0.018 → 0.997）—— 任务成功、日志干净、请求体形状也对。
    同类：模板里钉 `audio_control.mode=native` 会把驱动音频**静默中和**，这种组合必须**当场拒绝**。
82. ⭐⭐ **上游说"提交结果不确定"时给的那个任务号，必须接住**（§二.R ③）：网关超时/5xx 的错误响应里
    可能带 `X-Task-Id` + `Retry-After`，文档明确"**保存它并查询**"、且"没拿到号时不要推断失败、
    更不要盲目重提"（重发=双扣）。判据是**提交次数**：一次提交、接着查，不是再发一次。
    同类：**"创建请求超时"≠"任务没创建"**，别把本地超时当成可以安全重发的信号。
87. ⭐⭐ **"红/绿"要由"这一步是不是失败"决定，不能猜消息里的字**（§二.T ①）：
    提示的语气原来靠 `message.includes('失败')` 猜 —— 错误文案里没那几个词就显示成**绿色**
    （「登录名已被占用」这种）。规矩：**错误消息统一由 `errorText()` 打标记**，`Notice` / toast 见标记就红；
    调用方的 tone 只表达"非错误消息是什么语气"（一般是 success）。新写一处提示照这个来，别再猜词。
84. ⭐⭐ **"一个东西只能有一个"这类幂等，必须把"已提交"也算进去**（§二.S ①）：
    "进入课堂"= **幂等取得本场课堂的创作**（同一学生 + 同一课时 + 同一场课堂只该有一个项目）。
    只判 `status='DRAFT'` 的旧写法有个恶性后果：学生一提交，服务端就"找不到项目" → 客户端写回
    「进入课堂」→ 点下去**新开一个空画布**（用户原话：「这个肯定是bug」）。
    **提交不是终点**：已提交的项目要能被重新打开（画布只读），不是丢掉。
85. ⭐⭐ **画布不是作品读面**（§二.S ②）：作品页（广场 / 我的作品 / 老师预览）要展示**做出来的媒体**
    （图/视频/音频），画布只是**过程**（放到第二个标签里）。同一条还有：改"作品读面"时**三条链路都要动**
    —— 学生自己的、机构看学生的、**广场公开的**（后者在 `routes/communication/public.js`，别漏，坑 106）。
86. ⭐⭐ **课堂结束要能"推"到学生的界面上**（§二.S ④）：老师一点结束课堂，学生端就该退出画布、回课程中心 ——
    靠学生"下一次点操作才发现"不算。做法是画布每 10 秒问一个**极小**接口（`session-state`），
    不是 ACTIVE 就走人；**轮询失败不当回事**（网络抖一下就退出课堂比不退出更糟），
    没绑定课堂的老项目按"还在上课"处理。

83. ⭐⭐ **"上游对素材有角色"这件事要一路同源，而且角色该由课包定**（§二.R ①）：
    音频的 `drive_audio`（对口型：驱动画面 + 缺省保留原声）与 `reference_audio`（声音参考：只借音色）
    是**两种不同的东西**，写进请求的位置只有 `role` 一个字段 —— 所以"课包怎么配"必须一路传到
    `{{referenceItems}}`：后台 → 快照 → 判定 → 模板。**少任一环 = 看着配了、其实没生效**
    （我会栽两次：一次只改了实时配置、一次只改了 `materialGroups`；判定读的是 `generationBoxes`）。
    对外只暴露**老师看得懂的两种**（对口型 / 声音参考），其余扩展（重配乐/只作参考）按口径不做。


## 四、这一轮踩过的坑（承接 1–75；**本文新增 76–108**）

76. ⭐⭐ **诊断要直接调用生产代码，别拿自己的 JSON 判断去推**：我第一版诊断脚本用
    `JSON.parse` 自己判"快照缺这一键时读面是不是回退实时"，推断成"回退实时 → 那 15 节没事"，
    于是只报了 1 节课；后来改成**在副本上真的 import `lib.js` 调 `normalizeLesson`**，
    才看清是**17 节全中**（缺键给的是空数组）。**差一点就按错的范围去修**。
77. ⭐ **发布按 HEAD 走，会把别人"还没打算部署"的提交一起带上线**：这次就带上了另一个会话的
    客户端更新后台配置（他文档里写着"尚未部署"）。发布前扫一眼
    `git log --oneline origin/<branch> -3`，看清 HEAD 里都有谁的东西；影响评估与处置见 §二.F。
78. ⭐ **平台差异会伪装成"测试通过"**：原子写的并发证据在 **Windows 上根本跑不了**
    （rename 覆盖一个正被别的进程打开的文件会 EPERM），只能跳过 —— 而生产是 Linux。
    同一条还有反例：同一份 `setInterval` 读取在同步写循环里**一次都不会跑到**（事件循环被占死），
    于是"没读到半截 JSON"其实是**空转通过**。**写这种并发证据时一定要断言"读的人真的读到了"**
    （本轮两处都是这么发现的）。

79. ⭐ **给一条路上了闸之后，守卫的夹具也要跟着改**：p118/p119 的夹具原来只把**课时**改成
    VIBECODING，**没改课堂**（课堂是夹具按当时还是画布课的课时建的）—— 门禁一上，它们就被自己的
    门禁挡住（红在"client-context 没给出课堂"）。**先认出这是夹具不真实，别去松门禁**：
    真实的开课流程里课堂类型是跟着课时走的（`orgAdmin` 建课堂时按课时的 `deliveryMode` 取）。

80. ⭐ **nginx 的 `include sites-enabled/*` 是通配的 —— 备份文件不能放在那个目录里**：我给
    `sites-enabled/iicili.cyou` 做备份时顺手 `cp` 成 `iicili.cyou.bak-…`，于是它**也成了一块启用的
    server 块**（`nginx -t` 立刻报 `conflicting server name`）。这次靠"真文件按字典序排在前面"没出事，
    但下次顺序一变就是"改了配置不生效"。**备份一律放 `/etc/nginx/backups/`**（历次都放那儿）。
81. ⭐ **用 curl 量"到底谁挡的"要看穿透结果，别看 `%{http_code}` 一个数**：`--data-binary @-`
    会先把 stdin 整个读进内存再发（120MB × 1 次 = curl RSS 139MB、耗时 2 分钟），
    而 `%{http_code}` 遇上 `Expect: 100-continue` 会报 **100**（我第一版就把它当成了"返回 100"）；
    真正可信的是 **nginx access.log 里的那一行**（400 = 应用回话 / 413 = nginx 挡住），
    顺便还能看出是谁挡的。
82. ⭐⭐ **别把"看起来最像的那个假设"当根因**：这次用户报「视频跟参考完全不一样」，
    我第一反应是"参考没发出去"，也真的找到了一个成立的机制（默认视频模板里没有 `{{referenceItems}}`）
    —— 正准备按它修时，把**生产策略 dump 全**（第一次的输出被 `head` 截断了 12 行）才发现：
    那个渠道配了**模型级模板**、里面 `{{referenceItems}}` 好好地在，图确实发出去了 ✗。
    真因是语义（当参考发而不是当首帧发）。**教训：先把配置/数据 dump 全、看到全貌再下结论**；
    截断的输出会替你造一个通顺但错误的因果。
83. ⭐ **上游的报错原文就是线索，别急着猜**：`output_format is not supported by this model` 一句话
    就把字段名点出来了（我们把它塞在 `metadata` 里，2.5 只认顶层）。同一条也提醒：
    **别把参数一股脑塞进 `metadata`** —— 那看着"稳妥"，其实每换一代模型都可能踩雷。
84. ⭐ **窄屏下 flex 行里的按钮会被压到只剩一列字宽，中文按字折行 = "按钮变形"**：
    按钮要 `white-space: nowrap` + `flex: 0 0 auto`（同行的说明文字让它自己去换行）。
    （口径 57 那条"窄列要 nowrap"是同一个毛病的另一处；这次是按钮，不是表格列。）
85. ⭐⭐ **`set -o pipefail` 会让 `sed … | head -1` 静默中止整个脚本**：head 读完就关管道，
    sed 收到 SIGPIPE 退出非零 → 管道非零 → `set -e` 把脚本带走。表现是
    **"把该做的事都列出来了、然后什么都没做"**（本轮 `prune-releases.sh` 就是这个：
    列出了要删的 release、一条都没删）。给这种管道加 `|| true`，或者别用 head 截。
    **凡是"打印了计划却没执行"的脚本，先怀疑这一条。**
86. ⭐⭐ **在这台机器上「发布 = 重启服务 = 打断所有在途生成」**：本轮就真打断了用户的一条视频
    （上游已受理、会计费，结果拿不回来）。**发布前先看一眼在途任务**：
    `SELECT id,modality,status FROM generation_jobs WHERE status IN ('QUEUED','RUNNING')` ——
    有就等它跑完（视频 ~2 分钟）再发。兜底（口径 70）会让"被打断"变成"可重试"，
    但**钱已经花了**，而且 `usage_records` 里不会留下这笔成本（我们的账明明少了钱却看不出来，
    只能靠官方账单对账找回来）。
87. ⭐⭐ **"上游报错"要先分清是「这个模型没有这个能力」还是「值/位置不对」**（§二.M）：
    `output_format is not supported by this model` 被理解成"位置放错了"，于是把字段从
    `metadata` 挪到顶层 —— 线上**照样报同一个错**。那句话的意思其实是"这模型压根没有这个字段"。
    **先读上游文档里逐模型的能力表**（`/docs/llms.txt` 是全量 Markdown），再动代码；
    同一个系列里不同款（flare/sunburst vs 低价扩展版）能力可以完全不同。
88. ⭐⭐ **"任务成功"不等于"上游用了你的输入"**（§二.M）：上游读不到首帧图时**静默降级为文生视频** ——
    任务状态 `succeeded`、列表里的 `ratio`/`duration`/费用全部正常，**日志里看不出任何异常**。
    判断"输入真的生效"只有一个办法：**看产物本身**（把结果视频第 0 帧抽出来跟源图比）。
    `ffmpeg -i out.mp4 -vf "select=eq(n\,0)" -vframes 1 f0.png` 是这次的定位手法，留着复用。
89. ⭐ **multipart 上传要带**文件名后缀**：上游按后缀认类型（`filename=asset` → 400
    「unsupported file type; allowed: jpg/jpeg/png/webp, mp3/wav/flac, mp4/avi/mov/mkv」），
    而我们的下载路径是 `/download`、没有后缀 —— 按 content-type 补一个。
    第一版镜像就是死在这儿，而且当时报错只剩一句 `HTTP 400`（**把上游原文带进报错**才一眼看出来）。
90. ⭐ **拿脚本复现生产调用，要装上生产那一套 env**：视频的轮询上限跟着
    `AI_PROVIDER_TIMEOUT_MS`（生产是 **300000**，默认是 120000）—— 我在验收脚本里没装它，
    一条 130 秒的正常视频被报成"AI 服务响应超时"，白跑一趟、还差点当成产品缺陷去修。
    **脚本读 `production.env` 时把 `AI_PROVIDER_*` 真的 set 进 `process.env`**，别只拿来取密钥。
91. ⭐⭐ **验收必须走用户真正走的那条路**（§二.N，本轮最贵的一条教训）：
    画布生成走的是 `POST /api/ai/generations/async` → 入队 → **worker 自己再解析一次素材** →
    才轮到 provider。我上一轮"直接调 provider"验过就宣布修好了，恰好跳过 worker 这一步 ——
    结果是"我这边绿、用户那边还是错的"。凡是要宣称"用户看到的现象修好了"，
    **就在那条真实链路上跑一遍**（本轮的 `live-canvas-video-check.mjs` 就是为此写的：
    生产库副本 + 临时实例，让 worker 自己跑）。
92. ⭐⭐ **手动往部署 checkout 里 scp 文件会挡住之后的 `git pull`，而"发布成功"不会报错**：
    untracked 文件挡合并 → `git pull` 直接 abort，我却只 `tail` 了输出、没看报错 →
    接着照常 build + 发布 → **上线的是老 commit**（新 release 目录、旧代码）。
    识别方法只有一个：**发布后读 `BUILD-METADATA.txt` 里的 `commit=`，与本地 HEAD 对一眼**（本轮对出来了）。
    往部署目录塞临时文件要记得删；`git checkout -- .` 并不会清 untracked。93. ⭐⭐ **守卫自己会哑：把新断言插在 `if (failures)` 之后，它就永远绿**（§二.O 现场）：
    我给 p122 补了 5 条断言，位置在该文件的失败判定**之后** —— 结果屏幕上明明打了 `✗`，
