# 修复 · 课堂作品读面「看不全 / 没有」（2026-10-31）

## 现象

老师在课堂里查看学生提交的画布作品：

- 9 张图的卡片里，竖图被裁成 4:3，**只看得到中间一截**（看不全）；
- 点开大图后，长提示词只显示一行、被 `…` 截断（看不全）；
- 画布里的 **AI 文字产出完全不见**（9 张图都在，唯独文字那件没有）。

截图对应作品：`work_7f2e9aa1319c40d8ad27`（课堂 `csession_eb8c6309aacf4766afae`）。

## 数据核对

- 该作品的 `canvas_snapshot`：**1 个 prompt 节点 + 9 个 image 节点**；
- 9 个图片的 `file_assets` 全部 `ACTIVE`（205KB～2.8MB），不是素材丢失；
- `apps/server/src/lib.js` 的 `canvasMediaFrom()` 只收
  `assetUrl / previewUrl / referenceUrl`；prompt 节点只有 `generatedText`，没有 URL →
  **AI 文字产出在进入作品读面之前就被丢掉了**；
- 缩略图 CSS 是 `object-fit: cover` + `aspect-ratio: 4/3` → 竖图必被裁；
- 大图浮层的标题是 `white-space: nowrap; overflow: hidden; text-overflow: ellipsis` → 长提示词必被截。

## 修复

### 1. 文字产出进入媒体清单

`canvasMediaFrom()`：没有 URL 但有 `generatedText` 的节点 → 一条 `modality: 'TEXT'` 的媒体：

```js
{ url: '', modality: 'TEXT', fileId: null, caption: data.title || 'AI 文字', text: generatedText }
```

- 只认 `generatedText`（AI 产出）；纯输入提示词 `data.text` 不算，不把学生的问题当作品展示；
- 文字条目没有 fileId/url → **不发分享码**：`pieceKey` 置 `null`，
  `shareablePiecesOf()` 再挡掉空键（`media:`），避免分享面板出现一件发不出码的产出；
- 公共作品页、平台端、学生端共用 `canvasMediaFrom`，所以四处同时生效。

### 2. 缩略图不再裁图

`packages/shared/src/styles.css`：

```css
.work-media__thumb-img, .work-media__thumb-video { object-fit: contain; background: #0f0f11; }
```

竖图在 4:3 卡片里以黑边补足，**整张作品可见**；点开仍是大图。

### 3. 大图提示词完整显示

- `.work-media__lightbox-head strong` 允许换行（`white-space: normal`），最多 18vh 内滚动；
- 图片/视频高度改为 `calc(92vh - 18vh - 48px)`，面板 `overflow: hidden`，长提示词不再把图片挤没；
- 文字作品点开后在浮层里读全文（`work-media__lightbox-text`）。

## 验证

- 用真实 snapshot 跑 `canvasMediaFrom`：**10 条**（1 TEXT + 9 IMAGE），文字内容完整；
- 本地 gallery harness：10 张卡（含文字卡）、长提示词 170 字完整显示、文字浮层 162 字完整显示、
  竖图在卡片与浮层里都完整可见；
- 前端三端构建通过；服务端 `lib.js / orgAdmin.js / public.js` 语法检查通过。
