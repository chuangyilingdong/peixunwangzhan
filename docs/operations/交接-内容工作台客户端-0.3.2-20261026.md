# 内容工作台客户端 0.3.2 · 完整制作流程 · 2026-10-26

## 结论

0.3.1 把“生成文案后的下一步”写成了“复制去发布”，这是错误的：文案只是制作起点，后面还有内容方案、编导稿、分镜、渲染、发布包、发布和数据复盘。

0.3.2 已在客户端“做内容”内补齐完整六步流程，同时保持一级入口仍只有 5 个。

## 正确流程

```text
生成 3 个版本
→ 定稿：选一版并编辑标题、目标、口播、开场、画面提示词
→ 内容方案：保存方案，查看时长/画幅/渲染估价，确认生成编导稿
→ 编导稿与分镜：逐镜检查画面、口播、模型提示词、花字，可修改或换一版
→ 成片：单独勾选确认后提交视频渲染，轮询进度并下载原片
→ 发布包：生成字幕、封面、标题、发布描述、标签和 ZIP
→ 发布复盘：人工发布后才打开我的主页采集作品，进入数据复盘
```

## 关键修复

### 1. 文案生成后的引导纠正

- 删除“复制内容，去抖音或视频号发布”；
- 结果卡改为“先定稿，再进入完整制作流程”；
- “进入制作”成为主按钮，复制降为辅助操作；
- 明确显示：定稿 → 内容方案 → 编导稿与分镜 → 渲染成片 → 发布包 → 发布 → 数据复盘。

### 2. 完整制作页

仍在“做内容”一级入口内，不新增一级导航：

1. **定稿**：从生成结果解析版本，默认选中一版；可编辑标题、目标、完整口播、前三秒、画面提示词、时长、清晰度、画幅。
2. **内容方案**：调用 `/plans` 保存；读取 `/plans/:id/preflight` 展示渲染估价；确认后调用 `/plans/:id/submit` 创建视频任务。
3. **编导稿**：轮询 `/video/works/:id`；展示分镜；可修改每一镜的画面、口播、模型提示词和花字；通过 `PUT /video/works/:id` 保存。
4. **成片**：确认后调用 `/video/works/:id/confirm`；继续轮询渲染状态；成功后下载原片。
5. **发布包**：调用 `/video/works/:id/package` 生成包装视频、封面、字幕、发布说明和 ZIP；轮询发布包状态。
6. **发布复盘**：只有发布包 ready 后才进入人工发布步骤；发布完成后打开我的主页采集作品，再做数据建议。

### 3. 费用与发布边界

- 保存内容方案不扣费；
- 生成编导稿步骤不直接渲染；
- 渲染前必须再次勾选确认，并明确提示可能产生视频生成费用；
- 生成发布包不会自动发布；
- 客户端不自动登录或操作发布平台；
- 发布后仍需采集自己的作品，才能获得真实数据复盘。

### 4. 文件下载

新增主进程 IPC：

```text
junshi:app-download-asset
```

通过已登录会话下载素材文件，使用系统保存对话框保存成片或发布包，不把平台 token 暴露给 renderer。
