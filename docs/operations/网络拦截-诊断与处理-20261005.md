# 客户端/网站登录不上：运营商侧拦截的诊断与处理（2026-10-05）

> 结论先写：**这不是平台故障**。受影响用户在**自己那条线路**上对 `aicyld.com / 8.134.80.184` 的连接
> 被**运营商反诈拦截**（握手被重置、直连 IP 被跳到反诈提示页）；同一地址走代理 200 OK。
> 处置在"换 IP / 上 CDN / 备用入口 / 申诉"四件事上，平台代码**不需要改**。

## 一、现场证据

### 1. 用户侧（由用户提供的排查记录，图2）
| 检查 | 实际结果 |
| --- | --- |
| 系统 DNS、公共 DNS | 都解析到 `8.134.80.184`；**固定该地址后仍失败**（不是 DNS 劫持） |
| 直连平台 HTTPS | **在加密握手阶段被重置**，尚未进入账号验证 |
| 直连平台服务器 IP | 被**重定向到 `183.192.65.101`**，页面显示「上海市反电信网络诈骗中心 · 该网站疑似诈骗网站」 |
| 通过代理访问同一服务器 | **返回平台正常响应，HTTPS 200 OK** |

现象与用户描述一致：网站与客户端**同时**受影响，开 TUN/代理就恢复 —— 因为代理改变了访问路径。

### 2. 我们这边（2026-10-05 实测，全部正常）
- 生产健康：`/`、`/admin/`、`/org/`、`/student/`、`/api/health` **全 200**；服务 `active`、`NRestarts=0`。
- 公网 IP = `8.134.80.184`（与用户解析一致）；证书 `CN=aicyld.com` 有效至 **2026-12-22**。
- nginx **没有任何** `limit_req` / `limit_conn` / `deny` 规则（排除"被我们自己的限流误伤"）。
- 唯一对外端口：80/443（应用只监听 `127.0.0.1:8789`）。
- 我这边的网络访问 `https://aicyld.com/` → **200**（说明域名与源站本身是好的）。

### 3. 另一条独立线索：**老域名已经半死**（客户端若还钉着它，必然 ECONNRESET）
- `iicili.cyou` 现在解析到 **`39.106.183.200`**（迁移前的老机器，**不是**本平台）。
- 实测：`https://iicili.cyou/` → **连接被重置**；`http://iicili.cyou/` → **403**。
- 因此：**任何仍在用老域名的客户端/书签都会失败**，与运营商拦截是两件不同的事 —— 报障时先分辨是哪一种。

## 二、处置顺序（按"见效快 → 治本"排）

### ① 当天可用（零改动）
受影响用户先用**手机热点 / 其他网络**登录 —— 已验证有效。仅作应急，不是方案。

### ② 换公网 IP（最快见效，阿里云控制台 5 分钟）
证据倾向**按 IP 拦截**（直接访问 IP 就被跳到反诈页，未涉及域名/SNI）。
- ECS → 网络与安全 → 弹性公网 IP：**更换/换绑 EIP**；
- 换完把 `aicyld.com` 的 A 记录指到新 IP（TTL 建议 600s）；
- 换完告诉我，我在服务器上复核（证书、五入口、客户端 `client-context`）。

### ③ 上 CDN（推荐长期；备案已有）
用户连 CDN 边缘节点，**源站 IP 不再暴露**，某个 IP 被误伤也不会全站不可用；顺带提速。
- 备案：`鄂ICP备2025162545号-2`（已在页脚公示）；
- 回源：`aicyld.com` → 源站 `8.134.80.184`，HTTPS 回源；CDN 侧挂 `aicyld.com` 证书；
- ⚠️ 接 CDN 后**必须**在 nginx 信任 CDN 的 `X-Forwarded-For`，否则日志与限流判断都会把 CDN 节点当成用户；
  需要我改的只有这一处（`set_real_ip_from` + `real_ip_header X-Forwarded-For`，只列 CDN 回源段）。

### ④ 备用入口（第二条腿；平台侧可远程切换客户端地址）
- 官网：把新域名/子域指向本机 → nginx 加一个 `server_name` + 证书（`certbot --nginx -d 新域名`），
  并把 `CORS_ALLOWED_ORIGINS`（`/etc/ai-kids-platform/production.env`）加上新来源。**代码不用改。**
- 客户端：它的服务器地址**不是写死在客户端里**，而是登录时由平台下发
  （`GET /api/student/runtime/client-context` → `gateway.baseUrl` ← env `DSH_RUNTIME_GATEWAY_URL`，
  当前 `https://aicyld.com/api/gateway/v1`）。所以：**改这个 env + 重启服务，就能把客户端整体切到备用域名，不用重发客户端**。
  ⚠️ 注意客户端仍要能先访问到平台（登录/`client-context` 那一步），所以备用域名必须与主域名**同时可用**才有意义。

### ⑤ 申诉（与 ②③ 并行，因为名单里的 IP/域名会影响所有用户）
三路同时提：**96110**（反诈中心，警告页标注 `021-96110`）、**用户所在运营商客服**（电信宽带，提交访问故障工单）、
**阿里云工单**（说明源站被第三方拦截，请协助核查）。
材料清单：域名、源站 IP、拦截跳转页 IP `183.192.65.101`、出现时间、影响范围、备案号、业务性质说明（中小学 AI 教学平台）、
"代理可访问、直连被重置"的对比证据。申诉话术见文末附录。

### ⑥ 客户端体验改进（可选，优先级最低）
登录失败时把"检查网络"改成更具体的提示（例如"可能是网络侧拦截，可换热点或使用备用地址重试"），
并允许在客户端里手填备用地址。这需要**客户端仓库**配合，属于体验兜底，不解决根因。

## 三、报障时的分辨口诀（避免再绕一圈）
1. **只有客户端不行、网站正常** → 先查客户端用的域名/版本（老域名 `iicili.cyou` 已不可用），再看下面第 2 条。
2. **网站也不行** → 让用户做三个动作：`ping 域名`、浏览器直连、切手机热点。
   - 热点好、宽带不行 + 出现反诈页/握手重置 → 就是本文这一类（运营商拦截）。
   - 热点也不行 → 才是平台/证书/服务问题，找我。
3. **拿 `https://aicyld.com/api/health` 做基准**：代理能通、直连不通 = 线路问题，不是平台问题。

## 十一、执行记录：2026-10-05 已换公网 IP（②）

- 旧：`8.134.80.184`（EIP `eip-7xw848h6mpf8qpd6vned`）；**新：`8.138.150.19`**（华南3·广州，BGP 多线 /
  按流量 / 5 Mbps 峰值，与旧配置一致）。`aicyld.com` 的 A 记录已指向新 IP。
- 换法：先在 EIP 控制台**创建新 EIP** → 对旧 EIP **解绑** → 绑定到实例 `i-7xvggoko7nw4ee1ipj`
  → 改云解析 A 记录（TTL 先调 10 分钟）。**旧 EIP 未释放**，留作退路。
- 换后复测（本机，走公网域名）：`/`、`/admin/`、`/org/`、`/student/`、`/api/health` **全 200**，
  证书校验 `ssl_verify_result=0`（有效）；服务器自报公网 IP = `8.138.150.19`；服务 `active`、
  release `20261005T042957Z`。
- 运维注意：**开发机的 `~/.ssh/config` 里 `aicyld-prod` 的 `HostName` 已同步成新 IP**
  （本人机器，不进仓库）；新 IP 的主机指纹与旧 IP 逐字一致（同一台机器，已核对后再加入 `known_hosts`）。
- ⚠️ **DNS 缓存**：换 IP 前若 A 记录 TTL 较大，部分解析器会继续返回旧 IP（旧 IP 已解绑 → 表现为超时）。
  遇到"有人还打不开"先让他 `ipconfig /flushdns` 或等 TTL 过期，别误判成又坏了。
- ⚠️ **2026-10-05 下午：换 IP 后继续超时，真因是「旧 IP 还在 DNS 缓存里」**（不是运营商标记域名，也不是我们这边任何问题）。
  最终证据链（同一台机器，逐层拆开看）：

  | 检查 | 结果 |
  | --- | --- |
  | `Get-DnsClientCache -Name aicyld.com`（Windows 客户端缓存） | **3 条 `8.134.80.184`（旧 IP）**，TTL 约 886s |
  | `nslookup aicyld.com`（绕过客户端缓存，直连 DNS 服务器 211.136.192.6） | `8.138.150.19`（新 IP）✓ |
  | 公共 DNS（223.5.5.5 / 119.29.29.29 / 8.8.8.8） | 全部 `8.138.150.19` ✓ |
  | `curl --resolve aicyld.com:443:8.138.150.19`（强制新 IP） | **200** ✓ |
  | `curl https://aicyld.com/...`（走系统解析 → 命中旧缓存） | 打到 `8.134.80.184` → **超时** |
  | **`ipconfig /flushdns` 之后** | 解析器立刻变新 IP，连续 3 次 + `/admin/` 全部 **200** ✓ |

  ⇒ 旧 EIP 已解绑，凡是缓存/传播窗口内的客户端仍会打到那个已死的地址（表现为超时，或浏览器 `ERR_CONNECTION_TIMED_OUT`）。
  **处理：受影响机器 `ipconfig /flushdns`（必要时重启路由器）；把 `aicyld.com` 的 A 记录 TTL 设成 600，让以后变更收敛更快。**

- ⚠️⚠️ **过程中的一次误判，记下来避免重犯**：我曾据此宣布"按域名/SNI 拦截"，并让用户去考虑换域名/申诉。**它是错的。**
  误判原因是我那组"对照实验"没有控制住 DNS 这一层：拿"纯 IP 直连"（`https://8.138.150.19/...`，**不查 DNS**）去比"域名访问"
  （查 DNS → 命中旧缓存），于是差异被读成了"SNI 拦截"，实际差异是"解析到哪个 IP"。
  **教训：验证"域名是否被拦"时，两侧必须都走 `--resolve` 或都走解析**，否则测的是 DNS 而不是拦截。
- 另：用户转来的"上海反诈拦截页"证据来自**另一位用户、另一条线路**，针对的是**旧 IP `8.134.80.184`**；
  换 IP 已经避开它。它与本次"换成新 IP 之后的超时"无关，别混为一谈（那条线若仍出现反诈页，再按第二/五节处理）。
- ✅ 最终结果：清缓存后，用户侧与我这侧全部恢复；确认**不需要换域名、不需要 CDN**（就本次症状而言）。
- ✅ **结果（2026-10-05 上午，用户确认）**：换 IP 后问题短暂消失（旧 IP 那条拦截随 IP 换掉而消失）。
- 后续动作：旧 EIP 观察 1–2 天无异常后释放；**A 记录 TTL 建议 600**；受影响机器先 `ipconfig /flushdns`（本次超时的真因）。
