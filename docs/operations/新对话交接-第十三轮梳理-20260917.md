## 四、这一轮挖出来的判断口径（都是实测，别重走）

### 4.1 「深度求索中 · 计时器一直涨」不等于模型在算 ⚠️

学生界面显示「深度求索中… 110 分 46 秒」，真实用时只有 **24 分 02 秒**。
连接断了之后客户端会**继续空转计时器**（同时显示「自动重连中」）。
**判真伪的办法**：查 `usage_records` 按分钟分桶 —— 断崖式停止 = 卡住了，连绵不断才是真在算。
（注意 `created_at` 是 ISO 带 `T`/`Z` 而 `datetime()` 产出空格分隔，**字符串比较会串**，看形态别看边界。）

### 4.2 学生环境那次「卡死」的根因是内核 OOM，不是模型/网关

`dmesg`/`journal` 里：`Memory cgroup out of memory: Killed process … dsh-student-…service`。
**17:03:16 被杀**，而那一轮结束、工具调用被打断也是 17:03 —— 同一分钟。
平台侧两小时零错误、`usage_records` 每条都 `SUCCESS`，**别再往网关查**。
详见 `新对话交接-学生环境被OOM杀掉-20260917.md`。

### 4.3 「教学素材仅教师可见」这条错**只在身份是学生时抛出**

老师看到它时先怀疑「**这个请求用的身份不对**」，而不是「这个人不是老师」。
真因是：预览开在 iframe 里带不了鉴权头 → 回落到 `platform_token` cookie →
而那个 cookie 是 `Path=/` 无 `Domain`，**四个端共用**，浏览器里恰好是学生会话。

### 4.4 本地 `vite preview` 测不出「只有生产才犯」的问题 ⚠️

这一轮撞了两次：`.mjs` 被 nginx 当 `octet-stream`（+ nosniff → 浏览器拒收模块脚本）、
`blob:` 被 CSP `connect-src 'self'` 拦（Chrome 不把 `'self'` 算作覆盖 `blob:`）。
两者本地都跑得好好的。**规矩：验收必须包含「部署后对真实站点取响应头 / 真浏览器」**，
不能只看本地跑通。生产验收脚本 `scripts/verify-production-entrypoints.mjs` 已加上
`assetMimeOk`（资产 200 ≠ 能用），以后每次发布都该跑。

### 4.5 pdf.js 自己渲染时的三条硬约束

- **同一块 canvas 上绝不能并存两个渲染任务**：重画前必须 `task.cancel()` 并 **await** 它结束，
  否则缓冲区被写花（现象是「全屏后画面倒着、内容对不上」）。
- **不要喂 `blob:` 地址**（CSP 拦），直接用**同源票据地址**。
- 想关掉浏览器内置 PDF 阅读器那一排（下载/旋转/打印/保存到云端硬盘/文档属性）：
  它是**浏览器的 UI，不在 DOM 里删不掉**；`#toolbar=0&navpanes=0` 能让它整条不出现。
  但**要连 Ctrl+P/Ctrl+S/右键一起堵死，只能自己画 canvas**（我们最终就是这么做的）。

### 4.6 守卫要「反向自检」才可信

p76 里我故意把快照的票据改写成过期死链，再断言下发的是现签票据；
**把修复还原回去这条立刻变红** —— 否则它可能是一条空转的断言。
同理 p111 里加了「**像素指纹**」：光量画布尺寸量不出「画被写花」。

### 4.7 运维小坑（省时间）

- `pgrep -f build-production.sh` **会匹配到自己**（命令行里含这个字符串）→ 永远报 RUNNING。
  用 `pgrep -af "[b]uild-production.sh"`。
- 直连 `127.0.0.1:8789/api/health` 是 **404**；健康检查路径是 **`/health`**（`/api/health` 是 nginx 那层）。
- 服务器 **`/etc/nginx/mime.types` 的 javascript 那行没有 `mjs`**，已补（`js mjs`）。
  ⚠️ 别在 `server{}` 里写 `types{}` 补 —— 会**替换掉整张类型表**；
  ⚠️ 改完要**等 reload 生效再验证**（我第一次立刻探测，拿到的还是旧行为，差点误判）。
- 判断前先看清那一行长什么样：我因为 `grep include.*mime.types` 没匹配上（**行首是制表符**），
  误以为 nginx 没加载类型表，把改动还原过一轮。
- **本机打不通站点 ≠ 站点故障**（这条最容易开出假警报）：RUNBOOK 早写了「本机出口封 HTTPS」，
  实测比那还细 —— 这台 Windows 上 `curl https://iicili.cyou/` 与 `node` 的 https **都直接
  `ECONNRESET`**（`openssl s_client` 偶尔能通、不可靠）。**生产验收一律在服务器上做**
  （RUNBOOK 里那段 for 循环），别在本机跑出个红就判断「生产挂了」。
- 本机访问 `http://iicili.cyou/` 会拿到**阿里云的 `Non-compliance ICP Filing` 拦截页**
  （403、`Server: Beaver`）—— 那是阿里云在 80 端口那侧的备案拦截，**不是 nginx 故障**
  （HTTPS 五入口全 200）。我这次没核准它是不是长期如此，总之**别为它去改 nginx**。
