# 作品调用大模型 · 平台约定（2026-10-08）

> **一句话**：学生作品要在浏览器里用**自己的 Key** 调大模型，就按第一节那套接口写；
> 平台在预览里把它翻译成「浏览器直连厂商」，**Key 不经过平台服务器**、平台也不收这笔账。

## 〇、这份文档是怎么来的（现场）

用户拿一件学生作品来问：「填了大模型的 Key 为什么跑不起来」——
`https://aicyld.com/s/shs_ef2cc10bd95340abb8d9afaf`（作品 `summary.html`，界面里本来就有「接口设置」）。

真因**不是 Key**：那件作品是「前端 + 自带 Node 后端」的完整工程（旁边还有「启动智能内容总结.bat」），
网页里 `fetch('/api/llm')` 打的是**作者本机那份后端**。作品提交到平台只有入口 HTML，后端不跟着来，于是：

- 请求落到我们的 `/api/llm` → **404**（平台上从来没有这条路由）；
- 而且沙箱文档是 **opaque origin**（`Origin: null`），我们的 API **不给 null origin 发 ACAO**
  ⇒ 浏览器直接 `net::ERR_FAILED`，作品的 `.catch` 把进度文案设成「已中止」。

生产实测复现（2026-10-08，真浏览器 + 分享页）：`POST /api/llm` → preflight 失败 →「已中止」。
所以这一轮加了一座**大模型桥**，把这条约定接住（与 PDF 桥 / 素材 fetch 桥同构）。

## 一、接口约定（作品侧照这个写）

### `POST /api/llm` —— 调用大模型

```jsonc
// 请求 body
{
  "apiKey": "sk-…",                       // 用户在这个作品里填的 Key（只在本机浏览器里）
  "baseUrl": "https://api.deepseek.com/v1", // ⚠️ 不含 /chat/completions，平台自己拼
  "model": "deepseek-chat",
  "messages": [{ "role": "user", "content": "…" }],  // OpenAI 兼容格式
  "temperature": 0.3,                     // 可选
  "json": true                            // 可选；true → 转发成 response_format:{type:"json_object"}
}
```

```jsonc
// 应答（HTTP 恒 200，成败看 ok —— 与作者那份后端同形状）
{ "ok": true, "content": "…", "model": "deepseek-chat", "usage": { … } }
{ "ok": false, "error": "模型服务返回 401：…", "hint": "Key 无效、没有权限或已过期 …", "status": 401 }
```

### `GET /api/config` —— 非敏感默认值（Key 永远来自本机浏览器）

`{ "ok": true, "baseUrl": "https://api.deepseek.com/v1", "model": "deepseek-chat", "chunkChars": 4000, "temperature": 0.3 }`

### `POST /api/fetch` —— ⛔ 平台**不代理**「按链接抓网页正文」

那是「服务端去抓任意地址」（SSRF 风险面），另议。这里只回一句人话：
`{ "ok": false, "error": "平台不代理「按链接抓取网页正文」…", "hint": "请把正文直接粘贴进来，一样能总结。" }`

## 二、平台怎么实现的（桥的行为，改之前先读）

- 注入点：`packages/shared/src/vibecodingProject.js` 的 **`LLM_BRIDGE`**，
  在 preamble 里排在**素材 fetch 桥之后、PDF 桥之前**（PDF 桥仍排最后，p173 钉着顺序）。
- 拦截：只认 `fetch` 里 **pathname 以 `/api/llm` / `/api/config` / `/api/fetch` 结尾**的请求；
  其余 fetch 原样放行（含桥自身异常时的兜底）。
- 翻译：`POST {baseUrl}/chat/completions` + `Authorization: Bearer <key>`；body **白名单转发**
  `model / messages / temperature / top_p / max_tokens / presence_penalty / frequency_penalty / seed / stop / n / response_format`。
- 超时 **120 秒**；作品自己带了 `signal` 就听它的（有「停止」按钮的作品照样能停）。
- 错误都翻成人话：401/403 → 指向 Key；402 → 余额；404 → Base URL 多半少了 `/v1`；429 → 限流；
  超时 → 建议调小「每段字数上限」；CORS 不通 → 说清「有些厂商不允许浏览器直连」。
- ⭐ **Key 不出沙箱**：桥体里**没有任何 `postMessage`**（p187 断言这一条）——
  作品里那句「Key 只保存在你自己的浏览器里，不会写入网页源码或本站服务器」仍然成立。
- 认得出「禁网预览」：机构端/平台端预览会给学生文档注入 `connect-src blob:` 的 meta CSP，
  桥**先判这条**再判 Key（那种窗口里填了也发不出去），回一句「这个预览窗口关掉了作品的联网」。

## 三、哪些入口能用（网络口径）

| 入口 | 出网 | 依据 |
| --- | --- | --- |
| 官网分享页 `/s/<码>` · 作品广场 `/works/<码>` · 网站端作品弹窗 · 学生工作台预览 | ✅ | 走 `/vibe-preview.html` 转发壳，CSP `connect-src https: wss:` |
| 机构端课堂预览 · 平台端作品预览 | ❌ | 那两处**故意**给学生文档注入了 `connect-src blob:` 的 meta（老师/管理员看学生代码时不给它联网）；桥会给一句人话，改动必须是显式的 |

⚠️ **`/vibe-preview.html` 的 `connect-src https: wss:` 是这条能力的地基**（`deploy/production/nginx-site.conf`）。
谁把它收紧，所有「直连大模型」的作品会一起死 —— **p187 钉着它**（生产响应头里必须有 `connect-src … https:`）。

## 四、厂商侧要求（浏览器直连的硬条件，2026-10-08 实测）

浏览器直连的前提是**厂商给 CORS**（沙箱发的请求带 `Origin: null`）。实测：

- **放行**：DeepSeek（`ACAO: null`）· 月之暗面 Moonshot（`null`）· 智谱 bigmodel（`null`）·
  火山方舟/豆包（`null`）· 阿里百炼 compatible-mode（`*`）· 硅基流动（`*`）。
- **不通**：OpenAI（国内网络连不上）· Gemini（同上）· Anthropic（preflight 403，不给 ACAO）。

→ 作品里的「服务商预设」不要放 OpenAI / Gemini：那不是平台限制，是**网络 + 厂商政策**。

## 五、已知边界（别当新 bug 追）

1. **不支持流式**：约定是 `r.json()` 拿 JSON 回包，`stream` 不转发。
2. **Key 不持久**：沙箱里 `localStorage` 是平台注入的**内存替身**（`SANDBOX_STORAGE_SHIM`，为的是别让作品
   读存储就抛异常），**刷新一次就要重填 Key**。要留住得给替身加一层「落主站 localStorage + 按作品命名空间」
   —— 独立的一小块，有安全权衡（学生代码借此能往我们域写字符串），**待拍板**。
3. **`/api/fetch` 不代理**（见上）。
4. **老师端 / 平台端预览禁网**（见上）。
5. **平台不记账**：用的是用户自己的 Key，不进算力账本、与 `computePool` 无关。

## 六、怎么验

```bash
node scripts/p187-llm-bridge.mjs            # 新增守卫：源码口径 + 本地真浏览器 + 生产口径
node scripts/acceptance-suite.mjs scripts/p173-html-local-assets.mjs scripts/p123-preview-storage.mjs scripts/p95-vibecoding-quality.mjs
```

p187 三层：① 源码口径（桥在、顺序对、无 `postMessage`、超时够）；② 本地真浏览器（真转发壳 + 假厂商：
成功 / 厂商 401 / 厂商不给 CORS / 没填 Key / 收紧 meta CSP 五种路，且**本地站点的 `/api/llm` 一次都不许被打**）；
③④ 生产口径（生产壳 CSP 仍放行 https + 用**假 Key 打真 DeepSeek** 必须拿回**厂商的鉴权错误**）。

## 七、给客户端 / 生成侧的一句话

作品要调大模型时，**按第一节那套接口写**（`POST /api/llm`，Key 由用户在作品的「接口设置」里填）。
生成侧不用改 —— 现在生成的就是这个约定；我们要做的只是把它接住。
