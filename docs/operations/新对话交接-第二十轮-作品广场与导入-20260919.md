### L. 常见问题：空档位隐藏 + 三个标签后台可排优先级（2026-09-19 晚，用户新点名的两件）

用户口径：「① 学生端和老师端后台我把内容全部删除了，这里还出现，应该是**如果没有内容就隐藏，有内容才出现**；
② **这 3 个标签可以在后台排序优先级，优先级高的排在最前面**。」

线上当时的实际情况（读生产库）：`student: 0 条 / teacher: 0 条 / org: 6 条` ——
也就是访客打开 `/faq` 会**默认落在一个空档位上**（列表一片空白），正是他报的现象。

| 事项 | 做法 |
|---|---|
| ① 空档位隐藏 | `Faq()` 只渲染**有内容**的档位；当前选中的那档被清空后自动落到第一个还有内容的档位；键盘左右只在**看得见**的档位之间走；一档不剩时整条 tablist 不渲染（空 = 故意清空，**不回退**兜底内容，口径③） |
| ② 优先级 | 内容里新增字段 **`audienceOrder`**（数组）；官网按它排 tab，**没配就用代码里的默认顺序**（老内容不用迁移）；后台「官网内容 → 常见问题」按这个顺序渲染（**后台看到的顺序 = 官网的顺序**），每组标题右边一组 ↑/↓ 改它，并标出「官网会显示 / ⚠️ 官网不显示这一档」 |
| 档位名字 | 仍在代码里（沿用原口径），这次只把**顺序**交给后台 —— 所以改顺序不用发版、不用改官网代码 |

⚠️ 连带修掉一处**自相矛盾**：`/org`（机构方案页）那块 FAQ 也读 student 档，但它原来写死了
「student 为空 → 显示内置兜底」—— 于是运营删光学生端之后，`/faq` 那一档没了、`/org` 反而还在显示旧问答，

### M. 机构手册整页按设计稿重做（2026-09-19 晚，用户新点名的）

用户口径：「机构手册页面按照压缩包改造下，**图1可以找个合适的放**。」
拿到的包是 `design (1).zip`（3 个文件：`index.html` + `assets/css/styles.css` + `assets/js/main.js`），
里头那张「AI 时代的孩子 从这里起步」海报是用户单独附的。

**先问了一句才动手**：设计稿只有 5 个视觉区块，而当时的机构手册有 **8 个文字章节 + 7 行对比表**；
用户选了「**彻底换成稿子的内容**」。所以旧内容**先导出留底**：
`docs/operations/handbook-旧内容留底-20260919.md`（含可直接贴回后台的 JSON + 人眼可读版），
迁移脚本写入前还会再 dump 一份 JSON 到 `production/data/backups/handbook-before-<时间戳>.json`。

新页面（`.hb` 前缀，样式在 `styles.css` 末尾）：主视觉（两行大标题 + 通屏图）→ 关于（纸色区块）
→ **海报** → 横滑卡片区（5 张，滚动钉住 + 横移）→ 对比区（粒子 canvas）→ 结尾行动。

**三处必须换算、不能照抄设计稿的地方**：

| 设计稿 | 我们这边 | 为什么 |
|---|---|---|
| Tailwind + GSAP + ScrollTrigger + Lenis（外链 CDN） | **一个都不引**；入场/横扫钉住/粒子/光标用原生 CSS + rAF 复刻 | 生产 CSP 是 `script-src 'self'`，那 4 个 `<script src>` **一个都加载不了** |
| 图片热链 `a.lovart.ai`（7 张） | 自托管 `public/assets/handbook/*.webp` | 那域名**本机与服务器都连不通**（curl 000）；口径也不许热链、不把访客 IP 带给外域 |
| 配色 gold `#bca46c` + 黑 + 纸色 | **原样保留**，但**只挂在这一页**（`.hb{--hb-*}`） | 设计稿那 7 张配图本身就是暖橙/青的，套站内那支粉会跟图打架；变量作用域限定在 `.hb`，不影响其它页面 |

⚠️ **图1（海报）放哪、为什么**：它是一张**信息图**（字很密），所以单独一个**纸色区块整张显示**
（`object-fit: contain`，不裁不灰）+ 一个「点开看大图 ↗」；塞进设计稿那种会裁切/灰化的满幅槽位会把字切没。

⚠️ **多行标题用字符串数组**（`about.headingLines` / `work.introLines` / `compare.headingLines`），
**不是带 `\n` 的字符串**：① 免得在 JSON 里跟转义较劲（我第一版就是这么把文件写成语法错误的）；
② 后台可以每行一个输入框，运营不用在一个框里敲换行。**第 2 行在官网是描边字**（设计稿如此）。
渲染端 `hbLines()` 同时兼容"带换行的字符串"老写法。

⚠️ **浏览器 API 只出现在 `useEffect` 里、且每处 `typeof … !== 'undefined'` 兜底**：
p70 的 DOM 桩里**没有** `IntersectionObserver` / `ResizeObserver` / canvas，
渲染期碰它们会让渲染守卫直接报未定义（首页那段注释记过这个坑）。
幕布（预加载）做成**纯 CSS 自动收起**（`animation … forwards` → 移出屏外 + `visibility:hidden`），
JS 只数那 0→100 的计数器 —— **JS 没跑起来也不会把页面盖住**。

内容形状（HANDBOOK 键）：`{ hero{line1,line2,imageUrl,imageAlt}, about{index,headingLines[],body,imageUrl,imageAlt},
poster{eyebrow,title,caption,imageUrl,imageAlt}, work{introLines[],cards[{title,desc,imageUrl,imageAlt}]},
compare{eyebrow,headingLines[],body}, cta{headline,text} }`。
后台「官网内容 → 机构手册」的表单整体换成这个结构，**每个图都能上传替换**。

**上线后用户报的第一个问题（已修）**：「往下拉就是黑屏，应该是左右拉完再往下才对」——
横滑区**钉不住**。根因不在这一页，而在外层 `.site{overflow:hidden}`（详见口径⑰与坑㉜）：
`hidden` 让它成了滚动容器，里面所有 `sticky` 都静默失效。改成 `overflow: clip` 后
逐段实测：y=3200→4800 期间钉层 top 一直是 0、轨道从 −701 扫到 −2301，
y=5400 扫满（−2560）后钉层才离开、页面继续往下 —— 就是"左右拉完再往下"。
⚠️ 副作用：**站内顶栏现在会粘在顶部了**（它 CSS 本来就写着 `position:sticky` + 半透明模糊背景，
只是之前一直被同一个原因废掉）。这是全站的可见变化，已如实告知用户。

**用户接着提的两处外观（已做）**：
① **幕布文案**从「开课」改成「**让Ai真正进入课堂**」。字号必须一起改（原来按两个字写的
   `clamp(3rem,10vw,9rem)`，8 个字会顶出屏幕）→ 改成 `clamp(1.35rem,4.2vw,3.8rem)` + 居中 + 限宽。
   这句话做成了**后台可改**（`hero.loaderWord`）。
② **主视觉**：文字**居中**（去掉原来第二行那个 9vw 缩进，`.hb-line--offset` 连 CSS 一起删）、
   文字加**逐字升起**（每字一个 span、delay 内联错开）+ 慢速**浮动**，
   背景加三层特效（图**缓慢推近** / 一层**往下游走的网格** / 一道**缓慢扫过的暖光**）。
   ⚠️ 浮动最先是用 `text-shadow` 脉冲做的，**换掉了**：那会让文字层每帧重绘，是首屏最贵的一类动画；
   改放在遮罩层上用 `transform`，走 GPU 合成、几乎不花钱。**这条以后加动画时照着抄**。



## 三、不许破的口径（本轮新增 19 条：原 6 条 + §二.J 的 4 条 + §二.K 的 2 条 + §二.L 的 2 条 + §二.M 的 5 条）

1. **广场只放"能在我们站直接打开"的作品**：本体只有别家平台链接的**不上广场**
   （对方大多用 `frame-ancestors` 禁止被嵌，跳出去等于把流量送人）。
2. **分类只有两个**（画布作品 / VibeCoding作品），**归哪一类由服务端算**、映射后台可配；
   前端不许自己按类型判分类。
3. **媒体放 release 之外**（`/srv/.../public-media/`）+ 走 `/media/` 那条 location；
   **不许**复用 `/downloads/`（octet-stream + nosniff 会让图片/视频打不开）。
4. **导入的视频必须是标准 mp4**（QuickTime 容器 `ftypqt` 浏览器播不了）——导完跑 remux。
5. **作品的"上广场"要四样齐全**：`is_public=1` + `status='PUBLISHED'` + `share_token` +
   `copyright_confirmed_at`（缺一个广场就不显示，而且**不报错**）。
6. **广场的配色与图标是"口径"**：图标用 `icons.jsx` 的线性 SVG（不用 emoji）、
   实心紫用 `--pl-grad` 渐变。改版要连 p115 一起改。
7. ⭐ **`/media/` 必须带 `Access-Control-Allow-Origin: *`**：网页作品跑在不带
   `allow-same-origin` 的沙箱 iframe 里，文档 origin 是 opaque，里面 `import` 的 ES module
   一律按 **CORS 模式**取 —— 少了这个头，three.js 那几件**整片白屏**（文件明明 200 拿得到，
   是浏览器拒收）。改 nginx 时别把这行删掉，p120 会拦。
8. ⭐ **跑网页作品的 iframe 不许带 `allow-same-origin`**，也不给它「在新窗口打开」的出口：
   作品在 `/media/` 下**与主站同源**，这两条都是"把学生代码提到我们源上跑"。
9. **网页作品的 `entryUrl` 必须是本站 `/media/` 下的地址**：放外域就等于破了口径①
   （而且沙箱壳的 `frame-src 'self'` 也会挡）。
10. **导入件要连"相对引用"一起抓**：`url('bg.jpg')` / `<source src="bgm.mp3">` 这种
    同目录素材，只抓 HTML 里写出来的绝对地址会漏（单词小侦探就是这么漏掉背景图和背景音乐的：
    广场上打开缺图 + 没声音）。
11. ⭐ **「删除」是两档，不是一个动作**：「下架」= 可恢复的软删（默认路径，学生看得到原因）；
    「彻底删除」= 不可恢复，必须 `confirm:true` + 原因，且**导入件的媒体只挪进 `_trash/`、不 rm**。
    改这块时那条"共用媒体不许挪"的检查一定要留着 —— 它会挡住"一件作品删掉、另一件作品的媒体跟着没了"。
12. **后台「编辑」只改展示文案**：发布状态 / 展示授权 / 精选各有专门动作与审计，
    不许从编辑接口走 —— 否则"改个标题"就能顺手把发布状态改掉，审计账对不上。
13. ⭐ **FAQ 的空档位不显示，且不许回退兜底**：某一档问题清空 = 官网不出现那一档（口径③）。
    同一个 CMS 字段在多个页面（`/faq` 与 `/org`）必须表现一致 —— `/org` 原来写死了"空了就显示内置兜底"，
    于是同一份数据在两个页面一个消失一个还在显示旧问答。**别把那个兜底加回来。**
14. **FAQ 三个档位的顺序由内容字段 `audienceOrder` 决定**（后台 ↑/↓ 改），
    代码里的 `FAQ_AUDIENCES` 只是"没配时的默认顺序"。**名字仍在代码里** ——
    所以以后要改顺序，改后台即可，不用改官网代码、不用发版。
15. ⭐ **机构手册的图都在站内自托管**（`apps/website/public/assets/handbook/*.webp`，合计 752KB）：
    设计稿热链的 `a.lovart.ai` 那域名连不通，而且口径也不许热链。换图请在后台「官网内容 → 机构手册」
    上传（或填已有资源地址），**别往代码里写外域地址**。
16. ⭐ **多行标题是字符串数组**（`headingLines` / `introLines`），不是带 `\n` 的字符串 ——
    后台每行一个输入框、官网**第 2 行描边**。别把它们合并成一个 textarea 让运营敲换行。
    另外**每个页面区块的文案与图片都要留在 CMS 里**：机构手册那条口径（"图与文字基本都能后台配"）没变。
17. ⭐⭐ **`.site` 必须是 `overflow: clip`，不能是 `overflow: hidden`**（2026-09-19 改）：
    两者**裁剪效果一模一样**，但 `hidden` 会把这个外层 div 变成**滚动容器**，
    于是它里面所有 `position: sticky` 的元素改去粘**它**（而它自己从不滚动）＝ **sticky 静默失效**。
    实测代价有两条：机构手册的横滑区钉不住（滚下去是一大片黑屏，用户报的就是这个），
    以及**站内顶栏 `.site-topbar` 的 sticky 一直没生效**（它那半透明 + 模糊背景本来就是按
    "内容从下面穿过"写的）。→ **新增 sticky 之前先确认没有祖先带 `overflow: hidden`**；
    要裁剪又想留 sticky，用 `clip`（同 `.website-login` 那条）。
18. ⭐ **官网加动效只动 `transform` / `opacity`，别动 `text-shadow`、`box-shadow`、`background-position`**：
    后面这几个每帧都要**重绘**（首屏尤其贵），`transform`/`opacity` 才走 GPU 合成。
    机构手册主视觉那三处背景特效与文字浮动都是照这条做的（原来那个 `hb-glow` 的 text-shadow
    脉冲已按这条换掉）。另外所有新动效都要在 `prefers-reduced-motion` 里关掉。
19. **机构手册的文案字段**：`hero.loaderWord` = 进场幕布那行字；`hero.line1/line2` = 两行大标题
    （现在**居中**，没有缩进）；`work.introLines` / `about.headingLines` / `compare.headingLines`
    都是**字符串数组**（第 2 行描边）。加新字段后**跑一次 `migrate-handbook-content-20260919.mjs`**
    把缺的键补进库里 —— 不然线上有字、后台输入框却是空的（见坑㉝）。

## 六、这一轮踩过的坑

1. ⭐ **`.mov` 的容器品牌 `ftypqt`，Chrome 加载不出来**：`<video>` 一直 `readyState=0`、
   `canPlayType('video/quicktime')` 返回空，而**同一份文件在源站能播**（源站 CDN 有 referer 保护，
   我们的 curl 拿不到它的响应头做对比）。**改 nginx 的 content-type、去掉 nosniff 都没用** ——
   问题在容器品牌。正解是转标准 mp4（`ffmpeg -c copy`，不重编码）。
2. ⭐ **不能复用 `/downloads/` 那条 location 放媒体**：它 `default_type application/octet-stream`
   + `nosniff`，`<img>`/`<video>` 直接被拒收（而 200 是好的、看着像"图片坏了"）。
3. **导入的图片有一批是"没有扩展名"的图床链接**（`space.coze.cn/api/coze_space/gen_image?...`）：
   只看扩展名判断"是不是图片"会漏 → 改成**先看类型、再看扩展名**。
4. **源站会返回 200 + 0 字节**（797 个文件里有 1 个）：下载器要**把空响应当失败**，
   否则会留下一个 0 字节文件 —— 广场上就是一张裂图，而脚本还以为"下过了"。
5. **公开接口的 limit 之前卡在 60**，两处（`works` / `vibecoding-works`）——改一处漏一处的典型。
6. **`vibecoding_submissions` 与 `works` 是两套字段**（前者没有 `unpublished_at`）：
   "把某件作品下架"先看它在哪张表。
7. **守卫的 fixture 要够量**：翻页这条**必须 >12 件**才测得出来；我一开始只造了 2 件，
   分页断言等于没测。
8. **判分类要用 `data-category` 而不是 `data-type`**：卡片的 `data-type` 是**类型角标**
   （图片/视频/网页…），`data-category` 才是**分类**（画布作品/VibeCoding作品）——两者不是一回事。
9. **点站内作品会跳详情页**：守卫里"点开看查看层"必须点**导入件**（站内作品是 `<Link>`），
   否则页面一跳，后面的断言全找不到元素。
10. **`margin-left:auto` 的 computed 值不是 `"auto"`**（flex 项上会被解算成 px）：
    守卫要判"机构名贴不贴右边"，得比**右边缘距离**，不是比字符串。
11. **本机出网受限是常态**：`iicili.cyou` 本机 curl 不通、`npm registry` 不通、GitHub release 资产不通。
    离线办法：能通的那个方向借服务器（`ssh … curl`）；出包用本地 Electron 镜像（客户端仓库有脚本）。

§二.J（抓 aimagc 那批）踩到的：

12. ⭐⭐ **沙箱 iframe 里 `import` 的 ES module 必须走 CORS**：文档 origin 是 opaque（`null`），
    从**同源** `/media/` 取 `three.module.js` 也会被当成跨域 —— nginx 不带
    `Access-Control-Allow-Origin` 就**整片白屏**，而文件本身 `curl` 拿到的是**好好的 200**。
    我是用**真浏览器**跑才发现的（`Access to script … from origin 'null' has been blocked by CORS`）。
    → 后来 4 件 three.js 作品全白屏的根因就是这条；修法是 `/media/` 加 `ACAO: *`。
    ⚠️ 别用"文件 200 能下载"当验证 —— 这是**浏览器拒收**，不是取不到。
13. ⭐ **只抓 HTML 里写出来的绝对地址会漏"同目录素材"**：`单词小侦探` 的
    `url('bg.jpg')` 与 `<source src="bgm.mp3">` 都是相对路径，不在绝对 URL 扫描里 ——
    广场上打开就是缺图 + 没声音。爬虫必须**另外扫一遍相对引用**（并且只在作品自己目录内取，
    不许顺着 `../` 爬到站上别处）。
14. **这台服务器连不上 `cdnjs` 与 `wikimedia`**（`unpkg`/`jsdelivr`/`threejs.org`/源站都通）。
    所以下载器要：**失败不抛异常**（第一版一遇到连不上就把整轮打断，剩下的作品全没抓）、
    **有镜像就换**（p5 从 cdnjs 换 jsdelivr 的同一份文件）、**没镜像就保留原地址**并报出来
    （月球图 —— 宁可留一条外链，也不悄悄换掉学生作品用的素材）。
15. ⭐ **改前端的 importmap 前缀，必须先把 addon 文件全下到**：前缀改了、文件没下到 → 白屏。
    （所以脚本里是"全成功才改前缀"，不是"下不到就算了"。）
16. **`works.aimagc.cn` 的根路径是 403 而不是 200**：那是阿里云 OSS 的 bucket ACL
    （禁止目录列表），**具体作品的路径是好的** —— 别看到 403 就以为"抓不了"。
17. **别把脚本 scp 成"未跟踪文件"留在服务器 checkout 里**：`git pull` 要创建同名文件时会
    `Aborting`（`untracked working tree files would be overwritten by merge`），
    发布就卡在第一步（这次卡了两次 —— 第二次是守卫脚本）。要么先提交再 pull，
    要么在服务器上把那份未跟踪副本删掉。
18. **`deploy-002.sh` 的期望提交要传真 sha，不能传 `HEAD`**：它拿 `HEAD` 去比
    BUILD-METADATA 里的 `commit=<sha>`，比不中就**拒绝切软链**（自检是对的，我传错了）。
19. **金丝雀测"沙箱有没有隔离同源"时，别拿 `location.origin` 当判据**：Chrome 在
    sandbox iframe 里**照样把 location.origin 报成真实源**，但它确实是 opaque origin ——
    我第一版因此误判"隔离不成立"。判据要用**碰不碰得到**：`document.cookie` /
    `localStorage` / `window.parent.document` 三项都必须是 `SecurityError`。
20. **金丝雀的 `postMessage` 监听要挂在导航之前**（`addInitScript`）：金丝雀脚本在 `goto`
    期间就发完了，等 `goto` 回来再挂 listener，消息早丢了 —— 这也会误判成"隔离不成立"。

§二.K（后台两件）踩到的：

21. ⭐ **改了服务端却没发布，守卫会把"路由根本不存在"报成通过**：p121 第一跑 9 条红，
    原因是我只改了本地 `works.js`、没提交也没发布，服务器上还是旧代码。
    而且我 ⑥ 那条断言当时只判 `status === 404` —— 路由没注册也是 404，**看不出来**。
    教训是两层：改完服务端**先发布再跑守卫**；断言要**认错误码**（`ROUTE_NOT_FOUND` vs
    `VIBECODING_SUBMISSION_NOT_FOUND`），不能只认状态码。
22. **直连应用时要打 `/health`，不是 `/api/health`**：后者是 nginx 那条
    `location = /api/health` 代理过去的；在起真服务的守卫里打错路径，会一直等到超时，
    而服务其实早就起来了（日志里那句 `listening on …` 就在超时消息后面）。
23. **`scripts/` 里新加的脚本 scp 到服务器算"未跟踪文件"**：它会让 `git pull` 报
    `untracked working tree files would be overwritten by merge` 而中止（§六.17 记过一次，
    这轮又踩了一次）。**先提交再传**，或者传完就在服务器上删掉。

§二.L（常见问题）踩到的：

24. ⭐ **同一个 CMS 字段在多个页面表现必须一致**：FAQ 的 `student` 档同时被 `/faq` 与机构方案页

    修法是去掉那个兜底（空 = 故意清空，口径③），并且**别再加回来**。
25. ⭐ **线上 `/org/` 是机构后台，不是官网的机构方案页**：nginx 的 `location /org/` 指向机构后台 SPA，
    所以官网那个页面在生产 URL 上**根本看不到**（老欠账里那条）。

    它的验证途径是 **p115**（p115 自己构建官网、在 vite preview 里访问 `/org`），这轮就是这么验的。

§二.M（机构手册）踩到的：

27. ⭐ **设计稿不能照抄进这个仓库**，三条各自独立的拦路虎：
    ① 它引的 GSAP / ScrollTrigger / Lenis 是**外链 CDN**，而生产 CSP 是 `script-src 'self'` ——
       **一个都加载不了**（不是"慢"，是直接拒收）；所以入场/横扫/粒子全部用原生 CSS + rAF 复刻。
    ② 它热链的图片域名 `a.lovart.ai` **本机与服务器都连不通**（curl 返回 `000`）；
    ③ 那 7 张配图**不在 `design (1).zip` 里**（那个包只有 3 个代码文件）—— 它们在**同目录的
       `export.zip`**（7 张 2048×1152 PNG）。**先翻一遍用户给的目录再下结论说"图拿不到"**。
28. ⭐ **别把"多行标题"存成带 `\n` 的字符串**：我第一版用脚本生成内容时，`\n` 在注解里被折成真换行、
    在字符串里又变成没终止的字符串字面量 —— **直接把文件写成了语法错误**（连改两次）。
    改成**字符串数组**（`headingLines` / `introLines`）之后问题消失，而且后台能一行一个输入框。
29. ⭐ **改了 `websiteContentDefaults` 对生产库那一行完全无效**：seed 的 `ensureWebsiteContent()` 是
    **insert-only**。所以**任何"内容形状"的改动都必须配一个迁移脚本**（照
    `migrate-website-content-20260918.mjs` / `migrate-handbook-content-20260919.mjs` 的写法：
    `--dry-run` → 事务内写 draft+published+revision → 复查 → 写入前 dump 老内容）。
    只改种子的话，官网上读到的还是老形状，新字段全是 undefined、页面等于空壳（而且**不报错**）。
30. **幕布/预加载这类"挡住整页"的东西，收起必须不依赖 JS**：这里做成纯 CSS 动画
    （`animation … forwards` → 移出屏外 + `visibility:hidden`），JS 只数计数器。
    这样 JS 出错/被拦时页面照样能用 —— 别用"JS 到点把元素删掉"那种写法。
31. **p70 的 DOM 桩里没有 `IntersectionObserver` / `ResizeObserver` / canvas**：
    这个页面要 canvas 粒子、IO 做入场，所以**浏览器 API 一律只在 `useEffect` 里碰、
    并且每处 `typeof … !== 'undefined'` 兜底**。p70 跑下来 87 条路由 0 失败，说明这么写是安全的。
32. ⭐⭐ **`overflow: hidden` 会静默废掉里面所有 `position: sticky`**（用户报「往下拉就是黑屏」的根因）。
    现象与排查值得记下来：横滑区那层一屏高的内容**正常滚走了**，剩下 2560px 空黑 ——
    因为 sticky 的"约束矩形"取的是**最近的滚动容器**，而 `.site{overflow:hidden}` 自己就是个滚动容器
    （它内容不溢出，所以永远不会滚动）→ 粘在它身上等于没粘。
    **排查动作**：从 sticky 元素往上遍历祖先，打印 `getComputedStyle(el).overflow`，
    谁是 `hidden/auto/scroll` 谁就是凶手（一行 evaluate 就能定位）。
    **验证动作**：在浏览器里**就地**把那个祖先的 `overflow` 改成 `clip` 再滚一遍 ——
    不改代码就能确认修法有效（这次就是这么做实锤的：改前钉层 top=-501、改后 top=0）。
    ⚠️ 这个坑还有个连带发现：**`.site-topbar` 的 sticky 也一直是坏的**，
    修完 `.site` 之后顶栏开始跟着滚动 —— 那是它 CSS 的本来意图，但对全站是**可见变化**，已如实告知用户。
33. ⭐⭐ **守卫报红时先看数字的"形状"，别急着信它**：p115 报
    「口径①：首页数据区数字不一致 —— 接口正常=[2 门, 27 节, 1 类, 1 套] 而兜底=[3 门, 48 节, 2 类, 1 套]」。
    那四个数**全部小于**目标值、形状完全一致 —— 这是首页数据区「从 0 滚上去」的
    `StatValue` 动画（900ms）**滚到一半**的中间值，不是回归。守卫自己第 238 行的注释就预言过这个失败模式。
    **根因**：无焦点 / 被遮挡的窗口里 Chromium 会**节流 rAF**，滚数慢得多，守住 1.3 秒也滚不完。
    **修法**：给两道带浏览器的守卫（p115 / p120）加
    `--disable-background-timer-throttling --disable-backgrounding-occluded-windows
    --disable-renderer-backgrounding`（只动启动参数、不动断言）。同一份代码连跑两次都是绿的，
    说明它是偶发 —— 但偶发最坑，会让人去查一个不存在的回归。
34. ⭐ **别用截图判断"动画有没有生效"**：承载窗口没有焦点时，Chromium 会把合成动画**冻在 0%**
    （实测：幕布 `visibility=visible`、`transform=none`，而 `animationPlayState` 明明是 `running`；
    这也让截图一直超时 —— 抓图等不到稳定帧）。
    **正确验法**：`document.getAnimations().forEach(a => a.finish())` 把动画推到终态，
    再读 `getComputedStyle` —— 幕布终态应当是 `hidden / translateY(-101%)`，
    逐字动画终态应当是 `transform: none`。页面静止后截图也能成功。
35. **重写脚本时别把 helper 弄丢**：我把 `migrate-handbook-content-20260919.mjs` 整体重写后漏了
    `const id = …`，`--dry-run` 不碰它所以看不出来，**正式跑那一步才 ReferenceError**。
    → 改这类一次性脚本，**先 `--dry-run` 再正式跑**，而且 dry-run 要覆盖到写入路径的引用
    （或者干脆跑一遍 `node --check` + 一次本地小样本）。
36. **手动 scp 过的文件会和 `git pull` 打架**：我把修好的迁移脚本 scp 到服务器，checkout 里就有了
    「本地改动」，下次发布 `git pull` 直接 `Aborting`（§六.17/㉓ 记过同类）。
    → 要么提交后再传、要么传完在那台机器上 `git checkout -- <file>` 把本地改动丢掉。
