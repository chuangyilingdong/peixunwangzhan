## 0. 一句话版本

**平台把「次数」开给机构 → 机构把「次数」分给学生（1 次 = 1 个课时次数）→ 学生上 1 节课扣 1 次。
没上过的课都能上、上过的课不能重上；机构可以把学生没用完的次数回收回自己的总次数。**

体验课包仍然独立成一条支路（只 1 节课、同一节课可反复上、按有效产出核销），**本次改造没有动它**。

三条账必须分开看：

| 账 | 表 / 字段 | 谁在动 | 一句话 |
|---|---|---|---|
| 平台库存账 | `course_series.stock_total` | 平台 | **只对体验课包生效**；普通课包已取消这个概念 |
| 机构次数账 | `course_assignments.quota_total / quota_used` | 平台开/调；机构分学生时 `quota_used+`、回收时 `quota_used−` | 机构手里「总次数 / 已分给学生 / 剩余」 |
| 学生次数账 | `student_course_grants.granted_units / consumed_units` | 机构分/回收；课堂结束核销 | 某个学生「授权几次 / 已用几次 / 还剩几次」 |
| 财务账（许可三账） | `license_purchase_batches` / `license_revenue_events` / `license_revenue_allocations` | 开通、追加、撤销、回收 | 成交金额、收入确认、FIFO 分摊 |

## 1. 五个容易混的东西

| # | 概念 | 字段 | 是什么 | 不是什么 |
|---|---|---|---|---|
| 1 | 机构试用 | `organizations.is_trial` / `status='TRIAL'` | 机构自身状态 | **不是**体验课包 |

                                   └────────────────────────────┘

权限：

- **平台 SUPER_ADMIN**：建课包、设体验包库存、开/调/撤机构授权、撤销学生许可（兜底）。
- **机构管理员 ORG_ADMIN**：给学生分次数、回收普通课包未用次数、建课堂。
- **老师 TEACHER**：建/上自己的课堂、加学生；不能看/改学生授权。
- **学生**：上课、生成、提交作品。

## 3. 数据模型

### 3.1 课包

`course_series`：`series_type`、`stock_total`（**仅体验包使用**）、`status`、发布快照。
`course_lessons`：普通包不限节数；体验包**正好 1 节未归档课时**。

### 3.2 平台→机构

`course_assignments`：

```sql
UNIQUE(series_id, org_id)
status IN ('ACTIVE','REVOKED')
quota_total   -- 总授权次数
quota_used    -- 已分给学生的次数（回收会回退；学生核销不回退）
expires_at    -- = 机构合同到期日
```

有效判据：`status='ACTIVE' AND (expires_at IS NULL OR expires_at > now)`。

### 3.3 机构→学生

`student_course_grants`：

```sql
UNIQUE(org_id, student_id, series_id)   -- 一个学生一个课包一行，次数累加
granted_units  DEFAULT 1                -- 授权次数
consumed_units DEFAULT 0                -- 已核销次数
revoked_at / revoked_by / revoke_reason -- 撤销/全回收只写这里，行不删
```

余额公式唯一实现：`remaining = max(0, granted_units − consumed_units)`。

`student_course_grant_consumptions`（核销幂等表）：

```sql
UNIQUE(grant_id, session_id, student_id)  -- 同一场课堂同一学生只扣一次
UNIQUE(session_id, student_id)
```

`course_grant_requests`（2026-11-10 新增，授权/回收的幂等登记）：

```sql
UNIQUE(org_id, kind, idempotency_key)   -- kind = GRANT / RECLAIM
status PENDING/DONE, result 存响应体
```

### 3.4 课堂

`class_sessions`：`PENDING / ACTIVE / ENDED / DISSOLVED`。
`session_students`：`PENDING / ACTIVE / COMPLETED / INCOMPLETE / REMOVED`，
唯一索引 `(session_id, student_id) WHERE status <> 'REMOVED'`。

### 3.5 流水

- `course_quota_changes`：`INITIAL_OPEN / ADD / REDUCE / GRANT_CONSUME / GRANT_REFUND`。
  `delta = (quota_total_after − quota_used_after) − (quota_total_before − quota_used_before)`。
- `license_*` 三张：财务账；授权每人次一笔 `GRANT`，回收/撤销每退 1 次一笔 `REVERSAL`。
- `audit_logs`：`ORG_COURSE_GRANT` / `ORG_COURSE_GRANT_RECLAIM` / `COURSE_GRANT_REVOKE` / `SESSION_END`…

## 4. 流程 A：平台建课包

- `POST /api/admin/course-series`，`seriesType`（NORMAL/EXPERIENCE）、`stockTotal`。
- 体验包允许先建 0 节课；**加课时**与**发布**两处都校验"正好 1 节未归档课时"。
- 普通包：1–100 节，不限；**不再要求/校验 `stock_total`**（填了也不参与任何校验）。

## 5. 流程 B：平台把次数开给机构

`POST /api/admin/course-series/:seriesId/assignments`

1. 课包必须 `PUBLISHED`。
2. `quotaTotal` 可以填 0（只开通查阅、分不给学生）。
3. **普通课包跳过库存校验**；体验课包仍然校验 `Σ机构占用 + delta ≤ stock_total`。
4. `delta > 0` 时必须带成交信息（金额/币种/已收款/订单号/合同号/幂等键），写许可购买批次。
5. 授权到期日 = 机构合同到期日。
6. 写 `course_quota_changes`（首次 `INITIAL_OPEN`，追加 `ADD`）。

增加次数：`POST /api/admin/license-purchases/append`（一律记账）。
减少次数：`POST /api/admin/organizations/:id/course-quotas/:seriesId/adjust`（`quota_total ≥ quota_used`）。

## 6. 流程 C：机构把次数分给学生

**入口**：机构端「学生授权」（批量）或「课包库存 → 添加课包」（单人）。
**接口**：`POST /api/org/course-grants`（ORG_ADMIN）

```json
{ "seriesId": "...", "studentIds": ["..."], "units": 3, "source": "GRANT_PAGE", "idempotencyKey": "..." }
```

规则：

- **1 次 = 1 个课时次数**；`units` 1–1000，两种课包都支持。
- **同一学生可以重复分配**：次数累加在同一行 `granted_units += units`，撤销过就顺手复活。
- 配额闸门（事务内、用刚读出的 `quota_used` 实算）：
  `quotaTotal > 0` 且 `quotaUsed + 人数 × units ≤ quotaTotal`，否则 409 `COURSE_QUOTA_EXHAUSTED`。
- 每人次写一笔许可收入 `GRANT`（幂等键带 `u<seq>`）。
- 写 `course_quota_changes.GRANT_CONSUME`，`quota_used += 人数 × units`。

### 幂等（必须带）

次数可累加之后，"同一个请求发两次" = 真扣两次。机构端每次提交带 `idempotencyKey`：

- 第一次：插 `course_grant_requests` PENDING → 处理 → DONE + 存响应；
- 重复：直接回放响应；
- 处理中：409 `GRANT_REQUEST_IN_PROGRESS`；PENDING 超过 60 秒允许接管。

### 并发

两个并发请求都查不到行时，后插的那个撞唯一索引 → **重新读行并 `granted_units += units`**（不能像旧版那样"跳过"，跳过等于这次授权丢了、机构额度也没扣）。

## 7. 流程 D：上课与核销

### 7.1 建课堂 / 加学生

- 建课堂：课时已发布 + 课包授权仍有效（`accessibleLesson`）。
- 加学生（`addSessionStudents`）按顺序判：
  1. 学生存在且属于本机构；2. 账号 ACTIVE 未过期；3. 有有效许可；
  4. 体验包先看剩余次数（0 → `NO_EXPERIENCE_UNITS`）；
  5. 没有被别的未结束课堂占用（`IN_OTHER_SESSION`）；
  6. **普通包**：这节课已完课 → `COMPLETED`；否则剩余 0 → `NO_UNITS`；
  7. 体验包**故意跳过**"同课时已完课"（同一节课可反复上）。
- 候选人列表用同一套判据，并把原因和占用它的课堂一起回给老师。

### 7.2 开始前预检

`GET /sessions/:id/precheck` 五项：状态 / 教师 / 课时 / 名单非空 / 学生资格。
两种课包都检查**剩余次数 > 0**（不让老师上完课才发现结束不了）。

### 7.3 结束课堂 = 结算 + 核销（同一事务）

`POST /sessions/:id/end`

对每个 `PENDING/ACTIVE` 学员：

```sql
-- "有有效 AI 产出" 的唯一判据
SELECT 1 FROM usage_records
 WHERE class_session_id=? AND user_id=? AND org_id=?
   AND status='SUCCESS'
   AND UPPER(model) NOT LIKE '%MOCK%'
   AND UPPER(COALESCE(json_extract(pricing_snapshot,'$.provider'),'')) NOT LIKE '%MOCK%'
   AND UPPER(COALESCE(json_extract(pricing_snapshot,'$.mode'),'')) NOT LIKE '%MOCK%'
```

- 有 → `COMPLETED`，**核销 1 次**（两种课包都核销）；
- 没有 → `INCOMPLETE`，**不扣**；
- 重复结束/重试/并发 → 唯一索引保证只扣一次；
- 没有有效许可（已撤销）→ 跳过 `GRANT_REVOKED`，不报错；
- 余额为 0 → 409 `COURSE_UNITS_EXHAUSTED`（体验包 `EXPERIENCE_UNITS_EXHAUSTED`），**整个结束事务回滚**。

### 7.4 解散

只有 `PENDING` 能解散；学员全部 `REMOVED`，**不进结算、不扣次**。

## 8. 流程 E：机构回收未使用次数（仅普通课包）

`POST /api/org/course-grants/:id/reclaim`（ORG_ADMIN）

```json
{ "units": 1, "reason": "学生转班", "idempotencyKey": "..." }
```

- 只对 **NORMAL** 开放；体验包 → 400 `RECLAIM_NOT_SUPPORTED`。
- `units` 省略 = 回收全部剩余；1..`granted − consumed`，超了 400 `RECLAIM_EXCEEDS_REMAINING`。
- 学生还在待上课/上课中的课堂里 → 409 `STUDENT_IN_LIVE_SESSION`（否则结束课堂会因余额 0 回滚）。
- 事务内：
  - `granted_units -= units`；全回收时写 `revoked_at/revoked_by/revoke_reason`（**不动 `granted_at`**）；
  - `quota_used = MAX(quota_used − units, 0)`；
  - 写 `course_quota_changes.GRANT_REFUND`（source `ORG_COURSE_GRANT_RECLAIM`）；
  - 每退 1 次冲销 1 笔许可收入；
  - 审计 `ORG_COURSE_GRANT_RECLAIM`（机构端「授权记录」里显示为「机构回收」+ 原因）。

## 9. 流程 F：平台撤销（兜底）

`POST /api/admin/course-grants/:id/revoke`（SUPER_ADMIN）

- **两种课包同一口径**：按未消费余额退 = `granted − consumed`；
- `granted_units` 归到 `consumed_units`，历史不动；
- `quota_used` 回补、每退 1 次冲销 1 笔收入、写 `GRANT_REFUND`；
- 体验包只能走这条（机构端没有回收入口）。

## 10. 体验课包（本次未改）

差异仍然只有三条：

1. 只能 1 节未归档课时；
2. 可重复分给同一学生、未用次数累积（与普通包现在一样）；
3. **同一节课可以反复上**（普通包不能）；
4. 核销规则与普通包一致：正常结束 + 有有效产出 → 扣 1 次；无产出/解散不扣。

平台库存 `stock_total` 仍然只对体验包生效。机构端**不开放**体验包回收（用户口径 2026-11-10）。

## 11. 机构端「已上课程」面板

`GET /api/org/students/:id/course-usage`（ORG_ADMIN）

数据源 `session_students + class_sessions + course_lessons`，只返回已结算的行：

| 列 | 说明 |
|---|---|
| 课包 / 课时 / 课堂 / 老师 | 具体上了哪一节 |
| 结束/完课时间 | `completed_at` 或课堂 `ended_at` |
| 结果 | `COMPLETED`（已完课）/ `INCOMPLETE`（未完课） |
| 扣次 | 这一场是否真的核销 1 次（查核销明细） |

入口：

- 机构端「学生授权」列表每行「已上课程」→ 弹窗；
- 「学生授权详情」→「已上课程」面板（最近 500 条，按时间倒序）。

未完课的场次也会列出来并标「未扣」，老师/机构能看出"来过但没产出"。

## 12. 对账 SQL

```sql
-- ① 平台库存（只对体验包有意义）
SELECT s.id, s.title, s.series_type, s.stock_total,
       COALESCE(SUM(CASE WHEN a.status='ACTIVE' THEN a.quota_total ELSE a.quota_used END),0) reserved
  FROM course_series s LEFT JOIN course_assignments a ON a.series_id=s.id
 GROUP BY s.id;

-- ② 机构次数账
SELECT org_id, series_id, quota_total, quota_used, quota_total-quota_used remaining, status, expires_at
  FROM course_assignments ORDER BY org_id, series_id;

-- ③ 学生次数账
SELECT id, org_id, student_id, series_id, granted_units, consumed_units,
       granted_units-consumed_units remaining
  FROM student_course_grants WHERE revoked_at IS NULL;

-- ④ 账实一致：consumed_units 必须等于核销明细之和
SELECT g.id, g.consumed_units,
       (SELECT COALESCE(SUM(c.units),0) FROM student_course_grant_consumptions c WHERE c.grant_id=g.id) detail
  FROM student_course_grants g HAVING g.consumed_units <> detail;

-- ⑤ 库存流水
SELECT * FROM course_quota_changes WHERE org_id=? AND series_id=? ORDER BY created_at DESC;
```

## 13. 错误码速查

| 错误码 | HTTP | 场景 |
|---|---|---|
| `COURSE_NOT_PUBLISHED` | 403/409 | 未发布课包用于授权/分学生 |
| `COURSE_NOT_AUTHORIZED` | 403 | 机构没有有效授权单 |
| `COURSE_QUOTA_EXHAUSTED` | 409 | 机构剩余次数不足（含 0 次开通） |
| `COURSE_QUOTA_EXCEEDS_STOCK` | 409 | **仅体验包**：平台库存不够 |
| `COURSE_QUOTA_BELOW_USED` | 409 | 减少次数后低于已分给学生 |
| `STUDENT_NOT_FOUND` | 400 | 学生不属于本机构 |
| `GRANT_REQUEST_IN_PROGRESS` | 409 | 同一幂等键的请求正在处理 |
| `COURSE_GRANT_ALREADY_REVOKED` | 409 | 已回收/撤销过 |
| `COURSE_GRANT_NO_REMAINING` | 409 | 没有可回收余额（全部核销） |
| `RECLAIM_EXCEEDS_REMAINING` | 400 | 回收次数超过未使用余额 |
| `RECLAIM_NOT_SUPPORTED` | 400 | 体验包不支持机构回收 |
| `STUDENT_IN_LIVE_SESSION` | 409 | 学生还在待上课/上课中课堂，不能回收 |
| `NO_GRANT` / `NO_UNITS` / `NO_EXPERIENCE_UNITS` | 加人 skipped | 没许可 / 普通包次数用完 / 体验次数用完 |
| `IN_OTHER_SESSION` / `STUDENT_IN_OTHER_SESSION` | 409 | 学生在别的未结束课堂 |
| `COMPLETED` | 加人 skipped | 普通包同课时已完课 |
| `COURSE_UNITS_EXHAUSTED` / `EXPERIENCE_UNITS_EXHAUSTED` | 409 | 结束课堂时余额不足（整个结束回滚） |
| `SESSION_HAS_MISSING_SUBMISSIONS` | 409 | 有学生没交作品（老师确认后可结束） |

## 16. 已知限制

1. `quota_used` 只记"分给学生的次数"，学生核销不回补；学生用掉多少看 `consumed_units`。
2. 普通包"上过的课不能重复上"依赖 `session_students.status='COMPLETED'`；没有产出（`INCOMPLETE`）的课可以重上。
3. 机构回收要求学生不在任何待上课/上课中课堂里 —— 这是为了保证结束课堂时余额一定够。
4. 平台库存对普通包已无意义，但 `stock_total` 列保留（体验包还在用），界面只对体验包显示。
5. 授权/回收的幂等键由前端生成；不走机构端 UI 的调用方（脚本/第三方）应自带 `idempotencyKey`，否则重试会重复扣/退。
