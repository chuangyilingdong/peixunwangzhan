# 客户端已独立成仓（2026-09-19）

桌面客户端**已从本仓库拆出去**，本仓库不再包含客户端代码。

**为什么拆**：客户端是「上游钉版检出 + Electron 打包」那一套 —— 构建方式、依赖来源
（上游 `deepseek-harness` 的几 GB 检出与缓存）、发版节奏都和平台不一样。
两个工作区并行开发时，放一个仓里只会互相绊（一边改网页一边看到客户端的构建脚本，
分支、守卫、CI 都会纠缠）。

## 客户端在哪

| 项 | 值 |
|---|---|
| 工作区（本机） | `E:\灵动ai客户端` |
| 被移出去的东西 | `deploy/desktop/**`（品牌 / 登录门 / 发布脚本 / client-patch）、`scripts/p116-client-gate-ui.mjs`、`upstream/`（上游检出 + 构建缓存） |
| 上游 pin | `https://github.com/deepseek-ai/deepseek-harness.git` @ `ddefc45`（tag **`dsh-v0.1.6-alpha.2`**） |
| 去读哪份文档 | 客户端仓库的 `README.md` 与 `docs/交接-客户端-20260919.md` |

## 两边怎么配合

1. **接口以客户端仓库的 `docs/平台接口契约.md` 为准**（唯一契约来源）。
   ⚠️ **改契约必须两个仓库同时改**，并在那份文档末尾记一行（日期 / 改了什么 / 两侧提交）。
2. **平台侧要验「客户端能不能上课」** —— 用本仓库的 `scripts/dev-bench.mjs`：
   它起一套**临时库**的平台（种子账号 `student-1/study123`、一节 VIBECODING 课堂、
   网关指回自己、`local-mock` 模型），客户端把 `LINGDONG_API_BASE` 指到它的端口即可联调。
   判据：发一条消息后平台 `usage_records` 记 SUCCESS、`session_students.vibecoding_sends` 恰好 +1。
3. 客户端出包/发布用客户端仓库的 `scripts/build-win.sh` 与 `deploy/desktop/publish-client.sh`；
   安装包落在**本仓库生产服务器**的 `/srv/ai-kids-platform/downloads/`（发布目录之外，换代不冲），
   清单 `manifest.json` 由那个脚本负责写回。

## 本仓库跟客户端有关的还剩下什么

- `scripts/dev-bench.mjs` —— 本地验证台（上面第 2 条）。
- **服务端三个交付面**（客户端只认这三个 + 登录）：
  - `GET /api/student/runtime/client-context`（课堂 + 网关密钥 + 预设提示词 + 剩余次数）
  - `POST /api/gateway/v1/chat/completions`（OpenAI 方言的模型网关，超次数时 429 + 中文原因）
  - `POST /api/student/runtime/submit-upload`（客户端把作品字节传上来）
  守卫：`p117`（网页不再拉起创作环境）、`p118`（发送次数判据）、`p119`（上传准入）。
- 官网 `/download` 下载页 + 服务器下载目录 + 清单。
- 网页侧**不再有创作环境**：VibeCoding 课时只把学生送到客户端（`lingdong://open` + 下载入口）。
