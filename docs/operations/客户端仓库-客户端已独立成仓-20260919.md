桌面客户端**已从本仓库拆出去**，本仓库不再包含客户端代码。

**为什么拆**：客户端是「上游钉版检出 + Electron 打包」那一套 —— 构建方式、依赖来源
（上游 `deepseek-harness` 的几 GB 检出与缓存）、发版节奏都和平台不一样。
两个工作区并行开发时，放一个仓里只会互相绊（一边改网页一边看到客户端的构建脚本，
分支、守卫、CI 都会纠缠）。

## 客户端分发与更新（2026-09-20 实查）

### 平台侧：**没有"后台"可配，就是两个静态文件**

```text
安装包 + manifest.json  →  /srv/ai-kids-platform/downloads/  （nginx 的 location ^~ /downloads/）
官网 /download 页  →  fetch('/downloads/manifest.json', {cache:'no-store'}) → 显示版本、给下载链接
发布脚本  →  客户端仓 deploy/desktop/publish-client.sh（传包 → 核对字节数 → 写回 manifest → 核验能下）
```

- `manifest.json` 的形状：`{version, channel, updatedAt, note, files:{'win-x64':{name,size,sha256}, 'mac-arm64':null}}`，
  当前线上 `version=0.1.6-alpha.2` / `channel=internal-beta` / 包 294MB。
- ⚠️ **别去后台找「客户端发布」**：库里那张 `client_download_releases` 是**历史遗留空表**
  （代码里早已删干净，`docs/operations/交接说明.md` 里记着它"可手工 DROP"）。
- `/downloads/` **完全公开、无鉴权**（`autoindex off`）。装机量大时要自己算带宽：一台 294MB。

### 更新提示：**目前没有**，而且不是"配一下就有"

上游 dsh 桌面**自带**一套自动更新（`electron-updater ^6.8.9` 是桌面包的依赖，
打包配置里有 generic provider、Windows 更新发布者、macOS 更新源），但：

- 它绑的是 **DeepSeek 自己的分发**（`download.deepseek.com` + 腾讯 COS 的 bucket/secret 环境变量，
  `DSH_DESKTOP_AUTO_UPDATE_ENV=test|production`），我们不该也不便复用；
- 更关键：我们出的是 **unsigned 包**（`package:win:x64:unsigned`），而打包脚本里一行写死了 ——
  `const update = unsigned ? undefined : resolveDesktopAutoUpdateConfig(...)`，
  于是产物里 **`publish: null`**：**客户端连更新源都没有**，`electron-updater` 就算被调用也无处可查。

所以"打开软件提示更新"要在**客户端仓**做，两条路：

| | 做法 | 代价 |
|---|---|---|
| **A（建议先做）** | 在品牌/登录门那层补丁（客户端仓 `deploy/desktop/`）里加启动检查：`fetch('https://iicili.cyou/downloads/manifest.json', {cache:'no-store'})` → 与 `app.getVersion()` 比 → 有新版就弹窗（版本号 + `note` 变更说明 + 下载链接 + sha256）。**平台侧零改动**，我们发版只维护 manifest.json | 只能"提示 + 跳浏览器下载"，不能一键更新；但不需要签名、不动打包 |
| **B（体验最好）** | 走 electron-updater：① 打包改成非 unsigned（`DSH_DESKTOP_UNSIGNED=0` + **Windows 代码签名证书**，上游配置里 `forceCodeSigning` / `publisherName` 都是为它准备的）② `publish` 配成 generic provider 指向我们自己的下载目录（顺带把 electron-builder 生成的 `latest.yml` 一起发布出去）③ 客户端 `autoUpdater.checkForUpdates()` | 要证书、要改打包、要发布 feed 文件；好处是差量下载 + 一键重启安装 |

⚠️ 版本号是 `0.1.6-alpha.2` 这种带预发布标记的 semver，比较时用 `semver` 的规则（别自己拆字符串比）。
`manifest.json` 里的 `channel` 字段（现 `internal-beta`）就是给"内测 / 正式"分流预留的。

### 批量装机要注意的四件事

1. **固定下载地址**：文件名带版本号（`lingdong-client-<版本>-win-x64.exe`），换代就会变 ——
   装机脚本/发给机构的链接每次都要改。建议发布脚本**另维护一个不带版本号的稳定入口**
   （`lingdong-client-latest-win-x64.exe`，软链或复制一份），装机说明写死它。
2. **未签名**：每台机器首次安装都会弹 SmartScreen「未知发布者」。学校批量装机时这会被当成风险 ——
   要么上签名（见上表 B 的前置），要么给一份带截图的操作说明。
3. **别让每台机都从公网拉**：单包 294MB，30 台就是约 9GB 出网。局域网内分发（一台下好、内网共享）更稳。
4. **装机 ≠ 开账号**：装完第一次打开要过**客户端登录门**，账号由平台/机构开。装机量与学生账号数是两件事。
