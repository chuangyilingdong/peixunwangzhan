# 真实三账对照操作说明（2026-09-14）

## 三本账

1. 机构购销账：平台给机构追加课包次数时记录购买数量、实际成交总额、币种、收款状态、订单号和合同号。
2. 许可收入账：机构把课包许可发给学生时，只从已付款购买批次按 FIFO 消耗，并写不可变收入事件；符合退款规则的撤销写反向事件。
3. 供应商成本账：供应商结算 CSV 导入后，按请求、响应、任务、用量或网关 ID 匹配到具体上游调用尝试。

`真实毛利 = 许可确认收入 - 已匹配供应商结算成本`。只有同币种且收入、结算成本都有证据时计算；未知和多币种不显示为 0。

## 对外售价与上游成本对照（逐笔 + 汇总）

调用账里同时显示四类金额，**禁止混读**：

| 金额 | 含义 | 是不是真实钱 |
|---|---|---|
| 对外售价 | 本次调用的快照价，来自「模型与算力 → 对外售价」当时配置；改价不追溯 | 否，仅观测 |
| 学生消耗 | 调用次数与对应对外金额 | 观测口径 |
| 上游计费 | COMPUTED 按合同单价折算 / ESTIMATED 估算 / REPORTED 上游报告 / MOCK 本地模拟 / UNKNOWN 未知 | 否，估值，不一定是实际付款 |
| 上游实际核销 | 供应商账单匹配后的金额 | 是，实际付款 |

- 上游计费一列同时标出来源与**用量证据**（tokens / 张数 / 秒数 / 分辨率）：`COMPUTED` 是按合同单价折算出来的，
  换算用了哪一层价也会标出来（`MODEL` 模型级覆盖 / `MODALITY` 素材类型价）。

- `差额 = 对外售价 − 实际核销`。存在对外价未知、未核销或跨币种时差额**留空**，不会被当成利润。
- 汇总可按模态、渠道、模型、机构、学员五个维度切换；未知对外价与未知上游成本**单列计数**，不并入差额、不按 0 处理。
- **对外售价不等于收入**：它不扣学生（`usage_records.cost_fen` / `credits_charged` 恒为 0），也不进入真实毛利公式。真实收入只来自机构购买批次与许可确认收入。
- 上游成本未知（没配估算成本）的调用**同样可以用供应商账单核销**——账单本身就是还原实际扣款的依据。

### 机构端 / 学员端看到的「消耗」是哪一笔钱（2026-09-15 定稿）

机构端与学员端凡是有金额的「消耗」列，口径统一是**对外售价合计**：

```text
消耗 = SUM(compute_attempts.sale_price_fen)   —— 只计 status='SUCCESS' 的尝试
```

- 它**不是**平台的上游成本。平台自己的进货价与毛利只在平台端「财务与对账」看
  （`upstream_cost_fen` + 供应商核销），机构/学员看不到，避免把平台的成本与毛利摊出去。
- **一次调用若有主备切换，只计成功的那次**：失败与重试没有交付东西，不该让老师/学生看到重复消耗。
- **历史行不计入**：2026-09-13 之前没有算力账本，那些行没有售价证据 —— 按「缺证据不猜」不计，
  不是拿旧值或 0 顶替。

⚠️ 这条口径是 2026-09-15 修正过来的。在那之前，机构端这些地方读的是 `usage_records.cost_fen`，
而那一列现行代码**恒写 0**（平台承担算力成本、不扣学生），所以机构端课堂页那列
「这节课消耗」**永远显示 ¥0.00**，老师看不出任何消耗。更麻烦的是那一列还混了三种含义：

| 写入方 | 写进 `usage_records.cost_fen` 的是什么 |
|---|---|
| 现行生成链路 | `0`（口径：平台承担成本、不扣学生） |
| `vibecodingIllustrations.js`（改前） | **对外售价**（为了让「每节课花了多少」算上插画） |
| 2026-09-13 之前的历史行 | **积分时代**的旧值 |

现在已经改成读算力账本里的售价快照，插画那条路径也不再往成本列写售价（恢复「恒 0」口径），
插画照样被算进消耗 —— 它走的是 `getGenerationProvider`，本身就会写算力账本。

守卫：`p92-sale-price-scope.mjs` 钉住「消耗 = 对外售价（只计成功尝试）」以及
「平台成本口径没被改坏」（预算/成本仍读 `upstream_cost_fen`，未知单列不按 0）。

生产实测（2026-09-15，release `20260915T041031Z` / commit `8ee280d`）：那条真实调用的账是
**对外售价 100 分、上游成本 4 分、而 `usage_records.cost_fen = 0`** —— 三个数字互不相同，
正好能看出读的是哪一列。机构端调用列表、账单/用量总览（总计 / 按模态 / Top 学员）、
学员端 AI 中心**全部显示 100**，即对外售价口径生效。

## 上游合同单价（自动折算 COMPUTED）

在「模型与算力 → 渠道与模型配置 → 上游合同单价」按渠道填**与上游签的合同价**，单位一律「非负整数分」：

| 素材类型 | 字段 | 折算口径 |
|---|---|---|
| 文本 | `inputFenPer1kTokens` / `outputFenPer1kTokens` | 上游 token 回执 × 每千 token 合同价 |
| 图片 | `perImageFen`（+ `byResolution` 档位价） | 张数 × 每次价；配了档位价就以档位价为准 |
| 视频 | `perSecondFen`（+ `byResolution`）+ `audioExtraPerSecondFen` | 请求秒数 × 每秒价；含音频时加收每秒加价 |
| 音乐 | `perCallFen` / `perSecondFen` | 拿得到时长且配了每秒价就按时长，否则按次 |

- 两层价：**素材类型价**（本渠道共用）与**模型级覆盖**（`modelUnitPrices`），优先级 **模型 > 素材类型**；模型级留空即回落素材类型价。
- 每次调用后按用量证据（tokens / 张数 / 秒数 / 分辨率）折算，来源写成 `COMPUTED`；快照留住「当时的价 + 当时的用量」，**改价不追溯**。
- **缺用量或缺单价 → UNKNOWN，绝不按 0 计**。负数 / 非数字会被后端拒绝，界面上直接显示错误。

## 官方账单自动对账（拉取侧）

「模型与算力 → 财务与对账 → 供应商账单 → 官方账单自动对账」按账期去供应商账单接口把官方数字拉回来：

1. 选账户 → 配**适配器**（generic-http / openai-costs / anthropic-usage）、账单接口地址、方法、账期天数，勾选启用自动拉取。
2. 请求头只填非敏感字段；密钥类字段会被后端拒绝。**凭据单独设置，只提交不回显**，界面只显示「已配置 / 未配置」。
3. 点「立即同步该账户」或「立即同步全部启用账户」（定时任务每天按账期补拉一次）。
4. 看「最近同步状态与失败原因」与「官方账单快照」：失败只落一条 `FAILED` 快照与错误原文，**不写半截聚合**。
5. 对账表按 **账期 × 模型** 并排：官方账单合计 / 平台 `COMPUTED` / `ESTIMATED` / `REPORTED` / CSV 已核销 / 差异（官方 − COMPUTED）。

三条边界：

- **合同单价折算（COMPUTED）≠ 供应商最终账单**；它只是自动估值，付款以官方账单或 CSV 核销为准。
- **官方账单是账期聚合**，不是逐笔明细（快照按「账号 + 账期 + 响应哈希」幂等，同一账期只认最新一份）。
- **CSV 手工导入保留为兜底**：接口不可用、上游不给历史账期、或需要票据级明细时，仍用上面的 CSV 路径核销。

缺失或未知一律留空并注明原因（官方没有这个模型 / 平台没有 COMPUTED 折算 / 平台有成本未知的调用），
「严格合计」留空时会另给一份「已拿到部分」的加总，两者不可混读。

## 更省事的一条路：直接读上游回传的逐笔实扣

如果上游在任务终态回执里**直接给出本次实际扣了多少钱**，那比事后拉账单更准，也根本不用配适配器：
平台把它按 `REPORTED` 收下来即可（来源优先级最高）。当前已接上的上游是 Seedance 直连
（`api.seedance.nz`，生产里图片 / 生视频 / 音乐三个渠道用它）：

- 实扣在 `usage.amount` + `currency`，位置按协议分三种（`data.usage` / 顶层 `usage` / `task.usage`）。
- **实测币种写法是 `¥`，不是文档示例的 `CNY`**；`CNY`/`RMB`/`¥`/`CN¥` 都按人民币认，`USD`/`$`/`JPY` 不认。
- 金额是小数元（实测 6 位小数），换算成整数分时才四舍五入。
- 这个上游**没有账期账单接口**，所以上面那套适配器对它用不上；余额接口（`GET /api/usage/wallet/`）
  可以另做一道总账校验。

口径、合同单价填法、实测数据与边界见 `docs/operations/上游实扣接入-20260915.md`。

## 日常操作

1. 在「模型与算力 → 渠道与模型配置 → 对外售价（观测口径）」先定对外价：按对话 / 图片 / 视频 / 音乐填模态基础价，再按渠道里的模型单独覆盖。这只是对外公告价。
2. 在同一个渠道卡片里填「上游合同单价」（素材类型价 + 模型级覆盖，单价单位是分）；填了它，调用账的「上游计费」会自动出现 `COMPUTED` 折算值，不用再手工填估算成本。上游是「按实际消耗结算」、没有发布单价的渠道（如 Seedance 的图片 / 音乐）**不要猜着填**，逐笔实扣会以 `REPORTED` 自动进来。
3. 在“次数授权管理”选择课包和机构，追加次数时填写实际成交总额、CNY、已收款、订单号和合同号。未付款或部分付款批次不能给学生发许可。
4. 在“模型与算力 → 财务与对账 → 供应商账单”创建供应商账户。账户只保存标识、关联渠道、币种和时区，不保存 API Key。
5. 下载 canonical CSV v1 模板，把供应商导出的账单映射到模板。支持 USAGE、REFUND、CREDIT、ADJUSTMENT、TAX；金额使用有符号最小货币单位整数。
6. 先执行“严格校验并预览”，确认行数、币种、金额和请求证据，再确认导入。重复文件和冲突行会拒绝，不静默覆盖。
7. 在“匹配与核销”处理未匹配或有歧义的行。系统只自动确认唯一精确 ID；人工匹配、拆分、排除、争议和取消必须填写原因并写审计。
8. 回到“调用账”看逐笔「对外售价 / 上游成本 / 实际核销 / 差额」，再用上方的模态、渠道、模型、机构、学员汇总看总量对照。
9. 在“三账与毛利”按机构、学生、课包和币种看收入侧与真实毛利。
10. 想少手工搬账单：在上一个面板的「官方账单自动对账」配好适配器 / 端点 / 凭据，点「立即同步该账户」，直接看「账期 × 模型」的官方 vs 平台口径对照。

## CSV v1

固定表头：

```text
schema_version,provider,provider_account_id,invoice_id,line_id,line_type,occurred_at,currency,amount_minor,original_line_id,usage_id,response_payload_id,response_request_id,request_id,task_id,gateway_id,description
```

- `schema_version` 固定 `v1`。
- `occurred_at` 必须是带时区的 ISO 8601 时间。
- `USAGE`、`TAX` 为正数；`REFUND`、`CREDIT` 为负数；`ADJUSTMENT` 不得为 0。
- 退款和贷项用 `original_line_id` 关联原消费，累计不得超过原消费。
- 标识、金额和时间字段拒绝公式载荷、科学计数法和未知币种。

## new-api 的位置

new-api 不是三账对照的前置条件。没有 new-api 时，平台直连渠道并保存 request/response/task/usage ID，仍可通过供应商 CSV 完成真实核销。部署 new-api 后，文本与图片多一层网关日志证据，可提高自动匹配率；网关 quota 仍不是供应商最终账单。视频和音乐继续使用直连任务 ID 对账。

## 历史与边界

- 历史授权只迁移未使用余额，金额和币种保持未知；不能用当前目录价倒推历史收入。
- ESTIMATED、REPORTED、COMPUTED（按合同单价折算的自动估值）和 new-api quota 都不覆盖供应商结算成本。
- 首版提供严格通用 CSV。拿到具体供应商原始账单样本后，再增加该供应商的一键映射模板，不猜表头、时区或计费单位。
- 所有人工核销动作保留原因与审计；取消匹配不会删除原账单行。
