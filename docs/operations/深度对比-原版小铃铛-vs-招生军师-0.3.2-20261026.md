## 二、原版真正的产品心智模型

原版不是“几个表单页面”，而是一个 **Chat-first 的创作工作台**：

```text
对话 / 今日选题
→ 选文案大脑或同行参考
→ 创作卡片在消息流内展开
→ 选版本 / 双击改稿
→ 内容方案
→ 编导稿与分镜
→ 确认渲染 / 数字人合成
→ 成片进入素材库
→ 发布包 / 发布
→ 数据复盘 / 周期计划
```

关键不是功能数量，而是三件事：

1. **所有工作流都长在消息流里**：创作、爆款复刻、热点结合、内容方案都是卡片状态机，不是独立表单。
2. **过程一直可见**：排队、提取原文、流式写稿、审稿、渲染、失败重试都有阶段状态。
3. **上下文持续积累**：账号档案、长期记忆、文案大脑、同行研究简报、素材分析共同进入下一次创作。

我们当前网页端已经学了大部分卡片和状态机；原生客户端 0.3.2 则选择了“功能收口”，所以看起来更像一个简洁的客户交付工具，而不是原版工作台。

## 四、“哪些是我们密钥实现的”

这里的“我们的密钥”要分成三类，不能混成一类。

### 1. DeepSeek 文本 / 搜索渠道 Key

用途：

- 对话、文案生成、编导稿、方案、数据洞察；
- 今日选题、爆款复刻、热点结合中的模型处理；
- 热点联网搜索：DeepSeek 官方 Search API；
- 作品数据截图识别回填（TEXT 渠道的图像理解能力）。

已覆盖原版：

- 小铃铛文本能力；
- DashScope/Qwen 文本与搜索的一部分；
- Gemini 快速档的部分替代；
- 原版截图回填/多模态分析。

当前状态：

- 生产渠道已跑通；
- 热点搜索已生产实测；
- 截图回填已生产实测；
- 模型名以生产渠道配置为准，代码不依赖用户端 Key。

### 2. seedance.nz 聚合渠道 Key

这一把 Key 覆盖了原版最容易分散的多条外部能力：

| 能力 | 我们用的实现 | 已验证情况 | 桌面是否已暴露 |
|---|---|---|---|
| 视频生成 | MiniMax-H3 / Seedance / Wan | 生产真实渲染通过 | 是，单条任务 |
| ASR 转写 | whisper-1 + 音频切片 | 185.6MB / 135.8MB 视频实测通过 | 是，同行/自己作品 |
| TTS | doubao / MiniMax speech 等 | 生产数字人链路通过 | 否，仅网页 |
| 数字人底片 | i2v 生成人物底片 | 生产付费冒烟通过 | 否 |
| 对口型 | kling-lip-sync | 生产付费冒烟通过 | 否 |
| 图片生成 | 平台图片模型 | 已生产验证 | 否，当前桌面不需要 |
| 图片/视频回流 | `/v1/files/upload` 24h 直链 | 已生产验证 | 后台使用 |
| 音色克隆 | doubao/minimax voice clone | 上游不稳定，当前优先参考音频直出 | 否，网页有 |

结论：

- 原版用 `toapis.cn` 做视频、用 DashScope 做 ASR/TTS/多模态的那部分，大部分已经能用 **同一把 seedance.nz 渠道 Key** 等价实现，不需要新增一套用户侧 Key。
- 数字人和视频已经过真实付费冒烟，不是只有演示。
- 音色“训练式克隆”仍是上游稳定性风险；参考音频直出可用，但不应宣称等同稳定克隆。

### 3. 阿里云 OSS Key

用途：

- 素材、成片、发布包的持久化；
- 签名 URL 下载；
- 大文件 Range、视频播放、ZIP 下载。

这不是创作能力 Key，但它是原版本地素材库迁移到平台化后的关键基础设施。

### 4. 不需要 API Key 的部分

| 能力 | 实现方式 |
|---|---|
| 抖音主页/作品采集 | 本机浏览器 + CDP + F2 开源 worker |
| 同行收藏/主页管理 | 本地采集 + 平台存元数据 |
| 视频包装 | 服务端 ffmpeg + 素材库 + 发布包 ZIP |
| 发布 | 人工发布，不自动操作平台账号 |
| 桌面托盘/通知/自动更新 | Electron 本地能力 |
| 登录态保存 | Electron safeStorage 加密 |

### 5. 与原版 Key 架构的根本差异

原版是“用户自己填 Key”：

```text
用户机器
→ toapis_key / dashscope_key / gemini_key / local_asr_key
→ 直接请求外部模型
```

我们是“平台集中管理”：

```text
客户端
→ 平台账号登录
→ 平台 API
→ 平台加密渠道 Key
→ DeepSeek / seedance.nz / OSS
```

这带来三个结果：

1. 用户不用自己找 Key，交付更像 SaaS；
2. 密钥不进入 renderer，安全边界更好；
3. 但所有渠道成本、配额、故障都由平台承担和排障。

## 五、当前最大的真实差距（按影响排序）

### P0：原生客户端没有 Agent 对话和工作流卡片

这是“最不像原版”的地方。

原版用户一进来就是和 Agent 对话，创作、复刻、热点、选题都从聊天里长出来。  
我们桌面端一进来是 5 页工具导航，做内容还是“填一句话 → 生成 3 版”。这会显著改变产品心智。

### P0：文案大脑 / 同行研究简报未进桌面

服务端已有：

- 转写档案；
- 时间码证据；
- 蒸馏大脑；
- 同行研究简报；
- 创作时选择大脑。

桌面只到“参考这条写一条”，没有“为什么这样写”“这个同行的方法是什么”“把这个方法沉淀成大脑”。

### P0：视频工作台被压成单条制作

已有：

- 编导稿修改；
- 分镜；
- 渲染；
- 发布包。

缺：

- 模式选择：分镜生成 / 爆款复刻 / 口播成片 / 一键托管；
- 项目列表和恢复；
- 模型/类型/比例/时长/钩子策略；
- 单镜试渲染、原帧抽取、分镜复刻；
- 任务队列；
- 数字人、音色库。

### P1：素材中心缺失

原版素材库是生产资产中心：树形文件夹、分析、可复用片段、成片画廊。  
桌面目前只能下载成片/发布包，不能管理创作资产。

### P1：内容计划/周期/任务中心缺失

桌面有数据建议和单条制作，但没有：

- 方案库；
- 周期日历；
- 历史任务详情/重试；
- 计划 → 制作的批量入口。

### P1：数据复盘仍偏轻

桌面只有汇总与 AI 建议；原版有：

- 截图回填；
- 指标趋势；
- 方案/周期关联；
- 策略快照；
- 任务与内容的全链路追踪。

### P2：用户自助配 Key / 价格 / 激活/计费

这是原版的商业系统，我们明确不做同构复刻，继续走平台机构账号与后台计费。

## 八、一句话判断

**底层能力已经接近能打，网页工作台也开始像原版；真正拖后腿的是原生客户端把工作流压缩成了工具页面。**

当前最划算的投入不是再重写模型链路，而是把平台已有的：

```text
工作流 + 文案大脑 + 同行简报 + 视频工作台 + 素材中心 + 任务中心
```

逐步接进 0.3.x 的原生客户端，同时保留“5 个一级入口”的简洁外壳。
