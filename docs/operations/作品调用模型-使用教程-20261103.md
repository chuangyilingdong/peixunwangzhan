# 作品调用模型 · 使用教程（2026-11-03）

> 目标：某节课的学生作品，在运行时自动用平台配置的 Key（默认 GLM-4-Flash），
> 学生不用自己填 Key；老师预览、广场、学生主页也能用。
>
> ⚠️ 两个独立的东西，别混：
> - **Agent 的文字渠道**（渠道与价格 → 文字主渠道）：学生跟 AI 对话、AI 帮学生写代码用的模型；
> - **作品调用模型**（AI 能力与价格 → 作品调用模型）：学生**做出来的作品**在运行时调用的模型。
>
> 本节课开关只影响后者，不改 Agent 的模型。

## 一、平台一次性配置

后台 → **AI 能力与价格 → 作品调用模型**：

1. 调用地址：`https://open.bigmodel.cn/api/paas/v4/chat/completions`
2. 模型 ID：`glm-4-flash-250414`
3. API Key：粘贴平台 Key（只写不读）
4. 单次最大输出 tokens / 温度 / 超时：按需
5. 配额：建议先小额度（公开页尤其）
6. 打开 **总开关**
7. 点 **「试一次」**，看到「连接成功」

> 这一步只做一次；改 Key/模型/配额也是在这里。

## 二、按课时打开

后台 → **课程 → 课时 → VibeCoding 入口**：

1. 勾上 **「作品使用平台模型」**
2. 保存

生效范围：

- 只有勾了的课时，平台才会给它的作品发授权；
- 没勾的课时保持「学生自己填 Key」；
- 保存后**不需要重启服务**；学生/客户端下一次拉 `client-context` 或重新打开作品预览就会拿到授权。

## 三、学生怎么操作才会触发

**触发点不是“对 Agent 说一句话”，而是作品运行时真的调用了 `/api/llm`。**

学生正常流程：

1. 老师开始这节课，学生进入客户端；
2. 学生让 AI 生成/修改作品（正常对话即可）；
3. 学生打开作品预览，**在作品自己的界面里操作**：
   - 作品有对话框 → 输入问题、点发送；
   - 作品有“生成/总结/推荐”按钮 → 点按钮；
   - 作品调用 `POST /api/llm` → 平台的桥自动带上平台授权。
4. 学生**不需要**填 API Key；作品里就算有“接口设置”，也可以留空。

> 如果作品本身没有任何调用大模型的代码，那就不会触发，也不会消耗额度。
> 学生想让作品“能对话”，可以让 AI 生成一个带聊天框、调用 `/api/llm` 的网页。

## 四、给学生的示例提示词

在客户端里对 Agent 说：

```text
做一个简单的聊天网页：一个输入框、一个发送按钮、一个消息列表。
发送时调用 POST /api/llm，body 是
{ messages: [{ role: 'user', content: 输入内容 }] }，
把返回的 content 显示在消息列表里。
不要生成 API Key 输入框，也不要硬编码任何 Key。
```

生成后打开预览，输入“你好”，能收到回复就说明平台模型已生效。

## 五、验证是否生效

### 后台

- **作品调用模型 → 今日用量**：学生调用后，总调用次数会增加；
- 用量表里能看到 `classroom` / `preview` / `public` 的计数。

### 学生端

- 作品里不填 Key，发消息能收到回复；
- 如果作品有 Key 输入框，留空也能用。

### 老师端 / 广场 / 主页

- 老师打开课堂作品预览，作品里的对话/按钮能正常调用；
- 作品发布到广场、学生主页、分享页后，手机打开也能用；
- 这些入口只有在**作品所属课时勾了开关**时才生效。

## 六、排错

| 现象 | 检查 |
|---|---|
| 作品提示「还没有填写 API Key」 | 课时开关没勾/没保存；或客户端没拿到 `worksLlm`；或客户端版本旧（没透传 `worksLlm`） |
| 后台「试一次」失败 | Key/模型/地址不对；先修「作品调用模型」配置 |
| 学生端能用、老师端不能用 | 老师端预览接口没拿到 `worksLlm`（平台版本/作品所属课时没勾） |
| 广场/主页不能用 | 课时开关没勾；或公开 scope 关了；或配额用尽 |
| 提示「今天的额度已用完」 | 后台「作品调用模型 → 配额」调大，或等 UTC 次日 |
| 课堂结束就不能用了 | 正常：课堂授权只在课堂进行中有效；老师预览/广场按作品所属课时重新发授权 |
| 学生填了自己的 Key，还是走平台 | 正常：课时勾了就是平台优先；作品显式写 `usePlatform: false` 才用学生自己的 Key |

## 七、客户端要求

客户端必须：

1. 用 2026-11-03 之后的 `packages/shared`（含 `worksLlm` 参数与平台优先规则）；
2. 把 `client-context.worksLlm` 透传给 `buildPreviewDocument(files, entry, { worksLlm })`；
3. 把 `GET /api/student/works/VIBECODING/:id` 的 `worksLlm` 同样透传（学生查看自己已提交作品时）。

客户端不需要知道课时开关：勾了就有 `worksLlm`，没勾就是 `null`。

## 八、边界

- 课堂内实时预览：课堂进行中才有效（老师一结束课堂，课堂授权立即失效）；
- 提交后的老师预览/广场/主页：按**作品所属课时**的开关判断，保存开关后即时生效；
- 配额：每学生/每作品/每 IP/全平台每天 + QPS，后台可调；
- 总开关关闭：所有作品的平台模型立即失效，回到「学生自己填 Key」；
- Key 永不下发：作品文档里只有短期 grant。
