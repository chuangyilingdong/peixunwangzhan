# 平台端 AI 能力与 CU 配置 —— 重梳理（2026-09-18）

> 用户原话：「现在平台端的 AI 能力与 CU 配置现在好好梳理下，很多无用的功能和逻辑很绕和重复的逻辑。
> 现在这个好乱好乱，我都不知道如何配了。必须做大量的减法。」
> 五条诉求：① 每个模型知道成本价（能 API 取就取、取不到让我们填）② 课程的算力上线预估在创建课包时填、
> 按成本价来 ③ 保留对外价格配置、仅用于统计 ④ 多渠道路由 ⑤ 每节课每个学生的实际算力消耗。
>
> **先说结论**：现在的配置面不是"功能多"，而是**同一件事有 3~6 套并行实现，其中大部分从不生效**。
> 量化基线（实测，不是感觉）：一个页面有 **4 个名字**、**6 个视图**、要人填 **≈130–320 个字段**
> （而真正拦住保存的只有 **4 项/渠道**）；**上游成本有 4 套机制**（填了合同单价，另两套就是白填）；
> **"学生的算力上限"有 6 套实现，只有 1 套真的会拦人**（而且它数的是**次数**不是钱）；
> **8 个后端端点前端从不调用**；1 个死组件；**5 张零业务引用的表**。

## 一、乱在哪：一张表看清"几套并行的同一件事"

| 概念 | 现在有几套 | 哪一套真在跑 | 其余是什么 |
|---|---|---|---|
| **上游成本价** | **4** | ③合同单价（`channel.upstreamUnitPrices` / `modelUnitPrices`）→ 落 `compute_attempts.upstream_cost_fen`，`cost_source=COMPUTED` | ①渠道级估算 `estimatedCostFen`、②逐模型估算 `modelCosts`（两者优先级低于③，**填了③就完全被忽略**）、④`platform_modality_settings.unit_cost`（**没有 UI 入口**，全仓只有它自己的读写） |
| **对外价格** | 1 | `compute_pricing`（`platform_settings` 的 JSON 列）→ `compute_attempts.sale_price_fen`，只进报表 | 与成本价**完全独立**：不同 API、不同面板、无加价率、不追溯改价。它**不扣任何人的钱** |
| **供应商** | **2** | `channels[]`（渠道列表） | 顶层 9 个字段（`provider/model/endpoint/displayName/note/websiteUrl/endpointMode/protocol/modelMappings`）= **永不触发的死路径**（UI 一个输入框都没有，后端还完整校验 + 落库） |
| **供应商账单** | **2** | 都不用 | CSV 手工导入（`supplier_billing_*` 4 张表）与账单 API 拉取（`provider_bill_*` 2 张表），**两套表两套路由一张页面上两个面板**。页面自己写着"我们上游是逐笔实扣，这里通常是空的 —— 不需要配"（`ModelCompute.jsx:48-50`） |
| **学生的算力上限** | **6** | 只有 `class_sessions.student_call_cap`（课堂×学生的**次数**上限）真的会 403 | ②课包 CU 额度（`student_course_cu_quotas/_ledger`：**`cu_limit` 全仓无人写** → 恒 UNLIMITED，两张表永远空）、③`platform_credit_quotas`（死表）、④`org_ai_budgets`（死表，且**建表写了两次**）、⑤`billing_packages.monthly_credits/bonus_credits`（积分时代遗留列）、⑥`per_student_budget_fen`（已降级为 write-only 兼容桩，`computePool.js:109-116` 恒返回 null） |
| **"记账"** | 3 | `usage_records`（事件流水，**钱的两列恒 0**：`creditUsage.js:31`） | `credit_entries`、`personal_credit_ledger`（均为死表） |

**"看着配了、其实不生效"的三个典型**（最坑人）：
1. **填了合同单价，另外两套成本估算就是白填** —— 取值链 `MOCK > REPORTED > COMPUTED > ESTIMATED > UNKNOWN`
   （`generationProvider.js:165-167`），而三者在 UI 上**挤在同一张渠道卡里**，用户不知道填哪个算数。
2. **备用渠道只在"没走算力网关"时才生效**（`generationProvider.js:126`）；
   且只有"明确的受理前拒绝"才切换（已输出/已提交/超时/网络歧义一律不切，`:198-200`）。
   另外网关模态白名单**只有 TEXT/IMAGE**（`computeGateway.js:24`）→ **视频/音乐永远直连、永远没有备用渠道**。
3. **`protocol` 字段**：UI 文案写"保留但暂不使用"（`BillingPanels.jsx:400`），
   但 `runtimeGateway.js:309-314` 还在按它拼路径（`ANTHROPIC` → `/messages`）。
   如果历史数据里存着 `ANTHROPIC`，用户**在界面上看不到也改不掉**。

## 二、你的五条诉求，逐条对现状

### ① 每个模型的成本价 —— 能自动取的比你想的多，但没有"价目表 API"

**现状**：4 套入口（见上），**全靠人工填**。仓库里没有任何"从上游拉价目表"的代码。

但要纠正一个前提：**上游确实没有价目表 API 可拉**（现有的两个"自动"都不是价目表）：
- 拉的是**模型清单**（`billingConfig.js:372-392`）：只有 id / 显示名 / 上下文长度，**不含任何价格字段**；
- 逐笔回传的是**实扣金额**（`REPORTED`，`openaiCompatibleProvider.js:108`）。

**所以更好的路是：用"实扣金额 ÷ 用量"反推实测单价**，而不是让你手填。
我们已经在逐笔收实扣金额了（`compute_attempts.upstream_cost_fen` + `usage_snapshot`），
按 (渠道, 模型, 模态) 滚动聚合就能得到"实测单价"，再与合同单价对照 —— 这也顺带解决
"实际成本与报价对不上"的对账问题（现在对账是另一套 CSV/API，见减法 #2）。

### ② 课程算力预估 —— 字段有、能填、官网还展示，**但从来没和实际消耗对比过**

- 字段：`course_series.estimated_credits_per_person`；填空在平台端课包编辑器
  （`CourseManagement.jsx:594/632`），官网课包详情还显示"预估消耗 **灵动值**/人"（`website/src/main.jsx:327`）。
- **全仓只有"写入 / 回显 / 官网展示"三处，没有任何代码把它和实际消耗做过对比** → 现在是一份死数据。
- 同名的 `per_student_budget_fen`（课时/课包各一列）也已成 write-only。
- 因此你要的"按成本价填"，缺的不是入口，而是**让这个数字有用**（对比、预警，见第五节的决策 3）。

### ③ 对外价格 —— 已经在做"仅统计"，问题只是它和成本价分居两处

`compute_pricing` 的语义边界写得很清楚（`computePool.js:33-46`）：**不扣学生、不是上游成本、
不作为课堂预算基准**，只进报表（`financialReporting.js:30/101/500`）。
要改的只是**把它和成本价放到同一个地方填**（一张价目表两列），而不是两个 API、两个面板。

### ④ 多渠道路由 —— 机制齐了，但有三条硬约束会让它"看着配了其实不生效"

选渠道的优先级（`aiGeneration.js:445-462`）：`modelRoutes[]` 精确命中 → `modalityChannels[模态]`
→ 旧单渠道配置（`channelId='default'`）。备用在 `modalityBackupChannels[模态]`
或 `modelRoutes[].backupChannelId/backupModel`。三条约束见第一节末。

### ⑤ 每节课每个学生的实际消耗 —— **算得出来，而且数据齐**

- **唯一正确口径**：`compute_attempts.sale_price_fen` 且 `status='SUCCESS'`
  （定义只有一处：`computePool.js:74-105`）；真实成本是同一张表的 `upstream_cost_fen`。
- **粒度数据齐备**：`compute_attempts` 的 `class_session_id / lesson_id / user_id` 三列都在
  （建表补列 `schema.js:1390-1391`），`GROUP BY class_session_id, user_id` 是现成可行的。
- **已经固化了一处但没人看**：结课时 `session_students.completed_cost_fen`
  （`classroomSessions.js:167` 写入）—— **三个前端 0 处渲染**。
- **缺口只有一个**：报表的分组维度只有 模态/渠道/模型/机构/学员，**没有 课包/课时 分组**
  （`financialReporting.js:439-445`），所以"课包 × 学生"的聚合目前没有接口。
- 顺带一个口径不一致要记住：平台端"调用账"**按每次尝试各计一行**，机构端**每次调用只取第一条成功尝试**
  （`orgAdmin.js:578-580`），`computePool.js:76-78` 明确警告过"两者用途不同，别互相对数"。

## 三、目标模型（提议：配置面从"20+ 屏长表单"压到 **3 处**）

**唯一的真相表 —— 价目表（键 = 渠道 × 模型）**，一行就是"这个渠道的这个模型多少钱"：

| 列 | 来源 | 说明 |
|---|---|---|
| 成本价 | **优先自动**：由实扣反推的实测单价回填（可一键采纳）；也可人工覆盖 | 按模态计价：TEXT 分/百万 token、IMAGE 分/张、VIDEO 分/秒、MUSIC 分/次 |
| 对外价 | 人工填（或按成本价 × 系数批量生成） | 只进统计，不扣钱 |
| 能力 | 沿用现有声明（比例/清晰度/时长/音频/曲风/生成模式） | 只在需要时展开 |
| 备注 | 合同号/供应商账户标识 | |

**渠道页只留 4 项必填**（名称 / 调用地址 / 可用模型 / 默认模型）+ 密钥，
价格与能力**全部移出渠道卡**，进价目表。这样：
- 同一模型不再在 4 个地方各填一次；
- "填了哪个算数"这个问题消失（只有一处）。

**课程侧**：创建课包/课时时填"算力预估"（默认按所选模型的成本价 × 预估用量算出来，可改），
并把"预估 vs 实际"的对比做进课包详情（这是你诉求 ② 真正想要的东西）。

**机构/学生侧**：不再有独立额度配置（见减法 #4），消耗只做**统计展示**。

## 五、要你定的四件事（决定"减法"的边界）

1. **供应商账单那两条线（CSV 导入 + 账单 API 拉取）整体下线？** 6 张表 2 套路由 2 个面板，
   而我们上游是逐笔实扣、账已经在 `compute_attempts` 里，页面自己都写着"通常不需要配"。
2. **成本价的主要来源**：用"实扣反推的实测单价"（自动，可人工覆盖），还是坚持人工填合同单价？
3. **课程的算力预估要不要"咬人"**：现在填了没人看。改成 (a) 只展示 + 超预估预警，
   还是 (b) 真的拦截（超预估就不让继续调用）？（现在唯一会拦的是课堂**次数**上限）
4. **"学生算力上限"保留哪一套**：建议只留一套"按钱"的（基于成本价、按课包/按课堂），
   其余 5 套删掉；也可以选择"什么额度都不要，只统计"。
