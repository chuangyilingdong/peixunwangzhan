# 客户端换域名改动清单（2026-09-23）

> **给做客户端的人看。** 平台侧已于 2026-09-23 从 `iicili.cyou` 迁到 **`aicyld.com`**，
> 客户端里钉的是旧域名，而**旧域名被阿里云备案拦截**（`http://` 回拦截页、`https://` 直接 RST）——
> 所以**已经装出去的客户端现在就连不上**，这跟搬不搬家无关。
>
> 这份清单只描述**要改什么**。改动本身请在**客户端仓库**里做（`E:\灵动ai客户端`）。
> 平台仓库这边**不做也不应该做**客户端的改动。

## 要改的一共 5 处（2026-09-23 逐文件实查）

### ① 两处域名兜底（最关键）

两个文件里各有一行同样的兜底值，都是**旧域名**：

```text
deploy/desktop/client-patch/platform-gate.ts:35
   const API_BASE = String(process.env.LINGDONG_API_BASE || 'https://iicili.cyou').replace(/\/$/, '')

deploy/desktop/client-patch/LingdongUpdater.ts:15
   const API_BASE = String(process.env.LINGDONG_API_BASE || 'https://iicili.cyou').replace(/\/+$/u, '')
```

改成：

```ts
'https://aicyld.com'
```

- `platform-gate.ts` 管**登录门 / 课堂上下文 / 网关 / 作品上传**的地址；
- `LingdongUpdater.ts` 管**自动更新**读清单和下载安装包的地址 —— 两个都要改，只改一个会留下
  "能用但更新不了"或"更新正常但登录不了"的半坏状态。

> **为什么不只是"打包时 export 一个变量"**：`scripts/build-win.sh` **没有**设
> `LINGDONG_API_BASE`（实查过），所以实际生效的就是这两行兜底值。可以顺手在打包脚本里
> 也 export 上（双保险），但**代码里的兜底必须一起改** —— 否则谁忘了导变量，出来的包就是连旧域名的。

### ② 发布脚本连的服务器

```text
deploy/desktop/publish-client.sh:14
   HOST="${PUBLISH_CLIENT_HOST:-root@39.106.183.200}"      ← 旧机（已冻结，不要再往上发）
```

改成新机：

```bash
HOST="${PUBLISH_CLIENT_HOST:-root@8.134.80.184}"
```

⚠️ **旧机已经不接受任何使用**（平台服务、学生环境、定时任务都停了，只留 SSH 作参考），
往它上面发版等于发到一台死机器上。

### ③ 发布后的验证地址

```text
deploy/desktop/publish-client.sh:57
   ... curl -sI -m 20 'https://iicili.cyou/downloads/$NAME' ...
   ... curl -s -m 20 'https://iicili.cyou/downloads/manifest.json' ...
```

把这两处的 `iicili.cyou` 改成 `aicyld.com`。否则脚本的"发布后自检"永远失败，
你会以为发布没成功（其实发布成功了，是自检打在了死域名上）。

### ④ 接口契约文档里的说明

```text
docs/平台接口契约.md:22
   基线地址：`LINGDONG_API_BASE`（客户端里默认 `https://iicili.cyou`，本机验证时指到本地平台）。
```

改成 `https://aicyld.com`。**契约文档是两个仓库的共同依据**，留着旧域名会让下一个人再踩一次。

### ⑤ 版本号（不用改，只是提醒）

`scripts/build-win.sh:23` 里已经备好新版本号：

```bash
export LINGDONG_CLIENT_VERSION="${LINGDONG_CLIENT_VERSION:-0.1.7-alpha.2.1}"
```

也就是说**这次出包应该发 `0.1.7-alpha.2.1`**（当前线上是 `0.1.6-alpha.2`），
学生那边才会收到更新提示。

## 改完怎么出包、怎么发布

```bash
bash scripts/build-win.sh                                    # 出包
bash deploy/desktop/publish-client.sh                        # 传到新机并更新 manifest
```

发布脚本会把安装包传到新机的 `/srv/ai-kids-platform/downloads/`，
并写回 `manifest.json`（**manifest 里只有文件名、没有 URL，所以它本身不用改域名**）。
nginx 的 `location ^~ /downloads/` 直接映射那个目录，传完即可公网下载。

## 发布后怎么验（照做即可）

```bash
# ① 清单与安装包都能公网取到
curl -s -m 20 https://aicyld.com/downloads/manifest.json | head -c 300
curl -sI -m 20 https://aicyld.com/downloads/lingdong-client-0.1.7-alpha.2.1-win-x64.exe | head -3

# ② 清单里的 version / size / sha256 要与实际文件一致
#    脚本自己会核对（它上传后会用 stat 与 sha256sum 比对），这里只是复核

# ③ 真机验证（最要紧的一条）：装一版新客户端，走一遍
#    登录 → 进入课堂上下文 → 发一条消息 → 提交一次作品
#    平台侧可以在服务器上核对：
#      journalctl -u learning-platform-production -n 50 --no-pager | grep -iE "gateway|submit-upload"
```

## 两个仓库的约定（别漏）

- **接口契约以客户端仓库的 `docs/平台接口契约.md` 为准**；改契约必须**两个仓库同时改**，
  并在那份文档末尾记一行（日期 / 改了什么 / 两侧提交）。
- 平台侧要验"客户端能不能上课"，用平台仓库的 `scripts/dev-bench.mjs`：
  它起一套临时库的平台（种子账号 `student-1/study123`），客户端把 `LINGDONG_API_BASE`
  指到它的端口即可联调。判据：发一条消息后平台 `usage_records` 记 SUCCESS、
  `session_students.vibecoding_sends` 恰好 +1。

## 附：这次改动**不需要**动的东西

- `manifest.json` 本身（只有文件名，没有 URL）；
- 上游 `deepseek-harness` 的 pin（仍是 `dsh-v0.1.6-alpha.2`）与打包方式；
- 平台侧那三个交付面（`client-context` / `gateway/v1/chat/completions` / `submit-upload`）
  与登录接口 —— 它们只在域名上变了，路径与协议一个都没动。
