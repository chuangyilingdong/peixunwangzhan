## 二、这一轮做了什么

### A. 删掉登录页的「演示账号」（用户图1：「演示账号这些全部删除」）

那一排长在 `LoginPanel` 里（`packages/shared/src/ui.jsx`），平台端与机构端各传一组：

```text
平台端 apps/admin/src/shared.jsx ：'平台超管' root / admin123
机构端 apps/org/src/main.jsx     ：'机构管理员' org-admin / org123、'授课教师' teacher-1 / teach123
官网   apps/website/src/main.jsx ：早就传的是空数组（所以官网那一侧一直没显示 —— p115 钉着这条）
```

**删掉的不是"不好看"，是这一条**：那几个口令**明文写在前端包里**，打包出来的 `.js` 谁都能下载；
而且它指的是**生产上真在用的账号**（seed 里那几个人就是线上账号）—— 点一下「使用」等于把生产账号的
口令发给任何访客。所以这一轮把**区块 + prop + 样式 + 两端的传参 + 官网那处 `demos={[]}`** 一起删干净，
免得下一个页面又顺手传一组进来。

⚠️ **删的是"登录页那一排"，不是账号本身**：`root` / `org-admin` / `teacher-1` 照旧由 seed 建出来
（开发、p19/p134 这些守卫都要用）—— 守卫 p136 把这两件事**同时**钉住，免得下一轮有人把这条
误解成"删账号"。

核验：真浏览器（`.tmp/then-login-no-demo.mjs`）三端登录页各看一遍 —— 机构端 / 平台端 / 官网
都是「登录表单在 · `.demo-list` 0 个 · 「演示账号」字样 false · 「使用」按钮 0 个」；
线上同样三项全过（截图在服务器 `/tmp/live-r29-*.png`；本机副本见 §六）。

### B. ⭐ 三端「自助修改密码」（用户：「他们应该是有自行修改密码的按钮和操作」）

**做之前先把三端的现状摸清**（这一步花的时间最多，也最值）：

```text
平台端 SUPER_ADMIN  ：接口有（PUT /api/admin/me/password，p19 钉着）+ 界面有（应用壳的 🔑 → /security）
学生端 STUDENT      ：接口有（PUT /api/student/account/password，p37 钉着）**但界面上没有入口**
                      —— 学生自己改不了，只能让老师/机构管理员替他改
机构端 ORG_ADMIN/TEACHER：**连自助接口都没有**。orgAdmin.js 里只有
                      `PUT org/members/:id/password`（机构管理员改**本机构成员**的密码，改的是别人）
```

于是"创建账号时发的那个临时口令"三端都改不掉 —— 这正是用户那句话指的东西。

**服务端**：新增 `PUT /api/org/me/password`（`apps/server/src/routes/orgAdmin.js`，放在 `handleOrg`
最前面紧跟 `auth`：这是"对自己"的操作，不依赖任何机构权限域）。三条与另两端逐字对齐：

```text
① 必须验**当前密码**（只凭一个已登录的会话就能改密 = 捡到一次登录就能把别人的账号锁死）；
② 成功后撤销该账号**所有**会话（含当前这一处）→ 界面只能回登录页重新登录；
③ 新密码 ≥6 位、且不能与当前密码相同。
⚠️ 只按主键 id 定位，不再叠 org_id 之类的条件 —— 多一个条件就多一种"UPDATE 匹配到 0 行却照样
   返回成功"的静默失败；写完当场核对影响行数（≠1 就 conflict 报错，PASSWORD_WRITE_FAILED）。
```

**界面**：新建 `packages/shared/src/account.jsx` 的 `PasswordChangeForm`，**三端共用这一份**
（平台端那页也换成了它，不再各写一份；三处的校验规则、错误文案、成功行为从此不会各说各话）。
入口三处：

```text
· 平台端：应用壳侧栏 🔑 → /security（原来就有，只是表单换成了共用组件）
· 机构端：应用壳侧栏 🔑（onChangePassword）+ 左侧导航「账号安全」→ /org/account ← **新页面**
          ⚠️ 机构管理员与老师用的是**两份导航**（老师那份是另写的），两份都要加 —— 只加一份就是
             "机构管理员看得到、老师看不到"这种半边生效
· 学生端：右上角用户名下拉「账号安全」→ /account ← **新页面**（未登录会被带去学生登录）
```

⚠️ **平台端的返回体补了一个字段**：`sessionsRevoked`（**加法**，`reauthRequired` 一字不动 —— p19
钉着它）。三端界面共用同一个组件，靠这个计数说「已退出 N 处登录（含当前这一处）」；不补的话平台端
那句提示会比另两端少半句。

核验（两层，都真跑）：

```text
· 守卫 p134（起真服务发真 HTTP）：学生 / 机构管理员 / 授课教师 / 平台超管 四条线各跑一遍
  「错口令被拒 → 太短被拒 → 与旧密码相同被拒 → 被拒三次后原口令仍可登录 → 改密成功
   → ★旧 token 立刻 401（改密真生效的硬判据）→ 新口令能登录 / 旧口令不能 → 库里哈希确实变了」，
  外加反向自检（学生 token 打机构端被拒、机构 token 打学生端被拒、缺当前密码 400、未登录 401）。
· 真浏览器（`.tmp/then-account-password.mjs`）三端页面各打开一次，真在表单里敲：
  ① 当前密码错 → 页面上出现**红色**的「当前密码不正确」；② 两次新密码不一致 → 前端自己拦住；
  ③ 全填对 → 「密码已修改，已退出 1 处登录（含当前这一处）。请用新密码重新登录。」+「去重新登录」按钮，
  并且**没有任何原生弹窗**（平台端老版本是 window.alert，这轮统一改成页面内提示）。
```

### C. ⭐ 官网页脚上方的「三步」一栏（用户：「参考以下代码…文字和图片都可以在后台可以配置」）

参考稿是 AdGen AI 的 HowItWorks 三段（暗底 + 三张卡片 + 红色高光 + 悬停上浮 + 入场淡入）。

**照做观感、不照抄实现**（与 /faq、页脚那两轮同一条口径：不为一张页面引依赖进来跟全局 styles.css 打架）：

```text
· 入场：IntersectionObserver 加一次 `is-in` 触发 @keyframes（**卡片默认可见** —— 反过来写
  "默认 opacity:0、靠 JS 显示"，脚本一旦没跑/观察器没触发，运营看到的就是一整块空白）；
· 悬停：上浮 + 红色光晕纯 CSS（transform / box-shadow），reduced-motion 下不播也不动；
· 参考稿那三个依赖（Tailwind / framer-motion / lucide）与三个 Google Fonts 的 <link> 一个都没引；
· 位置：首页正文的最后一段（`main.hp` 里 stats 之后）—— 紧接着就是全站页脚，正是"页脚上方"。
```

**内容进 CMS**：`HOME.steps` = `{ title, lead, items: [{ number, title, desc, imageUrl, imageAlt }] }`。
后台「官网内容 → 首页 → **三步一栏（官网页脚上方）**」可改可传图（走平台已有的文件资产接口，
与机构手册那几处同一条路）；条数不固定，能加能删能排序；**三步全删 = 官网不显示这一栏**
（与首页数据区同一条口径：空 = 运营故意清空，不回退）。

⚠️ **三处必须同源**（这一块最容易做漏的地方）：

```text
① packages/shared/src/siteDefaults.js 的 HOME_STEPS_DEFAULT —— 官网兜底 + 后台表单预填共用；
② packages/database/src/websiteContentDefaults.js 的 HOME.steps —— 新库的种子默认（手抄一份，
   那个文件必须零依赖、不能 import shared）；守卫 p135 逐字段比对这两份，别只改一边；
③ 后台表单：草稿里**还没有这一块**时用 ① 预填，一改动就整块写进草稿（默认 + 本次改动）
   —— 见口径 89（不然运营打开后台是空框、官网上却有内容，他不知道那三条哪来的、也就改不掉）。
```

核验：真浏览器两条（`.tmp/then-home-steps.mjs` / `.tmp/then-cms-steps-form.mjs`）—— 前者验官网上
「3 张卡、编号 01/02/03、默认无图时画占位、**栏底 = 页脚顶**」，并且**走后台真接口**（登录 → 存草稿 →
发布）把第一步的配图填上，刷新后那张图 `naturalWidth > 0` 真的显示出来、占位从 3 个变 2 个；
后者把副本恢复成**生产现状**（HOME 里没有 `steps`）后打开后台，验「大标题/副标题/三步标题都按内置
默认预填、三个『上传配图』入口都在、改一下能存成草稿」。源码级 **p135**（含"两份默认值逐字段一致"
"没有引依赖""默认可见 + reduced-motion"）。

⚠️ **生产现在的状态**：生产 CMS 的 HOME 是这一栏**之前**发布的，里面**没有 `steps`** ——
所以线上显示的是**代码兜底**那三条（已打线上核过：3 张卡、占位 3 个、栏底=页脚顶）。
运营在后台保存并发布一次之后，官网就改成读 CMS 那一份（这一步没做之前，后台里看到的也是兜底那三条）。

## 三、不许破的口径（承接 1–88；**本文新增 89–91**）

### ⭐⭐ 口径 89：**后台表单里显示的那一份，必须等于官网正在显示的那一份**

给官网加"库里可能还没有"的新区块时（这一轮的三步一栏就是这样），很容易写成：官网读
`content.x ?? 兜底`，而后台表单读 `structured.x` —— 于是运营打开后台看到的是**三个空框**，
官网上却明明白白有三条内容。他不知道那三条从哪来、也就**改不掉**（"看着配了、其实没生效"的镜像版：
看着没配、其实生效着）。

判据两条：

```text
① 表单的**取值基准**与官网的**兜底基准**必须是同一个常量（这一轮是 HOME_STEPS_DEFAULT）；
② 一旦改动就把**整块**写进草稿（默认值 + 本次改动），不是只写被改的那个字段
   —— 否则第一次编辑会把默认那几条丢掉（只写 items[0] 的话，界面上另外两条就没了）。
配套：这一块要动**四处**且逐字一致（shared 默认值 / 种子默认值 / 官网兜底引用 / 后台表单预填），
      守卫 p135 逐字段比对前两处 —— 与首页数据区那四个图标（p131）同一条做法。
```

### ⭐⭐ 口径 90：**"改密码"三端一条口径；接口在、界面上没有入口 = 没做完**

三端（平台端 / 机构端含老师 / 学生端）的改密必须同时满足：

```text
① **验当前密码**（只凭一个已登录的会话就能改密 = 捡到一次登录就能把别人的账号锁死）；
② 成功后**撤销该账号的所有会话**（含当前这一处）—— 所以界面成功之后**只提示、不装还在登录**
   （留一个"看着还在、其实已经掉线"的界面，就是口径「界面看得到、点开说无权」的翻版）；
③ 新密码 ≥6 位、不能与当前密码相同；
④ **界面上必须有入口**：学生端这一轮之前的教训就是"接口早就有、界面上没有入口"——
   能力做完了不算做完，用户找得到才算。
```

⚠️ 三端的历史差异（`reauthRequired` vs `reloginRequired`、当前密码不对时 403 vs 400）**保持原样**：
两边都被 p19 / p37 钉着，改它们只是为了"好看"，代价是动另一个功能的断言。新写的机构端**跟平台端对齐**。

### ⭐ 口径 91：**口令不进前端包**

登录页的「演示账号」那一类东西（点一下就把登录名与口令填好）**一律不做**：打包后的 `.js`
谁都能下载，而它指的又是生产账号 —— 等于给访客发口令。判据是"**在前端源码/产物里搜得到口令就红**"
（p115 在官网那一侧、p136 在另两端）；要留快捷登录就用**沙箱账号**，且口令不进仓库。

## 四、这一轮踩过的坑（承接 1–115；**本文新增 116–119**）

### 坑 116：**全量守卫"扫一遍"时的红，可能是假红** —— 先单独复跑一次再下结论

这一轮扫 `scripts/*.mjs` 时 `p13-usage-work-linkage` 红了，我按惯例去"未改动的 HEAD 上实跑"，
发现 **HEAD 上它是绿的** —— 一度以为是自己弄红的。再单独复跑（带着我的改动）**又是绿的**，
第三次全量扫也没红。也就是说那条红是**批量跑出来的抖动**（同一批里前后脚起的服务互相影响 /
端口与时序），不是代码问题。
**教训**：批量扫出来的红，**先单独复跑一次**；只有"单独跑也红"才算真红 —— 否则会拿着抖动去改正确代码
（比漏掉一个真 bug 更亏）。顺带把当时唯一一条**真红**（p14）也修了，见 §二.D。

### 坑 117：脚本**自己**把"成功"报成失败 —— Windows 上 page-shot 的清理会把退出码弄成 1

`page-shot.mjs` 结束时 `fs.rmSync(temp, {recursive:true})`：Windows 上刚被杀掉的 Chromium /
前端静态服务**还攥着临时目录里的句柄**，删除当场 EPERM，**整个脚本以 1 退出**。
现象是：结论（每一页的 ✓ / ✗、截图、report）**全都打出来了**，`exit code` 却是 1 ——
脚本看起来失败了，其实成功。修法是带上退避重试（Node 对 EBUSY/EPERM/ENOTEMPTY 会按 `retryDelay`
重试），并按"不影响本次结论"降级提示。
**教训**：脚本的**退出码**和**结论**都要看；两者不一致时先弄清哪个在说谎（与坑 115 同一族：
"脚本自己不会告诉你它错了 / 它其实没做错"）。

### 坑 118：**源码级守卫自己写错**会假红（这一轮两种都踩到了）

```text
① 提取函数抠错了东西：p135 第一版用 `stepsBlockOf()` 去抠 `steps: {`，而 shared 那份文件里
   **整个对象就是那一栏**（没有 `steps:` 前缀）→ 抠出 null → 三条断言假红。
   第二版锚点写成 `'steps: {'`（带那个 `{`）→ 从"块里第一个 `{`"开始配平，**只抠出第一条**，
   比对还是红。锚点必须写 `'steps: '`（不带花括号）。
   → 能一眼看出来，是因为我把"抠出来的东西"打进了 detail（`shared=... seed=...`）——
     写源码级守卫时，**把中间结果打出来**，别只看 ✓/✗。
② 注释里的字样被当成功能还在：p136 第一版断言 `!/演示账号/`、`!/\bdemos\b/`，而我**到处都写着**
   「这里原来有 demos / 演示账号…」的说明注释 → 三条假红。判之前必须**去掉注释**
   （p130 踩过同一个坑：那两个文件里恰好都写了说明）—— 这是第二次，所以单独记一条。
```

### 坑 119：page-shot 的**通用页级判据**会把"故意造的报错"当成页面问题

改密页天然带密码框、改密测试天然会拿错口令 —— page-shot 两条通用判据立刻报
「落在登录页」「接口报错」，而这两条正是我要的效果。**别去改那两条判据的默认行为**（它们对别的页面
是有效的），也别把断言关掉：按 `--then` 既有的 `expectRedirect` 那套，加"**换准**"开关
（`expectPasswordForm` / `expectedApiErrors`）—— 见 §二.D。
**教训**：工具给出的红要先判断"这是工具不懂我的页面，还是我的页面真有问题"；前者给工具加"换准"的口子，
后者才改代码。
