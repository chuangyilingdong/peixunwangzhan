# 作品调用模型（2026-11-03）

> 一句话：学生作品运行时可以调**平台的 Key**（默认智谱 GLM-4-Flash），学生不用自己填 Key；
> 学生端 / 客户端 / 老师端 / 作品广场 / 学生主页都能用。Key 只在服务端，作品文档里只有短期 grant。
>
> ⚠️ 这套配置**独立于** `ai_provider_policy`（Agent 的渠道 / TEXT 路由 / 模型下拉）：
> 后台「渠道与价格」改的是 Agent，后台「作品调用模型」改的是作品，两边互不影响。

## 一、后台配置

路径：平台后台 → AI 能力与价格 → **作品调用模型**（`/compute/works-llm`）。

| 字段 | 说明 |
|---|---|
| 启用（总开关） | 关掉后所有作品的平台模型调用立刻失效 |
| 调用地址 | 完整的 chat/completions 地址；GLM 默认 `https://open.bigmodel.cn/api/paas/v4/chat/completions` |
| 模型 ID | 默认 `glm-4-flash-250414` |
| API Key | 只写不读；GET 只回 `keyConfigured` |
| 单次最大输出 tokens | 默认 1024（上限 4096） |
| 温度 / 超时 | 默认 0.7 / 60000ms |
| 生效范围 | 课堂内 / 老师与平台预览 / 广场·主页·分享页，三档独立开关 |
| 配额 | 每学生每天、每作品每天、每 IP 每天、全平台每天、QPS |

存储：

- 配置：`platform_settings.works_llm`（JSON）
- Key：`provider-secrets.json["works-llm"]`（与 Agent 渠道的 Key 分开）
- 日计数：`work_llm_usage`（`day + scope + subject_id` 唯一）

迁移：`deploy/production/migrate/52-work-llm-mysql.sql`。

## 二、运行时接口

### `POST /api/works-llm/chat`

调用方是**学生作品里的 LLM 桥**（沙箱文档，`Origin: null`）。服务端只放行这一条，并回：

```http
Access-Control-Allow-Origin: null
Access-Control-Allow-Headers: content-type
Access-Control-Allow-Methods: POST,OPTIONS
```

请求：

```jsonc
{
  "grant": "…",                 // 短期授权；里面只有 scope + subject + exp，没有 Key
  "messages": [{ "role": "user", "content": "…" }],
  "temperature": 0.7,           // 可选，服务端夹到 0~2
  "json": true                  // 可选，转发成 response_format:{type:"json_object"}
}
```

响应（平台统一信封，HTTP 200；模型级失败也用 `ok:false`，作品侧不用处理 HTTP 错误）：

```jsonc
{ "success": true, "data": { "ok": true, "content": "…", "model": "glm-4-flash-250414", "usage": { … } } }
{ "success": true, "data": { "ok": false, "code": "WORK_LLM_QUOTA_EXCEEDED", "error": "…" } }
```

校验：

- grant 签名 + 过期；
- `classroom`：课堂仍 ACTIVE、学生在名单（老师一结束课堂立即失效）；
- `preview` / `public`：作品仍存在（签发方已经验过权限）；
- 配额 / QPS；
- `enabled` / Key / scope 开关。

模型由服务端配置决定，请求里的 `model` 一律忽略（防滥用）。

## 三、grant 的三种 scope

| scope | 谁签发 | TTL | 服务端每次调用重验 |
|---|---|---|---|
| `classroom` | `client-context`（学生课堂内） | 12h | 课堂 ACTIVE + 学生在名单 |
| `preview` | org / admin 作品详情 | 2h | 作品存在 |
| `public` | 公开作品详情（广场 / 主页 / 分享页） | 24h | 作品存在 |

grant = `base64url(payload) + "." + HMAC-SHA256(payload)`，密钥取
`WORK_LLM_GRANT_SECRET` → `RUNTIME_GATEWAY_SECRET` → `AUTH_PEPPER` 的回退链。

> 公开作品的主页路径允许"未公开作品"（学生主页本来就列全部作品），所以 `public` grant
> 不要求 `is_public=1`；签发方（公开作品接口）已经验过主页 token / 分享码。

## 四、作品侧怎么用

作品里仍然按原来的约定调 `POST /api/llm`，**只是不用填 Key**：

```js
const res = await fetch('/api/llm', {
  method: 'POST',
  headers: { 'content-type': 'application/json' },
  body: JSON.stringify({ messages: [{ role: 'user', content: prompt }] })
});
const { ok, content } = await res.json();
```

桥的行为（`packages/shared/src/vibecodingProject.js` 的 `LLM_BRIDGE`）：

- 作品传了 `apiKey` → **老路径**：学生自己的 Key 直连厂商（行为完全不变）；
- 没传 `apiKey`、且文档里有 `window.__PLATFORM_WORK_LLM__.grant` → **平台路径**：调 `/api/works-llm/chat`；
- 两者都没有 → 仍然提示「还没有填写 API Key」。

`buildPreviewDocument(files, entry, { worksLlm })` 负责把 grant 注进文档：

```js
buildPreviewDocument(files, entry, { worksLlm: data.worksLlm })
```

## 五、五端怎么拿到 grant

| 入口 | 数据来源 | 状态 |
|---|---|---|
| 学生端课堂内（网页/工作台） | `client-context.worksLlm` | 平台已下发 |
| **桌面客户端** | `client-context.worksLlm` → 透传给 `buildPreviewDocument` | **需客户端发版**（见下） |
| 老师端课堂预览 | `GET /api/org/works/VIBECODING/:id` 的 `worksLlm` | 平台已接 |
| 平台端作品预览 | `GET /api/admin/vibecoding-works/:id` 的 `worksLlm` | 平台已接 |
| 广场 / 学生主页 / 分享页 | 公开作品详情的 `worksLlm` | 平台已接 |

### 客户端契约（需要客户端配合的一小段）

`client-context` 多了一个字段：

```jsonc
{
  "classroom": { "id": "csession_…", … },
  "worksLlm": { "grant": "…" }   // 没开/没配 Key/不在课堂内时为 null
}
```

客户端在拼预览文档时把它透传下去：

```js
const html = buildPreviewDocument(files, entry, { worksLlm: context.worksLlm });
```

如果客户端不做这一步：**课堂内实时预览**仍然只能让学生自己填 Key；
但作品提交后的老师端 / 平台端 / 广场 / 主页都由平台页面拼文档，不受影响。

## 六、安全与配额

- **Key 永不下发**：文档里只有 grant；`p206` 断言 `buildPreviewDocument` 的输出里没有 Key。
- **一键停用**：后台总开关；关闭后已有页面刷新即失效（grant 还在，但服务端拒绝）。
- **配额**：0 = 不允许；按 UTC 自然日；公开入口同时算作品与 IP。
- **QPS**：进程内 1 秒滑窗（单进程部署）。
- **内容**：作品可以发任意 prompt；平台至少保留用量计数与停用开关。是否保存 prompt 正文另议。

## 八、已知边界

- 第一版**不支持流式**（`stream` 不转发）；作品按一次性 JSON 回包处理。
- 只支持 OpenAI 兼容的 `/chat/completions` 回包；换非兼容厂商要加适配。
- 发布/分享页的模型调用按"作品"计，不按"访问者账号"计；公开页靠 IP 限流兜底。
- 后台试一次不写用量（它不是学生调用）。
