# 积分系统设计（当前基线）

> 状态：当前有效基线
> 更新日期：2026-09-08
> 适用范围：当前 main 分支代码，不是历史验收文档。

## 一、数据模型（权威定义）

| 表 / 字段 | 说明 | 位置 |
|---|---|---|
| `org_billing_accounts` | 机构积分账户：`credit_balance` 余额、`frozen_credits` 冻结、累计流入流出、支付金额、`version` 乐观锁 | `packages/database/src/schema.js` |
| `credit_entries` | 机构账本流水：IN/OUT、`credits`、`balance_after`、关联会话/用户/项目/订单/提交、状态、冲销、actor | 同上 |
| `usage_records` | AI 使用记录：org/user/session/project/job、modality/model、`credits_charged`、token、SUCCESS/FAILED/BLOCKED、fail 原因、pricing 快照 | 同上 |
| `user_credit_adjustments` | 用户配额调整历史：before/after/change、ALLOCATION/ADJUSTMENT/RECLAIM、actor | 同上 |
| `users.ai_credit_limit` / `ai_credits_used` | 用户 AI 独立额度与已用（后置迁移） | 同上 |
| `users.monthly_credit_allowance` / `monthly_bonus_credits` / `month_period_boost_credits` / `used_credits_this_period` / `period_start` | 月度额度模型 | 同上 |
| `users.magic_stones` | 旧余额字段：扣减时会同步递减，但**不参与可用性判断** | 同上 |

## 二、统一口径

```text
机构：
- credit_balance        （org_billing_accounts）
- total_credits_in
- total_credits_spent
- frozen_credits

用户：
- ai_credit_limit       （可分配上限）
- ai_credits_used       （已用）
- ai_credits_remaining  （计算字段：limit - used，不落库）

流水：
- credit_entries        机构账本
- user_credit_adjustments  用户配额调整历史
- usage_records         AI 使用记录
```

`personal_credits` 是后置迁移字段，当前 server 无业务读写（疑似死字段），在确认迁移依赖前不删除。

## 三、账本操作统一入口

`apps/server/src/services/creditLedger.js` 是机构账本的唯一操作层：

- `ensureOrgBilling` 初始化账户
- `insertCreditEntry` 写流水
- `adjustAccount` 原子更新余额并防透支
- `chargeCreditsInTransaction` 机构池扣减 + 写流水（AI 使用走这里）
- `refundOrReverseEntry` / `setFrozenCredits` / `reserve` / `reconcile`

新代码禁止直接 `UPDATE org_billing_accounts` 或 `INSERT INTO credit_entries`，必须走本 service。

## 四、AI 扣费路径（已去重）

`apps/server/src/services/creditUsage.js` 提供两条路径共用的底层操作：

- `debitUserAiCredits({ userId, orgId, credits })`：扣减周期额度 + ai_credits_used + magic_stones
- `recordAiUsage({ ... })`：写入 usage_records（model/credits/status/failCode/pricing 由调用方传入）

### 同步路径 `/api/ai/usage`（`routes/ai.js`）

校验：用户 ACTIVE、项目 DRAFT 且归属正确、课堂可用、能力开关、会话 AI 控制、`ai_credit_limit`、月度 allowance、`sessionCreditCap`；然后机构池扣减 + 更新会话消耗 + 扣用户计数 + 写 SUCCESS usage。

### 异步路径（`routes/aiGeneration.js`）

失败/阻断：只写 FAILED/BLOCKED usage（`credits=0`），不扣任何余额。
成功：校验同上（固定 1 积分），机构池扣减 + 扣用户计数 + 写 SUCCESS usage + 写 media_assets + 推进 job 状态。

### 已知差异（保留，需产品确认）

1. 同步路径检查 `sessionCreditCap` 并累加 `class_sessions.consumed_credits_total`；异步路径未做。
2. 流水类型前缀不同：`AI_${modality}` vs `AI_GENERATE_${modality}`。
3. 异步路径在 usage 中写入真实 `model`，同步路径固定 `local-p0`。

这些差异当前是**有意的**（异步路径结算发生在生成成功时，与同步预扣语义不同）。统一前需先明确业务口径并补测试。

## 五、配额管理入口

- 平台充值：`admin/organizations/:orgId/credit-adjustments`（`routes/adminCredits.js`）
- 机构列表/单用户/批量分配/历史：`org/members/credits*`（`routes/orgAdmin.js`）
- 官网学生积分：`website/my-credits/*`（`routes/websiteCredits.js`，挂载在 org 之前，旧 `adminOrg` 中的重复分支已删除）
