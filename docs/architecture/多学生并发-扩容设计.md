# 学生创作环境（dsh）· 多学生并发与扩容设计

> 2026-09-16 定稿。用户口径：**dsh 这套开源的要留**，服务器按需扩容，
> 但「支持很多学生」必须在**代码里成立** —— 不能出现「加机器也带不动」的硬编码上限。
> 本文只讲怎么改到这形态，不改 dsh 本体。

## 一、现在卡在哪（三层约束，一层比一层硬）

```text
① 寻址：一个学生一个端口，端口池写死 18201-18220（20 个）
     → 第 21 个学生**根本进不来**（不是慢，是启动失败）
② 放置：平台只认**一个**宿主（一个 broker socket）
     → 就算加 10 台服务器，平台也用不上第 2 台
③ 资源：一个学生环境 RSS 470-490MB（峰值 643MB，cgroup 上限 768MB）
     → 这台 1607MB 的机器只能同时跑 2 个
```

②③ 是「加钱能解决」的（加机器、加内存），**① 和 ② 是代码上限，加钱也解决不了** —— 这是本轮要改的东西。

实测数据（2026-09-16 生产）：

```text
单个学生环境   RSS 486MB / cgroup 峰值 643MB / 上限 768MB / 11 个进程
平台服务       48.6MB
机器           1607MB total，766MB used（1 个学生环境 + 平台 + nginx）
```

## 二、目标形态

```text
                   ┌──────────────────────────────┐
   学生浏览器 ──443─►│ 入口层 nginx（可以做多副本）      │
                   │  s-<hash>.students.iicili.cyou │
                   │   ↓ 按 server_name 路由          │
                   └──────────────┬───────────────┘
                                  │ proxy_pass http://<宿主>:<内部端口>
        ┌──────────────┬──────────┴────────┬──────────────┐
   ┌────▼─────┐   ┌────▼─────┐        ┌────▼─────┐   （继续加）
   │ 宿主 A    │   │ 宿主 B    │        │ 宿主 C    │
   │ dsh ×N   │   │ dsh ×N   │        │ dsh ×N   │
   └──────────┘   └──────────┘        └──────────┘
         每个宿主只跑 dsh（不开 443），学生数只受内存限制
                                  ▲
                        平台按容量放置（宿主表 + 可用内存上报）
```

三条原则：

1. **寻址用域名不用端口**：全部走 443，靠 SNI / `server_name` 分流 →
   单机学生数只受内存限制，URL 也不再带端口。
2. **入口与宿主解耦**：学生地址由**入口层**决定，不随他落在哪台宿主变。
3. **装不下就明确拒绝**：绝不要把学生塞进一台已经满的机器换 swap ——
   今天第 3 个学生进来会把所有人都拖慢（实测同一操作 9.7s → 59s）。

## 三、要改的三处（含现状代码位置）

### ① 寻址：`host-user/run-student-user.sh`

**现状**：分一个 18201-18220 的端口 → 写 `server { listen <port> ssl; server_name iicili.cyou; }`
→ `EDGE_URL=https://iicili.cyou:<port>/?t=…`。端口池 `PORT_BASE=18201` / `PORT_RANGE=20` 写死，
还要求云安全组放行这一段。

**改成**：学生域名 = `s-<username 哈希后段>.students.iicili.cyou`（username 已经是
`dshs-<10 位哈希>`，直接用即可），入口 conf 写
`server { listen 443 ssl; server_name s-xxxx.students.iicili.cyou; … proxy_pass http://127.0.0.1:<内部端口>; }`。
内部端口（dsh 自己那个 `127.0.0.1:19202`）继续用，但**它已经不对公网**，随便分。

连带要改：
- `--trusted-host` 现在给的是 `iicili.cyou` 与 `iicili.cyou:<port>`，要改成**学生自己的域名**
  （dsh 的 `/api` 信任栅栏按 Host 比对，不改会被 403 挡成「自动重连中」——上一轮踩过）。
- 票据闸门那段逻辑不变，只是挂在 443 的 vhost 上。
- 平台侧几乎不用改：`services/studentRuntime.js` 已经是「优先用脚本 stdout 里的 EDGE_URL」。

### ② 放置：`apps/server/src/services/studentRuntime.js` + `host-user/dsh-host-broker.mjs`

**现状**：`runHost()` 固定打一个 broker（单宿主）。

**改成**：
- 一张**宿主表**（配置或 DB）：`{ id, edgeHost, brokerSocket, memTotalMB, memFreeMB, launchedAt }`；
- 宿主上报容量：每次 launch/stop 后 broker 顺手回报 `MemAvailable`，或宿主上跑一个 30s 的心跳；
- 放置：按「可用内存能装下一个环境 + 余量」挑宿主（bin-pack 优先填满，省机器）；
- **同一 (session, student) 必须始终落在同一台**（否则会开两份环境）：
  用 username 哈希做一致性键，并把结果记下来（`session_students.runtime_host` 或一张映射表）。
- 挑不到宿主 → 明确报错（`RUNTIME_NO_CAPACITY`），前端提示「这台机器满了，请稍后再试或联系平台扩容」，
  **不要**降级塞进去。

### ③ 入口：把「写入口 conf」从宿主脚本抽到入口层

**现状**：宿主脚本在自己那台机器上写 `/etc/nginx/dsh-students/<user>.conf` 并 reload 本机 nginx
→ 学生直连那台机器的端口。多宿主时这个模型就断了（入口层不知道学生在哪台）。

**改成**：入口层持有所有学生的路由 conf（`include /etc/nginx/dsh-students/*.conf`），
内容由**平台侧渲染**、通过入口宿主的 broker 落盘 + reload（保持平台的 `NoNewPrivileges` 边界，
不给自己开提权口子）。宿主脚本只负责「起 dsh + 回报它的内部端口」。

## 四、需要你做的（很少，但绕不过）

1. **一条通配 DNS 记录**：`*.students.iicili.cyou` → 入口 IP。
   （也可以每台宿主一条 `h1.students…` / `h2.students…`，但入口层解耦后用一条通配最省事。）
2. **一张通配证书**：`*.students.iicili.cyou`。Let's Encrypt 的通配证书只能走 **DNS-01** ——
   需要 DNS 服务商的 API 凭据，或者你手工加一条 TXT（我可以把 certbot 命令和要填的值准备好）。
3. 安全组：走子域名 + 443 之后，**18201-18220 这一段就不需要再对公网放行了**（反而更安全）。

> 我做不到的部分就是这三条：它们是域名/DNS/证书层面的操作，代码里改不了。
> 你把 ① ② 弄好告我，剩下全部我来做并逐段验证。

## 五、分阶段（每段都能单独上线、单独回滚）

| 阶段 | 内容 | 解锁什么 | 前置 |
|---|---|---|---|
| **0** | 容量口径诚实化：宿主容量检查 + 装不下就拒绝（`RUNTIME_NO_CAPACITY`）；端口池与宿主目标改成配置 | 不再出现「第 3 个学生把全班拖慢」；加机器只需改配置 | 无（我马上能做） |
| **1** | 单机去端口化（子域名 + 443 + `--trusted-host` 跟域名） | 单机学生数**只受内存限制**；URL 不带端口 | 上面 ①② |
| **2** | 多宿主放置 + 入口层解耦 | 「加服务器 = 加一条 A 记录 + 一条配置」 | 阶段 1 |
| **3** | 预热池 / 按课堂整批放置 / 空闲回收 | 上课瞬间全班可用；没人用时不占内存 | 阶段 2 |

## 六、容量口径（用来算要买多少机器）

```text
一个学生环境：470-490MB（峰值 643MB，单环境 cgroup 上限 768MB）
平台+宿主+nginx：约 100MB
可跑学生数 ≈ (机器内存 - 200MB) / 600MB        # 600 取「稳态 490 + 余量」
```

| 机器 | 可跑学生 | 备注 |
|---|---|---|
| 1.6GB（现在这台） | **2** | 第 3 个开始 swap |
| 8GB | 约 11 | |
| 16GB | 约 23 | 此时**端口池 20 先卡住** —— 正是阶段 1 要拆的 |

**1000 个学生同时上课** ≈ 470GB 内存 ≈ 8GB 机器约 90 台 / 16GB 机器约 45 台
（不含入口层与冗余）。所以「很多人同时上」的现实路径是：**阶段 1+2 打通 → 按这个口径堆机器**；
如果要少堆机器，就得换更轻的学生运行时（那是另一个项目决策，不在本文范围）。

## 七、明确不做的事

- **不改 dsh 本体**，也不去绕它的 `<base href="/">` 硬注入（上一轮实测过子路径走不通）——
  所以「一个学生一个 origin」这条不变，我们只是把 origin 从「域名:端口」换成「子域名」。
- **不把多个学生塞进一个 origin**（路径分流）：会让 dsh 的 `/api`、WebSocket、静态资源全部错位。
- **不做进程内多租户**（一个 dsh 进程服务多个学生）：隔离靠的是「一个学生一个 Linux 用户」，
  合并就没了这道边界。
