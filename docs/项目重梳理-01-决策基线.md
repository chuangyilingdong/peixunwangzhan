## 1. 一句话定位

面向线下培训机构的 AI 少儿编程/创作教学平台：平台方维护课程和机构，机构负责成员与班级，教师负责授课与点评，学生从官网首页登录后仍停留在官网首页，再从首页进入学习相关功能。

当前不把产品定义为公开注册 SaaS、在线交易平台或开放社区。

## 2. 当前必须遵守的产品事实

- 学生从官网首页登录后，登录完成仍留在官网首页；首页是学生登录后的默认落点。
- 学生的学习、课程、项目、作品和课堂功能都从官网首页进入，不再在文档中维护另一套学生主入口说法。
- 平台、机构管理员、教师、学生四类角色继续保留。
- 业务主线是：机构购买积分 → 平台给机构入账 → 机构给学生/教师配置积分配额 → 上课和 AI 能力消耗从机构积分账户扣除 → 机构查看余额、配额和用量流水。
- 机构之间、教师之间、学生之间必须严格隔离数据。
- `packages/canvas` 暂按既有边界冻结，不在本轮重构底层。
- `local-mock` 或未完成的第三方能力不得在页面上伪装成真实成功。

## 3. 已有能力概览

### 角色和教学闭环

- 平台管理员：机构、平台课程、课时、授权、内容和审计。
- 机构管理员：教师/学生账号、班级、课程配置、积分配额、用量。
- 教师：班级、课堂、课时、学生作品、点评和课堂收口。
- 学生：从官网首页登录，进入课程学习、项目创作、作品提交和反馈查看。

### 技术和运维

- React/Vite 多应用前端、Node.js API、SQLite 数据库。
- 认证、会话、角色权限、机构隔离、课程/课时、班级/课堂、作品/反馈。
- AI 任务队列、重试、超时、取消、积分记账和审计基础。
- 生产服务、Nginx、systemd、备份/恢复、健康检查和基础运维记录。
- 文件安全上传基础代码存在，但是否达到生产完整可用标准，仍按路线图验收。

## 4. 积分与配额模型（当前唯一口径）

### 4.1 账户层级

```text
平台/机构购买积分
  → 机构积分账户（唯一扣费来源）
  → 机构管理员配置用户配额
      → 教师个人可用配额
      → 学生个人可用配额
  → 上课、AI生成等消耗
  → 先检查用户配额，再从机构账户扣减
```

### 4.2 必须明确的规则

1. 机构购买的积分归机构，不直接归某个学生或教师。
2. 机构管理员可以给教师和学生设置额度、调整额度、暂停额度。
3. 学生/教师的额度是机构账户下的授权额度，不是独立充值账户。
4. 每次消耗必须同时记录：机构、用户、角色、班级/课堂、课程/课时、能力、数量、结果和时间。
5. 失败、取消、超时或被策略拦截的任务不得扣除有效积分；若发生预扣，必须自动冲正。
6. 余额不足、用户配额不足、课堂额度不足时，服务端拒绝请求，不能只在前端拦截。
7. 机构管理员看到机构余额、分配总额、用户使用量和流水；教师/学生只看到自己被授权的额度和使用量。
8. 后续如果增加套餐、订单或支付，必须建立在这套机构账本上，不能另起一套扣费逻辑。
