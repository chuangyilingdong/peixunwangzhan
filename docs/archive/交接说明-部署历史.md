**① 后台「计费与模型」白屏（`1626098` / release `20260913T043716Z`）**

① pages/ 与 components/ 下每个独立组件；② 三个 App 内部**内联**的页面（org 绝大多数页面属于这种）——
路由清单从各自 `main.jsx` 的 `<Route path>` 自动解析，新增页面自动进覆盖。共 66 个渲染目标。
为此三个 `main.jsx` 把内联的 `App` 导出了。**已自证能拦住这个 bug**：故意把 `days` 放回去 →
`✗ admin/PlatformBilling` 与 `✗ admin/billing` 同时变红（后者正是用户点的那条路径）。
⚠️ 两个实现坑：临时入口必须放**仓库内**（放 os.tmpdir() 里 rollup 解析不到 node_modules）；

```text

原来的模型是「会话上挂一个 files JSON」，学生可手写、可导入导出。改成**产物（artifact）优先**：
AI 回复里每个带文件名的围栏（语言标识后面跟文件名）就是一个产物，有身份、类型、字节数、修订号。

- 新表 `vibecoding_artifacts`（`UNIQUE(conversation_id, name)`）。**同名 = 新修订**（revision + 1），
  不是新建一条——否则模型每次重写都会在聊天里堆出一串重复卡片。

  未闭合的围栏不会命中（不会产出半截文件）；没有文件名的围栏只当示例代码，不算产物。
- 删掉了「手写代码」相关端点与功能：`PUT /conversations/:id` 传 files 现在返回

**① 课程入口顶部一条白色横带（release `20260911T072737Z`）**

`/learn/vibecoding` 的标题几乎看不见，顶部压着一条白带。根因是站点全局样式里有元素级的
`header{height:76px;position:sticky;background:rgba(255,255,255,.92);backdrop-filter:blur(14px)}`
（官网顶部导航）——**类选择器的特异性虽高，但只在本组件声明过的属性上才赢**；
`.c-page__head` 没声明 background，白底就直接压了上来（sticky/height/z-index/模糊一起漏进来）。
同类可渗透的还有 `nav`、`label{margin:12px 0}`、`table{width:100%}`、
`th{font-size:10px;letter-spacing:.5px;text-transform:uppercase}`。

修法的关键是**特异性必须卡在中间**：`[data-console] :where(header)` = (0,1,0)，
压得住站点的元素规则 (0,0,1)，又输给控制台自己的类规则（同为 0-1-0、加载在后）。
⚠️ 写成 `[data-console] header`（0,1,1）会连 `.c-topbar` 的 `height:49px` 一起压掉——
**工作台的顶栏也是 `<header>`**。这条已写进 `kit.css` 的注释里。

#### 聊天框支持上传图片：两次实测推翻了我们自己的假设（release `20260911T095614Z`）

|---|---|

- **给模型看的** → 内联 base64（客户端上传时顺手读成 data URL；浏览器手里就有文件）
- **给页面用的** → 公开外链（用户要的"外联公开"）

另外两个实现细节：

  纯文本的话模型完全看不到图（实测：同样问题纯文本回「未看到图片」）。
- **不能靠渠道请求模板**放占位符：多轮历史会**整份替换**模板里的 `messages`，模板里的占位符会被一起替换掉。

**数据安全口径（用户明确要求"外联公开"）**：学生上传的图任何拿到 URL 的人都能访问。

#### 学生能直接产出 PPT / Word / Excel（2026-09-11，已发布 release `20260911T110724Z` / `0ea03b8`）

起因：用户问「像豆包那样，说一句就能出一张插画图、出一份 PPT，它应该是调用了很多能力吧，
你看下这个源码有这些能力吗、我们能做吗」——并把 OpenSquilla 的源码包发了过来。
调查结论：**那不是某个模型自带的本事，是 Agent 在调工具**；OpenSquilla 的生图是
`nano-banana-pro` 这个技能在调 OpenRouter 的图片模型，PPT 则是「模型写 python-pptx 代码 →
在沙箱里跑」；`file_authoring.py` 里还有一条**不需要沙箱**的等价路径（收结构化 slides、进程内渲染），
我们要的就是后者。用户随即拍板：「服务器后续我会扩的，现在不管是生成 docx、xlsx、ppt 等，全部跑通。」

**做出来的东西**：学生在对话里要一份文档，模型按平台规格给**内容**，服务端当场渲染成真正的
`.pptx` / `.docx` / `.xlsx`，作为产物卡片可下载。规格与语言标签：

```text
```pptx 去新疆旅游.pptx   → JSON 提纲 {"title","subtitle","author","slides":[{"title","bullets"}]}
```docx 我的暑假计划.docx → Markdown 子集（# 标题 / - 列表 / 1. 有序 / | 表格 | / **粗体**）
```xlsx 暑假花销.xlsx     → CSV（首行表头）
```

**两个关键取舍**（都是被这个仓库的现状逼出来的，值得记住）：

1. **产物里存「规格文本」，下载的那一刻才渲染成文件。** 产物表是一列 TEXT（256KB 上限、要参与版本比对
   与「源码」视图），而 Office 文件是 zip —— base64 塞进去又大又不可读。存规格反而是**天然的**：
   学生能在工作台看懂自己那份文档是怎么写的，版本/配额沿用现有口径，渲染器升级后老产物重新下载即可受益。
   代价是每次下载渲染一次（几毫秒）。
2. **自己写 ZIP + OOXML，一个第三方库都不引。** 服务端目前**零 npm 依赖**，release 也只拷
   `apps/server/src` + `packages/database/src`（`build-production.sh` 不在 release 里装 node_modules）。
   引 `pptxgenjs` / `docx` 这类库会打破整套发布方式、还要服务器联网装包。所以用 `node:zlib` 手写了
   ZIP 写入器与三个渲染器（`apps/server/src/services/ooxml/`），确定性输出、可复现。

**守住它的两条守卫，互补、缺一不可**：

- `scripts/p45-office-documents.mjs`（**纯 Node，不依赖 python**）：ZIP 中央目录/CRC/偏移自洽、
  UTF-8 名字标志位、自带一个极小的 XML 良构检查器、`[Content_Types].xml` 必须存在且是第一个条目、
  每个部件都被它覆盖、每条 rels 目标都能解析到真实存在的部件。
- `scripts/p46-office-independent-reader.mjs`（**python 独立读回**）：python-pptx / python-docx / openpyxl
  三个完全独立的库读回文字、表格、数字类型、冻结窗格。
  缺依赖时**显式失败而不是静默跳过**——跳过等于没有守卫（这个项目已经吃过三次
  「界面不报错、日志不报错」的亏）。装法：`python -m pip install python-pptx python-docx openpyxl`。

两条都按规矩自证过：**把 `a:pPr` 的闭合 `>` 去掉**，p45 报「标签不匹配」、p46 报 lxml 语法错。
而且写守卫的过程本身就抓出两个真 bug：`paragraph()` 拼串缺了闭合 `>`（**整份 PPT 打不开**）、
`w:pPr` 子元素顺序违反 schema（Word 能开、别的实现未必）。

**端到端实测 20 项全过**（`.tmp/vision-doc.mjs`）：真开浏览器要一份 PPT / Excel / Word →
产物卡片出现 → 点下载 → 拿到的字节交给**独立实现读回**校验内容。
发布后又用**生产实际下发的产物**重跑了一遍，全过。

#### PPT 配图：用学生自己传的那张图（2026-09-11，已发布 release `20260911T112517Z` / `b4f4566`）

学生在对话里传了图、又让做 PPT 时，「模型」现在会把图用上：那一页写
`{"title":"赛里木湖","bullets":[…],"image":{"attachment":1}}`，`attachment` 是**这条消息里第几张图**
（非图片附件不占号）。服务端在下载时把序号翻成真实字节，内嵌进 pptx。
只有图没有要点的那一页会占满正文区（配图页）；标题页不配图。

设计上守住的几条：
- **序号不是猜的**：带图的用户消息会多一条平台提示「附了 N 张图片，编号为 1、2…」——
  模型看不到我们给它编的号，不说清楚它就引用不对。
- **引用越界 / 素材被删 / 格式不是图片** → 只是**那一页不放图**，不让整份 PPT 下载失败。
- **按「产出那一轮」找图**，不是「最近一轮」：模型写「第 1 张」时指的是它当时看到的图，
  学生之后再聊几轮也不会串味（靠产物上的 `message_id` 回溯）。

**这一轮踩到三个「一句错都不报」的坑，值得记住**：

1. **图片形状的关系 id 写成了 `rId1`，而 `rId1` 被 slideLayout 占着，图片其实是 `rId2`。**
   于是图片形状指向版式 —— python-pptx 报 `image unreadable`、PowerPoint 会说文件需要修复。
   **p46 抓到了**（当初做「独立实现读回」就是为了这一刻）。
2. **`getArtifact()` 返回的是驼峰 `messageId`，我按数据库列名 `message_id` 去读** → 永远 undefined
   → 「这一轮有几张图」永远是 0 → PPT 里就是没图。
3. **`parseAttachments` 只带出 `id/name/url/inline`，把 `mime` 丢了** → 按 mime 筛图片永远筛不到。
   这是第 2 条的另一面：**字段在库里、在读取路径上丢了**（本项目第四次踩同一类）。

**新增 `scripts/p47-document-image-embedding.mjs`** 专门盯这条链路的三处断点
（产物 messageId / 附件 mime / 磁盘素材），不需要 python、不起服务。两条真 bug 都自证过：
**撤掉任一修复，p47 立刻报 `size=0`**。

`p42` 同步更新：带图消息的内容块不再固定「第 1 块文字、第 2 块图片」（中间多了编号提示块），
改为按类型找图片块，并新增「会告知图片编号」的断言。

端到端 23 项全过（`.tmp/vision-doc.mjs`）：学生真传一张图 → 要带图的 PPT → 点下载 →
用 python-pptx 把内嵌图**按 SHA256 跟原图比对**，确认就是同一张。发布后又用生产产物重跑了一遍。

**再往后一步（还没做）**：让 AI **生成**每页插画。我们已经有生图渠道，但渲染发生在下载那一刻，
而生成图既慢又花钱、还不能幂等 —— 所以它得挪到「助手这一轮结束时」去做，并接上配额与异步。
那是一个独立的产品决策（要不要为每页图扣积分），不是纯技术问题。

#### PPT 会去「收集素材」了：按规格生成插画（2026-09-11，已发布 `20260911T120321Z` / `a037229`）

用户拿豆包的成品来对比：豆包出 PPT 时会先「正在收集 PPT 素材」——规划风格、**生图 3 张**、再合成；
我们的几秒就出，而且是一页页干巴巴的要点。「是不是哪里不对」。

**核对结论：不是 bug，是能力缺口。** 豆包的流程是「规划 → 收集素材（生图/搜图）→ 合成」，
我们过去只做最后一步的排版，中间**没有素材环节** —— 所以快而单薄。这条把「生图」补上。

规格上多一种配图写法（与引用学生自己的图并存）：

```text
{"title":"赛里木湖","bullets":["湖水蓝得像宝石"],
 "image":{"prompt":"新疆赛里木湖的夏天，写实插画风格，蓝天、雪山倒影、湖边草地，横构图"}}
```

系统提示里明确：**全篇最多 3 张**、用在封面与最有画面感的页、不要每页都配；拿不准风格时不配反而更好。

**流程**：助手这一轮消息落库之后（产物已认领到这条消息、能回溯「产出那一轮」）→ 门禁 →
逐张调 IMAGE 渠道 → 存成**公开素材**（复用学生上传那套校验与下载地址）→ 记在产物的
`generated_images` 列 → 再把产物推一次（前端按 id 覆盖，预览立刻换上新版本）。
生成期间推 `status`（`phase=image`），前端显示「正在配图 第 1/3 张」——
对应豆包那句「正在收集 PPT 素材」，学生知道在干嘛而不是干等。

**三条刻意守住的规矩**：

- **门禁与画布生图完全同一套**（课时能力 / 课堂开关 / 平台模态开关）。为此把
  `assertGenerationPreflight` **导出复用**，而不是复制一份 —— 复制迟早漏检查，那就等于给
  文档产物开了绕过能力开关的后门。门禁不过就一张都不生成，且如实告诉学生，不报错、不打断对话。
- **单张失败只影响那一页**，其余照常；整份 PPT 永远能下载。
- **产物换版时清空旧插画**（content 变 → `revision+1` 且 `generated_images=NULL`），
  否则新 deck 的第 2 页会配上上一版的图，**而且不报错**。

**这一轮踩到三个「静默失败」，全在这条链路上**：

1. **调用时漏传了一个实参**（定义 4 个参数、调用只给 3 个）→ `artifactIds` 是 undefined →
   函数第一行就 return，整个功能静默失效。**是一行日志都没有才定位到的。**
2. **`fresh` 在 `transaction` 回调里声明，我在回调外引用** → 求值实参即 `ReferenceError`，
   被这一层 catch 吞掉，前端只表现为「没有插画」。
3. **平台的生图路径是 `/v1/image/generations`（单数）**，我按直觉给假上游写成了 `images` →
   404 被当成生成失败（这个反而**被正确记录**在产物的 `generated_images` 里，说明失败路径是好的）。

**守卫与实测**：

- `scripts/p49-illustration-planning.mjs`（新）：插画**规划**的口径 —— 只认 pptx、只认写了 prompt 的页、
  每份最多 3 张、提示词截断到 300 字。**把 3 改成 5 会立刻报「想改先想清楚账单」**（自证过）。
- `p45`/`p46` 覆盖「按幻灯片下标给生成图」以及「生成失败时仍能出文件」。
- 端到端 10 项全过（`.tmp/vision-illustration.mjs`）：真的要一份带插画的 PPT → 上游确实收到生图请求
  （带模型写的提示词、不超过 3 次）→ 预览里图能加载 → 下载的 pptx 里**内嵌图与这次生成的图
  SHA256 完全一致**。发布后又用生产产物跑了同一套。

**还没做**：豆包还会**搜真实照片**（它那份计划里写了「搜图关键词：喀纳斯、赛里木湖…大盘鸡、烤包子」）。
我们**没有搜索能力**，而且面向儿童的平台去搜开放网络的图片有内容安全风险 —— 要么接一个带
安全过滤的图库/搜索 API，要么明确不做。这是产品决策，不是技术问题。

#### PPT 版式升级：主题 / 封面大图 / 章节·金句·结尾页 / 页码 / 文字自适应（2026-09-11，已发布 `20260911T125501Z` / `25bb997`）

上一轮补了「生图」（内容不再单薄），这一轮补「好看」。原来所有 PPT 都是同一套配色、同一种版式
（标题 + 要点 + 右侧图），像同一份模板印出来的。现在：

- **5 套主题色板**：`ink`（默认）/ `ocean`（蓝，风景/科技）/ `sunset`（橙，美食/热情）/
  `forest`（绿，自然/环保）/ `candy`（紫，童趣/节日）。规格里写 `"theme":"ocean"`，
  不写或不认识就回默认。系统提示里给了「什么内容配什么色」的建议。
- **封面**：写 `{"cover":{"prompt":"…"}}` 让平台生成封面图 → 整页铺图 + 压一层 **58% 深色蒙层**
  再放白字。蒙层不是装饰：白字直接压在照片上十有八九看不清。没有封面图就走主题色版 + 一个几何色块。
- **版式**：`{"layout":"section"}` 章节分隔页（整页主题色 + 右下大序号）、`{"layout":"quote"}` 金句页
  （一句话居中放大）、`{"layout":"thanks"}` 结尾页；另有「只有图没有要点」时的整页图 + 底部色带压标题。
- **页码页脚**：内容页右下角 `2 / 7` + 左下角一根强调线；封面/章节/金句/结尾页不加（它们是视觉停顿）。
- **文字自适应**：按字数估高，超了就把正文自动降档（1800→1600→…→1000）。
  **溢出不会报错、只会难看**，所以宁可小一点也不能冒出去。

封面图与幻灯片配图共用同一条生成流程（用保留下标 -1 区分），同样算进「每份最多 3 张」。

**看不见 pptx 的情况下怎么验** —— 这次的难点是本机没有 LibreOffice/WPS，C 盘也只剩 6.7G（97%），
我没有擅自装 700MB 的渲染器，改用三层互补：

1. **几何断言（p45）**：把每一页每个形状的 `off/ext` 取出来算边界，**任何形状出画布即失败** ——
   这正是「内容被裁掉、但文件依然打开正常」那类不报错的失败。自证过：把封面强调线挪出画布立刻报错。
   同一段还断言版式真的落地（结尾页/金句页/蒙层/主题色在不在 XML 里）。
2. **独立读回（p46）**：python-pptx 读出页数、文字、内嵌图字节。
3. **站内预览截图**：预览是同一份规格的另一个渲染器，也是学生先看到的东西。
   顺手让 `vision-doc` 用**预览渲染的页数去核对 pptx 的页数**（两个渲染器交叉验证，也不用写死数字）。

**新增 `scripts/p50-theme-parity.mjs`**：色板是预览与文件**唯一需要手工同步**的东西，一旦漂移就是
「预览是蓝的、下载出来是橙的」，而且谁都不报错。p50 逐字段拉平两边（含默认主题与回落行为），
自证过（改一个色值立刻报「主题 ocean 的 accent 两边不一致」）。

**这一轮踩到的坑**：用脚本改大文件时按「第一个 `function run(`」定位，把中间的 `imageType`
和 OOXML 常量一起切掉了 —— **`node --check` 只查语法、查不出「引用了不存在的符号」**，
是跑起来才报的 ReferenceError。教训：大段替换之后要跑一次真实调用，别只看语法检查。

#### 作品广场显示并下载真正的文档产物（2026-09-11，已发布 release `20260911T134902Z` / `cfb70e6`）

**问题**：学生交的是一份 PPT 时，作品广场显示的是「你好，AI 魔法学院」起始页或一段规格 JSON 原文，
而且**没有任何地方能下载到真正的 .pptx**（学生自己那条下载口带鉴权，广场是公开页）。

**根因三条**（都是「选错了东西」，不是渲染坏了）：
1. 入口按「优先 `index.html`」挑（`pickEntryArtifact`）——而 `index.html` 是**平台给的种子产物**，
   学生进了课堂它就在，做 PPT 也不会消失，于是永远被选中。
2. 官网详情页只会 `buildPreviewDocument(files, entryFile)` 拼 HTML，文档产物在它眼里就是一段文本。
3. 文档的真文件是**下载那一刻渲染出来的**，而渲染只有学生那条带鉴权的口。

**改法**：
- **提交时定格产物清单**（新列 `vibecoding_submissions.artifacts`：名称/类型/字节/时间/配图引用）。
  为什么要快照：删掉点评之后提交不再锁创作（学生可以接着改、反复交），而广场要显示的是**交上来的那一版**。
  正文继续走原来的 `files` 快照，这一列只存元信息与图片引用（fileId），很小。
- **主产物 = 最近产出的那份**（`submissionPreview`，服务端说了算；前端不再自己猜）。
  学生端工作台的预览区本来就是同一个口径，两边现在共用同一条规则。
- **公开清单**（`publicArtifactCatalog`）：每个文件是不是文档、下载地址、配图地址，全在这一层拼好。
- **公开下载口** `/api/public/vibecoding-works/:token/files/:name/download`：从**快照**当场渲染真文件
  （文件名允许中文，所以要 `decodeURIComponent`；路径里不许有 `/`、`\`、`..`）。
- **配图**：平台生成的插画本来就是公开素材，直接用；学生传的图不是公开素材，
  新增**只认这份作品快照内 fileId** 的代理 `/api/public/vibecoding-works/:token/images/:fileId` ——
  准入名单就是提交快照本身（未发布的提交拿不到 token，也无从枚举）。
  同一张图走普通公开素材口仍然 403（p51 钉住这条）。
- **前端**：详情页优先渲染文档（`ReplayDocument` 与学生端工作台**共用一份**，不再各写一遍），
  可一键下载；可预览的产物不止一份时给一条切换条（网页 / PPT / Word / Excel），
  否则「后面又让 AI 做了份 PPT」会把原来的网页作品在广场上彻底埋掉；列表卡片说得出「演示文稿」。
- **平台端**：VibeCoding 作品列表的「发布到作品广场」按钮原先要求 `status === 'APPROVED'`，
  而删掉老师点评之后学生侧状态**恒为 PENDING** —— 也就是说**那个按钮永远不会出现**，
  学生的作品根本发不出去。改成只看「学生是否确认展示授权」（服务端本来就不要求已通过）。
  这类「删功能时把入口一起删掉」的错不会报错、只是按钮消失，后来是拿 p51 端到端才照出来的。

**顺带修掉一个真 bug**：提交快照读回时复用了**写侧**的 ASCII 路径校验（`parseFiles`），
而产物名允许中文（「去新疆旅游.pptx」这种），于是**提交已经落库、学生却收到 400
`INVALID_VIBECODING_FILE_PATH`**。用 `git stash` 回旧代码复现过（p51 第二项当场报 400），
改成读侧宽松（`parseSnapshotFiles`）、写侧校验随「学生不能手写代码」一起删掉。

**生产上的存量**：VibeCoding 提交**只有 1 份**（网页类、已发布、`entry_file=index.html`），
没有文档类旧作品。新列在下次启动时由幂等 `ALTER TABLE` 自动加；旧记录没有快照 →
`preview` 为 `null`、前端回退到入口文件那套（对这份作品＝网页预览，**与改动前一致**）。
发布后实测：公开列表/详情正常、那份作品的 `artifacts` 里三个文件都不是文档、不给下载地址。

**测试**：
- 新增 `scripts/p51-public-document-work.mjs`（26 项，临时库 + 真实 HTTP）：中文名提交 →
  主产物是 PPT（不是种子页）→ PENDING 也能发布 → 广场清单 → 公开下载（解开 pptx 校验正文与图）→

**这一轮之后还剩下的**（与上一轮那份待办的对应关系）：

上一轮算力网关只做到「配得上、看得见」（额度记在网关上、用量能归集），**拦不住调用**。
这一轮把它接上：学生的每次 AI 调用带着**他自己的令牌**打到网关，令牌额度用尽网关直接拒服务，
于是「1 个学生在这节课 50 元」是网关给出的硬闸，不再是我们自己算出来的一个数。

**令牌名改成多段**：`机构:<id>/学生:<id>/课时:<id>`（能带几段带几段）。解析顺序**最具体优先**：
`机构+学生+课时` → `学生+课时` → `机构+学生` → `学生`。所以平台管理员手动分发的单段令牌
（上一轮的老约定）和按课时预算**自动发**的令牌都能被用上，老数据不用迁。
归集侧也改成逐段解析：一张多段令牌会同时归到机构 / 学员 / 课时三个维度。

**哪些模态走网关**：只放**同步 OpenAI 兼容**的两类（TEXT / IMAGE）。
音乐与视频在我们的上游是「自定义路径 + 提交后轮询」的异步任务，new-api 要用它的任务插件才能接
（写了插件就受 AGPL 约束）→ 这两类**继续走我们自己的出口**，只把用量记进我们自己的表。
👉 **这是已知缺口：视频/音乐的消耗目前不受令牌额度约束**，别当成已完成。

**自动发牌（硬闸的来源）**：学生在某节课第一次调用时，若网关上没有他的令牌，
就用这节课的「每学生算力上限」自动发一张（`per_student_budget_fen` 5000 分 → 25000000 quota = 50 元）。
课时没填预算就不发牌（只记账不拦，与用户口径一致）。同一名字并发只发一张。

**出口接线**：`generationProvider.getGenerationProvider()` 支持网关出口（`selection.gateway`）——
走网关时**不套**我们自己上游的请求模板/路径（那些是 MiniMax/Mureka 的私有形状，网关不认），
改用内置的 OpenAI 形状模板。接线点共 6 处，其中**异步 worker 必须在 worker 里重新解析一次**
（任务创建时算出来的 selection 不够用）；令牌 key 不落库、每次现解析（令牌轮换/改额度立刻生效），
解析结果有 60 秒进程内缓存，改网关配置或发新令牌时清掉。

**两个明确的行为保证（都有守卫钉住）**：
1. 网关没启用 / 解析不出令牌 → **回退直连**（学生能正常上课），但 `console.warn` 记一笔
   （回退意味着这一次既没额度闸也没归集，属于必须被看见的状态）。
2. 网关说「额度用尽」→ 明确报 `COMPUTE_QUOTA_EXHAUSTED`，**绝不回退直连**（否则闸门形同虚设）；
   异步任务也**不重试**（重试只会再被拒一次）。

**额度耗尽时，学生看到的是人话**（这条单独说，因为很容易做错）：网关额度耗尽在 HTTP 上是 403，
我们上游的错误归一化会把它判成「认证失败」→ 学生看到的是
「AI渠道认证失败（HTTP 403）。请在管理后台重新填写并保存该渠道 API Key。」
——**把给运维看的话甩给了一个十来岁的学生，而且真因完全不同**。所以：
- 归一化里把「额度用尽」**排在认证失败之前**判，文案是「本节课的算力额度已用尽，请联系老师为本节课增加额度。」
- 这条**不拼上游原文**（`withDetail`）：一拼就把「请重填 API Key」那句又还回去了。
- VibeCoding 的 SSE 出错分支原来直接透 `error.message`（没归一化）→ 现在也归一化了
  （画布那条走 `markJobFailed`，本来就是归一化的）。三条都有守卫（p59 ⑥）。

**用户拍板后的第三刀：算力池 → 按「学生 × 课包」，四种模态共用一个池子**（本轮最后一段）

用户口径（原话）：「按学生 × 课包」+「视频 / 音乐 / 对话 / 图像生成都要算到我们给学生设的这个上限里」。

- **为什么必须搬**：视频与音乐在上游是「提交 + 轮询」的异步任务，走不了 new-api（要写任务插件、

  「一节课 50 元 × 5 节 = 250 元」），之后管理员清空课包预算不会被回填回来。
- **闸门**：`services/computePool.js` 的 `assertComputePoolBudget()`，接在两处**已有的**统一前置上

- **结算**：成功按同一套单价记 `cost_fen`，**失败记 0**（不花学生的钱，但留一条记录）。
  拦的时候与记的时候用**同一个函数取价**，所以两边不会打架。
