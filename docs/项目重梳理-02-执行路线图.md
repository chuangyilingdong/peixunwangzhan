- 版本：2026-09-07
- 工作区：`E:\学习平台正常`
- 当前阶段：受控生产交付稳定化

## P0｜现在必须完成

### A. 对账真实生产状态

- [ ] 记录当前生产 release、commit、数据库备份、服务状态和最近业务验收时间。
- [ ] 以服务器实际配置确认 AI 当前运行模式、启用能力、预算和失败处理；代码能力不能代替生产验收。
- [ ] 确认官网首页登录后的落点始终是官网首页。
- [ ] 清理文档和验收脚本中已失效的学生入口描述。

### B. 账号与权限安全

- [ ] 轮换生产检测账号密码；测试完成后禁用。
- [ ] 清理默认账号、旧会话和无业务必要的管理员权限。
- [ ] 验证平台、机构、教师、学生之间的正向访问和反向越权。
- [ ] 生产发布增加 `node --check`、构建、import smoke、health、数据库完整性检查。

### C. 机构教学闭环

使用专用 UAT 机构和可回滚窗口完成一次完整写入验收：

- [ ] 机构管理员创建教师和学生。
- [ ] 机构管理员给教师和学生配置积分配额。
- [ ] 教师创建班级、配置课程课时、开始和结束课堂。
- [ ] 学生从官网首页登录，登录后仍留在官网首页，再进入课程学习和创作。
- [ ] 学生创建项目、保存版本、提交作品。
- [ ] 教师查看作品、点评/审核，学生看到结果。
- [ ] 学生/教师配额不足、机构余额不足时服务端正确拒绝。
- [ ] 成功消耗从机构积分账户扣减，并写入完整用量流水。
- [ ] 失败、取消、超时和拦截任务不产生错误扣费。
- [ ] UAT 结束后清理测试数据，保存备份和验收报告。

## P0-D｜课程包基础对账

课程包是当前平台的内容资产中心，必须先把配置口径定下来：

- [ ] 平台管理员可以创建课程包、课时和课时素材。
- [ ] 课程包支持草稿、发布、归档和版本变更。
- [ ] 课时支持教学目标、正文、素材、作业和排序。
- [ ] 课时支持课堂能力配置，并且服务端真正校验能力开关。
- [ ] 课程包支持可见范围和机构授权；未授权机构不可见。
- [ ] 已被班级/课堂引用的课程和课时不能被直接删除，只能归档。
- [ ] 机构管理员可以把已授权课程配置到班级，教师只能使用被授权内容。
- [ ] 课程包详情能看到引用班级、课堂、作品和积分消耗。
- [ ] 课程包的版本、授权和变更写入审计。

## P0-E｜课堂画布最小闭环

课堂画布不是首页自由功能，而是“课时—课堂—项目—作品”的教学工具：

- [ ] 课时配置画布能力后，教师开启课堂时能力状态正确下发。
- [ ] 学生只能打开本人所属机构、班级和当前课时的课堂项目。
- [ ] 学生可以创建项目、编辑画布、保存版本/快照和继续编辑。
- [ ] 画布 AI 生成按课时能力、课堂控制、学生配额和机构余额执行。
- [ ] 生成成功才形成资产并扣费；失败/取消/超时不扣费。
- [ ] 学生提交作品后，教师可以查看、点评/审核，学生可以读取结果。
- [ ] 课堂结束后项目、作品、点评、用量和审计均可追溯。
- [ ] 验证跨机构、跨班级、跨学生项目访问全部被拒绝。

## P1-D｜课堂 VibeCoding 建设

VibeCoding 作为独立课堂模式建设，不用占位按钮冒充完成：

- [ ] 定义课时 `VIBECODING` 的教学流程、任务状态和交付标准。
- [ ] 设计学生代码项目、版本、运行、预览和提交数据模型。
- [ ] 设计受控代码运行环境和资源/时间限制；不能直接执行不受控代码。
- [ ] 接入 AI 对话/代码生成，并关联课时能力、用户配额、机构余额和流水。
- [ ] 教师可以查看任务进度、代码版本、运行结果和提交物。
- [ ] 完成代码运行失败、超时、AI 失败、重复提交和权限越权测试。
- [ ] 用一个真实 VibeCoding 课时完成教师授课—学生创作—提交—点评闭环。

## P1-E｜课堂与课程包体验统一

- [ ] 官网首页登录后的学生仍停留在官网首页，再进入具体课程和课堂。
- [ ] 课程包、课时、课堂画布、VibeCoding 入口名称和状态一致。
- [ ] 没有真实运行时的 VibeCoding 课时显示明确不可用状态，不能让学生进入空页面。
- [ ] 教师端只显示自己有权使用的课程、班级、课堂和学生作品。
