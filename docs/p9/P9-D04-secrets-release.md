# P9-D04 环境变量与密钥发布机制（生产版）

- 版本：v0.1
- 日期：2026-09-04
- 适用服务：`learning-platform-production`
- 适用域名：`https://iicili.cyou`

> 本文只定义流程和台账字段，不包含任何真实密码、私钥、Token、密钥值或 `.env` 内容。生产仍使用 `AI_PROVIDER=local-mock`；当前没有真实 AI、支付、OSS、短信、邮件或微信密钥需要伪造或接入。

## 1. 当前发布原则

1. 生产配置只在服务器受控路径维护，服务用户按最小权限读取。
2. 凭据不进入 Git、GitHub Actions 日志、前端构建产物、截图、工单或聊天。
3. 生产发布必须人工批准；CI 只负责验证和产出候选制品，不自动部署。
4. 配置变更与代码发布分离记录：记录时间、负责人、原因、影响、回滚方式和验证结果，不记录值。
5. 任何密钥轮换都必须先准备回滚窗口，再执行服务重启和健康检查。

## 2. Secret 分类台账（值不落文档）

| 类别 | 典型变量 / 资产 | 当前状态 | 存放与负责人 | 轮换触发 |
|---|---|---|---|---|
| 认证 | `AUTH_PEPPER` | 生产受控 | 服务器安全配置；授权运维 | 泄露、负责人变更、定期轮换 |
| 服务器访问 | Deploy / SSH key | 生产只读拉取资产保留 | GitHub / ECS 受控权限 | 人员离职、权限变化、泄露 |
| Cookie / 会话 | `COOKIE_SECURE`、会话配置 | 由部署模式控制 | 生产配置 | 域名 / HTTPS / 会话策略变化 |
| AI | `AI_PROVIDER=local-mock` | 无真实供应商 Secret | 不接入真实 Key | 重新授权真实 AI 时建立独立台账 |
| 支付 / OSS / 消息 | 未接入 | 无生产 Secret | 不创建占位 Secret | 供应商、合同、预算和授权确定后 |
| 管理账号 | `owner` 凭据 | 仅服务器受控凭据文件 | 不进 Git / 文档 / 日志 | 人员变更、泄露、定期轮换 |

真实台账应由授权负责人放在受控密码管理器或服务器权限系统中；本仓库只保留类别、用途、责任人、最近轮换时间和验证记录。

## 3. 发布前检查清单

- [ ] 变更单已批准，明确生产 / internal-test 目标。
- [ ] 变更只包含必要配置；无密码、私钥、Token、`.env` 或前端暴露值。
- [ ] 代码候选通过 CI，commit、构建制品和 release 可定位。
- [ ] Secret 已在目标环境准备，权限为最小读权限。
- [ ] 已确认 internal-test 回滚资产未被覆盖或删除。
- [ ] 已安排发布后 `/health`、systemd、HTTPS 和关键入口验证。

## 4. 轮换 SOP

1. 建立变更记录：Secret 类别、原因、执行人、审批人、计划窗口、回滚期限。
2. 在临时 / internal-test 环境先验证格式和服务启动，不使用生产数据库。
3. 生成新值并通过受控渠道写入生产 Secret 存储；旧值保持可回滚但不可在日志显示。
4. 按版本化 release 执行服务重启或 reload，避免直接编辑运行中的代码。
5. 验证服务状态、`/health`、HTTPS、登录会话策略和相关功能。
6. 在确认新值稳定后撤销旧值，并完成台账记录。任何输出都只能是“成功 / 失败 / 指纹摘要”，不得输出原值。
7. 轮换失败时停止继续发布，恢复旧配置并重新验证；保留审计记录。

## 5. GitHub Actions 使用边界

当前工作流：

- `.github/workflows/ci.yml`：PR / `main` push 验证和制品上传。
- `.github/workflows/production-release-gate.yml`：手动选择 ref，经过 `production-approval` environment 后验证并上传候选制品。

当前不允许：

- 在工作流中写入生产 `.env`；
- 将生产 Secret 打包进 `dist`；
- 在日志中执行 `printenv`、输出 Secret 或上传配置文件；
- 通过 Actions 自动 SSH 到生产服务器部署；
- 用同一把服务器 Deploy key 兼作 Actions 写入权限。
